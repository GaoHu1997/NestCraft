# FEAT-020：自动验证与结果交付

- 类型：Feature（新增能力）。
- 所属 Epic：[EPIC-002 研发需求与交付](../Epic/EPIC-002-研发需求与交付.md)。
- 来源：[CR-016](../../PRD/CR-016-需求派发与自主研发任务系统.md)，2026-11-19 用户要求新增完整需求与设计，未授权本轮真实自动验收、合并或发布。
- 目标用户与价值：使用者派发后收到有 AC 证据与差异的技术交付，失败可有限返工，批次部分失败时仍能查看独立成果。
- 优先级：P1；负责人：文档代理，集成负责人为主代理；所属迭代：CR-016 设计评审。
- 状态：设计中；正式自动验证、串行集成和交付写回未实现；设计稿待评审，未获用户验收。
- 依赖：FEAT-018 需求/设计/AC 与权限快照；FEAT-019 执行租约、产物基线与调度。

## 范围与边界

包含产物修订绑定的 AC 验证、最终 diff 审查、允许本地分支的串行集成队列、集成后回归、有限返工、批次 succeeded/partial/failed/cancelled 报告和受控 Story 状态写回。默认技术交付使 Story 到「待验收」，「已完成」需要真实用户验收或预授权客观自动验收规则。

不包含以 exit 0 直接完成 Story、把未执行测试标通过、降低 AC、删除失败历史、伪造费用/提交、自动远端操作或生产部署。本轮不执行真实构建/CLI/Git集成/数据库迁移。
