## 用户、问题与目标

个人研发与办公使用者希望在一个工作台内，按项目组织需求、文件和知识，让 AI 在可见、可控的上下文中完成工作。不应因换 CLI 重复配置模型、MCP、技能和工具，也不应因全局知识库共享而让无授权项目获取资料。

- code：以愿景 → Epic → Feature → Story 管理敏捷需求；详细 Story 指导设计、开发、验证和验收，需求树、单页正文预览与设计稿入口相互可追踪。[CR-016](../PRD/CR-016-需求派发与自主研发任务系统.md) 补充在需求中一次派发已确认范围，在项目任务视图追踪自主执行、依赖等待、安全并行和技术交付；这是新增设计目标，不是已经接通的自动任务引擎。
- work：仅办公类型项目，围绕源资料阅读、连续编辑、AI生成与修改审阅、保存成果和导出检查，不强加研发需求树与迭代，不新增全局办公模式。[CR-038](../PRD/CR-038-办公类型项目文档协作.md)细化此闭环；目前仅需求与设计，真实Office能力未实现。
- 知识：按项目授权只读使用，AI 可通过受控检索和阅读工具找到资料并给出来源。
- AI：统一会话侧栏，支持附件、@上下文、/命令、新建与历史，CLI 和模型选择透明；设置一处管理，权限在执行层校验。

## 范围与边界

### CR-022：把研发经验持续沉淀为软件能力

本项目既是被开发的软件，也是研发 agent 工作思想的实践场。用户在开发过程中完善思想；每次反馈先以实际差异更新需求和设计、保留用户已有新设计，再让软件在明确编码授权下逐步承接。不是用现有实现定义愿景，也不是一次性替代全部 agent 能力。

以可追踪诉求／事实、明确工作层级与授权、按需委派、安全并行、真实验证／用户验收分离、反馈闭环为核心；已有派发和协作能力复用，不重复规划平台。新增工作包与视觉证据门禁分别由 [STORY-054](Story/STORY-054-Agent规则与分层授权工作包.md)、[STORY-055](Story/STORY-055-设计覆盖与视觉证据门禁.md)承接，范围以 [PRD-002 CR-022](../PRD/PRD-002-需求派发与自主执行.md#cr-022研发-agent-思想的渐进承接) 为准；当前只需求设计，真实执行门禁未实现。主原型仍是 [同一固定入口](../UI/仿真原型UI.html)，不会随迭代换位置。

CR-015 起实现载体为 [Tauri 正式应用](../PRD/CR-015-启动Tauri正式实现.md)，已有模块实际状态与限制见 [REPORT-008](../Test/REPORT-008-Tauri正式实现验证.md)；旧 HTML 仿真冻结保留。CR-016 当前交付任务系统需求、技术/UI/数据/测试设计和独立本地评审稿，新持久化 runner、DAG、受管 CLI 自动执行、集成和验收尚未实现。未扩大到团队协作、登录角色系统、知识库编辑、向量检索、自动生产发布或任意 CLI 无条件兼容。

本轮任务系统需求源见 [PRD-002](../PRD/PRD-002-需求派发与自主执行.md)；Story 状态/AC 与运行状态/证据分别由需求正文和执行存储承担权威。一次授权范围内免逐步人工调度，不意味着 AI 可修改业务目标、放宽权限或自动取得验收授权。

## 成功指标与关联

- 用户可在一个页面读完愿景、Epic、Feature 与 Story 正文，并从树打开详细文档和适用设计稿。
- 无授权项目的 AI 在列表、搜索、阅读与引用入口均拿不到该知识库信息。
- 同一份全局配置通过受管适配提供给不同 CLI；无法满足能力时明确阻止，不悄悄换模型/引擎。
- 需求、设计、数据方案、验收标准和验证状态可追踪，技术验证与用户验收分开。

各项指标由上述 Epic 和所属 Story 细化；真实产品的性能与成功率指标待实现阶段有测量条件后建立，不虚构指标已达成。
