# STORY-055：设计覆盖与视觉证据门禁

- 类型：用户故事（现有验证交付能力细化）；所属：[FEAT-020](../Feature/FEAT-020-自动验证与结果交付.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)；来源：[CR-022](../../PRD/CR-022-存量设计回填与Agent思想承接.md)，2026-11-19 用户要求 agent 研发思想由软件逐步承接；[AGENTS](../../../AGENTS.md) 的设计先行与视觉验证为当前规则来源。
- 负责人：lead；优先级：P1；状态：设计中；依赖：[STORY-038](STORY-038-多粒度需求派发与执行准入.md)、[042](STORY-042-自动验证集成与有限返工.md)、[043](STORY-043-批次交付与验收依据.md)。[STORY-050](STORY-050-设计先行规则与一致性核对.md) 仅是规则维护，不代表已有软件拦截器。
- 目标：作为研发使用者，我希望系统分别证明能否按稿开发、是否有证据表明软件符合稿件，而不是只给一个设计链接或构建成功。
- 包含：页面／状态覆盖、版本继承、适用授权、成对证据、差异阻止放行和历史失效。
- 不包含：本次编写像素回归软件、运行正式应用、修改正确新设计去匹配错误实现、测试后放宽标准。

## 验收标准

- AC-STORY-055-01：界面任务逐场景列出页面、弹窗、菜单、展开区和适用状态；各项有可打开设计资源、有效版本／确认与替代边界。缺稿或冲突明确拒绝该部分开发，不影响无关合格任务。
- AC-STORY-055-02：新稿未包含已授权存量界面时标待补，不自动取消旧能力；用户已修改设计保护，不以软件截图、共享 CSS 或旧实现反向覆盖它。
- AC-STORY-055-03：视觉证据绑定设计／实现版本、同一视口／缩放／主题／数据／状态和环境，保存设计与软件成对截图或可复核叠加及差异结论；功能、DOM 和构建通过不能代替视觉通过。
- AC-STORY-055-04：未运行正式软件、少一侧证据或仍有未解决视觉偏离时，记录未执行／失败及下一步，不满足对应交付／完成门槛；纯设计交付只验证设计，不声称软件一致。
- AC-STORY-055-05：设计／实现／验证条件变更后旧证据保留历史但不能放行新版本；容许差异与阈值事前确定，不能验证失败后临时扩大。
