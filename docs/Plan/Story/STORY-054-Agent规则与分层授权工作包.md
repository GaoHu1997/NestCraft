# STORY-054：Agent规则与分层授权工作包

- 类型：用户故事（现有派发能力细化）；所属：[FEAT-018](../Feature/FEAT-018-需求派发与项目任务追踪.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)；来源：[CR-022](../../PRD/CR-022-存量设计回填与Agent思想承接.md)，2026-11-19 用户要求把开发本项目的 agent 思想补充到需求，随开发经验渐进由软件承接。
- 负责人：lead；优先级：P1；状态：设计中；依赖：[STORY-038](STORY-038-多粒度需求派发与执行准入.md)、[041](STORY-041-CLI隔离执行与故障恢复.md)、[022](STORY-022-按需子智能体与用量统计.md)。
- 目标：作为研发使用者，我希望自己和受派代理能看清任务遵循什么规则、当前授权做什么，以免确认设计被自动解释成修改正式软件。
- 包含：适用规则／版本、任务工作层级、授权来源、可读写范围、委派必要性与继承、重检／交接。
- 不包含：新建聊天或编排平台、自动授权、实现执行层拦截、扩大父授权、真实开发／构建／发布。

## 验收标准

- AC-STORY-054-01：预检工作包展示并绑定适用项目／目录规则的来源和 hash、唯一 Story／AC／设计引用、需求／设计／正式开发工作层级、允许读写范围、授权原话／范围／时间；缺项或冲突给原因并拒绝受影响步骤。
- AC-STORY-054-02：仅需求或设计确认及一般“继续／执行”不能放行正式源码、依赖、运行配置、构建／发布产物写入，也不能转成 implement。已有设计确认、旧编码授权或上层标题不自动覆盖本次范围。
- AC-STORY-054-03：明确编码授权只允许其具体范围；软件验证／构建、本地集成、远端、生产发布各核对对应有效授权。新业务决定、权限、成本或 AC 变化回需求变更，不悄悄扩权。
- AC-STORY-054-04：先判断是否需要委派，再评估独立性／依赖／风险与真实难度；子工作包携带目标、规则、上下文、产物和验证条件，范围只能缩小，不能因为点名 CLI 绕过门槛。
- AC-STORY-054-05：规则／需求／设计变化使对应旧包失效待重检；保留当时快照与未提交工作保护信息。交接含状态、已完成、实际验证、遗留和下一步；软件逐步承接不创建第二事实正文。

## CR-031：规则分层与有限修复

- 来源：[CR-031](../../PRD/CR-031-受管执行可靠性需求与实施分解.md)，2026-11-19用户要求整理完整可执行需求／方案；负责人lead，状态设计中，仅文档。
- AC-STORY-054-06：给定可信宿主baseline、授权项目根及范围内祖先/子目录AGENTS.md、已选Skill规则，当RuleResolver编译工作包及子计划时底线常驻，规则按规范目录段/阶段/范围选择并记录source/hash/理由/输入修订，CR027设计工具不能代读规则。必需源不可读/未接入阻塞，子目录规则变化使scope相交Plan待重检，独立兄弟Plan保持有效，根规则影响全项目；授权底线不可被更深规则放宽，自然语言冲突标RULE_CONFLICT不自行择有利版本；摘要/缓存不恢复撤权。
