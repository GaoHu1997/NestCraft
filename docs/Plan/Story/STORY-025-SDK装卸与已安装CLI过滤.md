# STORY-025：SDK 装卸与已安装 CLI 过滤

- 类型：用户故事；所属 [FEAT-015 CLI SDK 装卸与会话可用性](../Feature/FEAT-015-CLISDK装卸与会话可用性.md) / [PRD-001 CR-012](../../PRD/PRD-001-个人Agent界面需求.md#cr-012设置中心弹框模型供应商与会话切换sdk-装卸)。
- 来源与确认依据：2026-11-18 用户要求“SDK 管理参考 dsh-maestro-codex，可安装/更新/卸载 SDK，使用官方 logo 作为图标；目前支持 codex / claude / grok 三种；这里安装的与会话框切换的 CLI 类型对应，没有安装的不在切换列表里”。同轮确认：SDK 页只保留三种 CLI SDK，移除能力 SDK 分组。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P0 / 待验收（仿真回归 80/80 通过，等待用户验收）/ 设置弹框、模型候选过滤、会话 CLI 选择。
- 目标：作为工作台使用者，我希望在设置里看到这三个 CLI 的安装状态并直接装卸，以便会话里只出现真正可用的引擎。

## 本次包含 / 不包含

- 包含：SDK 管理只呈现 codex / claude / grok 三张卡（官方 logo 作图标，缺失时用同尺寸占位）；每卡显示安装状态、当前版本、可更新版本、渠道与检测路径；安装、更新、卸载三个操作及其进行中/成功/失败反馈；未安装项不出现在会话 CLI 切换列表；移除原「能力 SDK」（office/code/embed）分组。
- 不包含：真实 npm 全局安装、真实版本探测、真实 registry 查询、真实进程启动。原型用固定步骤模拟，并明确标注未执行真实安装。

## 行为与边界

- 三张卡固定存在，即使未安装也列出（否则无法安装）。未安装时显示“未安装”与“安装”按钮，版本与路径为空占位，不伪装成本地已就绪。演示初始态为 Codex 与 Claude 已安装、Grok 未安装。
- 安装/更新进行中：按钮进入忙碌并禁用重复点击，显示当前阶段（解析版本 → 下载 → 校验 → 完成）；同一时刻只允许一个 CLI 的安装或卸载在进行，避免并发改写同一环境；其余卡的操作给出“另有安装进行中”的提示而不是静默排队。
- 失败：保留上次成功的版本状态不变，显示失败原因与可重试入口；不把失败写成已安装，也不把部分成功当成完成。
- 卸载需行内确认；卸载后该 CLI 立即从会话 CLI 候选消失；若有会话正用该 CLI，这些会话显示“CLI 已卸载”并禁发，历史保留；不回落到其他已安装 CLI。
- 更新：仅当检测到可更新版本时显示“可更新 x.y.z”，执行更新沿用同一忙碌与失败规则；版本来源在原型中标为样例快照。
- 渠道：每卡保留渠道选择（稳定版/预览版/本地），切换渠道不自动安装，只改变后续安装/更新目标并标注为仿真。
- 与会话的一致性：会话 CLI 候选 = 已安装且已启用；安装完成即时出现在候选，卸载即时移出。这条一致性是本轮关键契约，不靠刷新页面实现。
- 官方 logo：codex、claude、grok 各用自己的官方标识作为卡片图标，尺寸统一（同一 viewBox 与视觉重量），不混用项目自身品牌标识；图标只作识别，不暗示官方背书。缺失官方资源时使用中性占位并标注“图标待补”，不臆造近似官方 logo。
