# STORY-073：AI 请求面板与工具结果呈现

- 类型：用户故事
- 所属 Feature / PRD：[FEAT-021 会话中心工作台](../Feature/FEAT-021-会话中心工作台.md) / [CR-054](../../PRD/CR-054-会话中心工作台.md)
- 来源与确认依据：2026-11-21 用户提出“侧栏默认关闭，但是 AI 和用户都可以打开这个侧栏。侧栏提供一些工具给 AI 使用，比如浏览器”；2026-11-22 用户明确第三条决策原话：“右侧开栏 ai 调用的时候可以开了，比如要验证 ui 预览的时候，调用浏览器之类的。除此之外就是用户点击了会话中的连接（需求/史诗/特性/文件/文件行等）开栏定位”；同日追加“**ai 自动开栏，不需要人工确认**”。**规则已确认。**
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P1 / **验证中（2026-11-23 已实现，待用户验收）** / 依赖 STORY-071 右栏容器、STORY-072 预览与链接定位、现有工具/审批机制、CR-037 运行事件。
- 目标：作为项目用户，我希望 AI 在需要验证时请我配合打开右侧面板展示预览或工具结果，同时我始终保有控制权，以便看到 AI 的依据而不被打断。
- 本次包含：AI **请求**打开只读面板（UI 预览、浏览器类工具结果、文件、需求）；工具执行与结果在右栏呈现；用户关闭优先与防抢焦点；非法/未支持类型拒绝并给可读原因；不扩大工具权限。
- 不包含：内置浏览器/网页抓取/浏览器自动化内核（独立立项）；自动执行未授权操作；新审批体系；跨项目工具结果；AI 自动修改用户正在编辑的文档；AI 强制开栏或绕过用户关闭。

## 验收标准

- AC-STORY-073-01：AI 只能**请求**打开面板，不能直接改动布局状态以外的任何权限；前端按当前页签、用户设置与授权决定是否执行，拒绝时给 AI 可读结果（含原因码）。
- AC-STORY-073-01b：**AI 开栏不需要人工逐次确认**——请求符合规则时直接打开，不弹确认框；用户仍可随时关闭，且关闭后受 AC-02 约束。
- AC-STORY-073-02：用户手动关闭面板后，AI 不得在同一轮自动重开抢焦点；运行中按轮次判定，非运行态按时间窗判定；再次打开需新的用户操作或新轮次请求。
- AC-STORY-073-03：AI 请求打开的目标必须是当前项目内、当前权限可读的只读内容；越权、跨项目或不可读目标明确拒绝并记录原因。
- AC-STORY-073-04：AI 请求的面板类型必须来自受支持清单（UI 预览、浏览器结果、文件、需求）；非法或缺类型必须拒绝并返回原因码，不得打开空白或伪造面板。
- AC-STORY-073-05：面板需显式标注“由 AI 请求打开”，用户可随时关闭；关闭后不残留标签或状态；面板内的消息、步骤与工具卡须与 AI 侧栏同一套结构，不另建外观。
- AC-STORY-073-06：工具执行在右栏或会话步骤区显示名称、状态、耗时与结果摘要；失败显式，不伪造成功；不替代现有步骤/统计口径。
- AC-STORY-073-07：涉及写入、命令执行、网络访问或外部系统的工具仍按现有审批与授权执行；**侧栏打开本身不构成授权**，也不等于允许发起网络访问。
- AC-STORY-073-08：面板打开/关闭/切换不新建会话、不中断执行、不改变当前会话；多会话运行时不串扰。
- AC-STORY-073-09：无权限、目标不存在、工具不可用或审批拒绝时，显式提示且不阻塞会话继续。
- AC-STORY-073-10：浏览器内核不在本 Story 实现；若浏览器类工具由用户自配 MCP 提供，只呈现其结果，不承诺内置能力或登录态处理。
- AC-STORY-073-11：UI 与 LLD 登记版本后，按同条件做设计/软件对照与人工触发实测；未执行不得记为通过。

## 方案与准入

- 方案：原型已实现结构化请求通道 `WorkbenchUI.requestPanel({kind, key})`，返回 `{ok, code, message}`；支持类型 `ui-preview`／`browser`／`file`／`requirement`。原型自检覆盖：请求成功开栏、显示请求来源条、用户关闭后同轮再请求被拒（`declined_by_user`）、非法类型（`unsupported`）与缺类型（`invalid_request`）被拒。正式 LLD 仍需定义 AI→UI 请求的真实来源（工具调用事件或结构化消息）、审计与权限校验。
- UI 准入：设计说明待补（原型已可操作）；正式软件无设计版本登记，不具备编码准入。
- UI / DB：复用现有工具/审批记录；是否需要新事件字段待 LLD；不新建持久化结构。
- 实现位置：正式软件 `src/modules/chat/panelRequest.ts`（通道与四种返回码）、`src/modules/workbench/Workbench.tsx`（订阅与呈现）；原型 `docs/UI/workbench-v4/workbench.js`。未提交。
- 验证结果：原型层已通过 5 项相关断言（C17～C19 等），见 [REPORT-CR054](../../Test/REPORT-CR054-会话中心工作台设计验证.md)；正式软件未验证。
- 验收结论：需求已确认；原型验证通过；正式软件的通道已实现且构建通过，但会话内真实触发与面板呈现未实机验证；**验证中**。
- 遗留事项：浏览器能力的来源、安全边界与网络访问审批需独立立项；AI 请求**已确认不需要逐次人工确认**（2026-11-22），但保留“用户关闭后同轮不重开”与“非法类型拒绝”。

## 实现记录（2026-11-23）

- 后端：`ai_tools.rs` 新增 `open_panel` 工具（registry_id `workbench.open_panel`，风险 low）。只做参数校验与「请求」语义，不写文件、不联网、不扩授权；非法 kind 直接返回可读错误。
- 前端：`ChatPanel` 在收到 `toolUse` 事件且工具名为 `mcp__workbench__open_panel` 时，解析 `{ kind, key }` 并调用 `requestPanel(projectId, req, { currentProjectId, turn })`。
- 复用既有规则（`panelRequest.ts`）：四种返回码、用户关闭后同轮不重开、跨项目拒绝。非 `declined_by_user` 的失败会 toast 提示，不静默吞掉。
- 验证：`node scripts/verify-ai-tools-ui.mjs` 覆盖 `open_panel` 前后端映射一致；`cargo test --offline --lib` 通过。
- 未验证：真实 CLI 会话中模型是否稳定调用该工具（依赖模型行为，需真实账号端到端）。
