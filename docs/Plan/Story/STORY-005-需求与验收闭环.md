# STORY-005：需求与验收闭环

- 类型 / 归属：[FEAT-003 需求维护与交付验收](../Feature/FEAT-003-需求维护与交付验收.md)下的用户故事；规格见 [PRD-001 CR-003](../../PRD/PRD-001-个人Agent界面需求.md#cr-003闭环需求规格待评审尚未实现)。此编号与旧原型中的同号演示数据无关。
- 来源：2026-11-18 用户要求补全需求、闭环和细节，仅确认整理目标，具体规则待评审。
- 优先级 / 负责人 / 状态：P0 / 本轮负责代理 / 待确认。
- 用户价值：作为个人工作台使用者，我能从一条需求追溯范围、交付物、验证和验收；失败时知道下一步，而不是只能不断点「推进」。
- 范围：code 的「需求与迭代」、需求树与详情、交付物链接、缺陷复验、状态记录与迭代统计；仅仿真。CR-004 已明确模式，本文的附加规则仍待评审。

## 验收标准

| 编号 | 给定 / 当 | 则 |
| --- | --- | --- |
| AC-STORY-005-01 | 在空 code 项目新建 Story；缺少归属、标题或目标时提交；随后填齐创建字段，在缺 AC 时提交确认 | 缺创建字段不建记录；创建后为待澄清；缺确认材料保持原状态并标出缺项；确认拒绝后保留原因并退回待澄清，确认且依赖满足后才进入已就绪。 |
| AC-STORY-005-02 | Story 正在设计或开发，但缺少设计依据或本次交付版本；补齐后从 Story 打开交付物再返回 | 缺材料无法进入下一阶段；链接能打开指定交付版本，返回后仍选中原 Story。 |
| AC-STORY-005-03 | 正在验证的交付版本有必验 AC 未通过，或存在关联阻塞缺陷；登记失败，修复后进入复验 | 不可提交验收；验证失败回开发中并保留旧结果；缺陷提交修复后仍阻塞，只有同版本复验通过才关闭；复验失败继续阻塞。 |
| AC-STORY-005-04 | 处于待验收，用户选择退回、关闭对话或批准 | 退回理由必填，按原因回开发、设计或待澄清；关闭对话不改状态也不留下结论；批准且当时依然满足条件才完成，记录交付版本、证据与结果。 |
| AC-STORY-005-05 | 待验收时改变交付版本，或改变范围/AC | 旧提交流程停止，历史记录继续可查。交付变更后进入验证，旧结果不可用于新版本；范围/AC 变化后回待澄清，重新确认和验证。 |
| AC-STORY-005-06 | 将实施中的 Story 标记阻塞后解除；另取消 Story 或完成本次验收 | 阻塞与解除有原因及原状态；解除恢复原阶段；取消不计完成、保留记录；迭代计数与详情一致，分母为 0 有明确反馈；不提前完成父项。 |

## 评审走查示例

网关项目的 Story「扩展健康检查」有两项 AC：返回服务标识，保留旧状态字段。交付 V1 时发现旧状态字段缺失，记录 AC-02 失败并关联缺陷，Story 回开发中；提交 V2 修复后缺陷仍为待复验。对 V2 重新检查两项 AC，复验通过并关闭缺陷后，Story 可提交验收。验收人若发现业务范围遗漏，以「范围不完整」退回待澄清；补齐并重新确认后，V3 另起验证记录。最终批准 V3 时，V1 的失败、V2 的退回和 V3 的验收仍可同时追溯。

- 依赖：评审确定取消统计口径与已验收后变更处理；复用原型已有项目、文件、需求树入口。
- 验证与交付：待确认后编写 LLD/UI 和可操作原型；按上述用例逐项执行，当前未实现、未做功能验证。
