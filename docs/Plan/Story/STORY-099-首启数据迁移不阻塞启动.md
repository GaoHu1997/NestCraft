# STORY-099：首启数据迁移不阻塞启动（BUG-001）

- 类型：缺陷修复
- 所属 Feature / PRD：[FEAT-001](../Feature/FEAT-001-工作台框架与可操作评审.md) / [CR-081](../../PRD/CR-081-本地数据统一存储.md)
- 缺陷编号：BUG-001
- 来源与确认依据：用户 2026-11-25 报告「exe 启动摆平，提示未响应」。现场取证：便携版 `D:\devlop\NestCraft_portable\NestCraft.exe`（0.0.5）首次启动把 `%APPDATA%\com.agentworkbench.app`（11617 个文件 / 3.5 GB）同步复制到 `data`，Windows 于 14:27:22 记录 `AppHangB1`（WER 报告界面文本「栖造 未响应」），用户点「关闭程序」；14:28:04 重启后完成。用户同日明确回复「授权修改代码」。
- 负责人 / 优先级 / 状态 / 依赖：lead / 高 / 验证中 / 依赖 CR-081 已实现的数据根与迁移机制。
- 目标：作为使用便携版或切换数据存储位置的用户，我希望首次启动尽快进入窗口、不出现「未响应」，并且迁移被打断后下次启动能补齐，而不是永久缺失会话数据。
- 本次包含 / 不包含：
  - 包含：启动同步迁移不再搬 `chat/<cli>-profiles`；迁移改为逐文件合并（可续传、不覆盖）；后台上传并写启动日志；单测覆盖。
  - 不包含：新增启动进度窗口或前端「正在准备数据」提示（无界面变更）；不迁移第三方 CLI 家目录；不改数据根配置语义与设置页；不删除用户既有数据。
- 验收标准：
  - AC-STORY-099-01：启动同步迁移路径不包含 `chat/<cli>-profiles`，该类目录只进入后台待迁清单。
  - AC-STORY-099-02：迁移改为逐文件合并；目标已有文件保留，缺失文件补齐；中断后再次启动继续补齐。
  - AC-STORY-099-03：后台续传在窗口与数据库就绪后执行，写 `<root>/logs/startup.log`（同步耗时、待迁条目、后台完成耗时）。
  - AC-STORY-099-04：既有迁移语义不退化：分类落位、目标存在不覆盖、二次执行幂等、无关文件不搬、同根不处理。
  - AC-STORY-099-05：数据库仍最后打开（迁移核心数据完成后 `db::init`），不出现两库分叉。
- 方案：[LLD-CR081 §BUG-001](../../LLD/LLD-CR081-本地数据统一存储.md)。
- UI 准入（涉及界面时）：**不适用**——本次不加弹窗、进度窗、文案或布局，启动窗口与首屏结构不变；无视觉/交互变化，故无新增设计稿要求。若后续要加「正在准备数据」提示，须按 §6.3.1 先出可视设计。
- 实现位置 / 提交或 PR：`src-tauri/src/storage_layout.rs`（`migrate_on_startup`／`merge_path`／`spawn_deferred_migration`／`log_startup`）、`src-tauri/src/lib.rs`（setup 启动段）。
- 验证结果：见 [REPORT-BUG-001](../../Test/REPORT-BUG-001-首启迁移未响应修复验证.md)。`cargo test --lib storage_layout` 4/4、全量 `cargo test --lib` 538 通过 / 0 失败 / 8 忽略、`cargo check --all-targets` exit 0；全新 exe 目录 + 真实 3.5 GB 源实测：窗口 3806 ms 出现、全程 Responding、同步迁移 1887 ms、后台待迁 3 个会话目录。**未验证：release 便携版 exe 重建、3.3 GB 会话存储完整后台迁移耗时。**
- 验收结论及依据：**待验收**（技术验证通过范围如实登记；真实便携版二次首启场景由逻辑与单测保证，未重跑 3.5 GB 全量迁移）。
- 阻塞、遗留事项和下一步：无阻塞。历史中断留下的半份 `data\chat\codex-profiles` 由新代码在下次启动后台续传补齐；用户也可自行用 robocopy 补齐。用户验收后更新状态。
