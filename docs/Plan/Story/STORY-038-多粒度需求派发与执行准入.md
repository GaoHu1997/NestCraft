# STORY-038：多粒度需求派发与执行准入

- 类型：用户故事（新增能力）。
- 所属：[FEAT-018 需求派发与项目任务追踪](../Feature/FEAT-018-需求派发与项目任务追踪.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)。
- 来源与确认依据：[CR-016](../../PRD/CR-016-需求派发与自主研发任务系统.md)，2026-11-19 用户要求按完整设计增加需求和设计稿；仅本轮文档与评审产物获执行授权。
- 负责人：文档代理；优先级：P1；状态：设计中；依赖：需求正文/索引、可执行设计、配置与授权；受管引擎由 STORY-040/041 实现后接入。
- 目标：作为研发使用者，我希望在需求页按故事、特性、史诗或当前范围的全部合格需求一次派发，以便在明确授权边界内自动研发。
- 本次包含：范围解析、准入原因、外部依赖提示、CLI/模型/难度/预算策略、快照及幂等。
- 不包含：自动扩入后续需求、任务页派发、真实 CLI 开发、真实账单、迁移或远端操作。

## 验收标准

| 编号 | 可观察标准 | 验证方式 |
| --- | --- | --- |
| AC-STORY-038-01 | 给定 code 项目，当选择 Story/Feature/Epic/全部合格范围，预检只展开当前项目当前选定范围的叶子 Story，并列出选中范围、合格集合和排除原因；work 项目不出现研发派发。 | 范围解析测试、UI 操作 |
| AC-STORY-038-02 | 给定未确认、缺设计或设计不可执行、有待同步草稿、已完成或已取消的 Story，当预检时，该条被排除且不创建执行任务；范围内零合格条目时确认禁用。 | 准入参数化测试 |
| AC-STORY-038-03 | 给定准入通过的范围，当确认派发时，冻结 Story 集合、需求/设计/AC hashes、代码基线、授权策略版本；后续新 Story 不加入，基线改变时旧预检确认返回 BASELINE_CHANGED 并要求重检。 | 快照与并发修改测试 |
| AC-STORY-038-04 | 给定范围外前置，当没有可消费的有效产物或独立执行授权时，预检说明缺失依赖并排除受影响任务，不自动扩大范围；循环依赖拒绝整个候选 DAG。 | 外部依赖/环测试 |
| AC-STORY-038-05 | 给定相同幂等键与相同请求，当重复确认时返回同一批次；不同请求复用同键报错；同项目同 Story 同基线已有活动任务时拒绝重建并定位现有任务。 | 幂等与并发事务测试 |
| AC-STORY-038-06 | 给定用户指定 CLI/模型，当其不在允许集、缺必要能力/最低难度、权限控制不可强制或预算不足时拒绝执行；UI 显示具体门槛，不能因点名绕规则或静默更换。 | 能力/策略门槛测试 |
| AC-STORY-038-07 | 给定合格范围，当一次确认时记录最大并发、预算类型及上限、重试/返工上限、权限和默认终点「技术验证后待验收」；无预授权客观自动验收不提供自动完成依据，默认不推送/保护分支合并/发布。 | 授权记录审阅 |
| AC-STORY-038-08 | 给定预检加载失败、配置失效或用户取消确认，当退出时未创建批次/进程/写入副作用，错误可重试且取消恢复焦点。 | 失败/取消 UI 与接口测试 |
