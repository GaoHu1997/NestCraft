- 当前状态（2026-11-24）：已有平台通道实现并合入main（`0b39d40`），真机／视觉及原AC-11重试等遗留不冒充通过。下文状态/验证为建立时历史，原确认和AC保留。新增上下文工作归 [STORY-094](STORY-094-平台会话完整历史与预算.md)/[STORY-093](STORY-093-分层摘要与安全原文找回.md)，不改本故事历史验收。
- 历史负责人 / 优先级 / 状态 / 依赖：主代理 / 高 / 待确认 / 依赖 FEAT-014 供应商模型配置已实现（`providers.rs`）、FEAT-015 的 CLI 路径保持不变。
- 目标：作为项目使用者，我希望不先选择 CLI 就能开始对话，以便平台已配置的模型与能力可直接使用。

## 本次包含

1. 会话运行通道字段 `runner`（`cli` | `platform`），旧记录默认 `cli`。
2. 平台模型调用客户端：支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议的非流式与流式请求。
3. 会话发送分派：`runner=platform` 走平台通道，`runner=cli` 保持现有 `chat_send` 完全不变。
4. 上下文编译复用：知识、Skill、文件引用、需求引用的校验与注入逻辑沿用现有实现。
5. 流式事件回传：复用 `ChatEvent` 枚举，前端不需要新增事件类型即可显示增量。
6. 落库复用：助手消息、工具消息写入沿用 `insert_assistant_messages`。

## 本次不包含

- 工具调用循环（STORY-090）。
- 派发工具（STORY-091）。
- 真实 worker 执行。
- CLI 路径的任何行为变更。
- 协议转换（例如 Anthropic 模型接 OpenAI 端点）。
- 新 UI 设计；界面改动另行准入。

## 验收标准

- AC-STORY-089-01：给定未安装任何 CLI，当用户新建 `runner=platform` 会话并发送「你好」，则收到模型回复，且消息落库；刷新应用后该回复仍在。
- AC-STORY-089-02：给定会话 `runner=cli`，当用户发送消息，则走现有 `chat_send` 路径，CLI 未安装时报错文案与现状一致，不出现平台通道行为。
- AC-STORY-089-03：给定供应商已停用，当 `runner=platform` 会话发送，则拒绝发送并提示该供应商已停用；不自动改用其他供应商。
- AC-STORY-089-04：给定供应商缺少与协议匹配的启用端点，则拒绝发送并明确说明缺少哪种协议的端点。
- AC-STORY-089-05：给定供应商缺少可用密钥，则拒绝发送并提示在设置中补充；错误信息不含密钥内容。
- AC-STORY-089-06：给定会话绑定的模型协议为 anthropic，则请求发往 Anthropic Messages 端点且使用 `x-api-key` 与 `anthropic-version`；为 openai 时发往 chat/completions 且使用 `Authorization: Bearer`。
- AC-STORY-089-07：给定模型支持思考档位且会话选择了档位，则请求按该档位下发；`null` 映射表示不下发该参数（对齐 `models.rs:197-198`）。
- AC-STORY-089-08：给定回复生成中，则前端按增量显示文本；文本结束前不写入完整消息；结束后一次性落库并更新会话 `updatedAt`。
- AC-STORY-089-09：给定本轮上下文（引用＋附件）超过上限，则拒绝发送并提示减少引用，草稿保留。
- AC-STORY-089-10：给定引用包含未授权知识库文件，则拒绝注入；错误信息明确为授权问题，不返回文件内容。
- AC-STORY-089-11：给定流中断且错误为限流或服务暂时不可用，则按现有重试判定重试；401/403 等认证错误不重试。
- AC-STORY-089-12：给定用户停止运行，则停止请求生效，已产生文本归档，不标记为成功。
