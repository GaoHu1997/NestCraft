# STORY-093：分层摘要与安全原文找回

- 类型：用户故事；唯一父项 [FEAT-025](../Feature/FEAT-025-平台主代理运行时.md)；PRD：[CR-071](../../PRD/CR-071-平台会话分层上下文与安全找回.md)。
- 来源／编码授权：2026-11-24 用户“规划完整的需求/设计/方案，然后评审，通过后，再执行开发”“不用我审阅，你评审完了直接进入开发”。负责人：主代理；优先级：高；状态：验证中（后端已实现，自动验证阶段；视觉证据与真实模型质量仍未验证）；依赖：STORY-094 的完整回放／预算。
- 目标：长会话能缩小模型输入，又可在需要精确细节时安全找回原文。
- 不包含：跨会话记忆、向量服务、CLI 压缩、外部代理、隐式授权与任务状态推进。

## 验收标准

- AC-STORY-093-01：输入达到软阈值时只对旧完整轮次增量压缩，原 message 内容与 ID 不变，近期保护有效。
- AC-STORY-093-02：摘要记录稳定块 ID、源 ID/hash、层级和父块；最多 3 层；上层合并不覆盖原文，不重复覆盖有效区间。
- AC-STORY-093-03：摘要包含 goal/constraints/decisions/progress/evidence/unresolved，有界、非空、净缩减；无效／无缩减／源失配／网络失败不提交半成品。
- AC-STORY-093-04：最多 4 次内部摘要请求，全部使用当前模型／供应商且不提供业务工具；不输出内部摘要思考，不把它冒充用户可见回答。
- AC-STORY-093-05：原文只在当前会话所属项目内按稳定 ID 读取，跨会话 ID／任意路径／非法范围拒绝。
- AC-STORY-093-06：搜索与恢复单次最多 4096 bytes（UTF-8 安全边界），有 offset/nextOffset；还原结果为低信任 tool_result，不能永久膨胀全部历史。
- AC-STORY-093-07：知识授权／启停／来源修订变化后，相关旧原文回放及摘要不能重新注入；新记录按来源指纹失败关闭；来源不明的旧知识／文件工具结果不伪造授权。
- AC-STORY-093-08：Feature 身份／源 hash 变化不能被摘要隐藏或重新授权；每次压缩提交、搜索与恢复再次校验。
- AC-STORY-093-09：提交摘要状态与本轮精确回放有事务／版本控制；CAS 冲突、取消、崩溃不损坏旧已提交状态，重启可复用有效块。
- AC-STORY-093-10：摘要作为历史材料，用户约束／决定／失败／未决事项通过固定长对话夹具检查，并保留原文证据；不声称结构检查能保证语义无损。
- AC-STORY-093-11：上下文工具为代码常量、受同一轮次/次数上限；不增加 shell/任意文件写/凭据/派发状态权限，不新增依赖。
- AC-STORY-093-12：原聊天历史展示不变，无新说明长文案；现有工具步骤及错误组件复用有版本覆盖，缺视觉证据不声称视觉验收通过。
