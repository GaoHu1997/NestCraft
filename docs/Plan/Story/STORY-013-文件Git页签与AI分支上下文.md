# STORY-013：文件/Git 页签与 AI 分支上下文

- 类型：用户故事；所属 [FEAT-007 文件草稿与分支上下文](../Feature/FEAT-007-文件草稿与分支上下文.md) / [PRD-001 CR-006](../../PRD/PRD-001-个人Agent界面需求.md#cr-006文件git-页签与-ai-当前分支)。
- 来源/确认依据：2026-11-18 用户追加 code 编码与 work 左侧竖向文件/Git tab、Git 管理，并要求 AI 对话框显示当前分支。仅需求/设计和仿真，不执行真实 Git。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P0 / 设计中（仿真待评审）/ 项目工作目录、现有文件预览与 AI 会话；真实阶段需受管 Git 状态与操作服务。

## 价值与范围

作为研发或办公项目使用者，我希望在左栏切换文件和 Git 管理，并在 AI 输入区看到当前分支，以便同时管理资料与版本，避免 AI 在错误分支生成或应用修改。

- code 编码、work 文档左栏内部增加竖向“文件 / Git”，中央和右侧结构不变；切换保留所选文件、草稿、预览和会话，偏好按项目隔离。code 需求 tab 不增加文件栏。
- Git 最小管理：仓库与分支、刷新、未暂存/已暂存修改及 diff、暂存/取消暂存、提交信息/提交、搜索本地/远程分支、切换/新建分支、近期提交、提取/更新/推送入口。模拟行为明示，真实网络/提交/分支操作另按权限执行。
- 不包含：强推、reset/clean、自动stash、删除分支/worktree、标签/网络加速/自动导入凭据等参考工具全量能力。不自动初始化无仓库项目。
- 脏修改或未保存草稿阻止切分支并提示先处理，不自动丢弃；冲突或被其它 worktree 占用不能假报成功；无 remote/upstream/历史/修改和读取失败有对应状态。
- AI 常驻当前分支 chip，来源为项目实际工作目录状态，包含 repo/worktree 与 HEAD 基线。未初始化、读取中、未知/失败、detached HEAD 分别显示；不能硬编码 main，服务器会话不冒称项目分支。
- 发送/提案冻结当前 branch/HEAD/revision，批准复检；切分支或同分支 HEAD 变化使旧提案失效。历史保留消息当时分支，但恢复历史不会切回旧分支，当前显示仍取当前工作目录。
