# STORY-064：主界面按评审意见重构

- 类型：用户故事（界面设计）；仅需求／可操作设计，不是正式软件开发。
- 所属 Feature：[FEAT-001](../Feature/FEAT-001-工作台框架与可操作评审.md)；PRD：[CR-036](../../PRD/CR-036-主界面按评审意见重构.md)。
- 来源与确认依据：2026-11-19 用户提交 16 页 PDF 修改意见（`docs/未命名.pdf`），要求按意见调整 UI 并同步修改需求；指令作为本批设计范围确认，不是正式编码授权。
- 负责人 / 优先级 / 状态 / 依赖：lead / 高 / 开发中（2026-11-20 BUG-013，全量照稿修复；尚未验收） / CR-035 的视觉基线与既有仿真数据。
- 本次正式编码授权：用户明确要求「据新的进行开发和调整」，继而指出品牌／AI 不符并要求「其他的也需要检查」。工作层级为正式软件修复与验证；采用 UI-CR036-v4、UI-BRAND-001-v2、AI-CR042、办公-CR043，具体版本 hash／范围／审查及实际结果见 [REPORT-BUG013](../../Test/REPORT-BUG013-全量设计对齐.md) 与 [LLD-FEAT-002 §0](../../LLD/LLD-FEAT-002-Tauri正式实现方案.md)。用户可視资源不改、不扩服务器操作授权，不删除历史记录；未就绪的级联／执行核心保留阻塞，不能用样例冒充完成。
- 目标：作为工作台使用者，我希望按我的评审意见调整后的原型可以直接操作所有流程，而不是只弹提示，以便确认信息架构、交互细节与数据形态后再进入正式开发。
- 本次包含：工作台页；项目卡片与目录选择；需求树整宽与行尾菜单；设计三栏一体；任务 CLI 标识；编码三栏与 Git 面板；AI 侧栏体系；知识库授权与树形阅读；服务器满高三栏；设置固定弹窗与模型／CLI／能力配置。
- 本次不包含：正式软件源码、依赖、构建或发布；真实 SSH／CLI／Git／模型连接；真实文件系统选择器；CR-026 并行执行计划桥接的合并。

## CR-044：窗口、品牌、图标与对齐（2026-11-20）

用户本轮明确先需求／可视设计再代码调整；复用已选帆船与现公共壳，UI-CR044-v1局部替代旧品牌承载底、字母CLI标识及导航。方案与资源登记：[CR-044](../../PRD/CR-044-窗口融合图标与Tab导航.md)／[UI-CR044](../../UI/文档/UI-CR044-窗口图标与导航规范.md)，旧确认和验证保持历史。

- AC-STORY-064-26：界面显示原选定透明帆船，无底色／边框／阴影，中英文独立排版；快捷方式和任务栏使用独立有底PNG／ICO，不以UI透明图替代系统资产。
- AC-STORY-064-27：平台现有不合适图标替换为统一已登记资产；图标样例仅置于UI规范文档，覆盖语义／尺寸／主题与控件参考，不在平台或业务原型新增展示页面／入口／弹窗；未知图标不能默默退化为其他语义。
- AC-STORY-064-28：按钮尺寸、图标文字中心线、弹窗档位、颜色和1px分割线按统一规格；项目内部44px页签与AI44px头对齐，详情栏40px从最左开始，浅深／窄屏没有遮挡关键控件。
- AC-STORY-064-29：CLI在模型选择、SDK／CLI配置、任务／子智能体等位置使用可核官方品牌图形并保留比例／许可，不使用字母块或自绘近似作为官方Logo；无独立CLI标志时准确说明使用官方厂商标志。
- AC-STORY-064-30：桌面顶栏与主题融合，只有一套名称／窗口操作区；最小化、最大化／还原、关闭、拖动／双击与resize正确；按钮不被drag热区吞掉，关闭有未保存提示，失败如实反馈。浏览器原型只能标仿真，不冒充原生窗口验证。
