# STORY-012：统一配置与 CLI 能力适配

- 类型：用户故事；所属 [FEAT-014 供应商模型与能力适配](../Feature/FEAT-014-供应商模型与能力适配.md) / [PRD-001 CR-005](../../PRD/PRD-001-个人Agent界面需求.md#cr-005项目知识授权与统一-ai-工作台)。
- 来源与确认依据：2026-11-18 用户要求设置配置的模型、MCP、Skill、Tools 给 AI 使用，“一处配置，到处可用”，而不是每个 CLI 重配。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P0 / 设计中（仿真待评审）/ SDK 管理、模型注册与统一网关；真实 CLI 版本能力预检和隔离为接入门槛。

## 用户价值与方案摘要

作为工作台使用者，我希望在设置中心配置一次模型与能力，并由所选 CLI 使用同一配置，以便切换引擎时不复制密钥和服务配置，同时知道能力是否真正可用。

不是“让每个 CLI 读取同一种原生配置文件”，而是“统一配置事实来源 → 授权/能力交集 → 各 CLI 受管适配”。不同 CLI 的配置格式、运行模式和能力差异不能成为用户重复配置的负担，也不能掩盖不支持项。

## 范围与核心规则

- 配置项：模型供应商/baseURL/凭证引用/model/推理档位；CLI 安装/版本/渠道；MCP 的连接信息与启用；Skill 包/命令；Tools schema/风险/开关。凭证集中秘密存储，历史与仓库不存明文。
- 优先级：全局默认 → 项目允许范围 → 会话选择。模型等选择可覆盖默认，权限只能取交集。默认 CLI 不等于每个会话当前 CLI。
- 每次执行构建有效能力快照，展示 CLI/模型/配置版本/适配状态；受管适配器生成临时配置或启动参数，不覆盖用户原生 CLI 配置。
- 能力类别区分 tool/resource/prompt/skill/client-command。工具通过调用网关执行，资源先校验再读取为上下文，prompt 取模板和参数后展开；不能将三者混成同一“工具已调用”。@结构化引用由工作台解析，不假设非交互 CLI 会解析 @ 字符串。
- 状态分开：已配置、已连接、已鉴权、工具发现、已启用、当前 CLI 可适配、不可用。兼容矩阵为原生/网关适配/不支持/未验证，不能把模拟开关当真实握手。
- 不兼容模型/必需工具/技能时阻止发送，说明缺什么和修复入口；用户明确换 CLI/模型后再执行。不得静默回落、忽略技能、换模型或放松权限。
- 保存后新请求用最新配置；运行保持模型/provider 启动快照并显示版本。能力停用/撤权立即使后续调用和旧待审提案不可执行，必要时终止任务。
- 不包含：自动安装真实 SDK、无条件兼容所有模型/CLI、接入任意全局工具、不受控的外部服务连接。原型只在同一内存配置模拟共享，真实兼容待验证。
