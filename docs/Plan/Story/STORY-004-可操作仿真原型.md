# STORY-004：可操作仿真原型

- 类型：用户故事（设计交付）；所属 [FEAT-001 工作台框架与可操作评审](../Feature/FEAT-001-工作台框架与可操作评审.md) / [PRD-001](../../PRD/PRD-001-个人Agent界面需求.md) CR-002。
- 来源与授权：2026-11-18，用户明确要求调整风格、补设计漏洞，停止交付图片，改为可操作仿真原型。
- 优先级 / 负责人 / 状态：高 / 本轮负责代理 / 待验收。
- 目标：在浏览器实际操作工作台，验证常见路径和失败分支；不接入真实服务，不扩展未确认的产品规则。

## 验收标准

- AC-STORY-004-01：用项目卡片、搜索和类型筛选找到项目；创建项目后进入正确的工作区，能返回列表。设置不在左侧常驻展开。
- AC-STORY-004-02：在 work 项目能选择需求、查看缺陷、记录验收结果并推进状态；验证未通过或有未关闭阻塞时不能推进到待验收；到已完成需确认，迭代进度随状态重算。
- AC-STORY-004-03：code/work 能选择文件并看到对应内容；仿真 AI 可读取上下文或给出变更提案，拒绝不变更，确认仅修改仿真数据。
- AC-STORY-004-04：服务器可模拟连接、离线失败、授权与撤回、巡检及高风险审批。拒绝、取消、关闭授权或禁用 ssh-exec 都不能执行待审操作；不发送网络请求。
- AC-STORY-004-05：模型默认值与思考档位、引擎和 Skill/MCP/Tools 设置可操作并联动对应入口；无搜索结果及取消操作有合理反馈。
- AC-STORY-004-06：直接打开 HTML 无需依赖或服务器；1440×900 与窄视口不出现全页横向溢出；演示状态能恢复初始值；原设计图入口导向仿真原型。

- 方案：[LLD-FEAT-001](../../LLD/LLD-FEAT-001-仿真原型.md) / [UI-FEAT-001](../../UI/文档/UI-FEAT-001-界面设计.md)。
- 实现：[交互原型](../../UI/prototype/index.html)。
- 验证：六项 AC 已通过本地 Chrome 自动化验证，见 [REPORT-001](../../Test/REPORT-001-仿真原型验证记录.md)。
- 验收：待用户试用确认操作与视觉；技术通过不等于用户验收。
