- 类型：用户故事；所属 [FEAT-003 需求维护与交付验收](../Feature/FEAT-003-需求维护与交付验收.md) / [PRD-001 CR-005](../../PRD/PRD-001-个人Agent界面需求.md#cr-005项目知识授权与统一-ai-工作台)。
- 来源与确认依据：2026-11-18 用户要求 code 需求 tab 整体树形列表、弹框查看、详细 Story 文档、愿景/史诗/特性/Story 单页预览和仿真设计稿入口，并授权代理判断存储方式。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P0 / 设计中（仿真待评审）/ 已有需求模型及 [STORY-008](STORY-008-研发与办公工作模式.md) 的研发模式；文档索引为真实实现前置。

## 用户价值与使用场景

作为研发项目使用者，我希望在一棵树里浏览需求、在弹窗阅读详细故事，并一次预览完整需求正文和设计稿，以便评审目标、范围、验收与实现依据而不被目录/详情分栏切碎。

## 范围、正文规范与规则

- 需求内容区是一棵愿景 → Epic → Feature → Story 的树，Bug 挂 Feature 并关联 Story；右侧仍为 AI。移除常驻左目录与中间详情栏，不改变编码工作区的文件/内容/AI 布局。
- 展开与查看是独立动作；详情弹窗可读所有层级，Story 可编辑、查看 AC、关联设计/交付与验证记录、执行既有状态推进。关闭回树并保留节点、展开与定位；打开编码产物后可回原 Story。
- Story 正文最低字段：背景/用户价值、目标、包含/不包含、主流程与分支异常、业务规则/权限、AC、负责人/优先级/状态/依赖、父项与 PRD、LLD/UI/DB、实现位置、验证证据、验收结论、变更/阻塞/下一步。缺少必需字段时标“待补充”，不能以短标题代替文档，也不能虚构通过结果。
- “预览”连续展示愿景、Epic、Feature、所有 Story 正文及关联；不是只有树节点标题或当前选中故事。树、弹窗和汇总从同一源版本生成；汇总为阅读视图，不成为第二事实来源。
- “设计稿”进入该项目适用的仿真设计浏览入口，支持查看页面和返回，不误入真实服务、不重定向循环。
- 正式存储：Markdown 正文在项目 `docs/Plan/`，SQLite 保存派生索引与关系；文件正文为唯一事实来源。AI 和人工编辑先检查源版本再写回，冲突明确提示；重建索引不损坏正文。详见 ADR 与 DB。
- 不包含：新的敏捷统计/验收历史规则、看板、真实编辑器产品或发布；CR-003 的待确认规则保持待确认。work 不因本故事显示研发树。
