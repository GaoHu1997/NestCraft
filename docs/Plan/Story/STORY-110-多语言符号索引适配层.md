## 验收标准

- **AC-STORY-110-01**（统一适配层与三语言声明）：给定一个项目同时含 `.java`、`.cs`、`.py`、`.ts` 文件，当构建符号索引，则每种语言经各自适配器输出**同一结构**的声明条目（名称、种类、文件、行、列），Java 的 `class`／`interface`／`enum`／`record`、C# 的 `class`／`interface`／`struct`／`record`、Python 的 `class`／`def`／`async def` 均被识别，且 **TS/JS 的既有识别结果与 CR-090 一致、不减少**。验证方式：自动化（适配器单测，逐语言夹具）＋ 手工抽查。
- **AC-STORY-110-02**（Java 继承关系）：给定 `class B extends A implements I` 与 `import a.b.*`／同包无 import 的写法，当构建索引，则产出「B 的父类型＝A、I」与「I 的实现者含 B」两条关系，通配 import 与同包引用能连上；**泛型实参（`List<Foo>` 中的 `Foo`）不产生继承边**。验证方式：自动化（Java 夹具）＋ 手工。
- **AC-STORY-110-03**（C# 继承关系归一）：给定 `class D : Base, IFoo, IBar`，当构建索引，则在统一结构里 `Base`／`IFoo`／`IBar` **全部记为「父类型」并可反查子类型**，不尝试区分基类与接口；`using`／`using static` 能解析到项目内命名空间。验证方式：自动化（C# 夹具）。
- **AC-STORY-110-04**（Python 继承关系与「不猜」）：给定 `class C(A, B)`、`from m import A as X`、`class M(ABC)`，当构建索引，则产出基类列表与 import 映射；对**动态绑定**（`getattr`／`setattr`／`globals()`／变量或字符串基类）、`ABCMeta.register()` 虚拟子类、`import *` **不产生任何家庭关系，也不做猜测性连接**，而是在该类型的元数据上标记「可能不全」。验证方式：自动化（Python 夹具，含反例）＋ 手工。
- **AC-STORY-110-05**（失败隔离与只读）：给定项目内存在语法错误文件、二进制文件、非 UTF-8 文件或超大单文件，当构建索引，则**跳过该文件并计数**，其余文件索引正常完成，**不抛未捕获异常、不弹中断对话框、不阻塞编辑、不修改任何文件内容**；跳过数量可在索引进度／诊断入口看到。验证方式：自动化（损坏夹具）＋ 手工（打开损坏文件确认可正常编辑）。
- **AC-STORY-110-06**（规模上限与不阻塞输入）：给定文件数或单文件大小超过上限，当构建索引，则构建**异步分帧进行**、持续输入/滚动/切页签无卡顿（人工判定不出现可感知阻塞），超限时降级为「仅当前文件」或「已索引部分」并在界面标注降级原因；**空项目／无支持语言的项目**返回空索引且不报错、不转圈不停。验证方式：自动化（上限与降级分支）＋ 手工（大仓库计时与输入流畅度）。
