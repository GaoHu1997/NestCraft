# STORY-081：移除内置预置模型供应商
- 类型：维护任务（移除既有功能）
- 所属 Feature / PRD：[FEAT-014](../Feature/FEAT-014-供应商模型与能力适配.md) / [CR-061](../../PRD/CR-061-移除内置预置模型供应商.md)
- 来源与确认依据：用户 2026-11-22 指令「内置供应商移除，其他的先不要动」——明确的动作动词构成编码授权，范围严格限定为移除内置模型供应商。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / 高 / 验证中（自动化与进程级验证通过，待验收）/ 依赖既有 provider 存储（DB-FEAT-001）。
- 目标：移除写入本地库的预置模型供应商「TierFlow（预置，需填密钥）」，新装用户不再看到任何凭空出现的供应商，老装用户的预置遗留被清理，且用户自己配置的供应商完全不受影响。
- 本次包含 / 不包含：见 [CR-061 §2](../../PRD/CR-061-移除内置预置模型供应商.md)。包含：取消预置写入、冒烟链路改为自建供应商。不包含：自动清理老装遗留预置行（用户 2026-11-22 追加指令：老用户自己会删除）、删除用户自建供应商、供应商界面与协议/模型发现/密钥存储行为改动、内置 CLI SDK 改动、内置示例项目与知识库改动、新增供应商模板机制。
- 验收标准：
  - AC-STORY-081-01（预置不再写入）：给定全新空数据目录，当应用启动并完成迁移，则 `provider` 表为空，用户界面不出现任何内置供应商。
  - AC-STORY-081-02（不自动清理遗留行）：给定库中含 `prov-tierflow-default` 及其附属行，当应用启动，则该行原样保留（由用户自行在界面删除），应用不做任何自动删除。
  - AC-STORY-081-03（用户手动删除可用）：给定老装库中的预置供应商，当用户在设置中点击删除并确认，则该供应商被删除，且后端只清理其独占的 secretRef（被其他密钥复用的条目保留）。
  - AC-STORY-081-04（不误删用户数据）：给定库中同时含预置行与用户自建的同名供应商（任意其他 id、同协议同端点），当应用启动或用户删除预置供应商，则用户供应商及其附属行与密钥完整保留。
  - AC-STORY-081-06（冒烟链路可用）：给定设置真实网关密钥的冒烟环境，当冒烟套件执行真实供应商用例，则供应商由套件自建（`prov-smoke-tierflow`）并具备两条端点与 `tierflow` 模型，真实对话与真实工具调用用例继续可用。
  - AC-STORY-081-07（回归）：cargo test 全量通过；npm run build 通过；本机真实库（仅含用户自建供应商）启动后数据不变。
- 方案：[LLD-CR061](../../LLD/LLD-CR061-移除内置预置模型供应商实现.md)；DB 无变更（复用 [DB-FEAT-001](../../DB/DB-FEAT-001-知识授权与工作台数据设计.md)）；UI 不涉及界面变化（供应商列表已有空态「尚无供应商，请新建。」与删除入口，无需新增设计，UI 准入不适用）。
- 实现位置：
  - `src-tauri/src/db.rs`（删除 `seed_default_provider` 及其调用点）
  - `src-tauri/src/commands/smoke.rs`（`smoke_set_tierflow_key` 改为自建供应商）
  - `src/smoke/runner.ts`（冒烟断言同步）
- 验证结果：见文末登记。
- 验收结论及依据：待验收（自动化与进程级验证通过）。
- 阻塞、遗留事项和下一步：无阻塞。待验收项：如用户在老版本预置供应商上填过密钥，该供应商将被移除（预期结果，已在需求明示）。
