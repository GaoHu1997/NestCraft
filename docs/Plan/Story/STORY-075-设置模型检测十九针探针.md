- 来源与确认依据：用户 2026-11-22 指令（见 CR-058 来源），并明确「授权你做完了需求和设计后，直接开发」——需求/设计确认与编码授权同批取得。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / 高 / **待验收（2026-11-25 r5 增量实现完成：P20 行为指纹与归因 + 厂商盲区修补，单测/构建通过；软件界面走查、真实网关端到端与基线校准待用户验收）** / 依赖既有供应商配置存储（CR-012、STORY-029）与受管密钥机制。

- 本次包含：设置 → 模型管理页「模型检测」区块（供应商→模型两级选择、开始检测）、逐针进度与结果报告（总分/等级/真伪×渠道）、右上角历史记录弹层（最近 10 条）、后端 9 针探针引擎（OpenAI/Anthropic 双协议）、本地历史表。
- 不包含：见 CR-058 §2 不做事项。

## 验收标准

- AC-STORY-075-01：给定已启用且配置了模型的供应商，当打开设置，则左栏「模型管理」下方显示「模型检测」页签；进入后供应商下拉列出已启用供应商，模型下拉联动列出该供应商已配置模型；全程无需填写地址或密钥。
- AC-STORY-075-02（r5 修订）：给定「模型检测」区块，当查看其头部右侧，则有「历史记录」按钮；点击在其下方展开**悬浮下拉框**（非弹窗），按时间倒序展示最近 10 次，每行只显示探测时间、供应商、模型、得分与等级；点击任一条则下拉收起，结果区与下方 19 针列表同时切换为该次结果（结果区标注「历史回看 · 时间」）；点击外部或 Esc 收起下拉；无历史时显示空态文案。
- AC-STORY-075-03（r5 修订）：给定任一模型选择，当点击「开始检测」，则固定执行 19 针（UI 无任何探针选择控件）；**顶部结果区**依次呈现三态：空闲提示 → 进行中（当前探针名 + 已完成数/19 + 进度条）→ 完成（总分、等级 S/A/B/C/D、真伪×渠道结论与耗时）；下方 19 针列表每针显示 编号+名称+状态（通过/警示/不通过/未执行/不适用）+耗时+证据摘要。
- AC-STORY-075-04：给定请求 qwen-max 而网关回显 qwen-turbo（或请求旗舰回显 mini/nano/lite 类），当检测完成，则 P2 判红牌且总分封顶；GPT 系代数降级（如 gpt-6→gpt-5）同样红牌。
- AC-STORY-075-05：给定网关抢发心跳/空 delta 或末尾瞬间倾泻，当 P3 完成，则按帧时序证据给出警示或红牌（空包假首字/缓冲伪流式），证据摘要含帧统计。
- AC-STORY-075-06：给定同一供应商同一模型连续两次检测，当比较金丝雀/锚点/题目，则三次随机值均不同（防静态重放与背题缓存）。
- AC-STORY-075-07：给定推理模型（如 deepseek-reasoner、o 系列、*-pro），当执行完整 9 针，则全流程可完成且 P7 按推理规则放行，不出现「忽略解码边界」误报。
- AC-STORY-075-08：给定 Anthropic 协议供应商，当执行检测，则走 /v1/messages 与对应 SSE 帧解析，9 针结果语义与 OpenAI 协议一致。
- AC-STORY-075-09：给定检测历史，当应用重启后打开历史弹层，则记录仍在且最多 10 条（新纪录挤掉最旧）；任一记录 JSON 不含密钥或敏感请求头值。
- AC-STORY-075-10：给定停用供应商 / 无启用密钥 / 无协议匹配端点 / 无已配置模型，当点击「开始检测」，则给出明确错误提示且不产生历史记录。
- AC-STORY-075-11：给定检测进行中，当再次点击「开始检测」或切换供应商/模型，则发起按钮禁用防止重复运行；完成后恢复且结果不自动改写任何配置。
- AC-STORY-075-13（r4）：给定配置为非视觉的模型，当执行检测，则 P15 识图探针记「不适用」不扣分；给定视觉模型，则 P15 发送内存实时生成的随机色块+3 位数字 PNG，模型同时答对颜色与数字判通过，识图错误或静默吞图判不通过。
- AC-STORY-075-14（r4）：给定 OpenAI 协议供应商，当执行检测，则 P16 发送 /v1/responses 流式请求，支持则拼出事件流判通过，不支持记警示；Anthropic 协议 P16 记「不适用」。
- AC-STORY-075-15（r4）：给定网关在 usage 中虚标输入 Token 1.5 倍以上，当 P17/P18 完成，则按差分基线判不通过；流式与非流式输出 Token 报告不一致时 P18 判警示或红牌。
- AC-STORY-075-16（r4）：给定 4 路并发同模型请求，当 P14 完成，则全部回显档位一致且无 service_tier=flex 判通过；并发中检出跨档降级判红牌；P19 以重复长前缀探测缓存命中，连续 0% 命中记警示（OpenAI 协议专属，Anthropic 记「不适用」）。
- AC-STORY-075-12（UI-SCROLL-001）：给定逐针结果列表或历史详情超高，当实际滚动，则滚动条仅在滚动时显示、停止后隐藏；无内容溢出时不出现滚动条。
- AC-STORY-075-17（r5）：给定任一检测完成，当查看结果页，则逐针列表含 P20「行为指纹与归因」行（第 20 行）；P20 权重为 0——其 fail/warn 不扣分、不触发封顶、不单独改变真伪轴结论；P1 失败时 P20 记「未执行」。
- AC-STORY-075-18（r5）：给定 P20 执行成功，当查看结果区下方，则显示归因面板：一致性三态（与声称家族一致/不一致/无法判定）+「最像的已知候选」top-3 排名（候选名 + 距离条）；候选仅限内置基线库内模型，库外情形显示「无法判定：与所有已知候选都不像」；面板措辞为概率性提示（「最像的已知候选」），不出现「实锤/确定是」类断言；历史回看时归因面板随该次记录还原。
- AC-STORY-075-19（r5）：给定 P20 探针请求，当检查其会话构造，则为全新短会话（单条 user 消息、无多轮历史注入），且数字偏好序列题面含当次随机盐值（两次检测题面不同）；身份自述仅作弱信号参与一致性判定，不单独定红牌。
- AC-STORY-075-20（r5）：给定请求 minimax-m3 回显 abab6.5、grok-4 回显 grok-4-fast、kimi-k3 回显 kimi-k2、doubao-2.1-pro 回显 doubao-2.1-lite 等命名，当 P2 判定，则按新增厂商规则给出降级/匹配结论，不再落入「档位规则未覆盖」兜底；P5 对含 `request-id`/`anthropic-ratelimit-*` 响应头识别为 Anthropic 官方特征；P7 关键词表含 grok/gemini CLI、qwen-code、iflow 等非 OpenAI/Anthropic 套壳词。
