## 验收标准

- AC-STORY-094-01：平台下一轮能恢复 user/assistant/工具调用与结果，调用 ID 正确配对，结果不以 system 身份注入。
- AC-STORY-094-02：新轮次回放保留原多轮调用顺序；旧平面消息只能恢复可证明的配对，不声称重建已丢失的原顺序；孤立工具交换不得发送。
- AC-STORY-094-03：每个请求预算含完整系统、工具 schema、历史、当前输入／引用与输出预留；上下文窗口未知标为估计上限，模型已声明值不能被忽略。
- AC-STORY-094-04：保护系统、本次输入与最近 4 个完整轮次；保护内容本身超限则拒绝，不静默截断。
- AC-STORY-094-05：预算或引用预检失败时不新增用户消息，不清草稿；供应商停用／身份失配同样先拒绝。
- AC-STORY-094-06：工具结果增长后每次模型请求重新检查预算，达到硬上限终止，不发送必然超预算的请求。
- AC-STORY-094-07：停止／流中断时已有文本／thinking／工具结果归档，不发成功 Done；持久化失败必须报错。
- AC-STORY-094-08：实际 usage 按本轮所有模型调用累计（含摘要），无 usage 时保持未知，不把字节估计当计费。
- AC-STORY-094-09：迁移与回放不改旧 message 正文/refs/meta；删除会话级联清理新增状态，CLI 默认及既有发送逻辑不变。
- AC-STORY-094-10：双协议 mock、完整回放、超限、取消与回滚新增测试通过，既有断言不改；源或代码变化后旧结果不能自动放行。
