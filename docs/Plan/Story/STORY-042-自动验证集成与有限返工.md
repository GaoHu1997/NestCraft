# STORY-042：自动验证集成与有限返工

- 类型：用户故事（新增能力）。
- 所属：[FEAT-020 自动验证与结果交付](../Feature/FEAT-020-自动验证与结果交付.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)。
- 来源与确认依据：[CR-016](../../PRD/CR-016-需求派发与自主研发任务系统.md)，2026-11-19 用户要求增加需求及设计；本轮无真实自动验证/集成授权。
- 负责人：文档代理；优先级：P1；状态：设计中；依赖：STORY-038 冻结 AC/策略、STORY-040 调度产物门槛、STORY-041 受管尝试。
- 目标：作为研发使用者，我希望执行产物自动验证、必要时有限返工并在允许基线上集成，以便收到可验证结果而非单纯进程结束。
- 本次包含：AC 测试矩阵、产物修订绑定、差异审查、串行本地集成、集成回归及返工上限。
- 不包含：降低 AC、以 exit 0 或 AI 自评代替结果、无限返工、默认合并受保护分支/推送/发布。

## 验收标准

| 编号 | 可观察标准 | 验证方式 |
| --- | --- | --- |
| AC-STORY-042-01 | 给定 CLI exit 0，当缺目标产物、必需 AC 证据、最终差异审查或适用集成回归时任务不能 succeeded，缺项按未执行/失败/待人工评审显示。 | 成功门槛测试 |
| AC-STORY-042-02 | 给定冻结 AC，当执行验证时记录 AC ID、命令/步骤、环境、预期、实际、退出码、时间、产物修订和日志；未执行不能通过，不适用必须有原基线允许的原因。 | 证据结构测试 |
| AC-STORY-042-03 | 给定已通过证据，当代码、设计/AC 或消费基线修订改变时证据标失效且重新验证；旧证据保留为历史，不能继续释放下游或被静默删除。 | 修订失效测试 |
| AC-STORY-042-04 | 给定自动可修复的验证失败，当预算与返工额度允许时自动发起有限修复并生成新尝试/修订；不能改 AC/扩大需求/提权限或换引擎，达到上限失败并保留过程。 | 返工状态机测试 |
| AC-STORY-042-05 | 给定多个可集成产物，当用户允许本地集成分支时队列一次只处理一个，先校验目标 HEAD 再合入并执行集成回归；保护分支、远端与生产操作默认拒绝。 | 集成串行/权限测试 |
| AC-STORY-042-06 | 给定集成后验证失败或语义冲突，当处理时保留候选分支/差异和失败证据，有限修复或阻塞，发布基线不推进；下游不得消费未验证候选。 | 集成失败/消费门槛测试 |
| AC-STORY-042-07 | 给定前置验证产物进入允许基线，当下游启动时记录具体 consumedRevision 并更新自身基线；前置之后返工替换修订时受影响证据失效，正在运行的后继先安全停再重评。 | 依赖修订传播测试 |
| AC-STORY-042-08 | 给定最终差异越界、敏感内容或需要人工判断，当审查时阻塞交付而不是以测试通过掩盖；独立安全分支可继续，报告保留阻塞条目。 | 差异/敏感信息负向测试 |

## CR-037 主代理技术审查与返工

来源与范围见 [PRD-002 的 CR-037](../../PRD/PRD-002-需求派发与自主执行.md#cr-037主代理协调与答疑)。沿用 FEAT-020，状态设计中，负责人为主代理。

- **AC-STORY-042-11** 给定工作代理返回完成报告，主代理对当前候选修订检查差异与必需 AC 证据，并经 runner 提交既有验证流程。候选声明、通知回执或进程退出均不得放行依赖。只有必需检查、审查和适用集成回归通过，才进入技术交付。业务验收沿用人工验收或事前授权的客观规则。
- **AC-STORY-042-12** 给定当前修订存在可修复的阻塞项，主代理按 AC 编号、受检修订、证据、修复目标和允许范围定向退回。重复退回只产生一次受管返工，且须确认旧写进程停止后才允许新写入。同 Task 的定向子返工新建关联旧调用的新 Invocation，根 Attempt／fence 不变、独立兄弟继续；根任务返工才创建新 Attempt。预算或轮次用尽时保留失败证据。重新提交产生新产物修订并重验已失效证据。授权、需求或验收标准变更走确认流程。

见 [协作与验证衔接](../../LLD/LLD-CR037-主代理协作契约.md#4-技术审查与返工)和 [测试映射](../../Test/TEST-CR037-主代理协调与答疑.md)。真实验证与验收未执行。
