# STORY-043：批次交付与验收依据

- 类型：用户故事（新增能力）。
- 所属：[FEAT-020 自动验证与结果交付](../Feature/FEAT-020-自动验证与结果交付.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)。
- 来源与确认依据：[CR-016](../../PRD/CR-016-需求派发与自主研发任务系统.md)，2026-11-19 用户要求增加完整需求与设计；不等于真实验收或发布授权。
- 负责人：文档代理；优先级：P1；状态：设计中；依赖：STORY-038 批次快照、STORY-039 追溯、STORY-042 有效证据。
- 目标：作为研发使用者，我希望一次派发后收到成功、部分成功或失败的可追溯报告，以便清楚知道哪些可验收、哪些仍阻塞及下一步。
- 本次包含：批次聚合、AC/产物报告、文档状态写回、预授权客观自动验收、未知用量和遗留跟踪。
- 不包含：把技术完成当用户验收、默认发布、静默删除失败和伪造费用/提交。

## 验收标准

| 编号 | 可观察标准 | 验证方式 |
| --- | --- | --- |
| AC-STORY-043-01 | 给定批次已终结或无可推进节点且非人工暂停，当所有任务成功时为 succeeded，成功与失败/取消/最终阻塞混合为 partial，无成功且非全部取消为 failed，全部取消为 cancelled；仍有可执行活动任务时 running，人工暂停则保留 running 并单列暂停汇总。 | 聚合真值表测试 |
| AC-STORY-043-02 | 给定交付报告，当查看时列出冻结范围/策略版本、逐 Story/AC 结果、产物修订与基线、尝试/差异/日志、未验证项、阻塞原因、操作步骤与实际时间，能从报告定位原需求。 | 报告字段/追溯测试 |
| AC-STORY-043-03 | 给定技术门槛通过而无自动验收授权，当写回时 Story 仅到待验收，Feature/Epic 作为汇总不提前完成；文档写回以当前 hash 为前置条件，冲突保留结果并显示待同步。 | 写回/状态权威测试 |
| AC-STORY-043-04 | 给定预先冻结的客观自动验收授权，当全部规则与 DoD 满足且证据有效时才可已完成，记录授权者、规则/修订和验收时间；没有授权、主观评审未达成或证据失效不能自动完成。 | 自动验收负向/正向测试 |
| AC-STORY-043-05 | 给定失败、取消、阻塞或返工耗尽条目，当交付时保留所有历史并列编号、影响、负责人和下一步；不得把未达 AC 改写成普通优化或将取消计为完成。 | 遗留/历史审阅 |
| AC-STORY-043-06 | 给定 usage 未知、费用估算或仿真数据，当展示时分别标未知/估算/仿真，未知不按零累计为总账单；无真实提交、部署时明确未生成/未发布。 | 诚实展示测试 |
| AC-STORY-043-07 | 给定报告已生成，当事件重复或重启对账时同修订交付记录幂等，新产物/AC/基线导致新报告与旧版失效提示，旧报告可查但不可作为当前验收凭据。 | 交付幂等/版本测试 |
| AC-STORY-043-08 | 给定本次仅设计仿真通过，当记录结果时与正式 CLI/daemon/集成/权限测试分栏，正式能力仍未实现/未验证，用户未验收不能写通过。 | 设计/正式验收隔离审阅 |

## CR-031：证据完整性与报告封存

- 来源：[CR-031](../../PRD/CR-031-受管执行可靠性需求与实施分解.md)，2026-11-19用户授权需求／方案整理；负责人lead，状态设计中。
- AC-STORY-043-09：给定大输出、头尾截断、捕获写盘失败或未知完整性，当查看／引用交付证据时分别显示完整／截断样本／捕获失败／未知及可用范围，不把不完整资源称为完整原日志；资源读取复查项目和当前授权，未授权者不能靠产物URI或内容hash读取。
- AC-STORY-043-10：给定完整报告与证据封存，当文件写入、hash校验、DB引用登记或ACK任一步崩溃时可按封存身份对账，未完整发布不标有效，不重复生成交付或重跑副作用；完整报告/长日志由文件保存，DB仅短摘要/状态/URI/hash，索引重建不能伪造旧成功，损坏报告阻止当前验收且保留历史。
- 方案：[LLD-CR031](../../LLD/LLD-CR031-受管执行可靠性契约.md)、[DB-CR031](../../DB/DB-CR031-事件审批与产物记录.md)、[TEST-CR031](../../Test/TEST-CR031-受管执行可靠性验证.md)，继承[CR-028](../../PRD/CR-028-文件与数据库按职责存储.md)。UI日志／报告状态覆盖见[UI-CR031](../../UI/文档/UI-CR031-执行可靠性场景覆盖.md)，本轮不改可视稿。
- 实现／验证：新增正式AC未执行，未运行存储故障注入、账单或真实交付，本次报告只证明文档整理检查。
