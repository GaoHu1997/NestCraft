# STORY-076：模型配置评审调整（CR-059 A/B/C + r3/G）

- 类型：用户故事（需求／设计）
- 所属 Feature：[FEAT-014 供应商模型与能力适配](../Feature/FEAT-014-供应商模型与能力适配.md)
- 来源与确认依据：用户 2026-11-22 设置中心评审意见（[CR-059 §1 A/B/C](../../PRD/CR-059-设置中心评审调整.md)）＋同日第二轮模型配置细化意见（§1.G，8 条）；**同日用户明确「代码实现了没，需要实现」＝正式编码授权（范围仅本 Story / FEAT-014）**。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P1 / **验证中（2026-11-22 正式实现完成，待用户验收）** / 依赖既有供应商存储（DB-FEAT-001）；B2 依赖内置思考等级知识库引入（MIT，版权保留）；G4 依赖内置 workbench MCP 通道（CR-060）。
- 目标：作为配置者，我希望供应商与模型配置更顺手（拖动排序、卡片式协议与模型选择、单一保存入口、轻量获取模型、自动思考档位），并能配置多生图模型按序兜底、把生图作为工具交给 AI，以便少填少等、不被上游缺失字段阻塞。

## 本次包含 / 不包含

- 包含：A1～A5、B1～B3、C1、G1～G8 的需求基线与可操作设计稿；获取模型与能力填充解耦；批量＋单模型两级思考档位解析；单一保存入口与成对放弃修改；供应商/模型/生图列表三种拖动排序；供应商 ID 与名称分离；固定两种端点；生图配置（多模型顺延）与 `generate_image` 工具契约；高级配置页签移除。
- 不包含：正式软件实现；Gemini 协议；请求头/伪装任何入口；生图独立端点/密钥表单（复用供应商配置）；生图历史画廊与编辑链；Midjourney 等无 images API 服务。
