# STORY-041：CLI隔离执行与故障恢复

- 类型：用户故事（新增能力）。
- 所属：[FEAT-019 依赖调度与受管执行](../Feature/FEAT-019-依赖调度与受管执行.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)。
- 来源与确认依据：[CR-016](../../PRD/CR-016-需求派发与自主研发任务系统.md)，2026-11-19 用户要求增加完整设计；本轮不调用真实 CLI/AI。
- 负责人：文档代理；优先级：P1；状态：设计中；依赖：STORY-038 授权、STORY-040 资源与 DAG、可证明的 CLI/版本/平台能力。
- 目标：作为研发使用者，我希望授权任务在受管 CLI 和隔离工作区中执行，故障可有限恢复且不重复写入，以便无人逐步干预也不失控。
- 本次包含：能力矩阵、独立 worktree/分支、执行层权限、租约/心跳/fencing、checkpoint、进程停止及有限恢复。
- 不包含：worktree 等同 OS 沙箱、绕过授权、无限恢复、真实 runner/CLI或安全隔离落地。

## 验收标准

| 编号 | 可观察标准 | 验证方式 |
| --- | --- | --- |
| AC-STORY-041-01 | 给定 CLI/版本/运行模式组合，当启动时必须来自允许集且已证明非交互、模型/难度、结束事件、停止和必要权限能力；未验证 Grok 参数或模型不映射时拒绝，不能偷偷换 CLI/模型。 | 适配器契约/能力矩阵测试 |
| AC-STORY-041-02 | 给定任务获得授权，当准备时创建该任务独立分支/worktree，并记录基线与读写范围；用户未提交修改和其他任务文件保持不变，工作区失败不进入运行。 | 隔离仓库测试 |
| AC-STORY-041-03 | 给定知识/密钥限制，当 CLI 直接文件、shell 或网络尝试旁路时执行层拒绝；日志仅存引用/掩码，能力做不到强制隔离则任务 blocked，不能靠提示词声称安全。 | 沙箱与网关负向测试 |
| AC-STORY-041-04 | 给定两个 runner 同时领取，当租约事务竞争时仅一个领取成功；心跳和回调须匹配递增 fencing token，旧回调不能修改新尝试状态、证据或释放新锁。 | 多实例/迟到事件测试 |
| AC-STORY-041-05 | 给定租约过期、超时、暂停或取消，当恢复或释放写资源前需停止并确认旧进程树退出；无法确认时保留阻塞且不启动第二写进程，checkpoint 与副作用键用于对账而非盲目重放。 | 进程树/恢复故障注入 |
| AC-STORY-041-06 | 给定暂时网络故障，当重试时在授权次数/时间/预算内退避并保留每次尝试；认证、额度、配置、权限或需业务决定的问题停止受影响分支，独立分支继续且达到上限不循环。 | 故障分类测试 |
| AC-STORY-041-07 | 给定独立 runner 运行模式，当关窗口时任务继续由 runner 持有；主进程退出不取消 runner，主机重启先对账和确认旧进程不存在，再按冻结 restartPolicy 安全恢复；未具备独立 runner 的模式明确停机语义，不承诺常驻。 | 窗口/进程/主机生命周期测试 |
| AC-STORY-041-08 | 给定真实执行用量未知或 adapter 未给出可信 usage，当展示时保持未知而非零账单；未知情况下不得承诺可强制的费用封顶，所需硬门槛不可测则拒绝，仿真不生成真实账单。 | 用量/预算诚实性测试 |

## CR-031：协议与恢复边界

- 来源：[CR-031](../../PRD/CR-031-受管执行可靠性需求与实施分解.md)，2026-11-19用户授权需求／方案整理；负责人lead，状态设计中。
- AC-STORY-041-09：给定明确CLI/adapter/平台/模式，当握手预检与启动时返回支持/不支持/未核验及证据修订，必要能力未知拒绝；accepted只表示接纳，promptEnded只表示提示结束，executionSettled表示无活动/待批/排队执行，sessionSettled聚合所属根，均不等Story验收。仅UI通知deliveryPending时执行可以静止；内部必需子结果消费失败独立resultWaiting、冻结期限到期blocked不假成功；版本/未知必要事件拒绝不静默换组合。
- AC-STORY-041-10：给定UI/runner断开或重启，当恢复时按根/子InvocationBinding、PID+启动身份/epoch/fence、工作区/effect对账，通知ACK幂等不重跑；旧writer未停或作用未知保锁blocked，子恢复不踩根Attempt/fence。pause/retry_wait/可恢复blocked安全释放物理资源后仍保activeKey=1并拒同Story/baseline重派；不可恢复终态或finalBlocked且整树停/清理完成才释放。新根/重试先满足CR026 G-PLAN真冻结/授权/能力证据，旧游标失效必须重取快照。
- r2修订依据：审查后用户要求“继续”，修正文档activeKey/子fence与静止投递、明确G-PLAN和M1/M2；新增实际运行/恢复测试仍未执行，当前状态设计中。
- 方案：[LLD-CR031](../../LLD/LLD-CR031-受管执行可靠性契约.md)、[DB-CR031](../../DB/DB-CR031-事件审批与产物记录.md)、[测试](../../Test/TEST-CR031-受管执行可靠性验证.md)；继承CR-026原计划重试、STORY-059停止／换计划边界。适用UI缺口见[场景覆盖](../../UI/文档/UI-CR031-执行可靠性场景覆盖.md)。
