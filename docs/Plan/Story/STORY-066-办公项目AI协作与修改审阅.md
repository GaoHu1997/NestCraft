# STORY-066：办公项目 AI 协作与修改审阅

- 类型：用户故事／需求设计。
- 所属 Feature：[FEAT-006](../Feature/FEAT-006-办公资料解读与产物预览.md)；需求：[CR-038](../../PRD/CR-038-办公类型项目文档协作.md)。
- 来源：2026-11-19 用户指定仅办公类型项目，要求参考同类工具提高好用程度。
- 负责人／优先级／状态：lead／P0／设计中（待评审，非正式实现）。依赖 [STORY-065](STORY-065-办公项目资料与连续编辑.md)，关联现行知识授权／会话能力，不新造任务引擎。
- 目标：作为办公用户，我能基于明确资料让AI解读、写作，直接看到改了什么并决定保留哪些，而不是复制粘贴一大段回答。
- 范围：项目内上下文、生成与解读、候选草稿、逐项审阅、冲突／取消／失败恢复；不包含真实模型或无人审批覆盖源文件。

## 验收标准

| 编号 | 给定／当／则 |
| --- | --- |
| AC-STORY-066-01 | 给定选中文档，两次主动操作内可打开解读／Word或PPT生成表单；用途、标题、受众与来源范围可编辑；不要求新建Story或逐次配置CLI/MCP。 |
| AC-STORY-066-02 | 给定待发请求，来源列表只包含当前work项目可读资料和已授权引用；可增删引用并显示定位范围；无权限、不可读、模型缺失时说明具体原因，仍可手动编辑；远程模型须明确发送片段范围并确认，不能将本地保存说成不出网。 |
| AC-STORY-066-03 | 给定解读结果，引用能打开原项目文件和对应段／页；没有来源支撑的结论标待补／推断；不能生成虚假来源、页码或授权。 |
| AC-STORY-066-04 | 给定AI修改或新生成内容，展示原内容／建议内容及来源；逐项接受／拒绝，接受只进入编辑草稿；全拒绝或取消不新增成果，保存成功才产生新版本，原件不变。 |
| AC-STORY-066-05 | 给定提案依赖版本与当前版本不同或用户存在新编辑，应用被阻止，可重新比较／重新生成／保留两份；不能直接覆盖或复用旧审阅确认。 |
| AC-STORY-066-06 | 给定运行中、失败、停止、切项目或重试，步骤／原因可查，保留输入和已产候选；请求有独立代次，迟到结果不复活取消、不写另一个项目、不重复创建成果。 |

## CR-043：复用编码模式完整AI侧栏（2026-11-19提出，11-20更新）

用户要求右侧AI与编码模式一致。以 [CR-043](../../PRD/CR-043-办公文件树与统一AI侧栏.md)／[UI-CR043](../../UI/文档/UI-CR043-办公文件树与统一侧栏.md) 取代CR-038办公专用简化栏；原解读／生成／审阅规则保留为共享栏中的办公工具结果。

| 编号 | 给定／当／则 |
| --- | --- |
| AC-STORY-066-07 | 给定办公项目，AI与code使用同一渲染器／样式及完整控件：历史/新会话/子代理/后台、三统计、+/@//、CLI/权限/模型/思考、发送/停止/排队及拖宽，均有实际仿真行为而非外形相似的空按钮。 |
| AC-STORY-066-08 | 给定两个办公项目和code，切换时输入、会话、文件引用、消息、工具提案分别隔离；共享库存但不共享私有上下文；生成中切换/停止，迟到回复只绑定原项目原会话有效代次，不串写。 |
| AC-STORY-066-09 | 给定办公仿真会话，消息/工具调用与当前项目业务文件一致，文件链接可定位树节点；生成与审阅可在公共侧栏接续，接受只入草稿，既有保存/版本保护仍有效；不返回研发AC占位答复。 |

本批设计验证见 [REPORT-CR043](../../Test/REPORT-CR043-办公文件树与统一侧栏.md)。2026-11-20 编码授权批：AC-07（统一侧栏完整控件与演示行为）、AC-08（项目/会话隔离）、AC-09（引用定位树节点、真实 CLI 回复）已随统一 ChatPanel 落地；提案/逐项审阅/保存事务仍未实现（LLD §6bis 明确边界）。正式软件侧验证见 [REPORT-CR043-正式软件实现](../../Test/REPORT-CR043-正式软件实现.md)；用户未验收。
