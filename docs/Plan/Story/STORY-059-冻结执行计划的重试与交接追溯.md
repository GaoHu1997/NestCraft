# STORY-059：冻结执行计划的重试与交接追溯

- 类型：用户故事；所属[FEAT-019](../Feature/FEAT-019-依赖调度与受管执行.md)。
- 来源/确认：[CR026](../../PRD/CR-026-统一任务执行计划与能力闭环.md)，用户要求研究后形成闭环；仅设计。
- 负责人/优先级/状态/依赖：主代理/P0/待验收/原Run/Attempt/预算/依赖产物与新计划。
- 目标：新默认不偷换旧运行，重试交接使用可追溯计划与授权，交付能解释真正使用的配置。

## 验收标准

- AC-STORY-059-01：确认时冻结具体ExecutionPlan与来源hash，每Run/Attempt不可变引用；目录变动只影响新计划，不覆盖旧。
- AC-STORY-059-02：原计划重试保留CLI/model/权限能力/预算计数，按当前撤权证据复检，原组合不可用阻塞不偷偷套新模板。
- AC-STORY-059-03：fresh只改变上下文连续方式、不默认改变授权配置；换CLI/model/runtime/扩大能力属于新计划确认并关联sourceRun。
- AC-STORY-059-04：运行中或stopPending不改执行计划，无法证明旧writer停止不得生成新writer，暂停/停未来规则不等停当前进程。
- AC-STORY-059-05：阶段交接用单独预检计划及最小权限，评审不自动继承开发写权限；主/子计划角色及来源明确。
- AC-STORY-059-06：依赖消费只接受有效验证产物/修订，取消/关闭/某次Run结束不当成功；旧证据失效不验收。
- AC-STORY-059-07：任务/Run/产物/交付报告显示实际CLI版本、模型、权限能力、计划hash与授权来源，来源需求/管理可往返，历史不误标当前。
- AC-STORY-059-08：端到端走改管理→派发→冻结→变默认不改旧Run→撤权拒绝→原计划重试/新计划授权→安全交接→有效交付，不仅显示占位或toast。
