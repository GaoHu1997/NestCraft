# STORY-023：设置中心弹框与菜单重组

- 类型：用户故事；所属 [FEAT-013 统一设置入口与菜单](../Feature/FEAT-013-统一设置入口与菜单.md) / [PRD-001 CR-012](../../PRD/PRD-001-个人Agent界面需求.md#cr-012设置中心弹框模型供应商与会话切换sdk-装卸)。
- 来源与确认依据：2026-11-18 用户要求“左下角设置和用户信息合并，点击后弹出弹框（不超过页面 70%），菜单为基础设置、模型设置、SDK 管理，能力拆成 skill / mcp / tool 三个菜单”。同轮确认：“SDK 管理只保留三种 CLI SDK”“移除旧 #settings 深链接路由”。
- 负责人 / 优先级 / 状态 / 依赖：主代理 / P0 / 待验收（仿真回归 80/80 通过，等待用户验收）/ 设置路由、模型与 SDK 子页、能力开关与审批复检。
- 目标：作为工作台使用者，我希望在左下角一键打开统一设置中心，并在一个不遮挡整页的弹框里切换全部基础配置，以便不离开当前工作上下文就完成配置。

## 本次包含 / 不包含

- 包含：左下角「设置 + 用户信息」合并为单一入口；点击打开弹框，宽高均不超过视口的 70%；弹框内左侧菜单为「基础设置 / 模型设置 / SDK 管理 / Skill / MCP / Tool」六项；打开弹框不离开当前路由，关闭后回到原位置并保留原滚动与选中状态；移除 `#settings/*` 深链接，旧链接回落项目主页。
- 不包含：真实配置持久化、账号登录与多用户、设置项权限隔离、真实 SDK 安装（见 STORY-025）、真实模型探测（见 STORY-024）。

## 行为与边界

- 入口只在主页侧栏底部出现一次，同时承担“我是谁”和“去设置”两种语义：整块可点击、有 `aria-haspopup="dialog"`，键盘可达；不再保留独立的设置菜单项和独立的用户卡片。
- 弹框为模态对话（`<dialog>`），焦点进入弹框并在其中循环；`Escape` 与关闭按钮都能退出且不保存未提交的编辑；弹框内的危险操作（删除供应商、卸载 SDK）改用弹框内联确认条，不再嵌套第二个模态层。
- 弹框尺寸随视口收缩：取 `min(1040px, 70vw) × min(680px, 70vh)` 并同时限制 `max-width/max-height`，桌面与窄屏都不超过视口 70%；窄屏下菜单横向滚动、内容区单列，不产生整页横向溢出。
- 菜单切换不重建弹框外层；切换时保留其它页已填但未保存的草稿，切回可继续。当前菜单有高亮与 `aria-current`，`role=tablist` 语义。
- 移除旧路由后，`#settings` 与 `#settings/general`、`#settings/models`、`#settings/sdk`、`#settings/skill`、`#settings/mcp`、`#settings/tools` 不再渲染设置页或打开弹框，地址栏统一改写为 `#projects` 并渲染项目管理；旧 `?s=1…12` 序号保持不变、不前后移动，原设置五项序号回落项目管理，其余序号仍对应原页面。
- 能力不再是一个含三个子 tab 的聚合页：Skill、MCP、Tool 各自是独立菜单项与独立内容区，各自保留原有的启停、风险等级、授权关联与停用复检行为。
