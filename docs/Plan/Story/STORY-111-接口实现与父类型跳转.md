# STORY-111：接口实现与父类型跳转

- 类型：用户故事（正式能力增量）
- 所属 Feature / PRD：[FEAT-007 文件草稿与分支上下文](../Feature/FEAT-007-文件草稿与分支上下文.md)／[CR-094 多语言代码阅读导航](../../PRD/CR-094-多语言代码阅读导航.md)（S2）
- 来源与确认依据：CR-094（S2）；用户 2026-11-26 原话「先支持 java/C#/python 然后尽量 ide 精确，不行就精度损失吧」「我这里主要是方便看代码，阅读代码，不会实际运行启动代码」。
- 负责人 / 优先级 / 状态 / 依赖：lead（集成）／P1／**验证中（源码已实现，技术验证通过；真机与视觉待验）**／依赖 [STORY-110](STORY-110-多语言符号索引适配层.md) 的适配层与继承关系；复用 CR-090 的 `GotoPopup`／导航历史／打开定位入口。
- 目标：作为读代码的人，我希望在一个接口上能一步跳到实现它的类、在一个实现类上能一步跳到它的父类型，以便顺着调用链读懂结构，而不用满地找 `extends`／`implements`。
- 本次包含：接口→实现类（含**间接继承**标注：经中间父类继承而来的实现要说明「经由 X」）；实现类→父类型；快捷键 `Ctrl+Alt+B`（跳实现）、`Ctrl+U`（跳父类型）、鼠标 `Ctrl+Alt+左键`，右键菜单「转到实现」「转到父类型」；多目标复用 CR-090 多目标选择器；三语言各自的精度边界提示。
- 不包含：查找引用（Find Usages）、类型层级树面板、悬停文档、用法高亮、埋点式「谁调用了它」；LSP；C/C++/Go/Vue。

## 验收标准

- **AC-STORY-111-01**（Java 接口↔实现双向跳转）：给定 Java 项目里 `interface I` 与 `class A implements I`、`class B extends A`，当在 `I` 上按 `Ctrl+Alt+B`（或右键「转到实现」、或 `Ctrl+Alt+左键`），则弹出多目标选择器列出 `A` 与 `B`，其中 `B` 标注「经由 A 间接实现」；在 `B` 上按 `Ctrl+U`（或右键「转到父类型」）则跳到 `A`，在 `A` 上再按 `Ctrl+U` 可选 `I`；全程**只读、不修改文件内容**。验证方式：设计原型操作 ＋ 手工 ＋ 自动化（解析夹具）。
- **AC-STORY-111-02**（C# 接口／抽象类跳转，父类型统一呈现）：给定 C# `class D : Base, IFoo, IBar`，当在 `IFoo` 上执行「转到实现」则列出 `D`；在 `D` 上执行「转到父类型」则**把 `Base`／`IFoo`／`IBar` 同列**，条目与标题统一写「父类型」（不出现「基类 vs 接口」的分类标签），并在提示中说明**语法索引无法区分二者**。验证方式：设计原型操作 ＋ 手工 ＋ 自动化。
- **AC-STORY-111-03**（Python 继承跳转与动态绑定不可见）：给定 Python `class Child(Base)` 与 `class Impl(ABC)`，当在 `Base` 上执行「转到实现」、在 `Child` 上执行「转到父类型」，则分别列出 `Child` 与 `Base` 并正确跳转；而对**动态注册／`getattr` 生成的子类**，结果中不出现猜测项，界面提示「基于语法索引，可能不全」。验证方式：手工 ＋ 自动化（Python 夹具含正反例）。
- **AC-STORY-111-04**（精度边界不静默给错）：给定 Java 的**匿名内部类**、**Lambda 体**、**泛型实参**（`List<Foo>` 中的 `Foo`）、**跨 jar** 实现，或 C# 的 `partial class`／源生成器实现，或 Python 的 `ABCMeta.register()` 虚拟子类，当用户在这类位置上执行跳转，则**不跳到一个看似正确的错误位置**：要么给 0 目标并提示「基于语法索引，可能不全 · 该语言限制」，要么列出候选并在选择器顶部常驻该提示；提示必须可点开查看该语言的「识别不到什么」说明（口径同 CR-094 §5.1）。验证方式：设计原型操作 ＋ 手工。
- **AC-STORY-111-05**（边界：无实现／多实现／同名跨包）：给定某接口**无任何实现**，当执行「转到实现」则提示「未找到实现（基于语法索引，可能不全）」且不弹空白选择器；给定某接口有 **20 个实现**，则选择器最多一次列 **12** 条并显示「共 20 个，已显示前 12 个」，可继续查看其余；给定**同名类型分布在不同包**（如 `a.User` 与 `b.User`），则候选条目以「包/命名空间 + 类型名 + 文件:行」区分并列展示，**不默认选中**第一项，确认后才跳转；跳转失败一律只提示，不抛异常、不影响编辑。验证方式：设计原型操作 ＋ 手工 ＋ 自动化（计数与截断分支）。
- **AC-STORY-111-06**（回归与只读）：给定 CR-090 已交付的能力，当本故事上线后，`Ctrl+点击`跳定义、多目标选择器、面包屑、`Alt+←/→` 导航历史、TS/JS 文件上的既有跳转结果**与 CR-090 一致**；所有新增跳转（`Ctrl+Alt+B`／`Ctrl+U`／`Ctrl+Alt+左键`／右键菜单）只读，**不修改文件内容、不改变页签脏点状态**，且新增快捷键不与编辑器既有快捷键冲突（`Ctrl+U` 在编辑态原有行为须先查清并在 LLD 记录）。验证方式：自动化（回归夹具）＋ 手工（CR-090 五类场景复跑）。
