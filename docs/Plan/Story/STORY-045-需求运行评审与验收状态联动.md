# STORY-045：需求运行评审与验收状态联动

- 类型：用户故事；所属：[FEAT-020](../Feature/FEAT-020-自动验证与结果交付.md)。
- PRD：[PRD-002](../../PRD/PRD-002-需求派发与自主执行.md)；来源与确认依据：[CR-017](../../PRD/CR-017-统一设计入口与需求任务闭环.md)，用户要求和需求模块打通、状态联动且没有闭环断点。
- 负责人：lead；优先级：P1；状态：设计中（正式能力未实现，设计稿待评审）；依赖：STORY-038快照、STORY-042/043证据与交付、STORY-046续接与退回。
- 目标：作为研发使用者，我希望派发、执行、验证、评审、验收与需求状态实时一致，以便在需求树看到真实阶段而不是另一个孤立任务看板。
- 本次包含：同源需求状态、父项汇总、评审/验收通过与退回、修订失效、历史及取消区别。
- 不包含：合并业务状态与运行状态字段、伪造真实用户验收、把任务结束当需求完成、改AC让失败通过。
