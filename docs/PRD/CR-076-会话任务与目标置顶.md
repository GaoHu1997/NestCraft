# CR-076 会话任务与目标置于输入区上方

2026-11-24 用户明确授权「这次我明确授权，先调整代码，然后反向调整 需求/设计/方案」。该顺序适用于本次变更。`FEAT-010` 与 `FEAT-011` 各自在独立执行上下文先修改正式软件，随后补原型、需求、UI 与实现方案，验证持续进行。CR-019 和 CR-068 的历史设计、授权与验收记录保留。

本页是 CR-076 的需求入口。`FEAT-011` 涉及会话任务与目标，见 [FEAT-011](../Plan/Feature/FEAT-011-会话历史与后台任务.md) 和 [STORY-048](../Plan/Story/STORY-048-会话任务折叠与目标管理.md#cr-076-正式实现)。`FEAT-010` 涉及聊天输入与答复呈现，详见 [CR-034 的 CR-076 增量](CR-034-会话答复呈现与文件定位.md#cr-076-聊天输入与答复呈现)。当前处于验证中。

用户应能在输入前看到本会话的计划进度和目标。把任务面板和目标条独立放在输入区上方。任务来自 Claude 专用任务工具和 Codex 原生计划事件。消息历史保留正文、思考和只读工具记录的到达顺序。打开历史会话时从存储记录恢复任务投影。目标可通过 `/goal` 创建，可编辑、暂停、恢复和确认清除。目标和展开状态以当前应用进程内的会话为作用域。

本次范围限普通会话输入区、任务投影和对应的消息记录。项目 Task/Run、平台执行、目标自动续跑及目标跨进程持久化属于独立范围。滚动条继承 UI-SCROLL-001，覆盖消息滚动区、任务列表、目标多行编辑、创建弹窗和原生输入。详见 [UI-CR049-v1](../UI/文档/UI-CR049-滚动条按需显示.md)。

验收口径以 [STORY-048](../Plan/Story/STORY-048-会话任务折叠与目标管理.md#cr-076-正式实现) 中 `AC-STORY-048-CR068-01` 及关联交互项为准。实现契约与验收证据分别登记在 [LLD-CR076](../LLD/LLD-CR076-会话任务与目标置顶实现.md) 和 [REPORT-CR076](../Test/REPORT-CR076-会话任务与目标置顶验证.md)。
