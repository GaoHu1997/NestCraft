## 1. 用户目标与场景

用户在使用桌面应用时，不希望主动去设置页查找更新：有可安装的新版本时，标题栏右上角直接出现「更新」；点一下完成下载，按钮变成「重启」；再点一下完成安装并回到新版本。全程不打断当前工作，不弹独立更新窗口。

成功的结果是：

1. 没有新版本时，右上角没有任何更新占位，不影响现有搜索、主题、通知、账户与窗口控制。
2. 有可安装的新版本时，出现一个绿色的「更新」文字按钮。
3. 点击后按钮就地显示下载进度；下载并校验完成后变成橙色的「重启」。
4. 点击「重启」后：免安装版替换当前程序并重启；安装版运行已下载的安装包完成升级。失败时旧版本仍可正常使用，并给出明确提示。
5. 安装版与免安装版各自只使用适用于自己的更新包，不把安装包塞给免安装版，也不把绿色版文件塞给安装版。

## 2. 本次范围

### 2.1 入口位置与形态

- 唯一入口固定在主窗口标题栏右侧，位于「主题」按钮左侧（其右依次为主题、通知、账户），沿用现有 56px 顶栏、6px 控件间距与 30px 图标控件高度；按 2026-11-20 用户指令删除顶栏搜索框入口，搜索功能改由 `Ctrl K` 触发（不再是可见按钮）。
- 入口是一枚 54×22、圆角 6px 的纯文字徽标，不加常驻图标、不占空位：
  - `available`：绿色「更新」，悬停显示目标版本号与「点击下载」。
  - `downloading`：同一枚按钮内部显示下载进度（边框描边生长 + 无障碍进度文本），按钮禁用，避免重复下载。
  - `ready`：橙色「重启」，悬停显示「更新已下载，点击重启并安装」。
  - `applying`：橙色语义保留，内部显示加载环，按钮禁用。
  - 无更新：整个按钮不渲染、不占布局宽度。
- 深色与浅色主题分别取既有令牌与语义色，不新增第二套配色体系；窄屏（≤720px）保持可见并允许与通知／账户一同收敛，不挤压窗口控制。

### 2.2 更新流程

1. **检查**：应用启动后延迟 2 秒检查一次，此后每 30 分钟检查一次；用户点击时以当前状态为准，不额外弹确认框。
2. **提示**：只在存在「比当前版本更高且适用于当前安装形态」的版本时显示「更新」。检查失败、离线、清单不可用一律静默，不打扰用户，也不把旧状态改成错误。
3. **下载**：点击「更新」开始下载更新包；下载中显示进度；同一时刻只允许一个下载任务。
4. **校验**：更新包必须通过清单声明的大小与 SHA-256 校验；校验失败即删除暂存文件、恢复「更新」并提示，绝不安装未通过校验的文件。
5. **就绪**：下载并通过校验后按钮变为「重启」；暂存文件与版本信息写入本机更新目录，应用重启后仍能恢复为「重启」。
6. **重启／安装**：点击「重启」后按安装形态执行；成功后旧进程退出并由新版本启动；失败时保留旧版与暂存包，允许重试，并明确提示原因。

### 2.3 安装版与免安装版

两版共用同一套检查、下载、校验与按钮状态机，只在「如何落位」上分叉：

| 形态 | 判定依据（按优先级） | 更新包 | 点击「重启」的动作 |
| --- | --- | --- | --- |
| 免安装版 | 可执行文件同目录存在便携标记文件（由免安装构建写入） | 绿色版可执行文件 | 当前 exe 改名为 `*.old` → 新 exe 落位 → 分离启动新进程 → 旧进程退出；落位失败把旧版改回原名 |
| 安装版 | 本机存在本应用的 NSIS 卸载登记项（`HKCU`／`HKLM` 的 Uninstall 键，按应用标识匹配） | 官方 NSIS 安装包 | 启动已校验的安装包并退出当前进程，由安装包完成文件替换与卸载登记更新；安装包自身的静默／界面行为以其支持能力为准，不伪造「完全无界面」 |
| 未知／开发环境 | 以上都不满足（例如 `tauri dev` 或直接运行构建产物） | 不适用 | 不检查、不显示更新入口，避免开发环境误升级 |

- 更新清单必须同时能描述两种资产；运行时只取与当前形态匹配的一种。当前形态资产缺失时，不显示可安装的「更新」，并在可诊断日志中记录原因。
- 安装版的更新包在启动前必须再次校验 SHA-256，防止下载后被替换。
- 免安装版替换前必须确认目标目录可写；不可写时不显示可安装状态，提示需要移动程序或改用安装版。

### 2.4 更新源

- 默认更新清单地址沿用项目发布仓库的 GitHub Releases 最新正式版资产，清单文件名与资产命名在 LLD 中固定；不把版本号写死进代码。
- 本机可覆盖：环境变量优先，其次更新目录下的 `feed.json`，用于内网镜像、灰度或离线验收；覆盖内容只接受 `http(s)` 地址。
- 清单下载与更新包下载均支持备用镜像候选；任一候选成功后仍以清单 SHA-256 为准，不因走镜像而降低校验。

## 3. 不包含与保护

- **本轮只做右上角入口**：不改设置页、不新增「检查更新」菜单项、不新增独立更新弹窗、不新增托盘入口。更新说明、跳过版本、自动更新开关、更新历史属于后续独立需求。
- 不做差分更新、代码签名校验、断点续传、后台静默安装；不承诺安装器一定无界面。
- 不改发布流程、不创建 GitHub Release、不上传构建产物、不提交或推送代码，除非另有明确指令。
- 不读取、不上传用户项目、知识、会话或凭据；更新只访问清单与安装包地址。
- 不覆盖用户数据目录；更新失败不得删除用户草稿、数据库或配置。
- 开发环境不得真实替换正在运行的调试程序。

## 4. 业务规则与安全

1. 版本比较按语义化版本：数字段逐段比较，预发布版本低于同号正式版；只接受严格大于当前版本的清单。
2. 更新包地址只允许 `https://` 或 `http://`；拒绝空地址、非 HTTP 协议与 `file://`。
3. 清单必须包含版本、目标资产地址与 SHA-256；缺失或哈希格式非法时拒绝该清单，不降级为「不校验安装」。
4. 暂存目录固定在应用数据目录下的 `update/`；文件名固定，不接受清单指定任意落盘路径，避免路径穿越。
5. 下载写入临时文件，校验通过后才改名为正式暂存文件；校验失败删除临时文件。
6. 安装前重复校验暂存文件；失败即取消安装并保留旧版本。
7. 失败提示使用现有 Toast，文案包含可操作原因（网络、校验、权限、安装器启动失败），不泄露本机敏感路径之外的信息。
8. 更新状态不写入数据库；只使用本机更新目录与内存状态，避免迁移与数据耦合。
