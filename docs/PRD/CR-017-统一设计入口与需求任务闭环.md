# CR-017：统一设计入口与需求任务闭环联动

- 日期：2026-11-19（Asia/Shanghai）。来源：用户要求「tab上不要标数字；任务开头需要CLI的logo；设计合并成一个入口；参考项目的任务功能要抄闭环，不要断点；和需求模块打通，状态联动」。
- 类型：CR-016既有设计细化与功能闭环补全。授权本轮需求和可操作设计修改，不授权正式CLI/数据库/Git/发布。
- 状态：设计修订中；用户指令为本轮范围确认依据，最终设计尚未验收。
- 当前基线：[PRD-002](PRD-002-需求派发与自主执行.md)。正式Tauri代码与冻结旧原型不改，本轮继续在既有评审工作台内部整合，不再新建孤立任务稿。

## 1. 单一入口与视觉约束

唯一当前交互设计入口为 `docs/UI/task-workbench/index.html`，更新为统一工作台，而非任务补充页：项目管理、需求/设计/任务/编码、知识库、服务器、设置与账户在同一壳内导航。现行设计总览只保留这一个主入口；历史资料/品牌候选在次级资源区，不作为另一个当前应用入口。旧任务路径仍保留，避免断链；普通设计总览保持静态，不强制跳转。

- 所有Tab只显示名称，无数量数字或数量badge；任务数量留在任务列表统计、项目进度或概览，不显示在Tab。
- 任务行最左为该运行实际选定CLI的Logo，然后任务标题/Story编号；详情、运行历史与会话也使用同一映射。至少Codex/Claude/Grok；未知执行器有可访问fallback，不误画成另一CLI。Logo来源/许可/品牌归属集中登记，作为标识而不是产品品牌，不取参考产品的品牌或UI代码。
- 统一入口内共享需求数据与执行数据，不用iframe拼接两个互不相通的仿真；不得把按钮做成无响应或仅toast的主流程占位。

## 3. 任务功能闭环（产品机制，不复制受限代码）

完整可走链路：需求新增/修改→确认/就绪→设计依据同步→指定CLI（只分配不启动或确认派发）→排队/Runtime离线等待→领取/执行→运行记录/流式日志与评论→依赖/资源等待→暂时故障自动有限重试→失败后修复原因并从原运行重试/新上下文重跑→验证/串行本地集成→评审代理通过或退回→待验收→人工模拟验收通过/退回或预授权客观自动验收→Story与Feature/Epic汇总同步→批次报告/交付证据。

补全的用户路径：

1. 需求页真实显示业务阶段、运行状态、实际负责人/CLI、运行中chip；需求详情内有AC、设计/代码证据、运行历史、评论与任务定位，不靠另一个DEMO数据源。
2. 一条Story可以有多次Attempt/Run；人工重试失败或取消运行保持原CLI、上下文/工作区连续性及失败日志，不随新负责人偷偷换CLI。主动改CLI仅在需求侧明确重新分配且按新的预检/授权生效；旧运行保持原执行器和历史。

同项目同需求/设计/AC基线的前置任务若已在其他批次独立授权并运行，可冻结引用该前置任务ID、将后继直接排队等待产物；不新增或扩大前置范围，也不重复启动前置。正常前置进度不使预检失效，失败/取消阻塞后继，原前置修复后自动恢复受权后继。范围外没有已授权前置或有效产物仍拒绝，不把此优化当隐式开发授权。
3. 运行中的补充消息写回该运行和Story讨论，结束后的讨论不冒充已执行。编辑需求/AC/设计使基线失效，安全停止受影响运行；旧回调不能把新阶段推进。只改查看指针或换模块不停止任务。
4. 暂时网络故障有限自动重试；认证/额度/Runtime离线/配置失败需要可定位修复入口：设置/运行环境→恢复有效配置→重新预检/重试，不让阻塞只有文字而无下一步。
5. 评审退回必须理由，形成有限返工新尝试且保留旧证据；技术任务成功不直接已完成。验收通过只有当前产物/AC/设计修订有效且相关阻塞关闭时成立；拒绝/失效不能通过。所有验收仅DEMO模拟，不伪造真实用户授权。
6. Feature/Epic由子Story的当前业务状态和验收结果派生；执行中显示开发/验证等进度，未完成的草稿与取消数单列。不能因为任务批次成功就把整个未覆盖的Feature/Epic标完成。
7. 条件唤醒可演示评论到达、另一Story达到有效状态/产物、阶段子任务完成、模拟CI/合并结果或仿真时钟到达；有创建/停用/触发/到期/触发历史/次数上限，旧规则不在新阶段乱写。需要字段/产物门槛，不将取消算依赖成功；重复触发不创建并发重复写任务。
8. 工作流交接可选开发/评审/验收角色的CLI或人工；默认仍一次派发授权内自动开发/验证，终点待验收。handoff/退回记录阶段绑定和执行器，不把一个已结束run误当需求结束。
9. 执行配置展示已安装/启用/能力、Runtime状态、并发/预算/重试上限；真实用量未知仍未知，仿真用量有明确来源。审核界面可展示运行时间/请求/工具/错误/日志，不伪造真实账单。

本轮闭环范围是任务相关能力及与现有模块的必要连接，不复制团队多租户、31种CLI、真实渠道通知、云托管/付费服务或生产发布。自动化规则在本机仿真时钟执行，不创建宿主真实定时任务。

## 4. 需求与执行状态联动契约

需求正文仍是业务状态/AC事实来源；Task/Attempt仍是执行权威，不能合成同一状态字段。本轮DEMO仅同一state.requirements共享对象，字段并列展示：

| 事件 | Story业务状态 | 执行行为 |
| --- | --- | --- |
| 只分配CLI/尚未派发 | 原状态不变 | 只记录负责人，不建运行 |
| 排队/等待前置 | 已就绪并列排队/等待 | 不提前冒称开发完成 |
| 实际领取/执行 | 开发中 | 准备/运行记录归属同Story |
| 技术检查 | 验证中 | 验证/集成；失败有限返工回开发中 |
| 外部阻塞 | 阻塞+原阶段/原因 | 可修复入口；独立任务继续 |
| 取消需求 | 取消 | 停止活动运行及唤醒；保留历史 |
| 仅取消一次运行 | 恢复原可执行阶段或明确待处理 | 需求不自动取消；可从原run重试 |
| 技术交付通过 | 待验收 | 证据/报告同Story，等待真实或模拟验收 |
| 当前证据验收通过 | 已完成 | 仅明确模拟验收/预授权规则，父项重新汇总 |
| 验收/评审退回 | 开发中或原需调整阶段 | 理由必填，新尝试与旧证据保留 |
| 需求/设计/AC改变 | 待确认/待同步/需重检 | 失效传播；旧阶段run不写新状态 |

需求编辑/新建/删除有编号/父类型/子项保护；运行中允许受控修改形成新版本并停旧run，不直接改变冻结输入；完成项后续修改保留原验收记录并生成新修订。人工随意把状态改成已完成不能绕过证据门槛。

## 5. 并行实现边界与API

主代理负责文档、Logo资源许可、导航总览与最终报告。状态机代理只修改 `scheduler.js` 和新 `docs/Test/cr017-scheduler-test.mjs`；UI代理只修改 `index.html/app.js/styles.css/README.md` 及新 `cr017-browser-smoke.mjs`；不交叉覆盖。

保留TaskReviewScheduler既有API，新增API全部返回 `{ok,state,error?,...}`（查询除外），失败保持输入state不变：

- `requirementSummary(state,id)` 查询：`{status,label,runStatus,latestTaskId,counts:{total,completed,cancelled,pending,blocked},acceptance}`，父项必须真实聚合。
- `saveRequirement(state,id,patch)`：编辑标题/描述/目标/AC/确认/设计准备与同步、明确执行器；基线变化、主动分配语义与旧run保护。
- `createRequirement(state,{kind,parent,title,...})` / `deleteRequirement(state,id)`：稳定新DEMO编号、合法父类型、不覆盖既有；有子/活动/历史引用时拒绝删除。
- `assign(state,storyId,{cli,model,start:false})`：记录负责人，不创建运行；有活动任务时不改其配置。
- `retryTask(state,taskId,{requestId,reason,fresh:false})`：同基线同原CLI、修复有效配置后受控重试，保留旧attempt/终结记录；重复request幂等，无预算或基线变化必须提示修复或重新预检，不暗中重置授权。依赖阻塞后继只能在产物有效且未被主动取消时恢复。
- `comment(state,storyId,{text,actor:'user',taskId?})`：同需求讨论/同run消息，运行中可续接、不越界。
- `review(state,taskId,{decision:'approve'|'reject',reason})`：模拟评审，当前证据/阶段绑定，退回新尝试受限；不可把失败证据通过。
- `accept(state,storyId,{decision:'approve'|'reject',reason})`：模拟验收，通过需当前有效技术产物，拒绝理由必填；记录历史、父项汇总，不修改真实正式需求。
- `configure(state,{cli?,enabled?,online?,models?,permissions?})`：仿真修复已声明组合；不扩出允许集/写域。Runtime可离线排队/恢复。
- `wakeup(state,{op:'create'|'disable'|'trigger'|'delete',rule?,id?})`：持久化DEMO规则和触发历史，tick条件处理有限、幂等；规则带需求版本/工作流阶段。

UI以这些稳定API实现闭环；可为需要的更细字段由双方协调扩展，不能各自建立第二份requirements。已有CR016测试保留，若业务状态联动调整了原测试预期，主代理核对后只更新对应断言，不删除安全不变量。

## 6. 验证与完成门槛

必须走通：唯一入口→项目→新增/确认需求→设计依据→分配但不启动→派发→CLI Logo任务→开发/验证实时反映需求及父项→Run/日志/评论→失败修复配置→原CLI重试→评审退回返工→待验收→验收完成→父项汇总与证据返回；另覆盖取消运行≠取消需求、失效证据不能验收、旧run不推进新阶段、离线/唤醒/重复/预算/失败后继。

所有Tab无数字，Logo实际映射有accessible名称、离线资源。统一项目/知识/服务器/设置导航可返回，原有功能入口不丢失。截图、文档、AC和实际结果同批更新；本轮真实CLI/runner/DB/网络/生产仍未验证/未接通，不用页内模拟宣称正式完成。
