## 2. 采用的设计基线与未授权边界

1. code 项目页签为需求 → 设计 → 任务 → 编码。任务是跨阶段执行视图，不是必须人工推进的新阶段；work 不强加研发任务树。
2. 派发入口只在需求中：Story、Feature、Epic 和「派发全部合格需求」。后者明确为当前项目当前选择范围内已确认、设计可执行、无待同步草稿、未取消且未完成的 Story；不是所有目录、所有草稿或所有未来新增项。
3. 默认终点为自动实现、技术验证并交付可审阅结果，Story 到「待验收」；仅用户预授权且客观自动验收规则满足时才可「已完成」。不默认推送远端、合并受保护分支或发布生产。
4. 派发前一次明确写入范围、CLI/模型允许集、必要能力、最大并发、预算和重试/返工上限；执行中不能自行扩大需求/AC/权限或偷偷换引擎。需求不清、设计缺失、跨范围依赖无授权时先拒绝或列为不合格，不启动开发。
5. 新批次冻结 requirement/design/AC hashes、授权策略版本、Story 集合；新增需求不自动入批次；重复派发使用项目+需求ID+基线的活动任务约束与幂等键阻止重复写入。
6. Story 状态和 AC 仍以 Markdown 为权威；运行/步骤/尝试/事件/证据以独立执行数据为权威，SQLite 不另存可编辑需求正文。任务页是投影，不第二套需求树。

## 3. 调度与交付核心契约（编码评审稿前确定）

- 概念：DispatchBatch → ExecutionTask（关联 Story）→ Step → Attempt；会话与 CLI 进程是执行载体，不是项目任务本身。
- 依赖：业务父子树与执行 DAG 分离；显式依赖携带 requiredArtifact / verificationGate / consumedRevision。启动需准入通过、前置产物验证且可供当前工作区消费、锁与并发槽可用、能力/权限有效、预算足够。循环依赖拒绝；取消或失败前置不算成功。
- 运行状态：queued / waiting_dependency / waiting_resource / preparing / running / verifying / integrating / retry_wait / paused / blocked / succeeded / failed / cancelled。批次聚合另有 running / succeeded / partial / failed / cancelled，不替代 Story 状态。
- 隔离：计划每任务独立 worktree/分支，共享资源显式锁；锁在受管执行层校验，不只提示词。worktree 不是 OS 安全边界，也不解决语义冲突。集成队列串行，在允许的本地集成分支重新验证；下游更新代码基线后消费产物。
- 恢复：计划持久化队列、领取租约/heartbeat/fencing token、事件去重、checkpoint 与有限重试；过期回调不写新运行，恢复前确认旧写进程已停止，不能双实例写同一任务。浏览器关页/刷新模拟恢复不能当成真实 daemon 已实现。
- 判定：CLI exit 0 仅代表运行结束；任务成功必须有目标产物、关联 AC 的有效验证、最终差异审查及适用的集成验证。测试未执行不能通过；禁止降低 AC 以修复失败。
- 失败：暂时故障可有限重试；认证/额度/配置/权限/业务决策失败停止受影响分支，独立任务继续；每次尝试保留证据，达到限制终结，不无限循环。

## 4. 评审稿场景与显示

独立目录 `docs/UI/task-workbench/`，使用现行 `src/theme/tokens.css` 的白蓝/深色令牌（只读复用），可 file 协议打开，不新增依赖、服务器或真实调用。画面包括需求派发、派发预检、项目任务列表/依赖与详情、交付报告及定位需求/代码证据。任务页不新增需求派发按钮。

演示项目使用独立 DEMO 命名空间：先契约，再后端/前端并行；独立审计任务并行；两个声明同一共享资源的任务串行；暂时网络失败自动有限重试；验证失败有限返工；前置失败/取消阻塞下游；未确认/未同步/配置失效/循环依赖/重复派发明确拒绝。样例变更/HEAD/日志/用量均标「仿真」，不伪造真实费用、构建或提交。

评审可暂停/继续/取消、筛选、打开详情与追溯；在一次派发后计时器/确定性步进自动推进，不要求逐步点批准。可加入仅评审用异常注入控件，与真实业务操作明确分区。桌面 1440×900 和 1920×1080、窄屏 390×844 可操作，键盘/焦点/取消/空态有反馈。
