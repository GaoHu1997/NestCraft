# PRD CR-042：AI 侧栏交互细节调整

- 状态：已确认范围（用户本轮逐项提出，设计待视觉评审）；仅需求与设计资源，无正式编码授权。
- 来源：2026-11-19 用户提出「ui 做一下调整，同时看是否需要调整需求」并列出 5 项：
  1. AI 侧栏顶部的「n 个智能体」「n 个后台任务」不要弹窗，改为下拉悬浮框；
  2. 历史会话列表应为悬浮框，不挤占左侧位置，遮盖悬浮在左边，点击其他地方自动收起；右侧重复的历史图标删除；历史图标重新设计；
  3. 会话框模型选择中，模型列表后面的图标依次是上下文大小、视觉、思考；生图模型过滤掉，不展示；
  4. 会话统计、Token 用量、上下文移到对话框底部，各自悬浮框对齐各自控件右侧并紧贴；
  5. 大模型分步骤执行时，在会话框显示等宽折叠框，显示步骤及执行中／已完成／未开始状态。

## 1. 背景与当前偏差

CR-019／CR-025 已分别要求「历史在侧栏左外侧浮出」「子智能体与后台任务可直接下拉」「模型候选排除图像专用模型」「三统计入口在输入框下方」。当前 CR-036 壳的 AI 侧栏实现与这些既有设计存在偏差：

| 项 | 当前设计稿现状 | 与本需求冲突 |
| --- | --- | --- |
| 顶部智能体／后台 | 打开固定尺寸模态 `dialog` | 需要下拉悬浮框，弹窗打断会话上下文 |
| 历史会话 | 作为 260px 栏插在 AI 面板左侧，参与布局 | 挤占主内容；且右侧重复出现第二个历史图标 |
| 历史图标 | 退回箭头＋时钟，语义接近「撤销／刷新」 | 用户明确指出「现在不对」 |
| 模型列表 | 仅显示容量文本，无视觉／思考指示；生图模型 `tierflow-image` 仍出现在候选 | 需要三项能力按序显示并过滤生图 |
| 统计入口 | 位于输入框上方；弹层固定 `right/bottom`，不对齐控件 | 需要移到底部并贴住各自控件右侧 |
| 分步骤执行 | 无步骤呈现 | 需要全宽折叠框与逐步状态 |

因此本批不是新增一套会话体系，而是把上述 5 项交互收敛到既有 FEAT／Story 的定义上，并补齐可查看设计。

## 2. 目标

让 AI 侧栏的常用入口保持一致的空间关系与可预期行为：

- 顶部计数入口与历史入口都是**临时浮层**，打开时覆盖而非推动布局；再次点击、点击外部或 Escape 立即收起。
- 历史会话是**覆盖在主内容上的左侧抽屉**，主内容与侧栏宽度不变；右侧不再有重复入口。
- 模型候选**一行回答三个问题**：能给多大上下文、能不能看图片、能不能思考；不能生图的候选被排除。
- 用量信息**贴着触发它的控件**出现在输入框下方，而不是在输入框上方占据固定位置。
- 多步执行**在会话流内显式可见**，一眼区分执行中、已完成、未开始与失败。

## 3. 本次范围

### 3.1 顶部入口（子智能体／后台任务）

- 两个入口均为紧凑按钮，显示数量与名称；点击后在按钮下方 6px 展开下拉悬浮框，不使用模态弹窗、不遮挡输入框。
- 两个下拉互斥；再次点击同一按钮、点击浮层外任意区域或按 Escape 收起；收起后焦点回到触发按钮。
- 后台任务下拉按「进行中」「已结束」分组；行显示状态点、命令、状态、退出码与耗时；可展开查看 jobId、来源与输出；「清空已结束」只清当前会话的已结束展示，不终止任务、不影响其他会话与项目任务。
- 子智能体下拉行显示执行器标识、独立任务总结、状态、耗时与 tokens；无子智能体时入口整体隐藏；无后台记录时后台入口隐藏。
- 下拉宽度不改变侧栏宽度，内容过长时在浮层内部滚动。

### 3.2 历史会话浮层

- 桌面：历史浮层覆盖在 AI 侧栏左侧，右缘贴侧栏左缘，顶部与底部与侧栏对齐；宽度约 296px；主内容与侧栏宽度均不变化。
- 浮层包含标题、会话总数、关闭按钮、会话列表与「新会话」；行显示未读状态点与文字状态（成功／失败／待处理／已读）、标题、更新时间、用量与时长；当前会话有选中标记。
- 打开方式：点击头部左侧历史按钮；关闭方式：再次点击、浮层外点击、Escape、浮层内关闭按钮。切换会话或新建会话后浮层收起。
- 头部只保留一个历史入口且位于最左；右侧只保留「新会话」，不得重复出现历史图标。
- 历史图标重设计为「面板＋会话记录」语义（矩形面板加记录行与叠层轮廓），不再使用退回箭头＋时钟。
- 窄屏（<960px）：历史回落为视口内全宽抽屉，仍可滚动、关闭与切换，不产生横向溢出。

### 3.3 模型能力指示与生图过滤

- 模型行末尾固定三列，顺序为：上下文大小 → 视觉 → 思考。
  - 上下文：仪表图标＋数值（如 `922K`、`1M`）；未知显示 `—`，不推测。
  - 视觉：眼睛图标；支持为实色，不支持灰显但仍占位。
  - 思考：灯泡图标；支持为实色，不支持灰显但仍占位。
- 每项都有 `aria-label` 与悬停标题（如「上下文 922K」「视觉：支持」「思考：不支持」），不只靠颜色表达。
- 生图模型（模态包含「生图」或带 `image` 标记）不进入会话模型候选；供应商行的数量同步按过滤后的候选计数；切换供应商后仍过滤。
- 无思考能力的模型：思考档位区禁用并说明「该模型未声明思考档位」，底部模型触发器显示「无思考档位」；选回支持思考的模型时恢复有效档位，不保留 `—`。

### 3.4 底部统计与对齐

- 会话统计、Token 用量、上下文三个入口位于输入框下方，成为输入区最底部一行；输入框与统计之间不再有统计行。
- 每个入口点击后向上展开详情浮层：浮层右缘与所点控件右缘对齐（允许误差 ≤2px），浮层下缘与控件上缘间距 ≤8px，形成明确的「箭头指向触发控件」关系。
- 同一时刻只打开一个统计浮层；再次点击、点击外部或 Escape 收起；浮层不改变侧栏与输入框布局。
- 统计字段与聚合口径不变（沿用 CR-019／STORY-022）：会话轮次／模型用时／工具用时／TTFT／TPS；Token 总量／缓存命中／未缓存／读取／输出；上下文 used／limit 与分项。
- 窄屏：浮层改为视口内左右各留 12px 的底部浮层，不超出屏幕；统计入口仍可点击。

### 3.5 分步骤执行折叠框

- 当当前会话存在分步骤执行时，消息流内显示一个与消息区等宽的折叠框，位于最新消息之后、输入框之前；视觉上为浮层卡片（边框、圆角、轻阴影），不额外挤占输入区。
- 头部：步骤图标、标题「执行步骤」、已完成/总数计数、整体状态（进行中／已完成／有失败／等待继续）与折叠箭头。
- 展开后每步显示：状态图标、步骤标题、状态文字与耗时。
  - 已完成：勾选图标，状态「已完成 · 0.8s」。
  - 执行中：旋转进度环，行高亮，状态「执行中」。
  - 未开始：空心时钟，状态「未开始」，文字降级。
  - 失败：警示图标，红色行，状态「失败 · 退出码 1」，不得计入已完成，也不冒充成功。
- 折叠后保留头部计数与整体状态；展开/收起不丢失步骤状态；某会话没有步骤时不显示空框。
- 演示操作「推进演示」只推进本会话的合成步骤（下一条转为执行中），不调用真实模型、不写项目任务、不改变验收。
- 步骤状态来源为会话自身的执行记录；不得把普通消息切片伪装成步骤，也不得为无执行的会话伪造步骤。

## 4. 不做事项

- 不修改正式软件源码、运行配置、依赖或构建产物；本轮只更新设计资源与需求／设计文档。
- 不接入真实 CLI、后台 job、模型、持久化、真实用量或审批；下拉与步骤均为合成演示。
- 不新增历史体系、子智能体体系、后台任务中心或统计口径；上述仅改变呈现位置与交互方式。
- 不改动项目任务、Run、需求状态与验收；演示操作不写入任何业务状态。
- 不重做 CR-036 外壳、主题令牌与其他页面；Office 办公项目 AI 面板沿用其专有会话结构，不在本次 5 项范围内。

## 6. 待确认与已采用默认

- 已按用户原话采用：三项能力顺序、统计底部与右对齐、历史覆盖不占位、顶部下拉替代弹窗、步骤折叠框。
- 默认值（可调整，不影响需求边界）：
  - 历史浮层桌面宽约 296px；右键外点即收起。
  - 模型能力不支持时灰显但保留占位，以维持三列对齐。
  - 统计浮层宽约 296px，桌面允许向左覆盖主内容（与历史浮层同一浮层策略），窄屏回落视口内。
  - 步骤框默认展开；折叠状态在本次会话内保持。
