## 1. 背景与目标

编码项目中，用户越来越多地以对话推进实现（vibe coding），但现有项目窗口以需求/设计/任务/编码内容为主、AI 会话是右侧辅助栏，历史会话是覆盖式浮层。用户需要：

1. 进入项目即以会话为中心，减少页签与视线切换；
2. 左侧常驻当前项目的全部历史会话；
3. 右侧辅助栏承载文件/需求/工具结果，默认关闭、可随时打开；
4. 整个项目只维护一套 AI 会话，不按页签/模块隔离；执行中的会话跨页面连续运行，不新建、不中断。

本需求是交互形态与项目窗口信息架构调整，不改变现有研发流程规则：没有明确编码授权时，AI 仍只能修改需求/设计；界面变更仍须先更新设计再改软件。

## 2. 范围

### 2.1 页签与三栏布局

- 代码类项目与办公类项目均在页签最前新增“工作台”，**视觉上只显示「坐在电脑前的小人」图标、不显示文字**（可读名称由 `aria-label`／`title` 提供为「工作台」），**新建窗口默认进入工作台**。代码类为“工作台／需求／设计／任务／编码”，办公类为“工作台／文档／成果”。用户之后主动切到其他页签时，切页签或恢复窗口不强制拉回工作台。
- **左栏会话列表、中间会话消息与执行步骤必须复用 AI 侧栏现行渲染与公共样式**（历史列表结构、状态标识、计数、搜索/重置、置顶、分批「继续加载」、消息与工具卡、步骤折叠框），不得另建一套外观；用户近期已调整 AI 侧栏，工作台须与之一致。
- 三栏：左侧为当前项目历史会话列表；中间为当前会话（消息、步骤、统计、输入）；右侧为辅助栏，默认关闭。
- 两类项目共用同一工作台容器与同一会话运行时；按项目类型只改变“中间区回退目标”和右栏可预览的资料类型，不复制第二套会话界面。
- 左右栏可拖动、按项目独立记忆宽度、有最小/最大限幅，保证中间最小可用宽度；滚动条按 [UI-SCROLL-001](../UI/文档/UI-CR049-滚动条按需显示.md) 按需显示。
- 页签沿用现有紧凑/溢出规则（CR-052）；新增页签不得挤压右侧固定入口。
- 办公类项目打开工作台时隐藏全局左侧管理菜单的行为与现有对象窗口一致，不在工作台内另建一套导航。

### 2.2 项目级会话共享（强制约束）

1. **会话集合按项目唯一**：同一项目的会话不按页签、模块或布局实例隔离。工作台、编码/需求/设计/任务页签的右侧 AI 栏、历史浮层共享同一数据源与同一当前会话。
2. **历史全部可访问**：当前项目内所有会话都必须能被左侧列表和现有历史浮层访问，包括其他页签创建、执行中、已完成、失败、未读的会话；顺序、与未读状态一致，不因入口不同而隐藏。列表按 [CR-063](CR-063-会话历史分批加载与全项目搜索.md) 分批加载（默认 20 条/批，末尾「继续加载」），并提供当前作用域全量标题搜索与「全部」逐页浏览——**分批是呈现策略，不是数据裁剪**，任何会话都不得因未加载而无法查找或引用。
3. **执行连续**：切换项目页签、切到首页/其他项目/知识库/服务器等页面再返回，执行中的会话继续运行，不中断、不重置。返回项目后仍显示同一会话及最新消息、步骤、统计和运行状态。
4. **不自动新建**：只有用户显式点击“新会话”，或既有执行派发规则明确创建会话时才能新建。切换页签、切换页面、改变布局、视图重新挂载都不得新建会话。
5. **单实例/单订阅**：同一会话不得同时存在两个独立的会话视图实例或两套流式订阅；发送、停止、草稿、步骤、统计、未读状态在工作台主区与右侧 AI 栏之间同步。
6. **恢复显式**：前端重建、窗口关闭后再打开或原线程续接失败时，按 CR-037 既有机制显式提示并恢复原会话；不得静默新建或丢失历史。
7. **跨项目不共享**：会话仍归属当前项目；本需求不改变现有会话数据模型、权限与审批边界。

### 2.3 右侧辅助栏

辅助栏只有两种打开来源（2026-11-22 用户确认）：

- **用户点击会话中的链接**：需求、史诗、特性、文件、文件行（含工具条里的真实路径与会话标题中的实体 ID）→ 右栏打开并定位到目标；不跳页签。
- **AI 请求开栏**：AI 在需要验证时请求打开（例如验证 UI 预览、调用浏览器类工具并展示结果）。**不需要人工逐次确认**：前端按规则放行，用户可随时关闭；**用户手动关闭后同一轮不得自动重开抢焦点**；非法或未支持的面板类型必须拒绝并返回可读原因。

其余规则：

- 默认关闭，用户可打开/关闭；开闭状态按项目记忆。
- 首期内容：文件、需求、知识文件、办公成果文件的**只读预览**。代码项目覆盖文件/需求/知识，办公项目覆盖办公文件/知识/成果。
- 提供“在编码中打开／在需求中打开／在文档中打开”的显式回退，按项目类型显示对应项。
- 浏览器内核、网页抓取与浏览器自动化**不在本需求实现**（独立立项）；本需求只保证“AI 可请求打开一个只读面板并呈现结果”。
- 辅助栏不得扩大现有文件/知识/办公权限，不读取未授权内容，不编辑原文档。

### 2.4 定位行为分流

| 场景 | 行为 |
| --- | --- |
| 工作台页签内点击文件/需求/知识/办公文件 | 右侧辅助栏只读预览，不跳页签 |
| 编码/需求/设计/任务/办公文档页签内点击 | 保留 CR-034 既有跳转定位 |
| 用户选择“在编码/需求/文档中打开” | 跳转对应页签并定位，右栏可保持或关闭 |

## 3. 不包含

- 不改变需求/设计先行、单特性执行、编码授权和 UI 准入规则；vibe 只是交互形态，不是流程豁免。
- 不实现内置浏览器、网页抓取或浏览器自动化。
- 不实现 AI 主动控制侧栏（P2 另行确认）。
- 不新增会话存储模型，不做跨项目会话共享，不改变权限、审批、费用或外部服务边界。
- 不为办公类项目新建独立的会话界面或第二套会话运行时；办公项目只是接入同一工作台。

## 6. 已确认决策（2026-11-22）

用户逐条确认（前三条）与同日追加（后两条）：

1. **页签名称与形态**：名称保持「工作台」用于无障碍与提示，**视觉上只显示图标、不显示文字**；图标为「坐在电脑前的小人」（`atDesk`）。本条第 3 点由用户后续指令修订，覆盖此前“图标 + 文字”的方案。
2. **两类项目新建窗口默认进入工作台**；用户之后切到其他页签时，切页签/恢复窗口不强制拉回工作台。
3. **右侧辅助栏的打开来源只有两种**：
   - **AI 请求开栏**：AI 在需要验证时可请求打开（例如验证 UI 预览、调用浏览器类工具结果）；**不需要人工逐次确认**，前端按规则放行，用户可随时关闭。
   - **用户点击会话中的链接**：需覆盖需求、史诗、特性、文件、文件行。
   - AI 只能「请求」，由前端决定是否执行；**用户手动关闭后，同一轮不得自动重开抢焦点**；非法或未支持的面板类型必须拒绝并给出可读原因。
   - 浏览器能力本身不在本需求实现范围（独立立项）；本需求只保证「AI 可请求打开一个只读面板并呈现结果」。
4. **左栏会话列表与会话区必须复用 AI 侧栏的现行设计**，不得另建一套外观。用户近期已调整过 AI 侧栏历史会话与消息样式，工作台须与之一致。
5. 工作台的辅助栏、预览与链接交互，以“与 AI 侧栏同一渲染器/同一公共样式”为准，不复制成相似但缺功能的专用实现。
6. **输入区必须完整对齐 AI 侧栏**：`+` 添加、CLI、权限模式、模型/思考档位、发送/停止、统计行缺一不可；不得用简化三按钮替代。
7. **纯图标页签必须与文字页签视觉对齐**：同一垂直中心、同一选中下划线内缩，必要时做光学补偿。
8. **输入区交互必须真实可用**：CLI／权限／模型／`+` 点击后浮层必须出现、贴按钮、选择后状态与 chip 同步；统计行相对输入框居中。仅有状态字段变化而无可见结果不算实现。
