# PRD CR-039：任务页派发树与协调视图

- 状态：已确认范围（设计待视觉评审）；仅需求与设计资源，无正式编码授权。
- 来源：2026-11-19 用户提出「编码项目的任务页面是否需要同步调整，比如大管家执行的是什么任务，然后二级是其他的 CLI，每个分别执行的什么任务。按照一次调度/派发组成一棵树，也方便看大管家调用了哪些 CLI，分别干了什么」。
- 关联：[EPIC-002](../Plan/Epic/EPIC-002-研发需求与交付.md) · [FEAT-018](../Plan/Feature/FEAT-018-需求派发与项目任务追踪.md) · [STORY-039](../Plan/Story/STORY-039-项目任务工作区与追溯.md)。
- 前置：[CR-037](CR-037-主代理协调与答疑.md) 定义了协调者、工作代理、答疑与审查的行为契约；本文件只负责把这些行为呈现成可读的树。

## 1. 问题

任务页现在是**平铺列表**：每行一次运行，第一列是标题与 CLI 标识。它能回答「跑了哪些任务」，但回答不了三个关键问题：

1. 这次派发是谁在协调？协调者自己做什么？
2. 同一次派发里调用了哪些 CLI，各自负责哪一段？
3. 某个子任务失败了，它属于哪次派发、牵连哪些其它子任务？

在 CR-037 引入协调者与子工作之后，平铺列表会把「一次派发」拆散成互不相干的若干行；使用者需要自己按 Story 或时间去拼，无法一眼看出协调范围与责任链。

## 2. 目标

按**一次派发组成一棵树**呈现任务：

- 根节点 = 一次派发，由协调者持有，显示本次派发的目标和协调者自己的职责。
- 子节点 = 该派发下的工作代理任务，每个显示它被分到的那一段、所用 CLI、状态与产出。
- 支持折叠、全部展开与全部收起；切换选中节点时右侧详情同步。
- 从根节点能直接看到「调用了哪些 CLI、各自干了什么」；从子节点能回到所属派发。

目标用户是研发使用者：派发后需要判断进展是否正常、哪一段卡住、该由谁处理。

## 3. 本次范围

### 3.1 树结构

- 树从既有派发与运行权威派生，不另存树数据。派发稳定身份为 `batchId`；业务任务为 `taskId`，每次尝试为 `attemptId`，协调者及子调用为 `invocationId`／`parentInvocationId`。现有同 Story 样例中的无父运行只代表一次尝试的调用根，不能通用地等同一次派发；`parentId` 不得混用批次归属和调用父子关系。
- 同一派发的重试归原 batchId，历史 Attempt 可追溯且不重复计为新派发；跨多个 Story 的 Batch 如何安排协调根仍待确认，不以本次身份修订授权跨 Story 协调。
- 单层派发（协调者自己执行、未下派）显示为根节点，不显示子任务区，并注明「协调者直接执行」。
- 子节点只在所属根下出现，不重复出现在顶层。
- 派发批次、子任务数量分开显示：派发数按当前受权项目的 batchId 去重，不按无父运行数统计；子工作与历史尝试次数不能混算。父记录缺失／跨项目／成环时标关系异常，不把孤儿调用猜成新派发或泄露另一项目。当前可视稿未覆盖重试身份及异常投影，须后续补稿与验证，既有11/11不覆盖本次细化。

### 3.2 列表区

- 根行：折叠键 + CLI 标识 + 标题 + 「协调者 · N 个子任务」或「协调者直接执行」。
- 子行：缩进与连接线 + CLI 标识 + 标题 + 进度 + 「工作代理 · 模型」。
- 状态与耗时列沿用既有语义与配色，不新增状态词。
- 折叠根节点隐藏其全部子行；展开全部 / 收起子项作用于当前项目所有带子项的根。

### 3.3 详情区

根节点详情：

- 本次派发的目标与协调者职责。
- 「本次派发的子任务」列表：每个子任务一行，含 CLI 标识、任务名、一句职责、状态、进度与耗时；点击进入该子任务详情。
- 协调者自己的步骤、产物、日志与用量。

子节点详情：

- 顶部注明「工作代理」。
- 面包屑「所属派发 · 根标题」，点击回到根节点。
- 该子任务的目标、步骤、产物、日志与用量。

### 3.4 状态与边界

- 等待依赖的子任务在树中保留原位并显示等待原因，不从树里移除。
- 失败节点保留在树中，不因失败改变层级或隐藏父节点。
- 窄屏下树与子任务列表降级为整宽单列，不出现横向滚动。
- 深色主题沿用既有令牌，仅新增层级与连接线的表达。

## 4. 不做事项

- 不新建任务、批次或运行体系；树是既有运行记录的投影。
- 不在任务页新增派发入口（派发仍只在需求页发起）。
- 不改变需求页、设计页、编码页的既有结构。
- 不接入真实 CLI、不产生真实运行；演示数据明确标为仿真。
- 不把树的层级当作权限或验收依据。

## 6. 决定与待确认

已确认：

- 2026-11-19：用户要求任务页按一次派发组成树，并能看出协调者调用了哪些 CLI、各自做了什么。

代理采用的默认口径：

- 树由运行记录派生，不新增独立树表或第二套任务状态。
- 单层派发保留为一棵「只有根」的树，不隐藏。
- 协调者任务用其实际执行的 CLI 图标标识；协调者本身也可以是某个 CLI。

待确认：

- 一个根是否允许同时挂载跨多个 Story 的子任务（当前样例限定同一 Story 内）。
- 子任务是否需要在树上直接显示「提问/待决策」标记（与 CR-037 协作状态联动）；本批未做。
- 树的最大展示深度：当前为两层，是否需要支持子任务再下派。
