# CR-030：本地知识索引与按需引用

- 类型：既有知识能力细化；2026-11-19，Asia/Shanghai。
- 来源：用户要求知识库覆盖 Markdown、Word、PDF、Excel、图片、思维导图等，避免 AI 每次读原件；要求本地自行完成，不依赖大模型、云端或用户另装工具。随后明确“按照推荐方式，调整……需求和设计、方案等。需要逻辑闭环，不能浮于表面”。
- 授权：上述方向与需求／设计修改由直接指令确认；**没有正式编码、安装依赖、读取私人资料、迁移、运行或发布授权**。本批只修改文档、演示设计及其验证资源。技术参数属于拟议默认，不冒充用户验收或真实性能承诺。
- 归属：沿用 EPIC-005 下 [FEAT-008](../Plan/Feature/FEAT-008-项目知识授权与只读检索.md) 和 [FEAT-009](../Plan/Feature/FEAT-009-知识库目录与正文阅读.md)；原件／索引复用 [STORY-036](../Plan/Story/STORY-036-知识库正式实现.md#cr-030本地知识索引与按需引用)，AI 检索与授权复用 [STORY-009](../Plan/Story/STORY-009-知识库项目授权与AI检索.md#cr-030本地知识索引与按需引用)，阅读复用 [STORY-014](../Plan/Story/STORY-014-服务器列表与知识库三栏阅读.md#cr-030本地知识索引与按需引用)。不新增 Epic／Feature／Story 或第二个授权来源。
- 状态：需求方向已明确，详细设计待评审；正式能力设计中。CR-015／028 及其它旧验证保留，不能覆盖本次新增标准。

## 1. 要解决的问题与现有事实

现有 [扫描](../../src-tauri/src/commands/knowledge.rs#L19-L67)只收录 `.md` 元数据，未保存正文全文索引；[搜索](../../src-tauri/src/commands/knowledge.rs#L260-L313)遍历笔记并读取文件正文做子串匹配；[网关读取](../../src-tauri/src/commands/knowledge.rs#L412-L419)返回整篇。因此“数据库已有索引”不等于全文检索，也不等于少给 AI 正文。以上为已读源码事实，不是运行验收。

目标拆成两个独立但衔接的结果：
1. 本地解析与切片只在新增、原件修订或解析规则变更后执行；搜索读取派生索引，不逐篇扫描原件。
2. 模型输入只含必要切片及完整出处，所有检索／读取／恢复／发送受版本、预算和实时授权约束；不能搜索完又默认整篇注入。

原件 hash 校验在本地执行，不是让大模型读原件。本批不承诺完全没有磁盘 I/O，不把“再次核验单个已选原件”与“每次重解析全库”混为一谈。

## 2. 范围与格式契约

基线：**原件文件权威 → 应用内确定性解析 → 结构化切片 → SQLite FTS5 全文检索 → 授权内按需引用**。安装包内的解析库属于应用自身能力；用户无需安装 Office、Java、Python、搜索服务或 OCR。首次安装前可准备应用依赖，运行建库／查询无需网络或模型。

| 格式 | 设计支持与定位 | 明确限制 |
| --- | --- | --- |
| MD、TXT | 标题、段落、行号／解析文本偏移，显式链接 | 文本编码异常明确失败；Markdown／HTML 不执行脚本、不加载远程资源 |
| CSV | RFC 4180 规则解析引用、逗号、跨行单元格；以record ordinal与column定位，表头只有用户明确选择首行为表头时才启用，否则首条记录按数据保留；切片维持连续记录语境 | 不以物理行号伪造跨行记录号；不猜列语义／不默认丢弃首行 |
| DOCX、PPTX | 段落／表格及幻灯片，段落ID或序号、表格位置 | DOCX 源结构没有可靠版面页码时不虚构页码；不是高保真 Office 渲染 |
| XLSX、XLS、XLSB、ODS | 工作表、行区间、单元格范围，值／公式来源区分 | 可用应用内只读表格库；缓存值可能过期，不运行 Excel、不计算公式、不执行宏；未有缓存值显示“结果未知” |
| PDF（有文本层） | 实际页号、页内文字／块位置，表格优先保连续语境 | 多栏阅读顺序／字体编码可能导致失败或质量警告；不能把无文字当成功空文档 |
| XMind、FreeMind `.mm`、OPML | 版本匹配的 ZIP/JSON/XML 或 XML 解析；节点ID、父路径、备注、显式连接 | 版本不匹配明确 unsupported；不运行导图应用；节点父子关系不是自动语义事实 |
| PNG/JPEG/WebP/TIFF、纯扫描 PDF | 原件保留、文件名和允许的元数据可搜索，`metadata_only` | 无 OCR／识别模型，图片中文字不可搜、无可供 AI 读取的正文；不得伪报“已解析可问答” |
| 旧 DOC／未知格式、加密不可读／损坏文件 | 原件可登记保管，显示 unsupported／failed／corrupt 等 | 不偷偷走云端转换、外部工具或视觉大模型；不执行嵌入附件、宏、脚本 |

这里是**需实现并逐格式验证的支持矩阵**，不是宣称当前已支持所有格式。未达到该格式的客观验证时保持 unverified，不用另一格式样例替代。

不包含：OCR／任何识别或 embedding 模型、向量库、专用图数据库、自然语言自动摘要／实体关系抽取、图片视觉理解、音视频、云同步、多租户、富文本编辑、AI 上传／修改／删除原件、自动全盘扫描或物理删除。显式链接／节点关系是受权导航数据，不能扩展成 GraphRAG。

## 3. 闭环流程与状态

### 3.1 进入、保存、解析、发布

所有者选择**目录绑定**或**托管导入**：前者明确不备份原件、不修改源目录；后者先按 [CR-028](CR-028-文件与数据库按职责存储.md)完整保存原件并登记，才进入解析。首次建立库默认不授权任何项目。编辑库名、查看状态不改变授权；改变源绑定需单独确认，旧引用立即失效，不按文件名重认身份。

导入／索引有三个独立状态轴：`storageState`（是否已有耐久原件）、`parseState`（抽取结果及能力）、`indexState`（当前可检索代际）。导入已保存≠已索引≠已授权≠AI可读。列表、文件明细和工具均使用同一记录，统计分开显示正文可检索／仅元数据／未支持／失败／待更新数量。

增量任务：盘点受管来源 → 校验变化及稳定身份 → 未变化且版本相同则复用 → changed 文件新修订 → 解析／切片／关系新代际 → 校验完整性 → 单事务发布当前代际与 FTS。只有元数据的格式也可发布文件名索引，但无正文切片。单文件失败不污染其它 ready 文件，库状态 partial 并列原因。切片、FTS 和定位不得跨代际混用。

源已变化但新解析未 ready：旧正文切片不允许自动送模型；目录可显示“待更新”，历史可留但不可伪装当前。监视器丢事件／目录离线／状态未知要报告 freshness unknown，而不是永久声称最新。检索不得为核查全库每次打开所有原件；已选切片读取的源校验策略和监視补偿见技术方案。

### 3.2 搜索、局部阅读、引用与发送

1. 宿主从托管会话得到项目身份，取实时授权库；AI 不提交自称身份或任意文件路径。
2. 查询默认 literal，不直接执行用户输入的 FTS 操作符；同一中文规范化／分词规则用于建索引和查索引。全文检索基于完整已抽取正文的有序切片，不仅索引短摘要。
3. 返回最多5条命中、每条片段至多400 Unicode 码点，包含稳定出处、来源修订、索引代际、搜索方式、是否截断。排序在授权库范围内计算，不泄露未授权库的统计和内容。
4. 读取指定切片和必要相邻片段，返回实际正文与定位；单次完整JSON UTF-8响应上限8KiB、每个宿主轮次累计32KiB为拟议协议护栏，含工具结果的文本／元信息序列化字节。最终预算错误也必须计入同一轮上限并使用有限控制额度；发送最终错误后关闭该轮知识工具派发，不能靠错误信息越限或无限重试。超限明确返回剩余额度、截断／分页提示，出处不被截断；若最小完整envelope也无法放入则调用前拒绝。局部读取不默默变成整篇。
5. 引用绑定 `libraryId/fileId/sourceRevision/sourceHash/generation/chunkId/locator`，候选、点击来源、恢复历史、构造提示和发送之前都复检。同一片段在单次模型输入中去重，实际 token 由可用的可信 tokenizer／供应商计量另记；未知就显示未知，不承诺百分比节省。
6. 旧 `knowledge.read/read_many` 转有界读取，要求当前修订与局部范围；旧整篇引用只能重新选择，不自动拉整篇恢复兼容。新 `read_chunks/outline/relations` 仍受同一授权网关限制。
7. 发送复检失败保持草稿、说明不可用项，不自动发送部分缺失上下文；用户明确移除失效项／重搜后才可重试。历史已展示正文不能收回，后续模型输入不得重放；原生线程无法清理时停止并要求新会话，不假报已隔离。

游标与预算均由宿主生成并维护不透明账本，绑定查询、授权修订、当前代际和轮次；不接受模型伪造预算或任意范围，跨项目／过期／源变更后拒绝，取消轮次终止预算链。清掉 UI 展示或换页不能重置累计预算。

### 3.3 异常、取消、恢复与移除

| 事件 | 必须可观察的状态／下一步 | 禁止的捷径 |
| --- | --- | --- |
| 解析失败／格式未知／扫描件 | 显示原件已保存、能力限制和错误；可换有效原件或对同版本规则重试 | 吞错为空全文；偷偷调用模型或云 |
| 索引失败／FTS不可用 | 保留原件及解析产物、标待同步／失败；显式重建 | 每次搜索退回逐篇读取原件并假报全文检索正常 |
| 更新中源再次变化 | 废弃过时发布，重新排队最新修订；老任务回调不得复活 | 用迟到成功覆盖新修订 |
| 取消／重试 | 保留已存原件和有效已发布文件，未发布代际不开放；只重试合格失败项，有明确有限次数 | 取消当完成；无界重复解析全库；删除原件 |
| 重启／断点／磁盘满 | 对登记过的操作对账，区分封存与未完成、待同步、缺损；重建只修派生 | 从索引猜恢复权限／原件身份；旧writer抢发布 |
| 撤权／停库／删除绑定 | 后续搜索、游标、关系、缓存、引用和发送均失效；保留其它库草稿 | 只隐藏卡片；删除外部原件；清理历史当授权重置 |
| 文件缺失／损坏 | 不可读取、引用不可用；恢复有效原件后重新校验修订 | 用旧缓存冒充当前原件 |

## 5. 质量目标、待确认项与进入开发门槛

### 已确定的设计约束

无模型／网络／额外用户安装要求；不执行源代码／宏；无未授权信息返回；相同原件hash与规则版本不重复解析；可重建派生，原件与授权不可重建猜测；以可追踪片段减少上下文但不损失来源。上述为客观门槛，不以“更快、更省token”口号代替。

### 拟议参数与尚未验证的目标

8KiB单响应／32KiB每轮、5条搜索结果／400码点片段作为本版可逆设计默认；真实编码需验证边界JSON开销与编码，调整需版本记录，不静默放宽权限。查询性能需在隔离样本按文档数、抽取字节、切片数、中文查询类型和硬件记录p50/p95；解析统计按格式记时间、峰值内存、失败及定位质量。**不在本轮承诺毫秒延迟、最大库容量或固定token节省率**。

需要用户决定或真实样本才能确定：文件／库容量与留存配额、跨库同名原件去重策略、需支持的XMind版本、复杂PDF最低可接受顺序质量、无OCR模式是否符合扫描件实际需求。本文不将“未知”消去；这些不阻塞设计稿评审，但受影响正式工作包不得越过DoR。先使用公开/合成样本，不默认读取私人知识库。

### 实施准入与依赖順序

获得另行明确编码授权后：
1. **K1 原件登记与恢复**：复用CR-028，完成身份、路径、耐久保存、对账与备份；才允许报告导入成功。
2. **K2 确定性抽取与切片**：逐格式夹具验证，原文覆盖／序号／质量警告可核对；失败、限额、metadata_only 不混淆。
3. **K3 代际全文索引与中文查询**：SQLite FTS5构建探针、同库统计、增量／取消／CAS／重建一致；查索引不遍历原件的I/O计数验证。
4. **K4 有界授权网关与AI上下文**：绑定版本游标／预算、旧工具兼容、去重、撤权缓存及原生线程边界；单库成功不能代表跨项目隔离已验证。
5. **K5a 可视承接**：按UI-CR030有效版本完成正常／异常、窄屏／主题及键盘设计准入和逐场景实现；场景未覆盖不放行相应UI。
6. **K5b 端到端闭环**：针对所有已确认AC，在隔离资料中跑完原件→解析→增量→检索→切片→引用→源变更失效→重试发布→撤权拒绝→备份恢复；取得文档、数据、安全、性能及UI成对证据后才可提交技术验收，用户验收另记。

顺序为 K1→K2→K3→K4→K5a→K5b，K5a不是正式软件视觉一致的既成事实；每包门槛均见LLD／DB／TEST。源码事实与设计目标分别登记。需要图数据库／OCR／模型或服务时视为新范围，不能在实施阶段“顺手”引入。
