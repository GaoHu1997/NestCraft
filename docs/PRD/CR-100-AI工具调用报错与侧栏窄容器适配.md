# CR-100：AI 工具调用报错与侧栏窄容器适配

- 状态：**已实现，技术验证通过，待验收**（2026-11-26）
- 来源：2026-11-26 用户附图反馈「AI 使用中出现报错」，并指出「AI 侧栏模式下样式会被积压，需要适应侧栏的样式」；同轮明确回复「授权编码」。
- 归属：
  - 运行时部分 → [FEAT-025 平台主代理运行时](../Plan/Feature/FEAT-025-平台主代理运行时.md)／[STORY-090](../Plan/Story/STORY-090-平台工具调用循环与自干边界.md) 增量。
  - 侧栏界面部分 → FEAT-010 侧栏会话（STORY-047 输入区、STORY-062 消息流）增量；工作台继承 STORY-071／FEAT-021。

## 1. 三个报错的定位

| 截图现象 | 结论 | 证据 |
| --- | --- | --- |
| 「累计工具调用超过 24 次」 | **应用自身的安全上限**，8 轮／单轮 8／累计 24；触发即整轮硬失败 | `platform_agent.rs` 常量与本轮实现 |
| 「list-kbs 返回 unsupported call」「这个版本没实现」「服务端一律拒绝」 | **不是应用文案**，全库无该字符串；是模型自述或上游透传。但存在真实口径差异：system 按静态分组列全量工具，实际 tools 还经过启停过滤 | `platform_context_runtime.rs`、`platform_agent.rs` |
| `invalid_request`（请求内容参数无效） | **模型服务商透传**，应用只读取上游 `/error/message` 后包装提示 | 既有透传点；仓库内无该文案 |

用户截图的三个现象不是同一条根因：

1. **24 次上限**是可预期的保护机制，问题在于「被拒、停用、重复的调用也计入」，模型反复试错会快速耗尽预算。
2. **unsupported call 类叙述**说明模型认为工具不可用，与「提示里列了、实际没下发」的口径差异相符。
3. **invalid_request** 需要一个不合法的请求体。已确认一条可疑路径：模型未下发工具参数时，流式累积为空串，而只有 Anthropic 分支做了清洗，OpenAI 分支会原样回放。

## 2. 本次范围

### 2.1 运行时（已实现）

1. **口径统一**：system 的能力目录改为「本轮实际下发的工具名」，停用工具不再出现在提示里；MCP 工具单独列在「扩展」组；明确要求使用精确名称（下划线）。
2. **回放净化**：OpenAI 与 Anthropic 都对非法/空工具参数回放为 `{}`；执行侧仍保留原始参数与错误结果，便于排查。
3. **assistant 消息格式**：`tool_calls` 为空时不再输出该字段；无文本但有调用时 `content: null`，无文本无调用时用空串。
4. **提前止损**：
   - 同一工具同参数连续失败 2 次后，不再执行，直接回填「请改变参数或换用其他方案」。
   - 连续 3 轮工具全部失败时结束本轮并标注未完成。
   - 8／24 安全上限保留不变。
5. **超限收尾**：达到轮次/单轮/累计上限时先闭合未配对的工具交换，再返回带「本轮未完成」的原因，不再只抛裸错误。
6. **历史回放容错**：被拒调用按 AC-02 不写 tool_use，只留错误结果；回放时跳过无对应 tool_use 的结果，避免旧库被判「孤立工具结果」而整段上下文失效。

### 2.2 侧栏窄容器适配（已实现）

统一以**面板自身宽度**作为查询基准（`container-type: inline-size`），不再依赖整窗断点：

| 位置 | 窄栏行为 |
| --- | --- |
| 运行栏 | 分支 chip 是唯一可牺牲宽度的一段，超长分支省略；CLI／助理切换与 worktree 始终可见 |
| 消息区 | ≤480 内边距 14px、≤372 收到 12px；工具组缩进同步收窄；字号保持 CR-096 的 12.5px |
| 轮次刻度 | ≤480 收窄到 32px，浮框仍按真实坐标与视口夹取 |
| 浮层 | 最大宽度受面板约束（`min(设计宽度, 100cqw - 16px)`） |
| 长内容 | 错误卡与长参数换行；代码块/表格在自身区域滚动，不撑破面板 |

工作台布局保持原有 860px 居中基准不变。

## 3. 不做事项

- 不提高 8／24 上限（是否有必要需真实使用数据）。
- 不重写会话架构、不改 CLI 通道行为、不改知识库工具实现。
- 不声称已修复 `invalid_request`：本次只消除已知的不合法回放路径，供应商特有校验仍需真实失败请求验证。

## 4. 验收标准

- AC-CR100-01：给定模型返回不带参数的调用，下一轮请求中该调用的参数为合法 JSON `{}`，两种协议一致。
- AC-CR100-02：给定 assistant 消息无工具调用，OpenAI 请求体不包含 `tool_calls` 字段。
- AC-CR100-03：给定某工具被停用，system 能力目录不再列出该工具。
- AC-CR100-04：给定同一工具同参数连续失败 2 次，第 3 次不再执行并返回换方案提示。
- AC-CR100-05：给定连续 3 轮工具全部失败，本轮提前结束并标注未完成。
- AC-CR100-06：给定达到累计上限，未配对工具交换被闭合，错误含「本轮未完成」。
- AC-CR100-07：给定历史中存在被拒调用的孤立结果，会话仍可继续，正常工具交换不受影响。
- AC-CR100-08：给定侧栏宽度 320／372／480／620，运行栏、输入卡、消息区均无横向溢出，CLI／助理切换与 worktree 可见。
- AC-CR100-09：给定窄栏，正文与工具缩进随容器收窄，字号仍为 CR-096 基准。
- AC-CR100-10：给定窄栏且存在轮次，刻度条收窄且不遮挡正文可点区。
