# CR-102：会话流式重连提示样式修正

- 类型：展示缺陷校正（既有能力细化）；不改变重试策略本身
- 状态：**已实现，技术验证通过，待验收**（2026-11-26）。用户同轮明确「授权开发」后，已按 [LLD-CR102](../LLD/LLD-CR102-流式重连提示样式实现.md) 落地 `chat.rs`／`api/index.ts`／`ChatPanel.tsx`／`MessageList.tsx`／`chat.css`；`cargo test --lib commands::chat` 53/53、`tsc` 与 `npm run build` exit 0、组件定向回归 7/7、真实组件浅/深/窄成对截图与详情区滚动条动态证据通过，见 [REPORT-CR102](../Test/REPORT-CR102-流式重连提示样式实现与验证.md)。真实上游中断、真实 WebView2 整窗与用户目视验收未验证。
- 来源：2026-11-26 用户附软件截图——消息流中出现粉色色块整段英文报错 `Reconnecting… 1/5 (unexpected status 502 Bad Gateway: Upstream service temporarily unavailable, url: https://api.primerelay.online/v1/responses, request id: 28411477-…)`，下方悬浮「重试」按钮；用户明确要求：**「重试样式也不对啊，需要修改一下。不要色块，只写重试几次，为什么重试，需要展开再显示」**。
- 归属：
  - 界面部分 → FEAT-010 侧栏会话／[STORY-062 会话答复呈现与文件定位](../Plan/Story/STORY-062-会话答复呈现与文件定位.md) 增量；工作台布局继承。
  - 运行时部分（把内核重连事件结构化上报给界面）→ FEAT-025 平台主代理运行时增量（实现时确认具体 Story）。
- 背景实证（同日排查结论，仅作背景，不在本 CR 范围内解决）：平台多家上游中转（tierflow.cn、primerelay 等）存在间歇性 5xx／400；流式请求失败时内核自动重连（本例 1/5），原始报错被整段平铺渲染。另有一次 `invalid_request` 导致整个长回合作废的记录（会话 sess-3045b2f2…，2026-11-26 14:20Z）。

## 1. 现状问题（依据用户截图，软件代码位置待开发授权后只读核对补记）

| 问题 | 表现 |
| --- | --- |
| 色块 | 重连提示使用粉／红大面积底色，视觉强度与「正在自动恢复」的严重度不匹配 |
| 信息不分层 | 原始英文报错（状态码、URL、request id、堆栈式说明）整段平铺在消息流 |
| 不可追溯 | 用户想看细节只能整段读英文；没有结构化展示和复制入口 |

## 2. 需求规则

| 编号 | 规则 |
| --- | --- |
| R-CR102-1 无色块 | 重连进行中提示不使用任何大面积底色（红／粉等），透明背景、无边框，一行中性文字＋图标 |
| R-CR102-2 一行中文摘要 | 只显示「正在重试 n/5」＋原因中文摘要（如「上游暂时不可用（502）」），不整段展示原始英文报错 |
| R-CR102-3 详情折叠 | 完整原始错误（状态码、URL、request id、原始返回原文）默认折叠；点「详情」展开；等宽字体、可一键复制；再点收起 |
| R-CR102-4 状态闭环 | 重试成功→指示消失；5/5 仍失败→转为现行错误卡（沿用 CR-100 视觉与侧栏适配约束），保留「重新发送／继续」入口 |
| R-CR102-5 手动入口 | 保留「立即重试」文字链（替代现状悬浮按钮） |
| R-CR102-6 全局适配 | 浅／深主题、侧栏窄容器（390）与工作台两布局无溢出；展开详情超高时详情区自身为滚动容器，适用 UI-SCROLL-001 |

代理细化默认值（用户未逐项确认，实现前可推翻）：①重试成功后留一行灰色小字「途中上游中断，已自动重试 n 次后恢复」，也可按用户意见改为无痕；②手动「立即重试」保留；③原因摘要映射表由实现侧按状态码/错误类型给出（502/503/超时/连接失败/4xx 参数类）。

## 3. 验收标准（唯一事实来源登记于 STORY-062 增量节）

- AC-CR102-01：给定流式请求失败进入自动重连，当第 n 次重试进行中，则消息流仅显示一行无色块中文摘要「正在重试 n/5 · 原因摘要」，不出现原始英文整段报错与色块。
- AC-CR102-02：给定重连提示，当点「详情」，则展开显示状态码、URL、request id 与原始返回原文（等宽、可复制、可收起）；摘要行在前文输出不被打断。
- AC-CR102-03：给定 5 次重试全部失败，则提示转为现行错误卡并保留「重新发送／继续」；不得留下孤立的红块英文。
- AC-CR102-04：给定重试成功，则重连指示消失；按确认结果保留或不留恢复留痕，无样式残影。
- AC-CR102-05：浅／深、390 侧栏与工作台布局下无溢出、无横向滚动，动作可达；展开详情超高时按 UI-SCROLL-001 按需显示滚动条（滚动显示、停止 700ms 隐藏、悬停不唤醒）。

## 4. 范围外（明确不做）

- 不调整内核重试次数（5）与退避策略；不新增跨请求的自动重发。
- 不处理「invalid_request 400 终止整个回合」的策略问题（另行评估，见背景）。
- 不更换上游 provider，不新增 provider 探测逻辑。
- 不改动错误卡（CR-100）既有视觉。
