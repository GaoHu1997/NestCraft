## 背景与问题

平台 runtime 每轮把下列内容一次性塞给模型，与"只告诉它有什么、按需取"的目标相反：
1. **工具**：`workbench_tools()` 全部启用项（含记忆 34 个）+ 4 个上下文工具 + MCP，每个都带完整 JSON Schema。
2. **画像/记忆**：CR-092 每轮预注入画像摘要（≤2KB）+ 相关记忆 TopK（≤1.5KB）。
3. **不区分项目类型**：编码/办公/未绑定拿到同一套工具，噪声与引导偏差。
（技能已是"清单+正文按需"，是正确范本。）

## 决策：平衡，不走极端

高频且小 → 常驻；低频或大 → 按需：
| 内容 | 常驻 | 按需 |
| --- | --- | --- |
| 身份/硬约束 | 固定小段 | — |
| 项目类型角色 | 一行 | — |
| 画像 | **一行（≤120 字）** | `profile_get` |
| 记忆 TopK | 一句指引 | `memory_search` |
| 工具 | **该类型默认组 schema** | 其他组（P1 动态加载） |
| 技能 | 名称+一句 | `read_skill` |
| 知识正文 | — | 知识工具 |

## 范围（本轮 P0）

**包含**
- 工具分组与按项目类型默认集（`tool_groups`）：code / work / 未绑定各自默认组。
- 平台请求只为默认组注入完整 schema（`platform_tool_defs_scoped`）；旧全量函数保留用于测试/兼容。
- `Prepared` 增 `project_kind`、`profile_line`；`system()` 重写为「身份+角色+一行画像+默认工具组目录+技能清单+使用指引」，**移除 TopK 记忆预注入**。
- `memory::build_profile_line`（≤120 字一行画像）。
- `memory_save` 纳入副作用工具去重（同参数不重复写）。

**不包含**
- P1 动态 `enable_tool_group` 按需加载（后续增量）。
- 上下文工具按需注入（仍全给 4 个）。
- 真实 Tauri/模型端到端。

## 验收标准

- AC-CR095-01 平台 tools 只含该类型默认组（code/work/未绑定各异）。
- AC-CR095-02 system 含角色、一行画像（≤120 字）、默认工具组目录、技能清单与指引；**不含** TopK 记忆正文。
- AC-CR095-03 未绑定项目默认集不含 project/server/media/panel 等组。
- AC-CR095-04 `memory_save` 同参数第二次不执行（副作用去重）。
- AC-CR095-05 回退：`platform_tool_defs` 全量函数保留；可切回。
- AC-CR095-06 `cargo test --lib` 607 通过/0 失败、`cargo check --all-targets` exit 0。

## 变更影响

- 既有测试预期随行为更新（`mock_global_tool_switch`、`mock_tool_loop_scenarios` 改用默认组内工具），不改变其验证意图（全局开关重校验、副作用去重）。
- CR-092 的「画像 2KB + TopK 预注入」被本 CR 取代为「一行画像 + 工具按需」。
