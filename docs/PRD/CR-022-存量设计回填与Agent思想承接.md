- 状态：需求／设计调整已获本次指令授权；设计待评审；**没有正式软件编码、运行、构建、发布授权**。
- 来源：2026-11-19（Asia/Shanghai）用户指出软件与 UI 不一致，要求逆向把软件设计补到 UI，同时强调发现差异后新增／调整的设计不得再调整、原型统一入口和位置永久稳定、样例真实连贯，并把本项目 agent 思想补入需求、逐步由软件承接。
- 现行范围分别补入 [PRD-001](PRD-001-个人Agent界面需求.md) 与 [PRD-002](PRD-002-需求派发与自主执行.md)；本文只维护本批授权、优先级和变更说明，不作为第二份 AC 正文。

## 1. 设计回填的优先级

1. 用户明确新增／调整的有效设计优先于旧实现。冻结保护：CR-017 同源任务闭环与无数字 Tab／CLI 标识、CR-018/019 AI 侧栏／输入菜单／历史／目标／子智能体／原生权限／计量、CR-021 管理页和详情返回、栖造品牌。
2. 已授权能力但普通原型缺稿：先从源需求核对字段和流程，再参考软件已有控件，补进**原来的正常产品路径**。不是把只读历史查看器改成可执行页面，也不是直接截图覆盖新设计。
3. 正式软件偏离有效设计：登记软件差异，本轮不修改软件、不把错误行为写成新标准。
4. 来源不清／新增能力未经授权：保留差异，待澄清，不默认倒灌为需求。不把文件最近修改时间等同于用户已验收。

本次例外允许“软件现状 → 设计缺口补全”，仅用于未被新设计替代的已授权范围；不解除今后设计先行约束。

## 2. 交付与唯一入口

- 主原型固定为 [统一工作台](../UI/仿真原型UI.html)，资源目录固定为 [设计图总览](../UI/文档/设计资源索引.html)。后续增量原地更新，不另建带版本号的产品入口，不通过查询参数重定向到旧原型；版本写在说明／清单及证据中。
- 历史原型、品牌候选与旧截图是追溯资料，不是继续演进的入口。有效旧约束不因历史稿冻结而取消。
- 普通模型／SDK／能力设置、知识管理／只读授权、主机配置与认证为回填重点；项目／任务／AI 新设计保持。对应 [STORY-052](../Plan/Story/STORY-052-保护新设计的存量界面回填.md)、[STORY-053](../Plan/Story/STORY-053-固定原型入口与可信样例.md)。
- 已有软件的免认证 `none` 不在 STORY-035 明确密码／密钥授权范围，不能倒灌；known_hosts 信任策略也未授权。既有设计明确、软件尚未实现的供应商细节按“设计已存在、软件待承接”登记，不冒充本轮逆向发现。

## 3. 样例真实性

“真实一点”要求有项目语义、可信来源和关系一致，**不授权采集生产数据、会话日志、凭证或个人信息**。

- 仓库事实摘录：本项目研发规则、已有需求／设计缺口和验收边界；显示来源和采用版本。
- 业务情景夹具：预约服务等由现有需求机制组织的业务故事；明确虚构／脱敏情景，不宣称生产订单、真实负责人或用户决定。
- 故障与执行仿真：安装失败、等待／返工／批准、Run、SHA、时间和计量分别标注 DEMO；未知实测保持未知，不能因正文真实而把运行也标真实。
- 所有关联 ID、项目／知识／主机归属一致；统计由同一夹具计算；不随机填图表。IP 用文档专用网段，域名用 `.invalid`，密钥／密码用不可执行占位。
- 已保存的评审历史和用户草稿不自动覆盖；样例升级只用于新实例或用户明确载入。

## 4. Agent 思想变成产品要求

不重建已有需求树、任务平台或聊天功能；沿用现行 FEAT-018/019/020 和会话能力，把本项目 agent 的研发方式落到产品契约。

- 已有映射：诉求归类／唯一事实 → Markdown 源与索引；计划与执行分离 → Story 与 Run；一次范围授权 → 冻结工作包；必要才委派 → 语义必要性／依赖／风险判断；安全并行 → DAG／锁／隔离；验证／验收／发布分开 → 证据与状态联动。
- 本批实质补充：适用规则和**分层授权**的工作包、设计覆盖和**同条件成对视觉证据**门禁。分别由 [STORY-054](../Plan/Story/STORY-054-Agent规则与分层授权工作包.md)、[STORY-055](../Plan/Story/STORY-055-设计覆盖与视觉证据门禁.md) 保存 AC；方案见 [契约](../LLD/LLD-CR022-Agent规则与设计回填契约.md)。这些是需求设计，未接入真实执行器，不重画用户已调整的预检和任务界面。

## 5. 逐步承接而非一次替换

本次：把思想、边界、工作包与证据要求写清，补可操作设计；后续另有明确编码授权才先实现只读预检和缺口报告，再单 Story／单执行器验证，随后扩大到依赖／并行和持久化恢复，最后受控交付与验收写回。每次开发经历中的新思想先归类并复用既有归属，只提交实际变化、记录 CR／设计修订，不能悄悄改运行目标或抹掉用户新设计。

每一步独立记录已实现／待实现、真实验证／仿真／未执行；只读报告不等于执行层隔离，目标完成不等于 Story 验收，单次软件退出也不等于产品完成。远端与生产发布不默认开放。
