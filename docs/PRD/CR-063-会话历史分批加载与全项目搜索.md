## 1. 背景与问题

现状（2026-11-22 代码核对）：

1. `chat_sessions(project_id)` 一次返回该作用域全部会话，无 `limit` / `offset` / 关键词参数（`src-tauri/src/commands/chat.rs:162`）。
2. 每行附带 3 个相关子查询（消息计数、最近一轮 outcome/reason）与绑定派生视图（`src-tauri/src/commands/chat.rs:154`）。
3. 前端 `ChatPanel` 把全量列表存入 `sessions`，历史浮层与 `@` 引用候选都直接遍历该数组全量渲染（`src/modules/chat/SessionHistory.tsx:80`、`src/modules/chat/Composer.tsx:181`）。
4. 会话表只有 `idx_session_feature(projectId, featureId, updatedAt)`，按 `updatedAt` 倒序仍需额外排序（`src-tauri/src/db.rs:402`）。

会话数量增长后，三段会同时变差：后端查询与 IPC 传输全量、前端全量 DOM 渲染、以及**只能靠滚动查找**。用户诉求即针对第 3 点中最直观的“加载不出来”。

## 2. 用户结果

1. 打开会话历史时立刻可用，只加载最近 20 条，不因历史总量变大而变慢。
2. 滚到列表末尾能看到一个「继续加载」**文字按钮**，点击追加 20 条，位置不跳、不重复。
3. 想找很早以前的会话时，用搜索直接在当前项目**全部**会话的标题里查，不受“只加载了 20 条”的限制。
4. 点「全部」可以清空关键词，从第一条起逐页浏览整个项目的会话。
5. 当前正在看的会话一定能在列表中找到（不在最近 20 条时钉在顶部），不会“找不到自己在哪”。

## 3. 范围

### 3.1 分批加载

- 默认每批 **20** 条（`PAGE_SIZE = 20`），后端默认值同。
- 列表主体按 `updatedAt DESC, id DESC` 排序。
- 列表末尾是「继续加载」**文字按钮**（纯文字，无边框无底色；用户原话即“文字按钮”）；点击追加下一批；`hasMore=false` 时按钮替换为「已到全部」说明。
- 首批加载与追加加载都不得重置滚动位置；追加后新行出现在原列表末尾。
- 计数口径统一为：**头部** `已加载 X / 共 Y`；**按钮** `继续加载 · 还剩 N 条`（N = 总数 − 已加载）。首批加载中头部显示 `…`。

### 3.2 全项目搜索与「全部」

- 历史浮层顶部新增搜索行：输入框（占位「搜索本项目会话标题」）+「全部」文字按钮。
- 搜索范围固定为**当前作用域**（见 §3.4）内的全部会话，只匹配 `title`，不读消息正文。
- 输入即查（防抖 250ms），结果与总数同时返回；清空关键词恢复分批列表。
- 「全部」按钮与空态「清除搜索」行为一致：清空关键词、退出搜索态、**回到第 1 页按 20 条重新浏览**（正式实现会取一次无关键词首页，不是恢复搜索前的锚点）。
- 搜索态下同样分批追加，不一次性渲染全部结果；追加时仍携带同一关键词，`total` 为匹配总数。

### 3.3 状态与反馈

| 状态 | 呈现 |
| --- | --- |
| 首次加载 | 列表区「加载中…」，不显示空态 |
| 追加加载 | 按钮变为「加载中…」且禁用，列表保持原样 |
| 无任何会话 | 「暂无历史会话」 |
| 搜索无匹配 | 「没有匹配的会话」+「清除搜索」 |
| 已到全部 | 「已到全部」弱化文字，不可点击 |
| 加载失败 | 行内错误 + 「重试」，保留已加载内容 |
| 空关键词 | 等价于无关键词：按键回退到分批浏览并取一次首页，不做本地空匹配 |

### 3.4 作用域（强制）

分页与搜索的作用域必须与现有前端过滤完全一致（`src/modules/chat/ChatPanel.tsx:233`）：

| 当前上下文 | 条件 |
| --- | --- |
| 有项目、有服务器 | `projectId = ? AND serverId = ?` |
| 有项目、无服务器 | `projectId = ?` |
| 无项目、有服务器 | `serverId = ?` |
| 无项目、无服务器 | `projectId IS NULL AND serverId IS NULL` |

> 「无项目、有服务器」一栏**刻意不限制 `projectId`**，与既有 `filterSessions` 保持同一语义（评审 I-06）；该分支当前界面不可达，仅由后端单测覆盖。

不允许“后端只按 `projectId` 分页、前端再过滤 `serverId`”，否则每页条数不固定。

### 3.5 当前会话钉住

- 当前会话不在已加载主体内时，列表顶部显示单独一行，带「当前」徽标，不计入主体分页与 `X/Y` 计数。
- 当前会话进入主体后，钉住行自动消失，不出现重复行。
- 钉住行与主体行使用同一行结构，仍可点击切换、可删除。
- **搜索态不显示钉住行**：搜索是明确查找，结果外再插当前会话会与匹配计数混淆。

### 3.6 `@` 引用与会话归属校验（随本 CR 修正）

- `@` 引用候选中的会话改为按关键词向后端查询（限 20 条），不再只从已加载列表中过滤；未加载的老会话必须能被引用。
- `@` 会话候选沿用**完整作用域**（项目 + 服务器），与历史列表一致；当前应用只挂载项目上下文（不传 `serverId`），因此实际行为不变，但接口不再收窄为 project-only。
- 发送前对 `session` 类型引用的校验改为读取该会话元信息后比对作用域，不再以“是否在当前内存列表”为准（此前会把未加载的合法会话误判为“不属于当前项目”）。

## 4. 不做事项

- 不新增会话/消息存储模型，不改权限、审批、费用与外部服务边界。
- 不做跨项目搜索，不把其他项目会话混入当前项目结果。
- 不搜索消息正文；不引入 FTS 或新检索依赖。
- 不引入虚拟滚动库；每批 20 条下按普通列表渲染，若后续实测需要另行立项。
- 不改历史浮层的定位、尺寸、外点/Escape 收起与拖拽宽度机制。
- 不改变会话排序语义（仍以 `updatedAt` 为主），不新增“今天/更早”分组（属 CR-054 首期范畴，未实现）。
- 不修改 `chat_sessions(project_id)` 现有签名（冒烟与历史调用继续可用）。

## 5. 规则与边界

1. 分批是**呈现与查询策略**，不是数据裁剪：当前作用域内所有会话始终可访问、可搜索。
2. 分页以 `(updatedAt, id)` 游标推进，不使用 `OFFSET`；同一会话因新消息被顶到前面时不得产生重复行。
3. 新建会话插入列表顶部并 `total+1`；删除会话从列表移除并 `total-1`；两者都不整页重载。
4. 发送消息导致的 `updatedAt` 变化只更新该行与总数，不重置已加载分页。
5. 关键词需转义 `%`、`_`、`\`；空关键词等价于无关键词。
6. 滚动条按 [UI-SCROLL-001](../UI/文档/UI-CR049-滚动条按需显示.md)：实际滚动时显示、停止 700ms 隐藏；追加加载不得引发布局跳动。
7. 界面变更先更新可查看设计（UI-CR063），再改正式软件。
