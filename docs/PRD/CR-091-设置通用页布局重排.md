## 1. 来源与目标

用户 2026-11-25 原话：「重新设计一下，设置->通用 的整体布局，该分类分组的分类分组，该补充的补充，现在这里非常混乱，需要梳理」。

目标：让“通用”页按使用者在配置时的真实问题顺序分组，去掉重复与误导项，补齐缺失的常用配置，并把“改一下就被重开弹窗”的保存模型统一为单一草稿。

## 2. 现状诊断（基于现行设计稿与源码证据）

| 编号 | 现象 | 证据 |
| --- | --- | --- |
| D-01 | 六个区块平铺无层级，顺序在“数据存储 → 用户信息 → 代码样式 → 服务器配置 → 界面外观 → 会话”之间跳跃，语义不连贯 | `screens-more.js` `legacySetContent('general')` 区块顺序；`SettingsGeneral.tsx` 同级 `set-section` |
| D-02 | “用户基本信息”（名称/邮箱/角色/时区）与“界面外观”（头像/头像风格）本属同一身份域，被代码样式与服务器配置隔开 | 同上 |
| D-03 | “服务器配置”（默认端口/用户/认证/高风险确认）是新建主机的初始值，不是全局通用项 | `SettingsGeneral.tsx` §服务器配置 |
| D-04 | “高风险命令确认”以禁用开关呈现，容易被理解为“可以从界面关掉”，实际是后端强制策略 | `SettingsGeneral.tsx`：`<SettingsSwitch checked={true} onChange={() => {}} disabled …>` |
| D-05 | “会话”区块只有 1 项（生成中再次发送）却独占一组 | `SettingsGeneral.tsx` §会话 |
| D-06 | “头像风格”与“头像”两行描述同一件事，重复；风格单选组里的头像未绑定自身风格，选中态不反映到图形 | `SettingsGeneral.tsx`：`<UserAvatar size={26} />` 未传 `style`，五个选项外观相同 |
| D-07 | 存在两个“主题”：设置里的“编辑器主题”（键 `editor.theme`）与顶栏切换的界面主题（键 `theme`），用户以为改的是界面 | `general.rs` `get_theme/set_theme` 用 `theme`；通用页用 `editor.theme` |
| D-08 | 保存模型混用：整页一个“保存设置”，但“编辑器主题”“生成中再次发送”点一下即 `closeDialog()` 再 `openSettings()` 重开弹窗 | `main.js`：`set-code-theme` / `set-send-mode` 均关闭并重开 |
| D-09 | 校验只弹 toast，错误字段无内联标记、无定位 | `SettingsGeneral.tsx` `save()` 全部 `return toast(...)` |
| D-10 | 数据存储位置只能输入/选择，无打开目录、无占用、无“已改待重启”状态 | `SettingsGeneral.tsx` §数据存储 |
| D-11 | 无版本/关于/检查更新入口，无恢复本页默认 | 全页无对应区块 |
| D-12 | `Row` 声明了 `hint` 参数但渲染时丢弃，调用处仍全部传入（死参数）；与 CR-085「说明精简」并存但未收敛 | `SettingsGeneral.tsx` `function Row({label, children})` |
| D-13 | 时区只有“Asia/Shanghai / UTC”两项（外加当前值回显） | `SettingsGeneral.tsx` 时区 `select` |

## 3. 本次范围

### 3.1 重新分组（六组，按配置时的提问顺序）

| 组 | 名称 | 字段 | 说明 |
| --- | --- | --- | --- |
| G1 | 个人资料 | 头像（独立字段行，控件只有一个可点小头像，编辑在浮层内完成）；显示名称、邮箱、角色、时区 | 头像有明确归属字段，但不占大块版面；消除 D-02／D-06 |
| G2 | 外观与显示 | 界面主题（跟随系统/浅色/深色）、界面密度（标准/紧凑）；子块“代码编辑器”：代码高亮、字号、Tab、自动换行、预览 | 解决 D-07：界面主题与代码高亮各自明确；原“代码样式”降为子块 |
| G3 | 会话与行为 | 生成中再次发送、完成后通知、启动时恢复窗口 | 吸收 D-05 的单字段组，并补两项常用行为 |
| G4 | 新建主机默认值 | 默认端口、默认用户、默认认证、安全策略只读说明 | 解决 D-03／D-04：限定为“新建主机初始值”，高风险确认改为只读策略文案 |
| G5 | 数据与存储 | 数据存储位置（选择/打开/生效状态）、占用明细、知识库目录（只读+复制） | 解决 D-10 |
| G6 | 关于 | 版本、检查更新、日志目录、恢复本页默认值 | 解决 D-11 |

### 3.2 补充项（本次新增，均落到既有键值设置表）

| 字段 | 键 | 取值 | 消费点 |
| --- | --- | --- | --- |
| 界面主题 | `theme` | `system` / `light` / `dark`（原仅 `light`/`dark`，需扩展 `system`） | 应用根节点主题；顶栏切换按钮同步 |
| 界面密度 | `ui.density` | `standard` / `compact` | 设置、列表与表单行距 |
| 完成后通知 | `chat.notifyDone` | `false` / `true` | 回合结束与失败提示 |
| 启动时恢复窗口 | `ui.restoreLastWindow` | `false` / `true` | 启动时窗口与页签恢复 |

### 3.3 统一交互规则

1. **单一草稿**：所有控件只改本页草稿，任何控件都不关闭或重开设置弹窗；顶部粘附条显示“N 项未保存”，提供“放弃 / 保存”。
2. **即时预览**：界面主题、密度在选择时即时作用到界面，放弃或关闭即回滚；保存前不写入设置。头像在浮层内预览，应用后仅同步组头入口。
3. **头像浮层**：头像在“个人资料”里是独立字段行，控件只有一个小头像；点击在浮层内提供 5 种内置风格、上传图片、恢复默认与取消/应用。浮层内改动在点“应用”前不进入草稿；点外部、Escape、取消都回滚。
4. **校验内联**：非法值标红字段并给出一句原因，保存时定位到首个错误；不以 toast 代替字段标记。
5. **关闭保护**：有未保存改动时，X、遮罩与 Escape 都先询问“放弃未保存的更改？”，确认后才关闭。
6. **分组跳转**：顶部六项跳转可定位到分组，滚动时高亮当前组。
7. **说明克制**：每个字段最多一句必要说明（例如“改位置需重启生效”），不保留重复引导与大段描述；这与 CR-085 的精简目标一致，不恢复已删除的说明块。

### 3.4 明确不做

- 不新增“清理回收站 / 重建索引 / 导出诊断”等需要新后端能力的操作（后续单独立项）。
- 不做跨页设置搜索（本轮只重排通用页；如需要另行建 CR）。
- 不重排左栏七个分类，不修改设置弹窗 1040×700 与打开入口。
- 不把“新建主机默认值”拆到独立分类；本轮先在通用页内独立分组并注明作用范围，是否迁出待用户决定。

## 5. 待确认与已采用假设

- **待确认**：是否把“新建主机默认值”整体迁到独立分类或服务器页（本轮保留在通用页，独立分组 + “不影响已建主机”标签）。
- **待确认**：完成后通知与启动恢复窗口是“偏好记录”还是本轮就接入真实消费点；设计稿按“将接入”呈现，未接入前不得宣称已生效。
- **已采用假设**：`theme` 键扩展 `system` 时，旧值 `light`/`dark` 原样有效，缺失按 `system`；由前端按 `prefers-color-scheme` 解析，后端只存值。属可逆实现细节，不改变业务行为。
- **已采用假设**：占用明细由既有存储层统计，不新建表；本轮设计稿使用示例数值并明确标注“示例占用，非实时统计”。
