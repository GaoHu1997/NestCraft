## 1. 现象与实证

用户截图 330×1373，模型无法直接目视，已用像素解码核对（证据随截图留档）：

| 项 | 实测 |
| --- | --- |
| 主色 | `#4170F0` = `rgb(65,112,240)`，共 7616 px |
| 形状 | x=166..179 的竖长矩形；y=106-107 一条 14px 宽实心横边；y=108 起至截图底部三条 2px 竖线（x=166-167／172-173／178-179），竖线起点间距 6px |
| 位置 | 左侧底色 `#eff1f3`、右侧 `#f8f8f8`，即侧栏与主区之间的分隔条 |
| 色值来源 | `4170f0`／`65,112,240` 全仓（含 `src/`、`docs/UI/`）零命中 → 非作者设计色，为 UA 级／系统强调色焦点环 |

几何反推：`6px .pane-handle` + `::after` 2px 握把线（中线） + `2px outline + 2px offset` 焦点环（左右两线）＝ 14px 蓝框，与 [SC-045-08](../UI/文档/UI-CR045-文档工作区与可调栏.md)「细分割线＋6px 可命中把手，hover/focus primary，不新增厚卡片或宽装饰」冲突。

改前复现（`node scripts/verify-bug006.mjs --target=software --phase=before`，1680×1000，隔离预览 `?preview=design`，证据 `docs/Test/bug006-software-before.json` 与 `docs/Test/screenshots/bug006-software-before/`）：

| 状态 | computed outline | 命中区外蓝色轮廓 |
| --- | --- | --- |
| S0 静止 | `none` | 0 |
| S1 键盘模态后聚焦把手 | **`solid 2px rgb(43,108,246) 1px`，`:focus-visible`=true，grip=`rgb(43,108,246)`** | **3 条贯穿 887px 的蓝线，共 2661 px** |
| S2 拖动中 | `solid 2px rgb(43,108,246) 1px`（焦点环未消失） | 因把手移动出裁剪框，轮廓随把手平移 |
| S3 拖动后 | `solid 2px rgb(43,108,246) 1px` | 同上 |

设计侧同一脚本 `--target=design --phase=before`：**11/11 通过**，四状态命中区外均无蓝色轮廓 → 属 §6.3.1 第 5 类「软件偏离有效设计」，应修软件去符合设计，不得用软件现状反向覆盖设计。

## 2. 根因（代码事实）

1. `src/theme/base.css:33` 全局 `:focus-visible { outline: 2px solid var(--focus); outline-offset: 1px; }`；`src/theme/tokens.css:63` `--focus: var(--primary)`、`:15` `--primary:#2b6cf6`。
2. `src/components/pane-resize.css:4` `.pane-handle { … outline: none; … }` 本意抑制焦点环，但 `:focus-visible` 与 `.pane-handle` 特异度同为 (0,1,0)；构建后全局规则位于把手规则之后时即覆盖它。改前实测 computed `outline-style=solid`、`outline-width=2px`，证实覆盖发生。
3. `src/components/pane-resize.tsx:260` 把手 `tabIndex=0`、`role="separator"`；`:265-271` `pointerdown` 中 `event.preventDefault()` 后调用 `element.focus({ preventScroll: true })`。程序化 `focus()` 是否命中 `:focus-visible` 取决于浏览器键鼠启发式（前一次输入为键盘时命中），故用户看到「偶发」。
4. `src/components/pane-resize.css:8` `.pane-handle:hover/:focus-visible/.is-resizing::after { background: var(--primary) }` 令 2px 握把线在焦点／拖动时同样变蓝，与外圈 outline 一起构成「三条蓝线＋顶边」的 14px 框。
5. 排除项：不是文本选中（`.pane-dragging * { user-select:none!important }` 已生效、截图无淡蓝填充）；不是拖拽 ghost／占位（全仓无 `setDragImage`、无 HTML5 `dragstart` 占位）；不是 `.chat-panel` 容器（14px 全高竖条只能是分隔条）。
6. 次要假设（未证实）：截图色值 `#4170F0` 与软件主色 `#2b6cf6` 不同，可能来自 WebView2／系统强调色或截图色彩转换。修复不依赖该色值，判据是「命中区外不出现任何轮廓」。

## 3. 影响

1. 所有复用 `.pane-handle` 的可调栏（管理导航、AI 侧栏、需求树／目录、编码文件／Git、任务树／详情、知识文件／目录、服务器文件／监控、Office 文件、设置分类、会话历史、模型选择等十余处）在键盘模态后拖动时都会出现整条蓝色竖框，覆盖侧栏边界。
2. 与 UI-CR045-v1.1 SC-045-08 的有效设计冲突；仅为视觉伪影，不改变宽度调节、键盘、双击、pointer capture、宽度偏好等功能。
3. 不影响滚动容器、不改变正文宽度、不丢失草稿／光标／选区。

## 4. 验收标准（AC，事实来源）

- **AC-BUG006-01**：给定任一可见 `.pane-handle`（左／右侧栏），当处于静止、键盘聚焦、拖动中、拖动结束四状态时，把手 6px 命中区之外不出现任何主色／蓝色轮廓竖线或横边，且 computed `outline-style` 为 `none`。
- **AC-BUG006-02**：键盘 Tab 聚焦把手并用方向键／Home／End 调宽时，焦点仍可辨（`::after` 握把线保持 `--primary`）；全局 `:focus-visible` 不被删除，其它控件键盘焦点行为不变（继承 CR-068 结论）。
- **AC-BUG006-03**：拖动时 `.pane-dragging` 仍抑制文本选中；宽度限幅、双击恢复默认、pointercancel／窗口失焦／卸载清理、方向键步长均不回归。
- **AC-BUG006-04**：浅／深主题、AI 侧栏 320／372／480／620 与管理导航 176／224／320 档，以及其余复用 `.pane-handle` 的页面表现一致；≤600px 把手隐藏规则不变。
- **AC-BUG006-05**：[UI-BUG006-v1](../UI/文档/UI-BUG006-拖动侧栏分隔条无蓝色焦点框.md) 设计稿与软件在同视口、同四状态下成对截图／像素断言一致，无未解决视觉偏离；UI-SCROLL-001（滚动条按需显隐）行为不变。
- **AC-BUG006-06**：真实 Tauri WebView2 与用户目视验收由用户完成；未完成时保持「待验收」，不得标记已完成（模型不能判读必需视觉，静态像素证据不替代目视验收）。
