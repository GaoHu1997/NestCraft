## 1. 背景与目标

CR-090 把编码区补到「能像 IDE 一样读代码」的第一版：定义跳转、面包屑、导航历史都基于自研的**语法级符号索引**，不接 LSP。但它只覆盖 TS/JS（外加 Python 的 `def`／`class` 声明提取），**没有任何继承关系**，因此用户最常问的两个问题在界面里无解：

1. 「这个接口，谁实现了它？」——打开接口只能靠肉眼在文件树里翻。
2. 「这个类，父类／接口是谁？」——只能自己去找 `extends`／`implements` 那一行。

成熟 IDE 的做法是接 LSP（`textDocument/implementation`、`typeHierarchy`），代价是每个语言都要装语言服务器、管版本、离线不可用、进程与信任边界复杂（RESEARCH-007 §7.4、§12）。**本项目定位是「个人 Agent 工作台的辅助编码区」，不是 IDE**，用户也明确「主要是方便看代码，不会实际运行」。因此本 CR 选择**路线 A：把语法索引从「声明」扩展到「类型继承关系」**，用**精度换可用性**：不引入外部进程，对三语言的关键跳转做到「大多数时候够用」，识别不到时**在界面上明确说可能不全**，而不是假装准确。

> 取舍口径（写死在本 CR）：宁可少跳、并告诉用户「可能不全」，也不给出**看起来确定但其实猜的**位置。

## 3. 本次范围

### S1 语言适配层（→ [STORY-110](../Plan/Story/STORY-110-多语言符号索引适配层.md)）
把现有 TS/JS 专用索引抽成「语言适配层」：每种语言一个适配器，各自解析出 **声明**、**import／using／from-import**、**类型继承关系**（`extends`／`implements`／基类列表），输出到统一结构；统一 `resolve`（定义／实现／父类型）入口。既有 TS/JS 行为保持不变。

### S2 双向跳转（→ [STORY-111](../Plan/Story/STORY-111-接口实现与父类型跳转.md)）
接口→实现类（含**间接继承**标注）、实现类→父类型；快捷键 `Ctrl+Alt+B`（跳实现）、`Ctrl+U`（跳父类型）、鼠标 `Ctrl+Alt+左键`，右键菜单两项；多目标复用 CR-090 的 `GotoPopup` 选择器。

### S3 gutter 与语言标识（→ [STORY-112](../Plan/Story/STORY-112-继承gutter标记与语言标识.md)）
行号旁 `↓`（有实现／子类）、`↑`（有父类型），悬停显示数量与来源，点击跳转；三语言文件图标／语言标识；**精度提示常驻可见**。

## 5. 规则、精度与边界

1. **只读导航**：所有跳转、gutter 点击、右键菜单均为只读，**不修改文件内容**、不插入、不格式化、不触发保存。
2. **不静默给错**：任何「识别不到／可能不全」的情况，必须**在界面上可见地**提示 `基于语法索引，可能不全`，并提供该语言的限制说明入口；不得静默跳到一个错的位置，也不得静默无反应。
3. **精度提示位置**：至少覆盖三处——编码区状态栏（常驻文案）、gutter 悬停卡片、跳转失败／多目标选择器内。
4. **C# 语义归一**：C# 语法上无法区分「基类」与「接口」（`class A : B, IC`），界面**统一呈现为「父类型」**，并在说明中写清；不得假装区分。
5. **性能边界**：索引构建**不阻塞输入**（打字、滚动、切页签不卡顿），必须有单文件大小上限、总文件数上限与超限降级路径；降级时降级本身要可见。
6. **规模降级**：超大文件、超大项目、空项目都必须有确定行为（见各 Story AC），不得转圈卡死或抛未捕获异常。
7. **失败隔离**：任何语言解析失败、编码异常、二进制文件，只跳过该文件并计数，**不影响**同项目其它文件、不影响编辑、不弹错误弹窗打断阅读。
8. **回归不可破**：CR-090 的定义跳转、面包屑、导航历史、多目标选择器、文件树操作、页签行为全部保持；TS/JS 既有精度不得下降。
9. **滚动条**：新增的 gutter 提示卡、语言限制说明面板、选择器遵循 [UI-SCROLL-001](CR-049-滚动条仅在滚动时显示.md)，滚动时显示、停止隐藏，不得用 `overflow:hidden` 实现隐藏。
10. **深色与窄屏**：gutter 标记、语言图标、精度提示在深色主题与窄侧栏下不破版、不溢出、不因 gutter 改变行号区宽度导致正文横向抖动。

### 5.1 逐语言「识别不到什么」（界面说明与 AC 共用同一份口径）

| 语言 | 能识别 | **识别不到（必须提示可能不全）** |
| --- | --- | --- |
| Java | `class`／`interface`／`enum`／`record`／`@interface` 声明；`extends`／`implements` 列表；`import`（含通配 `import a.b.*`、同包无 import）；方法声明与 `@Override` 所在行 | **匿名内部类**（`new Runnable(){…}` 不产生可跳转的具名类型）、**Lambda 体**内的类型、**泛型实参**（`List<Foo>` 中 `Foo` 不作继承边）、**跨 jar**（依赖源码不在项目内）、注解处理器／生成代码、内部类按简名引用但未 import、重载与桥接方法 |
| C# | `class`／`interface`／`struct`／`record`／`enum` 声明；`class X : A, IB` 全列表；`using`（含 `using static`）；`override`／`abstract` 方法 | **基类与接口无法区分**（统一按「父类型」呈现）、`partial class` 分部、泛型约束中的类型、委托／事件／索引器、源生成器产物、NuGet 程序集内类型、扩展方法 |
| Python | `class X(A, B)` 基类列表；`def`／`async def`；`import x`／`from m import a as b`；`ABC` 直接继承 | **动态绑定**（`getattr`／`setattr`／`globals()`、变量或字符串作基类）、`ABCMeta.register()` 虚拟子类、`import *`、条件／延迟导入、元类魔法（`__init_subclass__`）、类型注解不构成继承、鸭子类型（无显式继承即无父子关系） |

## 6. 质量要求与外部依赖

- **设计先行**：界面新增（gutter 标记、语言标识、精度提示、右键菜单两项、`Ctrl+U` 反馈）必须先有可查看设计 UI-CR094-v1 并登记版本，再进入软件实现（AGENTS.md §6.3.1）；设计缺场景的受影响部分不得开发。
- **无外部进程依赖**：不新增语言服务器、不新增 native 二进制；解析全部在现有前端运行时内完成（与 CR-090 符号索引同层）。
- **无数据库变更**：索引为页面生命周期内的内存缓存，刷新或切项目即丢弃；不新增表（数据设计结论：不适用）。
- **依赖复用**：复用 CR-090 的 `modifier.ts`（窗口级修饰键）、`GotoPopup`（多目标选择器）、`history.ts`（导航历史）、`openFile(path,{selection})` 打开定位入口；不新建并行体系。
- **性能数值**：单文件解析上限与总文件数上限在 LLD 中定值，取值不得低于 CR-090 现有口径（单文件 1 MB／总 5000 文件）；超限行为见 AC。
