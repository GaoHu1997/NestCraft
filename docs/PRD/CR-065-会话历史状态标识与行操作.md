## 1. 用户结果

会话历史列表只保留必要信息：**状态用左侧小标识表达、当前会话用背景色表达、行操作收进「…」菜单**，列表底部显示当前会话的 token 消耗，不再出现「已读 / 未读 / 当前」文字，也不再出现新增会话入口。

## 2. 逐条范围

### 2.1 选中态：只高亮、不要边框（用户第 1 点）

- 当前会话行使用背景色（`--node-sel-bg`）表达选中。
- **移除行边框**：`.chat-hist-item.active` 不再设置 `border-color`；行基础边框保持透明（或 `border: 0`），保证选中/取消选中不引起 1px 位移。
- 行仍然有 `aria-current="true"`。

### 2.2 状态标识（用户第 2 点）

只保留左侧 10px 标识位，**删除行尾状态文字**（「已读」「运行中」「成功」「失败」「待处理」全部不再显示）：

| 会话状态 | 左侧标识 |
| --- | --- |
| 正在运行 | 旋转 loading 环（`--accent`，1.5px，`.8s` linear infinite） |
| 已完成且已读 | **无标识，留空**（保持 10px 占位，不塌陷） |
| 已完成未读 · 成功 | 绿色小圆点（`--good-dot`） |
| 已完成未读 · 失败 | 红色小圆点（`--bad-dot`） |
| 待用户处理 / 待用户回答 | 橘色小圆点（`--warn-dot`） |

规则：

- 未读标识随「进入会话」消失：`markRead` 成功后 `unread` 置空 → 无标识。三种颜色点都适用（用户只对绿点明说，其余按同一“未读”语义处理）。
- 运行中优先于未读：运行中的会话显示 spinner，结束后按 `unread` 显示点。
- 状态映射兼容既有 `unread` 取值：`success|green|done` → 绿；`failed|failure|error|red` → 红；其余非空（`pending|yellow|amber` 等）→ 橘；`null/""/none` → 无。
- 不使用颜色作为唯一信号：每个标识带 `title` 与 `aria-label`（如「运行中」「未读·成功」「未读·失败」「待处理」「已读」）。

### 2.3 移除新增会话入口（用户第 3 点）

- 删除历史浮层底部的「新会话」按钮。
- 新会话能力保留在 AI 侧栏头部的 `+` 按钮（`ChatPanel` 已存在，`aria-label="新会话"`），不另建第二入口。
- 删除底部栏后列表延伸到底，不再显示任何汇总信息（用户后续修正：每行元信息已有 token，底部汇总重复）。

### 2.4 不新增底部 token 汇总（用户第 4 点的后续修正）

- **不实现**底部「本会话消耗 … tok」：每行元信息已经显示该会话的 token，底部重复没有信息增量。
- 浮层底部不再保留按钮或文字栏；历史列表直接延伸到浮层底边。
- 若后续确有“当前会话累计消耗”需求，放到会话统计浮层（已有点击入口），不在历史列表重复。

### 2.5 「全部」改为「重置」（用户第 5 点）

- 文案由「全部」改为 **「重置」**；`aria-label="清空搜索并重新查询"`。
- 语义：清空关键词、退出搜索态、回到第 1 页按 20 条重新查询（与 CR-063 的「全部」行为一致，只改文案与语义提示）。
- 非搜索态（关键词为空）时按钮禁用（`disabled`，降低不透明度），避免“点了没反应”。
- 空态「清除搜索」文案保留，行为同「重置」。

### 2.6 行悬浮「…」操作菜单（用户第 6 点）

- 行 hover 或键盘聚焦时，行尾出现「…」按钮（24×24，替代现有单独删除图标）；占位固定，hover 不引发布局跳动。
- 点击「…」弹出菜单（锚定按钮下方/左下方，窄屏不超出视口），菜单项：

| 菜单项 | 行为 | 备注 |
| --- | --- | --- |
| 复制会话 ID | 写入剪贴板，`toast("已复制会话 ID")` | `navigator.clipboard.writeText`；失败回退隐藏 textarea + `execCommand("copy")`，仍失败则提示手动复制 |
| 分叉会话 | 调用 `chat_session_fork`，生成保留上下文的新会话并切换过去 | 运行中的会话禁用（`title` 说明原因）；新会话标题 `分叉 · 原标题` |
| 置顶 / 取消置顶 | 调用 `chat_session_pin(id, pinned)`；置顶后排到列表最前 | 置顶行标题前显示小图钉图标；非置顶时菜单项为「置顶」 |
| 重命名 | **原位编辑**：该行标题变成输入框（自动聚焦并全选），Enter 或失焦保存，Escape 取消 | 空标题提示并恢复原标题；长度 ≤ 200；不弹框 |
| 删除 | 既有确认弹窗（取消 / 确认，危险色） | 保留 CR-063 行为 |

- 菜单互斥：同一时刻只开一个；外点、Escape、滚动、切换会话均关闭。
- 菜单键盘可达：`↑/↓` 移动、`Enter` 执行、`Escape` 关闭。
- 置顶的排序语义：`pinnedAt` 非空的会话排在未置顶之前；置顶组内按 `pinnedAt` 倒序（最近置顶在前），未置顶组按 `updatedAt` 倒序。与 CR-063 的游标分页兼容（见 LLD §4）。

## 3. 不做事项

- 不改会话数据归属、权限、审批与派发链路；分叉不复制原生线程绑定（必须显式重建上下文）。
- 不做多选、批量操作、拖拽排序。
- 不做「置顶分组标题」（如「置顶」分组），只用排序 + 图钉图标表达。
- 不新增外部依赖；剪贴板用浏览器 API + 回退，不引入 Tauri 剪贴板插件。
- 不改变历史浮层的定位、宽度拖拽、外点/Escape 收起。
- 不改变分批大小（20）与搜索范围（当前作用域标题）。

## 4. 规则与边界

1. 状态点与 spinner 只表达状态，不承担点击；点击行仍切换会话。
2. 已读清除必须以后端 `chat_session_update({unread:""})` 成功为准，失败不假装已读。
3. 分叉会话生成后必须：
   - 复制源会话的消息（role/content/meta/refs/time），**不复制** `nativeThreadRef`、`nativeBindingRevision`、`nativeConfirmedTurnId`；
   - 新会话 `sessionRole` 为 `ordinary`，`featureId` 复制但 `featureSourceHash` 保留原值；
   - 新会话 `draft` 为空、`unread` 为空、`pinnedAt` 为空。
4. 运行中的会话：禁止分叉（避免复制到半轮消息）；允许置顶、重命名、复制 ID；删除仍受既有“先停止”约束（后端拒绝）。
5. 置顶字段变更必须持久化，重启后保留。
6. token 只保留在每行元信息中，不在列表底部重复；重命名用行内原位编辑，不弹框。
7. 重命名保存失败时恢复原标题并提示，不静默丢弃用户输入。
