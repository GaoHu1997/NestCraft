# CR-086：平台能力统一供给（skill / mcp / tool → CLI 与 runtime）

- 状态：**已实现，技术验证通过，待验收**（2026-11-25 用户明确要求「平台内部的 skill/mcp/tool 可以直接给 cli 或者自己的 runtime 用」，并限定只做这一件事）
- 来源：用户 2026-11-25 反馈「大管家和 CLI 工具都不能用，比如提供了生图工具，但不能用」，随后明确唯一要求：平台持有的能力统一供给两条执行通道。
- 关联：[FEAT-025 平台主代理运行时](../Plan/Feature/FEAT-025-平台主代理运行时.md)、[FEAT-013 统一设置入口与菜单](../Plan/Feature/FEAT-013-统一设置入口与菜单.md)、[FEAT-015 CLISDK装卸与会话可用性](../Plan/Feature/FEAT-015-CLISDK装卸与会话可用性.md)
- 关联 Story：[STORY-089](../Plan/Story/STORY-089-平台主代理会话与模型调用.md)、[STORY-078](../Plan/Story/STORY-078-能力管理评审调整.md)
- 关联需求：[CR-069](CR-069-平台主代理运行时与受管执行接入.md)、[CR-059](CR-059-设置中心评审调整.md)、[CR-060](CR-060-AI内置工作台工具集.md)

## 1. 问题

平台已经持有一份能力目录，但两条执行通道各用各的：

| 能力 | 平台已持有 | CLI 通道 | 平台 runtime（大管家） |
| --- | --- | --- | --- |
| Tool | `ai_tools::workbench_tools()`（22 项，含 `generate_image`） | 经 workbench MCP 全量注入 | **只用固定 13 项白名单**，生图、建项目、建知识库、存服务器等被挡 |
| Skill | `capability` 表 `kind='skill'`（名称、描述、正文） | 仅 `--add-dir` 加目录，未见按需读取入口 | **完全未注入** |
| MCP | `mcp_server` 表（stdio / http，含发现缓存） | 经 `mcp_servers` 注入 | **完全不支持** |

结果：同一句「生成一张图」，在 CLI 会话里看不到工作台的 `generate_image`（只看到 codex 自带的 `image_gen`），在大管家里模型直接回答「后台没有提供图像生成工具」。

## 2. 本次范围

1. **Tool**：平台 runtime 直接使用工作台工具目录全部启用项，取消固定白名单裁剪；`aiTools.enabled` 总闸与单工具 `capability.enabled` 仍然生效。
2. **Skill**：新增 `read_skill` 工具，CLI（workbench MCP）与平台 runtime 共用同一实现；平台系统提示列出已启用技能的名称与描述，正文按需读取。路径必须落在受管 `skills` 目录内，上限 256KB。
3. **MCP**：平台 runtime 读取已启用 MCP 服务器的发现缓存，把工具以 `mcp__<server>__<tool>` 暴露给模型；调用时 stdio 走独立短会话、HTTP 走现有会话与凭据路径。失败作为工具错误回填，不中断整轮。

## 3. 不做

- 不改变 CLI 通道既有的 MCP / skill 目录注入方式（只增加一个 `read_skill` 工具）。
- 不自动替用户执行 MCP「发现工具」；未发现过工具的服务器在平台通道不可见（设置里已有发现入口）。
- 不改工具目录的既有语义与写类工具的校验路径。
- 不做跨通道的会话上下文迁移。

## 4. 验收标准

- **AC-CR086-01**：平台会话下模型可见工作台工具目录全部启用项，包含 `generate_image`、`create_project`、`read_skill`；停用某个工具后当轮即消失。
- **AC-CR086-02**：`aiTools.enabled` 显式关闭时，平台与 CLI 都不再暴露工作台工具；显式开启或缺省时恢复。
- **AC-CR086-03**：`read_skill` 不传 `name` 返回已启用技能清单，传 `name` 返回正文；停用技能、越界路径、超限大小被拒绝。
- **AC-CR086-04**：已启用且有发现缓存的 MCP 服务器，其工具以 `mcp__server__tool` 出现在平台工具定义中；调用成功返回文本，失败返回可读错误且不影响后续轮次。
- **AC-CR086-05**：CLI 通道工具数随目录变为 23，`read_skill` 可经 workbench MCP 调用；既有 22 项行为不变。
- **AC-CR086-06**：未发现工具的 MCP 服务器不导致平台轮次失败；无 `mcp_server` 表的环境（隔离测试）同样安全降级。
