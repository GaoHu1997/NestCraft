# CR-086：知识库改为 Obsidian 式本地文件交互

- 状态：已实现，待验收（2026-11-25）。用户评审后指令“调整代码”作为本特性编码授权；实际结果见[正式实现与验证](../Test/REPORT-CR088-正式实现与验证.md)。悬停预览、自定义重命名对话框、`[[#本页标题]]` 自锚点与块锚点本版未做。
- 来源：2026-11-25 用户反馈「知识库操作更倾向于 Obsidian 的样式，本地文件知识库，不是在线文档」，并要求调研 Obsidian。
- 归属：[EPIC-005](../Plan/Epic/EPIC-005-知识阅读与项目授权.md) → [FEAT-009](../Plan/Feature/FEAT-009-知识库目录与正文阅读.md) → [STORY-014 CR-086 增量](../Plan/Story/STORY-014-服务器列表与知识库三栏阅读.md#cr-088-obsidian-式链接与反链)。
- 与 [CR-084](CR-084-知识库多格式预览与完整阅读.md) 的关系：CR-084 的 PDF 分页、Markdown 完整阅读继续有效；Office 转换预览按用户 2026-11-25 决定**维持现状**，不改为外部打开。

## 调研结论（Obsidian 官方定义）

1. **库就是一个普通文件夹**，配置在库根 `.obsidian`；文件就是真相，没有"在线文档"概念。
2. 只有 **Markdown** 是正文；`.base`、`.canvas`、图片、音视频、PDF 是附件/视图；**docx/pptx/xlsx 不在支持列表**，需插件或外部程序。
3. 附件是"普通文件，可用文件系统访问"；拖拽/粘贴会复制到**默认附件位置**（库根／指定文件夹／同目录／子目录四选一）。
4. 链接用 `[[wikilink]]` 或 Markdown 链接；**重命名文件时自动更新所有指向它的链接**；支持标题锚点、块锚点、悬停预览。
5. 删除三选一：系统回收站／库内 `.trash`／永久删除。

## 本次确认的三项决定（用户 2026-11-25）

| 议题 | 用户决定 | 对本需求的影响 |
| --- | --- | --- |
| docx／pptx／xlsx 打开方式 | **维持现状：默认库内转换预览** | 不调整为"外部程序打开"；保留 CR-084 转换链路与运行组件要求 |
| `[[wikilink]]`／反向链接 | **本轮就做** | 纳入本期范围，含重命名自动改链接 |
| 附件落点 | **上传到哪个目录就放到哪个目录** | 不做可配置"默认附件文件夹"，沿用"跟随当前目录"；不自动创建 `assets/` |

## 范围

**包含**
- `[[...]]` 双链：解析、跳转、悬停预览、未解析链接的"点击新建"。
- 反向链接面板：谁引用了当前笔记；区分已解析与未解析。
- 重命名／移动笔记时，预览并更新全库指向它的链接（含标题锚点写法）。
- 链接索引：随保存／扫描增量维护，可全量重建；不改变 AI 检索与授权口径。
- 交互形态向 Obsidian 靠拢：文件树 + 编辑器/阅读 + 右侧「大纲／反向链接」页签；空库与无结果有明确空态。
- 附件：上传即落在当前所在目录（现状固化），界面显示真实落点。

**不包含**
- 块锚点 `#^id`、`![[嵌入]]` 语法（本轮不做，另议）。
- `.canvas`、`.base`、图谱视图、命令面板、多库同时打开。
- 把 docx/pptx 变成可编辑正文；Office 打开方式维持 CR-084 现状。
- 改变索引检索、项目授权、AI 工具边界、回收站既有语义。

## 关键规则

1. **解析优先级**：完整路径精确命中 → 同目录同名 → 全库唯一文件名 → 仍不唯一则视为**歧义**，界面给候选，不静默猜一个目标。
2. **未解析链接**（目标不存在）保留原文并显式样式；点击可"按该路径新建笔记"，新建后该链接转为已解析。
3. **重命名/移动**：默认更新全库链接；操作前显示"将影响 N 个文件、M 处链接"；更新在同一事务内完成，失败回滚，不留半改状态。
4. **链接不改 AI 口径**：链接关系只用于阅读导航与反链展示，不扩大 AI 可读范围、不自动把关联笔记拼进上下文。
5. **索引可重建**：链接表是派生数据；损坏可全量重建，不影响原件与正文。
