## 2. 已确认的决定

用户 2026-11-26 回答三问，作为本轮需求边界依据：

- **D1 身份模拟范围**：全局开关＋身份二选一。设置在「通用 → 会话与行为」，一个总开关＋Codex／Claude 单选；开启后平台 runtime 调用模型时统一携带该 CLI 的客户端身份（**不伪造凭证、不伪造账号与计费头**）。
- **D2 权限挡位**：按参考 GUI 的已验证定义。用户指示「他是根据不同类型的 cli 定义的，他是经过验证的，直接用就好」。即以参考实现 `webview/src/components/ChatInputBox/selectors/ModeSelect.tsx` 的 provider 门控为准，不再保留「未核验」占位灰项。
- **D3 能力管理**：合并为一个「能力管理」左栏项，内部四个 tab：Skill／MCP／Tools／搜索。

## 3. 参考实现实读事实（决定 D2 的依据）

来源：[参考索引](../参考/README.md) 登记的 `jetbrains-cc-gui`（本地 `docs/参考/repos/jetbrains-cc-gui`，MIT）。正式文档不引用参考目录路径，以下为本项目术语转写后的机制结论：

| 事实 | 出处（参考实现文件） | 本项目采用 |
| --- | --- | --- |
| 五个静态权限模式：`default`／`plan`／`acceptEdits`／`auto`／`bypassPermissions` | `ChatInputBox/types.ts` `AVAILABLE_MODES` | 四档映射为本项目语义（见下表） |
| Claude：全部五项可选 | `ModeSelect.tsx` 兜底分支 | 默认／规划／代理／自动审核／完全访问 |
| Codex：五项可选，但 `auto` 需原生审查可用 | `ModeSelect.tsx` `provider === 'codex'` 分支 + `codexNativeAutoReviewAvailable` | 默认／规划／代理／完全访问；自动审核按版本可用性显隐 |
| 无头 CLI（Grok 等）：隐藏 `auto` 与 `plan`，只留 `default`／`acceptEdits`／`bypassPermissions` | 同上无头分支 | Grok 只给三档，不给灰项 |

与现状的差异（本项目后端 `chat.rs:1100 validate_permission` 只放行 `default`／`plan`／`agent`，其余一律拒绝）：**这是界面与能力定义不一致的根因**——界面把未实现档位画成灰项，用户看不到可用性理由。本轮先统一设计口径，实现需另获编码授权。

## 4. 本次范围

### 4.1 通用
1. 顶部粘附条上方出现溢出/穿模内容（截图 3 红框）修复设计：粘附条与滚动容器边界、`scroll-margin` 与吸顶底色须覆盖滚动内容。
2. 「会话与行为」新增「模拟客户端身份」：总开关＋Codex／Claude 二选一，默认关闭；说明写明「只改变客户端身份标识，不改变凭证、账号与计费」。

### 4.2 模型管理
3. 「新增供应商」移出头部，改为供应商列表下方的**文字按钮**。
4. 点击后只在「新增供应商」下方打开一张**未保存草稿卡**：页签与标准供应商卡一致（**供应商配置／模型配置**两者齐备）；不写入供应商数据、不计入「N 个在用供应商」、不进入上方列表；点「保存供应商」后才落到上方列表，草稿里的模型一并提交。
5. 停用供应商默认折叠；折叠入口位于**在用列表下方、新增供应商上方**，不与新增入口混排。停用卡**沿用原卡片与原开关**，只做折叠，不改样式。
6. 供应商配置两个端点输入框左边缘对齐（标签列定宽，输入框同起点）。

### 4.3 模型检测
7. 移除「检测进行中」这类会插入布局的提示行；进度只由结果区呈现（结果区已有状态与进度）。
8. 结果区**移除整段「存在不通过项」**；此处只展示**指纹归因到哪个模型**（最像的候选、一致性、声称家族、概率性提示），仍是纯文本，不带边框、底色、阴影与独立卡片。

### 4.4 SDK 与 CLI
9. CLI 模型下拉为空（截图 2 只有「未选择」）修复设计：候选来源、过滤条件与空态原因必须可见、可解释。
10. 权限下拉按 §3 的按 CLI 定义重做，去掉「未核验」灰项；不支持的档位不出现。

### 4.5 能力管理
11. 设置左栏由 8 项收敛为「通用／模型管理／模型检测／SDK 与 CLI／能力管理」5 项；「能力管理」内四个 tab：Skill／MCP／Tools／搜索。
