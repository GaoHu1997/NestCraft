# CR-038：办公类型项目的文档协作与交付

- 状态：用户已授权需求／设计调整；本细化稿与可操作原型待评审，正式能力未实现，未获得正式编码授权。
- 来源：2026-11-19 用户要求「汇总一下，根据这样参考调整我们办公模式的需求和设计，力求达到好用」，随后纠正「我指的是 项目类型为办公的」。范围严格为 `project.kind = work`，不是全局模式切换，也不是重做整个工作台。
- 归属：[EPIC-003](../Plan/Epic/EPIC-003-办公资料与文档产出.md) → [FEAT-006](../Plan/Feature/FEAT-006-办公资料解读与产物预览.md)。复用 [STORY-008](../Plan/Story/STORY-008-研发与办公工作模式.md) 的类型边界；新增 [STORY-065](../Plan/Story/STORY-065-办公项目资料与连续编辑.md)、[STORY-066](../Plan/Story/STORY-066-办公项目AI协作与修改审阅.md)、[STORY-067](../Plan/Story/STORY-067-办公项目成果检查与导出.md)。不新建 Epic／Feature。
- 继承：PRD-001 CR-004（办公不强加研发树）、CR-028（原文件权威）、CR-030（授权内按需读取）、CR-033（固定首页和同对象聚焦）、CR-036-v2（页签贴顶、单面分隔、白蓝视觉与 AI 侧栏）。

## 1. 目标与当前差距

用户打开办公项目，应能直接开始处理资料，而不是先创建敏捷需求或配置智能体。目标闭环：**选择资料 → 阅读／自己编辑 → 交给 AI 解读或生成 → 审阅修改 → 保存成果 → 检查并导出**。

当前设计静态核对：办公项目仍共用「需求／设计／任务／文档」页签；文档只显示 Markdown 样例，新建按钮仅提示；没有分格式编辑、项目内 AI 上下文、草稿审阅或交付状态。这是当前原型与既有 CR-004 的偏差，不能拿该原型反向取消办公边界。真实 Office 编辑、解析、写回、导出均未验证。

## 2. 本次包含与不包含

包含：办公项目内部的资料／成果组织、Markdown／Word／表格／PPT 阅读和基础编辑设计、PDF 只读解读、项目内 AI 与来源定位、修改提案审阅、防覆盖、成果版本与导出检查、桌面／窄屏／深色／异常状态，以及这些场景的离线可操作演示。

不包含：编码项目的需求／设计／任务／Git、全局工作台与设置重做、知识库授权模型重造、云端同步／团队实时共编、CAD／视频／设计软件全集、宏运行、自动发布／邮件发送、真实模型请求、安装第三方 Office 引擎或转换器。共享壳只允许为 `work` 接入所需的条件分支，不改变 `code` 行为。

本轮不修改正式源码、依赖、运行配置、构建／发布产物。可操作 HTML/CSS/JS 只用于设计仿真，不等于接通 Office 能力。

## 3. 办公项目的信息架构

1. 保留「项目管理 → 类型：办公 → 打开项目」，每个项目沿用自身独立工作区，不新增全局“办公模式”。CR-041明确：work创建／绑定资料与本地阅读、手工编辑不以前置配置CLI／模型为条件；所选位置仍须有效可访问，只有主动发起AI时才校验执行配置与资料发送授权。此处局部细化STORY-019 AC-01的work分支，code条件不变。
2. 办公项目只显示两个页签：**文档、成果**。默认文档，成果是同一文件集合的已接受版本视图，不是复制的另一套正文；不显示 Epic／Story、迭代、代码或研发派发页。
3. 文档区三栏：左侧项目资料（搜索、来源／草稿／成果分组、格式图标与状态）；中间文件页签、正文和按格式变化的工具条；右侧沿用 AI 侧栏位置与开关，内容限定当前办公项目。
4. 正文优先。来源信息／章节目录／运行过程按需展开，不永久堆成第四栏；复杂配置保留在已有设置，不要求普通办公用户懂 CLI/MCP。
5. 空项目提供“添加资料”“新建文档”，并解释资料与成果的关系；“载入演示样例”必须显式操作，不能自动覆盖已有项目、快照或草稿。
6. 复开同一项目只聚焦；文档页签、编辑草稿、引用选择、会话及待审阅修改按项目隔离。关闭有未保存编辑时给“保存／不保存并关闭／继续编辑”，不得悄悄丢失。离线原型刷新会丢会话内存须显著说明。

## 4. 文件与编辑体验

| 格式 | 设计目标 | 明确边界 |
| --- | --- | --- |
| Markdown | 阅读／编辑切换、即时草稿、保存状态、源文与预览一致 | 原 `.md` 为权威；不是另存数据库正文 |
| Word（DOCX） | 白纸正文、标题／段落基础编辑、选区 AI 操作与文档结构定位 | 不承诺复杂页眉、域、版式百分百往返；保真不足警告并另存 |
| 表格（XLSX） | 工作表切换、单元格选择、公式条、基础数据编辑，AI 说明范围 | 基础示例公式演示不冒充完整计算引擎；VBA 不执行 |
| 演示文稿（PPTX） | 缩略图选页、逐页预览、标题／正文编辑、由大纲生成并审阅 | 不承诺复杂动画或母版无损；生成内容不应只是换后缀的文本 |
| PDF | 页码导航、只读预览／解读与来源页定位 | 扫描件无 OCR 时明确不可读，不编造提取内容 |
| 未支持／损坏／加密文件 | 保留原件，展示原因与恢复入口 | 不伪装成功、不静默降成纯文本覆盖原格式 |

保存状态独立于 AI 状态：未保存、保存中、已保存、保存失败、版本冲突。手工输入不因切文档／收 AI／切项目丢失；失败保留草稿并可重试。新增同名文件拒绝覆盖，提供改名建议；原件默认只读，编辑采用创建副本，源资料不被生成结果覆盖。

## 5. AI 协作：少配置、看得见、可收回

### 5.1 输入与资料范围

- 高频快捷动作：解读资料、提取要点、润色所选内容、生成 Word、生成 PPT、分析选中表格；有资料时自动带上当前文件引用但不自动发请求。
- 生成前一个简短表单：用途／受众、输出类型、标题（PPT 可加页数）；资料引用勾选可见，允许移除；不强迫先配置一长串代理参数。
- 当前文件／页／单元格范围使用稳定引用；知识库引用仍用现行项目授权，不跨项目借资料。发送前检查可读性、当前权限、选中文本和版本；无来源的结论必须标“待补资料／推断”。
- **本地保存不等于模型不联网**。使用远程模型时提示将发送的文件／片段范围；未同意不发送。用户无模型或不可用时提供已有设置入口，仍能阅读和手工编辑。

### 5.2 执行与审阅

- 办公会话内显示“读取资料 → 生成草稿 → 检查结果”，详情可展开，失败附具体原因；提供停止、原输入重试，不创建研发 Story／任务树。
- AI 输出先进入候选草稿。解读显示证据引用可点回正文位置；修改显示“原内容／建议内容”，支持逐项接受／拒绝、继续修改、整份放弃。
- **接受建议只合入编辑草稿，不等于保存到原文件**；最终保存成功才晋升项目成果版本。新生成提案全拒绝／停止不加入成果。
- 若人已修改同一基线或源文件发生变化，阻止直接应用，给“重新比较／重新生成／保留两份”；不得以“全自动”权限绕过文件版本检查。
- 运行、取消、失败与完成事件按项目／会话／请求代次关联，晚到结果不得写回另一项目、复活取消提案或覆盖更新草稿。
- 审阅范围与用户决定需可追踪；不能把“AI 自检完成”当作用户验收。

## 6. 成果与导出

成果页显示文件名、类型、版本、来源、检查状态和最近保存时间；点文件仍在同一文档区打开。每次接受并保存生成新版本，旧版本可查看并“恢复为新草稿”，不改写历史。

导出前明确：目标格式、文件名、保存位置、当前版本、资料来源检查、未处理修改／未保存内容／兼容性风险。未保存先保存或明确选择已保存版本；同名默认建议新名称。权限拒绝、空间不足、引擎不可用或部分失败时保留候选和重试入口，不显示假成功。

**本轮设计稿的 DOCX／XLSX／PPTX／PDF 导出只演示检查与状态，禁用真实下载并注明“未接入导出引擎”**。不把 Markdown 文件改后缀假装 Office。真实可交付标准留在 Story／测试计划，须后续实际原生文件往返和打开验证。

## 7. 将“好用”变成可观察标准

- 打开任一办公项目后一步到文档，不出现研发空需求页。
- 选资料后，两次主动操作内进入解读或生成表单（不把填写和必要确认隐藏为自动操作）。
- 完整设计演示：从两份资料生成一份汇报 → 定位来源 → 拒绝一项／接受一项 → 保存成果 → 查看版本及导出检查；全过程无需离开办公项目。
- 常用按钮文字明确，主操作唯一；不将关键成功／失败只做短暂 toast；支持键盘、可见焦点、Esc 关闭弹窗、表单错误定位。
- 文档与 AI 均可独立滚动；1440×900／1280×800 正文可读；390×844 使用文档／AI 单主区切换或抽屉，不把三栏硬挤，无整页横向溢出；表格可内部横向滚动。
- 不把体验目标伪写为实测收益或用户可用性结论。真实性能、真实排版保真和新用户试用仍需正式实现后验证。
