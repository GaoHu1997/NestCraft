# CR-015：启动 Tauri 正式实现

- 日期：2026-11-19；来源：用户指令「根据需求开始开发，我倾向使用 tauri 进行开发」，并给出 8 个参考项目清单，明确「逻辑实现能抄就抄，然后根据我们的需要本地化……样式需要使用我们自己的 UI 设计。整个过程中，不要询问我，一切都按推荐的来，我只需要结果」。该指令作为本批实现范围的确认依据与执行授权。
- 类型：从仿真转入正式实现的启动变更；不改变既有需求行为（PRD-001 基础范围、CR-004～014 仍然有效），只决定实现载体与技术栈。
- 状态：实现中。

## 范围

1. **实现载体**：Tauri 2 桌面应用（Windows 优先），替代 HTML 仿真原型成为现行产品形态。仿真原型保留为历史评审资料，不再演进。
2. **技术栈**：见 [ADR-002](../LLD/ADR-002-Tauri技术栈选型.md)。前端 React 18 + TypeScript + Vite，自建白蓝设计令牌（CR-014 视觉基线）；后端 Rust + SQLite（rusqlite）；存储设计遵循 [ADR-001](../LLD/ADR-001-文档正文与统一能力网关.md)（Markdown 正文 + SQLite 索引/授权/配置/会话）与 [DB-FEAT-001](../DB/DB-FEAT-001-知识授权与工作台数据设计.md)。
3. **参考项目与移植策略**：8 个参考项目源码已集中存放于 `docs/参考/`（见参考索引 REF-002 系列）；逻辑按模块对照移植，不魔改原逻辑、不为改而改；UI 一律使用本项目白蓝设计体系重写，不复制参考项目的视觉资产或样式主题；复制产物按本项目结构与命名落地正式代码目录，保留各许可证要求的归属声明。
4. **模块移植映射**：
   - AI 会话栏 ← 会话 GUI 参考项目（消息流、流式、工具确认、子代理、用量）；
   - 模型配置与选择 ← 思考等级插件参考（供应商/密钥/端点/模型/思考档位/协议匹配）；
   - SDK 管理 ← CLI 管理插件参考（安装/更新/卸载队列、版本检测、会话候选过滤）；
   - Git 管理 ← Git 面板插件参考（未提交/分支/历史三段、diff、暂存提交）；
   - 服务器管理 ← TermX（主机卡片、SSH 终端、文件、监控）；
   - 知识库 ← zyplayer-doc（空间、目录树、正文、TOC、搜索）；
   - 编码区 ← openidea（文件树、行号编辑器）；
   - Skill/MCP/Tool ← skill/mcp 面板插件参考（全局统一管理，不按项目区分）。
5. **本轮不做**：不改变授权/审批边界（服务器高风险审批、知识只读网关仍按 PRD 执行）；不做多用户、登录、云同步；不做自动发布。
