# CR-052：页签紧凑与溢出下拉

- 状态：需求范围已确认；仅需求／可操作设计，待设计评审；**无本次正式编码授权**。
- 来源：2026-11-20 用户反馈「项目管理，需求的 tab 太高了，很不好看，需要调整一下设计」，随后明确「我指的是 tab 的页签本身，高度太高了，不用显示那么多的信息」，并补充「页面不能出现横线滚动条，如果页签过多，可以在末尾出现一个图标，点击之后悬浮下拉展示其他页签。所有有页面的地方都是这个逻辑」；记录更新于 2026-11-21。
- 归属：[EPIC-001](../Plan/Epic/EPIC-001-工作台导航与视觉体验.md) → [FEAT-001](../Plan/Feature/FEAT-001-工作台框架与可操作评审.md) → [STORY-064](../Plan/Story/STORY-064-主界面按评审意见重构.md#cr-052页签紧凑与溢出下拉)。复用共享视觉体验，不新增业务层级。

## 范围与行为

1. **页签只留一行信息**：需求工作区内部文档页签由 40px 双行（类型／编号 + 标题上下两行）改为 28px 单行——弱化编号在前、标题单行省略在后；类型「愿景」保留为编号位文字。关闭按钮同步缩为 16px，页签最小宽 92px、最大宽 196px。
2. **页签条不出现横向滚动条**：对象窗口页签、项目页签、需求内部文档页签、办公打开文件页签四条页签条一律 `overflow:hidden`，不再用横向滚动容纳超出项。
3. **溢出改为末尾「更多」入口**：页签放不下时，在页签条末尾显示一个下箭头图标按钮；点击后悬浮下拉按顺序列出**全部**页签（含当前页签高亮），选择即切换、下拉关闭。放得下时不显示该图标，不占位。
4. **选中页签始终可见**：溢出收缩时优先保证当前选中页签完整显示，其余从前往后保留，放不下的收进下拉；被收起数量记入「更多」入口的无障碍名称。
5. **统一规则**：以上不是只针对需求页签的特例，四条页签条共用同一套行为；后续新增页签条也应接入同一规则。

## 不包含与依赖

- 不修改正式软件源码、运行配置、依赖、构建或发布产物；既有其他 CR 的正式授权不延伸到本次。
- 不改变页签的业务含义、打开／关闭／切换逻辑、导航结构、栏宽与业务状态；页签点击仍走原有 `data-act`。
- 不合并、不重排页签顺序，不新增「全部关闭」「固定页签」等未要求能力。
- 不改动其它 CR 正在修改的 `base.css` 滚动条显隐规则（CR-049）。
- 无数据库需求：页签集合仍是既有会话内状态，不新增持久化、不迁移。
