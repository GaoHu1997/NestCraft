# BUG-005：生图报「密钥值不可用」——受管密钥已迁至 secrets/ 子目录，生图仍读数据根旧路径

- 类型：缺陷（数据根迁移后单模块读取路径未同步）
- 状态：**已修复，待验收**（2026-11-26 用户「修复」＝编码授权，同日修复完成；真实生图端到端待用户验收）
- 来源：用户 2026-11-26「在项目平台中，让他生图，提示 api 密钥不可用，但是我确定 api 密钥没有问题，在其他平台可以用。会话id sess-799355072e90425aa2f47e5141aad319」。
- 关联层级：[EPIC-005 供应商与模型适配]（以现行 Epic 索引为准）、[FEAT-014 供应商模型与能力适配](../Plan/Feature/FEAT-014-供应商模型与能力适配.md)
- 关联 Story：[STORY-076](../Plan/Story/STORY-076-模型配置评审调整.md)（AC-STORY-076-14/15 生图工具与顺延）
- 关联需求：[CR-059](CR-059-设置中心评审调整.md) §1.G（生图引入）、[CR-081](CR-081-本地数据统一存储.md)（数据根与 secrets/ 迁移）
- 同类隐患：[CR-081](CR-081-本地数据统一存储.md) 迁移遗漏面（见 §4）

## 1. 现象与实证

用户在平台会话 `sess-799355072e90425aa2f47e5141aad319` 中要求生图，AI 调用 `generate_image` 工具后工具返回：

```json
全部生图模型尝试失败：[{"error":"密钥值不可用","model":"mlgb7/gpt-image-2.5"}]
```

AI 据此告知用户「API 密钥缺失或失效，属于配置问题」。但该供应商（噜皮生图 mlgb7）密钥在设置中已启用，其他平台可用——即密钥本身有效，是**软件读不到**。

本机库与数据根只读核对（2026-11-26，`D:\devlop\NestCraft_portable\data`，只读、未输出任何密钥明文）：

| 项 | 值 |
| --- | --- |
| `image_gen_config` | enabled=1，order=`["mlgb7/gpt-image-2.5"]` |
| `provider` mlgb7 | openai 协议、未停用 |
| `provider_key` | 1 条，`secretRef=secret-41abff…`，enabled=1 |
| `data/secrets/secrets.json` | 存在，**包含 `secret-41abff…`**（密钥值实际在位） |
| `data/secrets.json`（代码读取的位置） | **不存在** |

结论：密钥配置完全正常；`generate_image` 读密钥的路径错了，读不到密钥后报「密钥值不可用」，且把锅甩给用户配置。

## 2. 根因（代码事实）

- `src-tauri/src/commands/image_gen.rs:219`：`provider_access` 用 `std::fs::read(data_dir.join("secrets.json"))` 读密钥，即 `<数据根>/secrets.json`。
- [CR-081](CR-081-本地数据统一存储.md) 把受管密钥统一迁到类别子目录：`providers.rs::secrets_file` → `storage_layout::category("secrets")/secrets.json`，即 `<数据根>/secrets/secrets.json`；启动迁移 `storage_layout.rs:112` 也把旧 `secrets.json` 搬到 `secrets/secrets.json`。
- 其余密钥读取方均已同步新路径：`dispatch.rs::read_secret`（CLI 通道）、`platform_agent.rs`（平台通道）、`capabilities.rs::mcp_secret_path`、`gitconfig.rs`、`memory.rs::read_provider_secrets`——**唯独 `image_gen.rs` 漏改**。
- 引入时间：`image_gen.rs` 的读取写于 CR-059 时期（当时 `secrets.json` 在数据根，路径正确）；CR-081 迁移时未同步该文件，0.0.5/0.0.6 均带此缺陷。

## 3. 影响

1. 生图功能在 CR-081 之后的所有版本对任何供应商**必然失败**（除非数据根残留旧版未迁移的 `secrets.json`），与供应商配置无关。
2. 错误文案「密钥值不可用」误导用户去改配置，实际配置无需改动。
3. 失败顺延机制（AC-STORY-076-14）在该错误下形同虚设：所有候选模型走同一错误路径，全部失败。

## 4. 修复方案（已按用户 2026-11-26「修复」授权落地）

`image_gen.rs::provider_access` 改为 `crate::storage_layout::category("secrets")?.join("secrets.json")`，与其余密钥读取方一致；`data_dir` 参数保留用于输出目录落盘。错误文案区分：条目缺失时报「密钥文件缺少该模型的密钥条目（<secretRef>），请在设置中重新保存该供应商密钥」，不再笼统报「密钥值不可用」误导用户。
