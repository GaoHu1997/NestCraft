# CR-033：固定管理首页与项目／知识库／服务器独立窗口

- 类型：既有导航需求的方案调整（替代详情返回按钮）；日期：2026-11-19（Asia/Shanghai）。
- 状态：需求按用户直接指令确认；UI-CR033-v1 设计待视觉评审，正式能力设计中。
- 来源：用户明确“首页固定，点击项目/知识库/服务器打开新的窗口，同一个项目再次打开，只定位到打开的页面即可”，并要求“原来的返回按钮就不需要了”。此前多项目顶部标签调研只给结论，本批采用多窗口方向。
- 工作层级与允许范围：仅需求、方案、可操作原型与设计验证；不修改正式软件源码、依赖、配置、构建或发布产物，不创建真实系统窗口。
- 归属：复用 [FEAT-001](../Plan/Feature/FEAT-001-工作台框架与可操作评审.md) 与既有 EPIC-001；新增 [STORY-061](../Plan/Story/STORY-061-固定首页与独立窗口导航.md) 承载本批 AC，不新建 Epic／Feature，不改需求业务父子关系。

## 1. 固定管理首页

1. 应用默认进入**管理首页**，由项目管理、知识库、服务器管理三个固定管理页组成；首页始终可回到，不因打开详情被替换、清空或占位。
2. 打开任意项目、知识库或服务器**不改变管理首页内容**：列表、搜索、滚动与已加载数据保持；返回首页时不重新初始化。
3. 管理首页之间切换仍通过左侧模块导航（窄屏为上方模块导航）；这类切换属于首页内部，不关闭已打开窗口。
4. 首页没有“详情返回”语义：详情不再是首页的一个替换页。

## 2. 独立窗口

1. 点击项目、知识库或服务器的“打开”动作，在**独立窗口**中打开对应工作区：项目含需求／设计／任务／编码；知识库含目录／正文／正文目录；服务器含主机／终端／监控。
2. 窗口以**类型＋稳定 ID** 识别：`project:<id>`、`knowledge:<id>`、`server:<id>`。不使用名称去重，改名或重名不得产生重复窗口或错误聚焦。
3. 同一对象再次打开时**只激活已存在窗口**：置前、恢复最小化（若设计支持）、定位到该窗口当前页面；不新建、不重载、不重置页签、选中项、滚动位置、草稿或 AI 会话。
4. 同一对象可在多个入口被再次点击（首页列表、搜索结果、关联跳转等），均聚焦原窗口。
5. 每个窗口独立保留自己的内部页面状态：项目窗口保留当前页签、需求选择、设计子页、文件页签；知识库窗口保留库、笔记与搜索；服务器窗口保留主机与终端显示。切换窗口或回首页不丢失。
6. 窗口栏列出“首页”和所有已打开窗口，指示当前窗口，可点击切换与关闭；窄屏横向滚动，不造成整页横向溢出。
7. 关闭窗口后再次打开同一对象，为**新的初始窗口状态**；关闭不是隐藏，除明确确认丢弃外不得静默删除项目、知识库、服务器或其数据。

## 3. 返回按钮取消

1. 详情窗口内**不再提供“返回项目管理／知识库／服务器”按钮**；关闭窗口就是回到管理首页的路径，键盘可完成。
2. 管理首页与窗口栏的切换不产生新的“返回”按钮；历史 CR-021 的返回导航设计由本批替代，历史记录保留、不删除。
3. 窗口关闭按钮在标题栏稳定可见；窄屏不隐藏。

## 4. 关闭保护

1. 无未保存草稿且无运行中任务时，关闭窗口直接生效，回到管理首页，其他窗口不受影响。
2. 有未保存文件或设计草稿时，必须先确认：可取消并保留窗口与草稿，或明确“关闭并丢弃”；不得默认保存、不得静默丢弃。
3. 有运行中任务时，关闭提示必须说明**任务继续在后台执行**；关闭窗口不停止、不取消、不重置任务，也不改变任务归属与证据。
4. 关闭窗口不影响其他窗口，不删除项目／库／主机，不触发连接关闭、验收或发布。

## 5. 隔离与边界

- 窗口只是查看与操作的独立表面，**不等于数据或执行隔离**。各窗口仍共享应用数据库与配置；AI 会话、任务、终端、审批必须绑定所属项目／对象与冻结权限，异步结果按窗口与对象防串写。
- 同一目录或同一 Git 工作树不能通过多窗口隔离 HEAD、暂存区与工作目录；相同规范化目录首版只聚焦已有窗口，独立并行写入需另立 worktree／分支协调。本批只登记约束，不实现并发写入。
- 不新增：系统级多窗口实现、全局项目标签条、任务／验收规则、知识授权规则、真实 CLI／SSH／Git 调用。首页数据仍为既有合成夹具。
- 本批不改正式软件；正式实现需另行明确编码授权，并按 UI-CR033-v1 与软件逐场景对照。
