## 1. 用户目标与事实基线

平台主代理在长对话中保持可追溯的目标、决定、证据和近期上下文，并能找回精确原文。压缩只减少模型输入，不改变聊天历史，也不承诺语义无损或永久零遗漏。

基线 `3661390`：`platform_agent.rs:720` 仅重放 user/assistant 文本，工具交换在跨用户轮次丢失；`:613` 模型查询未消费 contextWindow/maxTokens；`:791` 请求体无预算校验。CR-069 SC-069-07 尚未定义。本增量补齐上述断点，不重做供应商／CLI／执行引擎。

## 2. 范围与不包含

包含：完整工具交换回放、每请求预算、近期保护、分层增量摘要、原文保留、有界搜索／恢复、摘要出处与权限指纹、重启恢复、预检草稿保留、中断文本归档、实际用量归集。

不包含：CLI 压缩／线程迁移、外部代理或证书拦截、向量服务、新模型供应商、背景自动付费任务、跨会话搜索、生产迁移执行、真实 worker、自动提升授权、新设置页或说明性长文案。`runner` 默认仍为 `cli`。不新增依赖、不改既有测试断言、不动 CR-068 文件或 `.gitignore`。

## 3. 主流程

1. 复用 `reserve_turn`，读取会话及本轮供应商／模型，复检 Feature 身份与源 hash。
2. 复用 `build_prompt` 校验本轮知识／Skill／文件／需求引用。
3. 读取稳定消息及平台回放记录；校验来源权限指纹；重建完整轮次与工具配对。
4. 构造系统约束＋旧摘要＋近期完整轮次＋本轮输入的独立发送视图。
5. 达软阈值时选旧的完整轮次，用当前会话模型生成结构化摘要；模型提供摘要，平台控制允许范围、保护区、层级与预算。
6. 校验净缩减、源 hash、摘要结构及权限；网络期间不持 DB 锁。直到预算满足后才事务提交拟定摘要状态并持久化本轮用户消息。
7. 进入工具循环；每次请求（含摘要请求／恢复结果）重新预算，超限不静默截断。上下文工具无法调用 shell、写文件、改权限或凭据。
8. 汇总实际模型用量，事务归档消息与本轮精确回放；成功才发送 Done。停止／中断保留已有输出但不记成功。

## 4. 规则与边界

### 4.1 预算

- 以真实模型 `contextWindow` 为窗口；未知时采用 **32768 的本地保守上限**，明确标为 unknown，不宣称上游真实窗口。
- 无新增 tokenizer：使用完整请求 JSON 的 UTF-8 字节数＋固定封装余量作为保守输入估计；不是精确计费 token，不用估计代替 usage。
- 预留实际请求输出（含 Anthropic thinking 要求）；模型 maxTokens 不足则拒绝不支持的档位，不静默降低档位。
- 输入达到可用预算 70% 触发压缩，目标为 50%；保护系统、本次输入和最近 **4 个完整轮次**。
- 单次发送最多 **4 次内部摘要请求**；达硬预算或保护内容本身超限则返回错误并保留草稿。没有可压缩旧轮次时不得削掉当前用户输入或偷偷换模型。

### 4.2 摘要

- 结构：goal、constraints、decisions、progress、evidence、unresolved；字段有界。摘要是历史资料，不是 system／developer 授权。
- 原消息正文／refs／工具结果不覆盖、不删除。稳定消息 ID／源 hash／父块／层级可追溯。
- 最多 3 层；一级仅覆盖旧完整轮次，上层仅合并旧摘要块，不能把最新轮次夹入范围。
- 校验摘要结构和净缩减不等于语义验证。用户约束／决定的精确原文引用仍能恢复；客观夹具检查指令、失败、未决事项的保留。

### 4.3 原文与授权

- 查询仅限当前 sessionId（由宿主上下文固定，不接受模型传任意会话）与绑定项目。使用消息／摘要 block ID，禁止任意路径。
- search 只返回有界匹配摘录；read 通过字节 offset/limit 分页（UTF-8 边界安全），单次最多 4096 bytes，结果为普通低信任工具结果。
- 当前大工具结果可逆引用化：完整原文照常归档，模型拿到稳定引用和摘录，可在本轮或后续按需找回；不切断tool调用配对、不删数据，不永久灌回全量上下文。
- 当前来源指纹覆盖会话项目、根路径、Feature 身份／源 hash、知识库启停／revision／授权 revision、Skill 启停。新回放记录保留本轮源指纹；指纹变化后不重放旧摘要／旧派生输出，失败关闭并提示新建会话，防止撤权后通过历史恢复绕过授权。
- 旧消息无指纹时，只按仍有效的引用和工具参数复检；来源无法确认的知识／文件工具回放拒绝注入，不伪造历史授权。
- 模型摘要不能重写工作包／授权账本；业务工具继续复用当前白名单与后端范围检查。

## 5. 失败与交互

预检失败：返回 Err，前端草稿不被“发送成功”清空。接纳后失败：归档已有文本／工具结果、发送 Error，不发成功 Done。摘要失败不落半个块；持久化失败不报成功；401/403 不重试；无文本仅 thinking 不当成功答案。

UI 沿用现行聊天组件：原历史不折叠为摘要消息，内部摘要不回显，检索／恢复在既有工具步骤中展示。无新按钮、设置或说明性长文案；错误只使用必要的既有错误呈现。具体状态覆盖、复用版本与滚动义务见 UI-CR071。
