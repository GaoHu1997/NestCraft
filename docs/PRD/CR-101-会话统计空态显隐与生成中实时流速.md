## 1. 现象与实证（代码事实）

用户两条反馈是同一根因的两面：**空态判定漏判 + 隐藏方式仍占位**；另有一项真实数据源缺口。

| 位置 | 现状（只读核对，未改） | 导致的实际表现 |
| --- | --- | --- |
| `src/modules/chat/StatsBar.tsx:74-76` | `empty = rounds===0 && msgs===0 && steps==null && 各计量均 null` | 真实空会话多为 `rounds=null`（未知）且 `msgs>0`，`empty=false` | 
| `src/modules/chat/StatsBar.tsx:106,116` | 非空即渲染三组，未知字段输出 `—` | 底部出现「— 轮 — 步 · — tok/s／— tok · 缓存命中 —／—」三段全破折号 |
| `src/modules/chat/chat.css:319` | `.chat-stats.is-empty { visibility: hidden; }` | 即使判空成立，元素仍占 `padding:8px` 与 `min-height`，留下一段空白 |
| `docs/UI/workbench-v4/cr074.js:37` | 设计侧判空为 `Number(s.rounds)>0 \|\| known(t.total)` | 设计侧会隐藏，但同样依赖 `visibility:hidden` 占位；且判空只看轮次与总量，漏掉「只有 TPS／只有上下文」的合法部分数据 |
| `docs/UI/workbench-v4/ai.css:91` | `.ai-stats.is-empty { visibility: hidden; }` | 同上，空态仍占 25px 高的一行 |

数据源缺口（第 2 条中「轮次／步数／实时流速同时为空」的直接原因，**不是展示缺陷**）：

1. `rounds`／`steps` 只来自 DSH 权威闭合步骤（`sessionStats.ts` 的 `closedSteps`）。CLI 通道不上报内部步骤，平台通道在 `scope=partial` 或不完整覆盖时也为 `null`，因此该通道下始终为未知。
2. `tps` 目前只取 `PersistentSessionStats.tps`，而该字段仅在整会话完整覆盖时给值（`parseSessionStatsSnapshot` 对 `partial` 强制 `tps=null`），生成过程中则完全没有实时值。
3. `tokens`／`cache` 依赖 `curRt.usageKnown`／`cacheKnown`，未上报时为未知。

结论：展示规则可以保证「没有数据就不显示、有数据就只显示有数据的那部分」，但**不能凭空补出 CLI 通道没有的轮次与步数**；实时流速则需要新增生成中测量能力（本 CR 第 3 节）。

## 2. 需求规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| R-CR101-1 整条空态 | 三组统计全部没有任何可信数据时，统计条**不渲染** | DOM 不输出该行，不留 padding／min-height 空白，不提供三个详情入口；不得出现可点击却只能打开空浮层的入口 |
| R-CR101-2 组级显隐 | 某组至少一个字段可信 → 该组显示；组内无可信字段 → 该组省略 | 三组互相独立，例如只有 Token 有值时就只显示 Token 组 |
| R-CR101-3 字段级省略 | 组内未知字段省略该片段，不用「—」占位 | 分隔符随之收敛，不出现「4 轮 · · 148 tok/s」或「— 轮 4 步」这类残缺写法 |
| R-CR101-4 可信零值 | `0 轮`／`0 步`／`0 tok`／`缓存 0%`／`0%` 属于已知数据，必须显示 | 零值不得因「等于 0」被隐藏，也不得被当作未知 |
| R-CR101-14 文案收敛 | 统计条缓存项写两字「缓存」（例 `缓存 95%`），不再写「缓存命中」 | 2026-11-26 用户要求「缓存命中换成缓存，两个字更节约空间」；详情浮层仍写完整「缓存命中」，避免详情里丢失命中率语义 |
| R-CR101-5 判空依据 | 空态只以「是否存在可信数据」判定 | 不再用消息条数 `msgs` 参与判空；`msgs` 仅作为详情内的辅助信息 |
| R-CR101-6 详情一致 | 详情浮层的字段与统计条同一判空结果 | 某组在条上被省略时，其详情入口同样不存在；已显示组的详情内未知字段沿用「未上报」说明，不伪造数值 |

## 3. 生成中实时流速（新能力）

用户明确选择「新增：生成过程中实时计算并刷新」。本节定义口径，实现与验证需另有编码授权。

| 编号 | 规则 |
| --- | --- |
| R-CR101-7 实时值定义 | 实时速率 ＝ **窗口内观察到的 token 增长 ÷ 窗口跨度（秒）**。token 按 DeepSeek 官方字符密度逐码点估算（非 ASCII 0.6／ASCII 0.3 token/字），正文、思考与工具调用参数都计入，再乘会话校准因子。**不使用累计值作分子** |
| R-CR101-8 窗口与节拍 | 有界滑动窗口：下限 **200ms**（低于不发布，避免首块突发）、上限 **2000ms**（超时丢弃旧样本，不退化成正段平均）；节拍 **1000ms**。估算值不变的帧不推进窗口 |
| R-CR101-9 稳健性 | 增长超过 `max(跨度, 50ms) × 1.5 tok/ms` 判为 UI 积压帧，重锚不发；估算值下降（重试／块被替换）重锚；发布值按一阶低通 `weight = min(1, 距上次发布/1000)` 平滑；校准因子钳在 0.5～2；任何情况下不输出 `NaN`／`Infinity`／负值；从未测得读数时省略该片段，不显示 `0 tok/s` |
| R-CR101-10 与权威值关系 | 生成中显示实时估算值并带 `~` 前缀；本轮闭合后先用 provider 的权威 output tokens 校准密度因子，再清除实时值；权威 TPS 可用则显示权威值，不可用则该片段按 R-CR101-3 省略（不冻结过期数字） |
| R-CR101-11 终态停止刷新 | 完成／失败／停止／取消后立即停止刷新；停止态不保留「仍在增长」的假象 |
| R-CR101-12 来源可辨 | 详情浮层区分「生成中实时估算」与「本轮闭合测量」，两个数值不得混为同一口径；统计条只显示其一，不并列；实时值统一带 `~`，格式为 ≥10 取整、<10 保留 1 位小数 |
| R-CR101-13 权限与范围 | 实时值只属于当前会话当前步骤，不写入其它会话、不跨会话复用、不持久化 |

## 4. 替代与继承

- **替代**：[CR-074](CR-074-AI会话双布局统一与交互校正.md) 及 [STORY-022 CR074 增量](../Plan/Story/STORY-022-按需子智能体与用量统计.md#cr-074增量) 中「未知字段一律显示 —」的**静态占位部分**，以及「空态用 `visibility:hidden` 占位」的做法。

## 7. 未决项与风险

| 编号 | 内容 | 处理 |

| Q-CR101-01 | 实时流速是否需要在会话历史重开后回显（需持久化瞬时值） | 默认**不回显**：历史重开后只显示权威统计，实时值不落盘；如需回显另行登记数据设计 |
