# CR-105：AI 服务器连接工具补全（ssh_connect / ssh_disconnect）

- 状态：已实现，技术验证通过，待验收
- 日期：2026-11-27
- 来源：用户反馈「服务器命令缺失，AI 现在不能访问到服务器内」，并附 AI 自述——只有 `ssh_exec`，其前置是「主机已在服务器工作台建立连接且已授权」，AI 没有"建立连接/发起登录"的工具，错误即在该前置层返回。用户指示「补全一下服务器的相关工具」。
- 关联：FEAT-027（AI 搜索工具同批工作区）、STORY-117 之外的独立增量；服务器能力归属既有服务器工作台 Feature。

## 背景与问题

AI 工具目录中原有 `list_servers`、`save_server`、`ssh_exec`、`ssh_exec_status` 四项服务器工具，但缺少连接生命周期工具：

- `ssh_exec` 前置要求主机已连接（`ssh::get_connection` 命中），否则返回「主机未连接：请先在服务器工作台建立连接后再试」。
- 建立连接只能由用户在服务器工作台界面手动触发（`server_connect`）；AI 无法自主连接，导致会话中 AI 实际无法访问服务器。
- `list_servers` 返回不含连接状态，AI 无法判断应先连接。

## 本次范围

1. 新增 AI 工具 `ssh_connect`（工作台·连接服务器）：按 `hostId` 用受管密钥文件中的凭据建立 SSH 连接；已连接时幂等成功；不接受 AI 提供的任何凭据，AI 全程不经手密码/私钥。
2. 新增 AI 工具 `ssh_disconnect`（工作台·断开服务器）：断开指定主机连接；未连接时幂等成功。
3. `list_servers` 返回值增加 `connected` 字段，AI 可据此决定先连接再执行。
4. `ssh_exec` 工具描述补充「主机未连接时先用 ssh_connect」的指引。
5. 各登记点同步：`TOOL_COUNT` 34→36、`TOOL_LABELS`、设置·工具目录（BUILTIN_TOOLS）、工具组（server 组）、前端侧栏步骤标签映射。

## 不做事项

- 不新增 UI 布局/样式：侧栏步骤名沿用既有标签渲染机制，仅枚举新增两条中文名（`工作台·连接服务器`／`工作台·断开服务器`），无界面结构变化，UI 对照不适用。
- 不改变审批模型：`ssh_exec` 高风险命令仍走跨进程审批，本次不扩大任何执行权限。
- 不做主机凭据的 AI 录入：密码/私钥仍只能由用户在服务器工作台录入受管密钥文件。
- 不做 SSH 隧道、端口转发、交互式终端会话工具。

## 验收标准

- AC-CR105-01：工具目录含 `ssh_connect`／`ssh_disconnect`，且与设置·工具登记、`TOOL_LABELS`、server 工具组一致（同步测试通过）。
- AC-CR105-02：`ssh_connect` 对不存在主机返回可读错误；对已保存主机用受管凭据连接，已连接时幂等；返回值不含任何密钥。
- AC-CR105-03：`list_servers` 返回逐台附 `connected` 布尔值，与本进程连接表一致。
- AC-CR105-04：`cargo check --lib` exit 0；`cargo test --lib` 全量通过；`tsc --noEmit` exit 0。
