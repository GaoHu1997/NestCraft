## CR-037：主代理协调与答疑

2026-11-19 用户提出：任务派发可以结合「一个 CLI 做大管家、把任务派给其他 CLI、其他 CLI 有问题再找它解答、由它把关结果」的模式，并在本轮确认「可以，调整一下」。完整范围见 [CR-037](CR-037-主代理协调与答疑.md)。

本次不新建 Epic／Feature／Runner，也不引入第二套任务状态，只补上既有派发、执行、验证之间缺失的协作环节：

- **派发**：协调者提出的子工作经 runner 校验范围、依赖、能力、难度、预算与写入冲突后才启动；同 Story 子调用沿用根 Attempt，不提高 Task fence。越界或未核验组合拒绝，不静默换执行器。
- **答疑**：工作代理只就影响当前工作的具体问题提问，阻塞分支等待而其他分支继续；协调者依据已确认资料答复技术问题，涉及需求范围、验收标准、权限、成本或不可逆操作的转用户决定。答复须注明依据，否则只能算建议；决定改变冻结基线时该分支须重新确认。
- **交接与返工**：A 的封存修订引用可由 runner 按冻结计划直投 B，也可由大管家转发。两条路径共用受管消费记录。B 提交受检修订和缺陷证据，runner 回查 A 的产出调用及原生线程，确认旧 writer 停止后返工。新修订触发受影响证据失效与重验。
- **可靠性**：问题、答复、回执、决策与返工持久化，支持补读、去重与续行；协调者离线或决策超期显示等待原因并最终明确阻塞，补投消息不重跑已完成工作。

技术交付以 runner 的证据门槛为准，业务验收由使用者或事前授权的客观规则负责。普通侧栏续接由 [STORY-032 AC-05～06](../Plan/Story/STORY-032-AI会话正式实现.md#cr-037-普通侧栏原生续接) 承接。

## 1. 用户目标与当前事实

研发使用者在已确认需求和足够设计的前提下，一次决定范围与执行约束，系统自动领取合格任务：无依赖且无资源冲突可并行，有依赖/冲突自动等待；结束给出证据与结果，不要求使用者逐项派发会话或每一步批准。

Tauri v0.1 已有 React/TypeScript 项目工作区、Rust CLI 会话桥、SQLite、Git 和知识网关。`chat.rs` 的 RUNNING 是内存会话注册表，Grok 使用尽力适配参数；**没有**任务 DAG、持久化领取租约、常驻 runner、自动集成或任务交付系统。已有退出码、会话消息和 Git 命令不能作为新增能力已完成的证明。

## 3. 范围和准入

### 3.1 入口与粒度

code 项目页签为**需求 → 设计 → 任务 → 编码**，任务是执行视图，不是增加人工研发审批阶段。仅需求页出现 Story、Feature、Epic、「派发全部合格需求」入口。全部合格指当前项目当前选定范围的合格叶子 Story，不是所有项目、所有文件、所有草稿或未来新增需求。work 项目不增加研发任务树。

### 3.2 合格条件

Story 有稳定编号、唯一父项、真实需求确认依据、可观察 AC、可执行且与需求一致的设计；无待同步草稿；未完成、未取消。执行所需依赖可消费，资源/能力/权限/预算满足。设计中标签本身既不证明设计可执行，也不替代需求确认；预检必须检查实际基线材料和决策。缺失项按 Story 返回原因，不启动开发。零合格项无法确认派发。

范围外前置只可引用已有且有效、可消费的验证产物；尚需研发的范围外依赖必须先独立取得授权，不隐式加入本批次。循环/自依赖拒绝候选 DAG，不能用删边绕过。排除项及原因必须在确认前给使用者看到，不把部分范围当全部成功。

### 3.3 冻结与防重复

一次确认冻结 Story 集合、requirement/design/AC hashes、代码基线、策略和能力快照版本。新增需求不自动入批次。需求/设计变更不偷偷更新运行输入，进入重检/变更流程。预检与确认间基线变更拒绝提交。

幂等键绑定完整请求摘要：同键同请求返回原批次，同键不同请求拒绝。活动任务还按项目+Story+基线唯一约束防重；受影响事务全量回滚并提供现有任务链接，不产生半批次。已结束任务再次派发也需新的授权，取消/失败不等于完成。

## 4. 一次授权与执行边界

确认前展示并冻结：CLI/模型允许集与明确选定项、必要能力与最低难度/effort、写入与知识范围、网络/工具权限、最大并发、预算单位/硬软性质、暂时故障重试与修复返工上限、暂停/恢复及重启策略、本地集成分支允许集、默认交付终点。

点名 Codex/Claude/Grok 不覆盖最低能力、难度或预算规则。能力按 CLI/版本/模式/平台验证，未验证标未验证；不因安装或会话可用就认定任务可用。不静默切 CLI、模型、effort 或提权；不合格则停止受影响分支，独立合格分支继续。

自动运行只在授权边界内免逐步骤确认；新业务决策、范围/AC、权限或成本承诺变化需新授权。默认不推送、不合并受保护分支、不发布生产。原有人工批准模式未启用并授权自主模式时仍有效。

密钥使用引用及受控注入，不写提示词、日志、Git 或普通快照。知识只经项目授权网关且执行层阻止文件/shell/网络旁路。worktree 是代码隔离，**不是 OS 安全隔离**；实现不了所需安全边界时禁止该任务，不能用提示词补救。

用量缺失显示「未知」而非零；费用估算标估算，不是假定账单。要求费用硬封顶但缺可信计量/上游硬限额时准入拒绝；可采用经明确确认的时间/尝试等可控预算，不能承诺未知费用可硬封顶。

## 5. 调度与生命周期

运行对象为 DispatchBatch → ExecutionTask（一个 Story）→ Step → Attempt；会话和 CLI 进程是载体。业务树与执行 DAG 分离，边包含 requiredArtifact、verificationGate、consumedRevision。启动需前置产物有效并进入当前可消费基线，资源锁和槽可用，再二次校验能力/权限/预算。失败/取消前置不放行。

任务状态采用 queued / waiting_dependency / waiting_resource / preparing / running / verifying / integrating / retry_wait / paused / blocked / succeeded / failed / cancelled。暂停/取消请求标志与实际状态分开：旧进程树停止确认前不能释放写资源或显示可重新启动。

CR-041 评审补充：协作 `waiting_decision` 是 Invocation 的 waiting 原因，不是新增 Task 状态。全部必需分支待决定时使用可恢复 blocked＋截止时间，批次 running＋等待摘要；到期阻塞且无可推进节点时按既有静止聚合，不无限 running。具体映射及恢复见 [LLD-CR037 §6](../LLD/LLD-CR037-主代理协作契约.md#6-超期阻塞与恢复)。

正式设计要求独立持久化 runner：关窗口不停止 runner；主 UI 进程退出与 runner 生命周期分离。主机重启后对账旧 attempt，确认旧写进程不存在，再按冻结 restartPolicy 重建安全尝试。无法证明停止或副作用是否发生则 blocked，需要人工查明，而不是双实例写入。尚未部署独立 runner 的模式明确仅应用生命周期内运行，不能承诺「关闭也持续」。评审稿计时器/刷新不等于 daemon。

领取采用事务租约、heartbeat 和递增 fencing token。租约过期不能单独证明进程已死；旧回调不得更新新运行。暂时网络/短暂服务故障有限退避，认证、额度、配置、权限、需业务决定等停止；重试与返工各有上限，不能无限循环。独立分支继续，最终阻塞分支进入批次 partial/failed 聚合。

## 6. 自动验证、集成和交付

exit 0 只表示 CLI 结束；任务成功需目标产物、关联 AC 的有效证据、最终差异审查和适用集成回归。未执行不是通过，AI 自评不是客观验证。返工只允许修实现，不能改 AC 或范围来宣称通过。

集成在明确允许的本地非保护分支串行排队，合入后回归通过才提升可消费基线，下游记录其消费修订。若未授权集成，只交独立产物；有基线依赖的后继等待，不能凭文件复制自动当集成完成。冲突/失败不推进发布基线，保留候选和证据，不覆盖用户改动。

证据与产物 revision、AC hash、环境和消费基线绑定，修订改变使旧证据失效但保留历史；受影响后继重新评估，必要时安全停止。

批次有 running / succeeded / partial / failed / cancelled，不是 Story 状态。默认技术门槛通过后 Story 写回「待验收」；只有用户/指定验收者真实验收，或提前明确授权的客观自动验收规则满足 DoD，才能「已完成」。技术完成、验收完成、发布分别记录。

Story 状态/AC 在 Markdown 权威，SQLite 保存不可变快照和运行权威，不另存可编辑需求正文。写回基线冲突保留任务交付，显示待同步，不能将 DB 内容强制覆盖文档。
