## 1. 背景与问题

当前唯一原型（`docs/UI/workbench-v4/`，经 2026-11-21 实测截图核对）：

| # | 现象 | 位置／证据 |
| --- | --- | --- |
| 1 | 项目卡片左侧是 `BO`／`OP`／`RE`／`BR` 两字母块，项目之间只靠字母与底色区分 | `screens-home.js` 的 `proj-card`；[现状截图](../Test/screenshots/cr051/before-projects.png) |
| 2 | 知识库卡片 3 个库共用同一个 `book` 图标，且外部 sprite 的 `<use>` 在 `file://` 下未渲染，只剩空方块 | `screens-more.js` 的 `kb-card`；[现状截图](../Test/screenshots/cr051/before-knowledge-cards.png) |
| 3 | 知识库文件树虽已调用 `fileIcon`，但同因 sprite 未渲染看不到图标；映射里 md 与 txt 共用 `fileText`，也没有 html／音频／视频／未知类型 | `knowledge-workspace.js` 的 `fileIcon`；[现状截图](../Test/screenshots/cr051/before-library-tree.png) |
| 4 | 顶栏、侧栏、设置中的用户头像均为 `LC` 字母 | `core.js` 的 `avatar`、`screens-more.js` 的设置左栏；[现状截图](../Test/screenshots/cr051/before-settings.png) |
| 5 | 可选图标基本集中在编码／技术语义，缺少办公、商业、内容、生活类图形；项目标识只有单一底色，不能表达项目差异 | r2 用户直接指出；设计稿 r1 的 12 个图标清单 |

结论：不是「没有代码」，而是「没有可辨识、可配置的内置图形设计」。需要把「图标 + 背景色」当作一个完整标识，并让图标库覆盖真实项目类型，而不是只服务编码项目。

## 2. 本次范围

1. **项目标识（r2／r3 扩充）**：项目卡片、侧栏「当前项目」、知识库授权弹窗项目行使用「图标 + 背景色」组合。图标库为 **50 个、6 组**：通用（16）、办公（7）、商业（8）、内容（8）、产品（8）、生活（3）。默认编码 `code` + 蓝、办公 `briefcase` + 琥珀；可自选并可清空回默认；旧项目保持原样，手动切换才写入。
2. **知识库标识**：知识库列表使用 40px 图标砖 + 背景色；**与项目共用同一套 50 个图标**，可任意选择；默认按来源（本地 `bookOpen`、网页 `globe`、组合 `layers`、未标注 `library`），可清空回来源默认；旧库保持原样，手动修改才写入。
3. **背景色卡（r2 新增，r3 调整）**：提供 **10 个与白蓝视觉协调的色卡**：蓝、青绿、紫、琥珀、绿、玫瑰、靛蓝、橘、石板、沙金；每个色卡浅色／深色各一套承载底与图形色。**色卡只显示方形色块，不显示中文名称、无悬停中文提示**（读屏名称走 `aria-label`）。图标与背景色成对保存、成对显示，不能只存背景色。
4. **头像（r2～r5 调整）**：默认 **B 薄荷承载**。入口统一为「头像框悬停出现编辑 → 点击打开更换头像弹窗」：弹窗内展示 5 种内置样式，最后一格为「自定义」；选择自定义后打开系统文件选择（PNG／JPG／WebP、≤200KB、建议 ≥256×256），弹窗**固定尺寸 680×660**、**取景框常驻**：框内即最终显示区域、框外半透明遮罩；内置样式显示 Logo 且无需裁剪，自定义选图后可拖动摆放并缩放 100–300%，左侧实时预览；**已应用的照片重新打开也能继续拖动/缩放调整**；格式、超限或读取失败在弹窗内提示并保留原头像；应用后同步顶栏／侧栏／设置，取消不改，可恢复默认 Logo。
5. **文件树图标（r1 保留）**：文件夹固定 `folder`／`folderOpen`；文件按扩展名显示 14 类图标，类型小字保留为辅助；未知扩展名不阻止上传与元信息展示。
6. **图标集扩充（r2 新增）**：新增 40 个符号（7 文件类型／容器 + 33 通用），总计 84 个；全部 24×24、1.6px 描边、`currentColor`。

## 3. 规则与约束

1. 内置图标唯一来源为 `docs/UI/workbench-v4/icon-sprite.svg`；本批新增 40 个符号（含 `fileMarkdown`、`fileHtml`、`fileAudio`、`fileVideo`、`fileUnknown`、`briefcase`、`library` 及办公／商业／内容／产品／生活 33 个）。不新建第二套图标源。
2. 「图标 + 背景色」是完整标识：保存、读取、回退都以组合为单位；色卡缺失时回退默认色，不允许出现「只换背景导致对比不足」。
3. 色卡固定 10 个**整块填充的方形色卡**（无外框、无内框），不显示中文名称、无悬停中文提示、不在本轮开放自由取色；选中态为外环 + 白色对勾；读屏名称走 `aria-label`。浅／深主题各一套取值，图标与背景对比度符合图形元素 ≥3:1。
4. 禁止以 emoji、字母块或「PDF」文字块作为图标；字母块只允许作为「图标 id 未登记」时的最后回退，不得再作为默认显示。
5. 图标不承载权限或保存状态：未授权知识库仍显示正常图标；解析失败、未保存、失败重试仍由既有状态标签和文案表达。
6. 头像上传：格式 PNG／JPG／WebP、**≤200KB**、建议 ≥256×256；必须在「更换头像」弹窗内完成选择、裁剪预览与报错，不把上传按钮平铺在设置页；图片按当前风格容器等比裁剪填充；格式／大小／读取失败时在弹窗内提示并保留原头像；「恢复默认 Logo」回到 B 风格品牌头像。
7. 头像图片仅保存在本机应用数据目录，不上传网络、不进入知识库／会话／审计；删除引用即恢复默认。D 风格的反白只用于 Logo，上传照片保持原图。
8. 官方 CLI 品牌图形（Claude／Codex／Grok）继续使用官方资源与原色，不套本次描边、图标库与色卡；头像不使用 CLI 图形。
9. 外部 sprite 的 `<use>` 在 `file://` 下不得导致图标消失：实施时采用内联 sprite 或构建期注入；未登记 id 回退到 `file`，仍不可见时回退到可见占位，不能是空白方块。
10. 图标选择器、色卡选择器与头像风格组必须可键盘操作并有焦点环；上传按钮使用原生文件选择器，不伪造路径输入。

## 4. 不包含与依赖

- 不修改 `docs/UI/workbench-v4/` 现有原型、`src/` 正式源码、依赖、构建或发布产物；既有其他 CR 的编码授权不延伸到本次。
- 不做用户上传自定义图标、图标主题包、emoji 图标集、自由取色器；不改知识库权限、来源判定、索引与解析行为。
- 不做图片编辑（裁剪框、滤镜、旋转）；只做等比裁剪显示与「恢复默认」。不做头像云端同步或多设备同步。
- 不改变项目／知识库的权限、来源判定、索引与解析；新增格式图标不代表新增格式解析或预览能力。
- 依赖：现有 `icon-sprite.svg` 与 `UI-ICON-001-v1` 基准、品牌资源 `logo-sail.png`、既有设置弹窗与知识库三栏布局。

## 5. 数据结论

本批为显示层设计，正式实现时不新增业务实体，只增加可选显示字段（详见 [UI-CR051 §9](../UI/文档/UI-CR051-内置图标与头像风格.md#9-数据结论与实现边界) 与 [DB-FEAT-001](../DB/DB-FEAT-001-知识授权与工作台数据设计.md)）：

- `project.icon`、`project.icon_color`：可选，内置图标 id + 色卡 id，成对保存；空值按 `type` 推导（code + 蓝／work + 琥珀）。
- `knowledge_library.icon`、`knowledge_library.icon_color`：可选；空值按既有 `sourceKind` 推导（managed-directory → `bookOpen` + 青绿、connector → `globe` + 青绿、未知 → `library` + 青绿）。
- `user_settings.avatar_style`：`a|b|c|d|e`，默认 `b`；`user_settings.avatar_image`：可选，本机文件引用 + hash，不存原图字节。
- 文件类型图标由扩展名即时推导，不持久化；图标映射表与色卡定义随程序版本发布。
- 旧数据：**保持原样、不做批量映射**。旧项目沿用现有 tone 图标砖，旧知识库沿用现有图标；只有用户手动改图标或色卡后才写入新组合。

本轮不建表、不迁移、不修改数据库代码；字段命名与约束在正式实现时按现有迁移规范补齐并验证旧数据默认显示。
