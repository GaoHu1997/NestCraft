# CR-066：需求思维导图与阅读视图重构

- 类型：既有需求阅读方式的重构与补充；日期：2026-11-23（Asia/Shanghai）。
- 来源：用户 2026-11-23 直接指令三条：① 编码项目需求 Tab 中「愿景」改为 **Vision**，与下方 Epic／Feature／Story 对应；② 原思维导图「上面是导图、下面是内容」不是思维导图，要求**整块都是标准思维导图**（Xmind／ProcessOn 式：愿景连接史诗、史诗连接下级特性、**有连线**、**有目录**、**点击节点在右侧出现悬浮框展示内容**），且**用户可在导图页直接添加史诗／特性／用户故事**；③ 左侧菜单栏已有「预览」和「思维导图」，**顶部不再重复出现**。追加要求：预览中移除左侧需求树（不同菜单各自独立），右侧目录树支持折叠子目录。同日追加三点：④ 导图中折叠与新增下级图标冲突，**折叠按钮移到连线连接处、悬浮才展示**；⑤ 预览要**愿景／史诗／特性／用户故事四级全量显示**，**目录也要四级菜单**；⑥ **模型也要融入进去**。
- 状态：需求范围按用户直接指令确认；设计与实现已完成，视觉待用户评审；未用户验收。
- 工作层级与允许范围：需求／设计／方案／正式实现（需求 Tab 界面），不改需求正文存储、派发引擎、AI 侧栏与后端协议。
- 归属：复用 [FEAT-003 需求维护与交付验收](../Plan/Feature/FEAT-003-需求维护与交付验收.md)／[STORY-010 需求树与详细文档预览](../Plan/Story/STORY-010-需求树与详细文档预览.md#cr-066需求思维导图与阅读视图重构)，不新建 Epic，不修改业务父子关系。

## 1. 命名与层级对应

1. 需求实体的类型名统一为 **Vision → Epic → Feature → Story**（Bug 跟随 Story 层级）。原「愿景」中文名在需求树、内部文档 Tab、导图节点、导图目录、预览标题分级中一并改为 Vision。
2. Vision 是 Epic 的父级：Epic 必须在导图中由 Vision 连出，Epic 再连 Feature，Feature 再连 Story。Epic 若在源文件中未声明 `parent`，按项目 Vision 归位（沿用 CR-045 既有解析规则），但不伪造源文件内容。
3. 名称调整只改显示，不改文件正文、编号规则（VISION-/EPIC-/FEAT-/STORY-）与后端 `kind` 取值。

## 2. 标准思维导图

1. **整块是导图**。进入思维导图阅读方式后，主区**不再有"上方导图、下方正文"的拼接结构**，整块都是导图画布；页签条与工具栏保持在顶部，其余全部是画布。
2. **连线是导图的一部分**。父节点右侧边缘到子节点左侧边缘画贝塞尔曲线；子节点纵向排开，父节点垂直居中于其子树，形成从左到右的层级树。关系缺失的条目不丢弃，虚线标记为「关系待修复」。
3. **有目录**。左侧为「导图目录」，与画布同源同一份实体集合与同一套折叠状态；目录条目显示类型、编号与标题，点击即选中画布对应节点并把画布滚动定位到该节点。
4. **点击节点在右侧出现悬浮框**。点击（或键盘激活）任意节点，右侧浮出详情框，展示该节点的类型、编号、标题、状态、负责人、来源文件，并提供「在文档中打开」与「编辑」入口。详情是只读身份摘要，完整正文仍在文档页签阅读，不复制第二份正文。关闭详情框后画布恢复全宽。
5. **可在导图页直接新增**。节点上提供新增下级按钮：Vision → 新增 Epic，Epic → 新增 Feature，Feature → 新增 Story，Story/Bug 无下级新增。新增沿用既有的新建表单与编号分配规则，父项即被点击的节点；新增成功后导图、目录与需求树同步刷新。
6. 画布提供缩放（50%～180%）、重置 100%、**适应窗口**、全部展开、单节点折叠；折叠与缩放按项目保留，切换阅读方式回来保持原状。
7. **折叠控件的位置与显隐**：折叠按钮落在**父子连线的连接处**（父节点右边缘），是独立于节点卡片的 18px 圆形控件，**默认隐藏、悬浮画布或该控件时才显示**；已折叠的分支控件常驻可见。节点卡片内不再放折叠按钮，避免与「新增下级」图标重叠冲突。
8. **模型融入**：数据库／领域设计模型（项目 `docs/DB/` 下的设计文档，标题形如 `# DB-001：…`）作为 **Vision 下的项目级独立分支**进入导图与预览，用**虚线关联**（区别于父子实线）、节点用虚线边框；模型不是 Story 的第二父项，也不按名称猜需求关联。无 `docs/DB/` 目录时模型列表为空且不伪造。
9. 无真实愿景源时，导图明确显示「愿景源未提供」，**不**用项目名称或合成目标冒充 Vision，**不**生成虚构层级关系。

## 3. 阅读方式各自分离

1. 左侧轨道已有「文档／全文／导图」三个入口，**顶部工具栏不再重复**「全文预览」「思维导图」按钮。顶部工具栏只保留与当前文档相关的操作（编辑、派发预检）。
2. **预览不显示左侧需求树**。全文预览是独立的连续长文阅读方式，导航由右侧「全文目录」承担；需求树只在「文档」方式出现。
3. **导图不显示需求树**，左侧位置是「导图目录」。
4. 右侧目录支持**折叠子章节**：有下级的条目带折叠按钮，折叠后其下级别条目整体隐藏，展开后恢复；折叠状态按项目保留。
5. **预览四级全量与四级目录**：预览正文按实体层级分级排版（Vision H2 / Epic H3 / Feature H4 / Story H5，正文小节再下沉一级），四类需求全部出现；右侧目录以 **Vision → Epic → Feature → Story 四级需求结构**为主体（每条显示类型标签与标题，可折叠其下级），模型作为项目级分支列在末尾。文档方式仍以当前文档标题为 H1，右侧为本页目录。

## 4. 边界

- 不改需求正文文件、编号分配、后端 `read_requirements` / `read_requirement_sources` 协议与数据库结构。
- 不新增拖拽改父项、图内编辑正文、自动生成需求、模型分支或数据库设计模型导图分支。
- 导图是需求关系的只读投影加受限新增入口，不成为第二事实来源；文件正文仍是权威。
- AI 侧栏保持独立开关与窄屏行为，不被导图覆盖。
