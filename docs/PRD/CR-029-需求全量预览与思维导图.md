# CR-029：Code需求全量预览与可点选思维导图

- 来源：用户要求在Code项目需求Tab预览所有史诗／特性／用户故事，分级标题、正文全、排版合理；在预览旁新增思维导图，梳理愿景／史诗／特性／模型／用户故事，点击节点右侧显示完整详情；多项目顶部Tab切换仅调研。

- 工作层级与允许范围：仅修改 `docs/` 下需求、方案、可操作原型及设计验证资源；不改正式源码、运行配置、依赖、构建／发布产物，不提交／推送。
- 归属：复用 [FEAT-003](../Plan/Feature/FEAT-003-需求维护与交付验收.md)／[STORY-010](../Plan/Story/STORY-010-需求树与详细文档预览.md#cr-029全量分级预览与思维导图)，不另建Epic或修改业务父子关系。

## 1. 全量预览（现行增量）

1. 需求主区提供相邻的“需求树 / 预览 / 思维导图”阅读方式。外层需求／设计／任务／编码及AI侧栏不变。
2. 预览是**当前项目所有愿景、史诗、特性和用户故事的连续全文**；不受当前选中节点、折叠、列表筛选、任务派发资格影响。未确认、已完成、已取消也保留并如实标注状态；不是目录、卡片摘要或只显示当前Story。
3. 层级：项目文档标题H1，愿景H2，史诗H3，特性H4，用户故事H5，实体正文内小节H6。多愿景逐一展开，源文档内部更深层次采用有标签的段落而不是错误跳级；保留正文、列表、表格、代码、链接／附件引用与扩展字段，不截断尾部。
4. 正文覆盖背景／目标／范围与不包含、流程／异常／权限、AC、状态／负责人／优先级／依赖、PRD／LLD／UI／DB、实现／验证／验收／变更／阻塞。缺少源内容明确“待补充”或“源文件缺失”，不能编造事实，也不能把“全部节点”误标成“所有字段完整”。
5. 正文宽度、行高、段落留白、分级标题字号有区别；章节目录可定位，长表格／代码在局部容器滚动，长标识折行，无整页横向溢出。预览为只读，不保存第二份可编辑汇总或自动提交正文。
6. 无法归属的有效条目列在“关系待修复”区域，保留全文并说明原因；重复ID／循环不静默丢弃、不无限递归。加载／空数据／缺源／无权分别显示，不把失败当空项目；无权不显示标题／数量／正文。

## 2. 思维导图

1. 思维导图入口紧邻预览；图主区＋其右侧详情栏，两者都位于AI左边，不能替代AI侧栏。
2. 覆盖愿景、史诗、特性、**数据库／领域设计模型**和所有用户故事。这里模型沿用现行设计工作区数据库设计含义，不是供应商AI模型；如用户另指其他模型，可独立细化，不新增AI配置图。
3. 需求主关系保持愿景→史诗→特性→用户故事的唯一父项；模型按已有需求／模型关联表示，关联线与父子实线区分。共享模型只对应一个稳定身份，不复制成多个“事实实体”；未关联模型单独在项目模型分支，不按名称猜关联。不强制变成“特性→模型→Story”，无模型的Story也必须可见。
4. 节点显示类型、编号、名称及选中状态。点击或键盘Enter／Space选择**任意五类节点**，主区右侧立即显示该节点完整详情、来源／修订／父项或关联、正文、AC或模型全字段／类型／约束／关系。切换时清除旧节点详情，不在新节点加载／缺失／无权时留旧正文。
5. 提供图区域滚动、缩放、展开全部／折叠与定位选中；折叠不影响全量预览或实体统计。切换阅读方式保留原需求选择、树折叠、图选择／缩放；不修改需求、模型、任务或AI会话。
6. 主区不足宽度时详情回落到图下方，仍属于主内容区；AI独立保持其现行开关／窄屏行为。浅深主题、选中、长文本、无模型、异常状态有可查看设计。

## 3. 数据与边界

- 预览／图／详情为同一项目与源修订集合的只读投影。需求完整正文文件权威继承 [CR-028](CR-028-文件与数据库按职责存储.md)，数据库设计模型版本化DB权威继承 [CR-027](CR-027-Code项目设计资料与按需加载.md)；不因导图新增第二套可编辑正文，不执行SQL／迁移。
- UI完整阅读不等于向AI自动加载全文；仍按既有索引／片段预算读取，无新真实AI工具、图编辑、拖拽改父项或自动生成需求。
- 本次原型使用明确标记的合成预约正文补充和已有状态机同源字段，保留旧快照／草稿；未知新增条目不合成正文，只标待补充。原型不运行时读取本仓库MD，不冒充正式数据接入或正文持久化已完成。
- 多项目顶部Tab项只做仓库事实调研，不更新现行导航设计／正式软件，不纳入本批AC。
