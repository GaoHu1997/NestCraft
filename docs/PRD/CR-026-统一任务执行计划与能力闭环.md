# CR-026：统一任务执行计划与能力闭环

- 来源/日期：2026-11-19用户要求详细研究任务协作平台并结合本项目调整需求、设计与方案，形成闭环；前述质询明确要求每个派发任务的CLI、模型、权限及Tool/Skill/MCP真正贯通。
- 授权：仅需求/方案/可操作设计/设计验证；不改正式软件、运行配置/依赖，不启动真实CLI/安装/生产业务。保护CR019/023样式、CR021导航和新公共入口。
- 状态：范围已确认，设计中，最后用户设计待验收。CR024已用于目录入口收敛，不复用编号。
- 复用FEAT018/019/020；新增STORY057执行计划（FEAT018）、058能力编译（FEAT019）、059冻结运行与重试交接（FEAT019），交付配置追溯关联已有STORY043/045。不新建任务系统或可编辑需求源。

## 1. 必须形成一条配置—运行链

智能体管理/供应商/能力管理的有效配置 → 项目范围/当前授权 → 任务执行计划解析 → 预检逐任务展示与确认 → Run冻结 → Runtime领取和实时复检 → 受管能力执行 → 有限重试/阶段交接 → 验证/交付/验收及来源追溯。

CLI与Agent不是同一实体。现3CLI默认卡提供默认执行模板，任务可指向模板或明确指定；内置子执行类型仍独立且必须有可用通道。模板默认不等于授权，不改既有运行。主任务执行计划与内部子委派计划分开，二者都须在父授权内，不允许子任务越过限制。

## 2. 逐字段解析与来源

任务显式覆盖 → 选定模板默认 → 项目默认 → 经确认系统默认，逐字段保存来源/版本/解析理由。‘继承’在确认前解析成具体值，不能留给运行时猜。

- CLI：显式指定不可用/未安装/门槛或能力不足直接阻塞；自动选择按任务工作类型/语义难度/可用能力和事前允许回退解析，回退结果在预检展示，不静默換CLI。不能以标题关键词当授权。
- 模型：供应商/模型/思考/service-tier（若支持）精确绑定，协议/凭据引用/端点/版本/档位均有效；缺/不兼容阻塞不清档位默回默认。沿用主模型也要显式解析并验证。
- 权限：请求意图、配置上限和本批授权分开，最终不得超过项目/组织/执行器/Runtime可兑现边界；文件/命令/网络/知识范围精确，权限不足须重检授权不能偷偷提权。
- Tool：逐个稳定ID、版本、参数边界、路径/网络/风险策略；原生工具、宿主工具、MCP工具三通道不能混为总开关。
- Skill：固定内容/附件hash与版本，声明所需能力；选择Skill不授权工具，必需能力缺失阻塞，禁用/撤权实时拒绝。
- MCP：精确服务及发现的工具ID/schema版本，不整服务一开就全可用；未发现或未知安全能力不可当允许。服务凭据只引用不写快照/提示/日志，继承全局未审配置禁止。

## 3. 权威与冻结

设置实体只有一份可编辑目录：SDK/CLI默认模板、供应商模型、Tools/Skills/MCP/知识授权分别使用现有真实设计目录，同步规范化只读快照给解析器；不新增独立可编辑‘任务配置库存’。旧M模型示例与供应商设置的差异要显式迁移/失效/重选，禁止保留两个长期模型源。

确认冻结ExecutionPlan：profile/SDK/runtime/model/权限/能力/工作区/授权/预算/需求设计AC版本及来源hash。每个Run/Attempt引用不可变计划，修改管理默认只作用后续计划。冻结不阻止撤权：领取/启动/工具调用都按当前撤权与有效能力复检；不把当前配置值覆盖历史。

重试原计划和原执行者，沿原预算与计数，缺通道/版本失效/权限撤销阻塞；明确换配置/CLI/runtime属于新计划授权并链接旧Run，不能称原Run无缝续接。阶段交接可用不同预授权只读评审模板，但单独冻结计划，不自动继承开发写权限。Run结束不等于Task技术成功，更不等于Story验收。

## 4. 研究边界转化

已读外部平台的默认无人值守执行政策与我们的安全目标不同；不复制其默认高权限、claim时重读所有当前配置、重试只保留Agent身份的策略。借鉴Agent/Runtime/Run分离、明确触发、工作上下文/技能投送、有限重试与讨论回写。保留本项目更严格的预检配置冻结、有效产物依赖、串行受控集成、当前证据验收门槛。条件唤醒不是授权或依赖成功，取消不放行产物。

本轮只独立机制设计，不复用受许可限制代码或UI；实际研究证据另文记录。团队多租户/云托管/31CLI/渠道/生产发布不扩入范围。

## 5. 可操作设计交付与数据

公共入口固定[仿真原型UI](../UI/仿真原型UI.html)，内部不新造独立演示应用。保留管理CLI/SDK两tab；在现模板中补必要能力默认范围，在需求派发预检、任务详情、原Run重试/交接和交付里完整展示具体计划/来源/权限工具清单/失效原因。

必须实走：改默认 → 自动/显式任务计划 → 确认 → 修改默认旧Run仍原计划 → 权限撤销拒绝工具 → 修复后按原计划重试/新计划重授权 → 不同阶段安全交接 → 有效产物交付追溯。不可用/无模型/能力未知/必要Skill缺Tool/MCP未发现/超预算/Runtime离线/旧writer停止未知都有下一步，不只toast。

数据库仅设计扩展，复用原执行表/快照/outbox；本轮不迁移。正式实现要有明确编码授权及设计/软件同条件视觉对照，当前设计验证不能证明CLI真实限制生效。
