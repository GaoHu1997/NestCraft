## CR-003：闭环需求规格（待评审，尚未实现）

本节补足当前原型欠缺的规则；评审通过前不替代 CR-002，不回写历史验证。目标是让使用者能判断：当前卡在哪一步、谁决定下一步、根据哪份证据、失败后怎么恢复。沿用原模块与单用户、本地仿真边界，不新增真实外部操作。

### 研发闭环（code 需求与迭代）

- **关联与入口**：Epic → Feature → Story；缺陷属于 Feature，明确关联一个 Story 及受影响的 AC。Story 详情可定位对应交付物、验证记录、缺陷和验收结论；从文件返回仍定位原 Story。Epic/Feature 完成须满足范围内子项及整体验收，不能只改聚合状态。项目列表保留筛选及搜索，空项目可从需求树新建第一条 Story。
- **必填与留痕**：创建必填标题、目标、归属；从待澄清进入待确认前，补齐范围、负责人、依赖（无则明示）和至少一个可观察 AC。每次关键操作记录对象、执行人、时间、前后状态或版本、原因及关联证据；失败、退回与重做以追加记录呈现，不覆盖旧证据。新增记录均标为仿真数据。

| 动作 | 允许通过的条件 | 结果和恢复路径 |
| --- | --- | --- |
| 提交确认 → 就绪 | 需求内容齐全；用户模拟确认范围与 AC，关键依赖已满足 | 记录确认依据；拒绝需填原因，回到待澄清 |
| 设计 → 开发 → 验证 | 先挂接设计依据，再挂接本次交付物版本 | 缺项保持原状态并定位缺项；不允许仅通过「下一步」跳过 |
| 提交验收 | 当前版本的必验 AC 都有通过结果与证据，且没有未关闭的关联阻塞缺陷 | 进入待验收；验证失败登记原因和影响项，回开发中；修复后重新发起验证 |
| 验收通过或退回 | 仅待验收，显示交付版本和验证摘要；用户明确决定 | 通过记结论进入已完成；退回必须填写原因，按问题回开发中、设计中或待澄清；重提需重新验证，不复用失效结论 |
| 缺陷修复与复验 | 有复现、预期、实际、严重度和 Story/AC 链接；提交修复必须标明交付物版本 | 未修复 → 待复验 → 已关闭；复验失败退回未修复并继续阻塞。只登记修复不解除阻塞 |
| 阻塞、取消与恢复 | 阻塞记录原状态、原因、责任人和下一步；取消需说明原因与产物处置 | 解除阻塞回原阶段；取消不计完成，保留记录与链接；已完成的基线不改写，后续范围变化另起变更记录 |

- **版本与统计**：需求范围或 AC 变化必须重新确认；交付物变化后旧证据保留但不得用来放行新版本。待验收遇到上述变化应撤回本次提交，回相应阶段。迭代进度建议使用「当前迭代已完成 Story / 当前迭代未取消 Story」；取消数单列，分母为 0 显示「暂无可统计 Story」，不把缺陷计入分母。

### 文件、AI 与设置闭环

- **项目与文件**：创建项目提示空值、同名及类型校验，取消不留记录。code 默认进入需求与迭代、work 进入文档工作区（见 CR-004）。文件详情显示路径、已保存或草稿状态；切换文件或工作区保留当前草稿，放弃或重置前提示影响；保存成功才更新版本。办公格式仍只预览样例，不写实际文件。
- **AI 写入提案**：提案绑定项目、目标文件、基线版本和变更摘要。批准时复查基线版本、是否有待保存草稿及工具可用性；不满足则终止旧提案，提示保存草稿或按当前内容重新生成。批准、拒绝、失效分别记录结果；同一提案重复点击不得重复写入。文件拟回退时以新版本恢复，旧记录不删除；不要求通用版本管理。
- **设置联动**：设置区分本次会话和默认值，说明修改的作用范围。停用当前 SDK 引擎后无可选引擎时，助手显示不可发送原因和设置入口；停用 Skill 后手输该命令也不得触发；MCP 仅显示模拟状态。此处原“知识库只展示目录，不新增检索或引用”限制已由 CR-005 替代；其他 CR-003 待确认规则不随其生效。

### 服务器操作闭环（仅仿真）

- **连接与授权独立**：手动连接失败保留原因和重试入口，失败不改授权。主机授权不等于已连接，也不替代单次高风险审批；主机之间不继承授权。工作区同时显示连接状态、该主机授权和 `ssh-exec` 启用状态，缺项给出对应修复入口。
- **审批与结果**：高风险确认卡显示目标、动作、风险、申请时间和当前状态。批准前按该主机当前连接、授权和工具状态复查；拒绝、撤权、断开、停用任一条件使旧提案失效，恢复后须重新发起。通过审批只表示允许尝试，需分别显示模拟成功或模拟失败；失败保留原因，重试生成新提案，不重复执行旧提案。日志关联申请与结果，只记仿真信息、不收集凭证。

## CR-005：项目知识授权与统一 AI 工作台

- 来源：2026-11-18 本轮用户两项反馈；任务归类为既有需求细化与设计变更。用户已授权补充需求和设计并由代理判断文档存储，不授权本轮接通真实服务。
- **交付层次**：v2.4 本地仿真供操作评审；正式需求/技术方案供后续实现。所有真实授权隔离、CLI 适配、正文上传、数据库存储仍未实现。

### 项目知识库

知识库可授权给一个或多个明确项目；未授权项目不可使用，空授权默认拒绝。个人所有者在管理页授权、撤权；项目 AI 的可见库、@候选、搜索、读取、批读、引用打开全部依据当前项目授权，不暗含知识库写入权限。最小只读工具为 `knowledge.list/search/read/read_many`，结果有来源和版本；通过统一网关解析会话项目身份，每次调用复检，不接受 AI 自报 projectId 扩权。撤权后旧引用、缓存和相关待审提案失效，已显示给用户的资料不能声称可收回；原生 CLI 无法清理上下文时终止旧线程。

本轮提供内置样例授权与检索。真实知识源导入/同步仍待范围细化；不新增写入、删除、自动改链、向量检索或多用户权限。通用文件/shell/任意 MCP 不能成为绕过权限的路径，真实托管 CLI 缺隔离能力时阻止需隔离任务。

### code 需求与文档

- SDK 管理只保留 Codex、Claude、Grok 三种 CLI SDK，提供仿真安装、更新、卸载。会话切换列表只列出已安装且启用的 CLI，安装与卸载完成后即时更新候选。
