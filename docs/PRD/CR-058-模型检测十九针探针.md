## 1. 背景与目标

用户在 NestCraft 中配置了多个模型供应商（中转站、官方 API 等），无法判断所选模型是否被中转层「掺水」：偷换低价模型、吞 System 指令、塞隐藏提示词、偷裁多轮历史、假流式刷首字、伪造结构化输出、低智商小模型冒充旗舰。外部工具（gpttest.xyz）功能完整但面向 GPT 系深度定制，对 DeepSeek / Qwen / GLM / MiniMax / MiMo 等非 GPT 模型存在三类短板：

1. **档位识别**：降档判定只认 GPT 代数与档位秩，其他厂商命名（max/plus/turbo/flash、opus/sonnet/haiku 等）只能报「回显不一致」黄牌，给不出降档红牌。
2. **背题风险**：单一固定逻辑题可被网关配置缓存抢答。
3. **计费对账**：严格 BPE 对账以 OpenAI 分词为基准，对非 OpenAI 模型误报率高。

目标：把「模型检测」内建到设置中，复用已配置的供应商与模型（用户零填写），固定执行 9 针探针，输出 100 分制评分 + 真伪×渠道双轴结论，并保留最近 10 次历史。

## 3. 业务流程

1. 用户打开设置，在左栏「模型管理」下方看到并点击「模型检测」页签。
2. 选择供应商（已启用）→ 模型下拉联动列出该供应商已配置模型 → 点击「开始检测」。
3. 后端读取该供应商协议匹配的启用端点与第一条启用密钥，按 P1→P19 顺序逐针发起真实请求（约 20 次）；每针完成即推送进度（状态/耗时/摘要）到界面。
4. P1 失败（网关不可达/鉴权拒绝）时后续针标记「未执行」，检测终止并给出总评「无法判定」；其余情况跑完全部 19 针。
5. 聚合评分：100 分制扣分 → 等级 S（≥95）/A（86）/B（70）/C（50）/D（<50）；真伪轴（真实/存疑/假冒嫌疑/无法判定）× 渠道轴（官方直连/聚合中转/逆向套壳嫌疑）给出结论。
6. 结果写入本地历史（保留最近 10 条）；界面展示完整报告，用户可点右上角「历史记录」展开悬浮下拉（只列时间与供应商），选中任一条即收起下拉并把结果区与 19 针列表切到该次结果。

## 4. 规则与边界

- **零填写原则**：检测只使用已保存配置；不提供临时地址/密钥输入。停用供应商、无启用密钥、无协议匹配启用端点、无已配置模型时拒绝发起并提示原因。
- **密钥安全**：密钥仅在后端当次请求栈内使用（沿用既有 `secrets` 受管机制），不落日志、不进结果 JSON、不回传前端；请求不跟随重定向。
- **随机防背题**：P4 金丝雀、P6 锚点、P9 题目参数均当次随机生成；两次检测题面不同。
- **评分封顶**：P2 实锤偷换降档、P4/P5/P6 红牌时总分封顶（详见 LLD 评分表）；P1 失败总评直接「无法判定」。
- **推理模型**：请求参数自适应（`max_completion_tokens`、省略 temperature、允许推理耗时）；P7 对推理模型按「正常受控完成」放行。
- **UI-SCROLL-001（CR-049）**：逐针结果列表与历史弹层超高时，滚动条仅在实际滚动时显示、停止后隐藏；实现与验收义务登记见 STORY-075。
- **成本意识**：单次检测约 12 次请求、总输出受 `max_tokens` 约束（约 1500 token 量级），逐针最小化输出。
