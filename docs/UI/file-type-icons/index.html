知识库文件类型彩色图标

按知识库实际支持的文件格式设计的一版彩色文件类型标识：14 类（含目录），每类一张纸 + 格式色 + 白色内容符号，浅色与深色两套取值，16px 文件树内可辨、20px 文档头可直接用。

01两种呈现变体

同一套图形，只切“纸面怎么上色”。两个变体共用一套 24×24 symbol 与类型色令牌，实施时选一套或按场景混用。

A · 实底彩色SOLID
色彩最强，远看即分类型。适合 20px 以上：文档头、空态大图、类型说明卡、导出图。
建议用于：知识库阅读区标题、上传/导入结果、类型图例。
B · 淡底描边SOFT
密集列表更安静，深色主题更稳。适合 14–16px：知识库文件树、会话引用、搜索结果行。
建议用于：文件树默认态（选中行仍保留类型色）。

两变体差异仅在“纸面填充/描边”，折角、内容符号、比例与网格完全一致，切换不引起布局变化。

02全部 14 类 · 实底彩色（A）

类型集合按知识库真实格式矩阵确定：可渲染/可检索的文本类、可预览的图片、仅元信息的原件类、以及必须兜底的未知格式。

03全部 14 类 · 淡底描边（B）

同一组图形在文件树里的推荐形态；与 A 变体逐类对照，形状、折角与符号位置一致。

04尺寸阶梯

单一 24×24 网格等比缩放，不做逐尺寸重绘；15px 为文件树行内值，20px 为文档头，44px 为类型说明与空态。

上排：单个图标在 14 / 15 / 16 / 20 / 24 / 32 / 44px 的实际观感；下排：14 类全部按 16px 并排，检查彼此是否仍可区分。

05知识库场景仿真

按知识库三栏阅读的真实结构排布：左侧目录树（B 变体 16px）、右侧文档头（A 变体 20px）与信息区。树内文件名为示例知识库的演示样例。

知识库授权与检索

知识库 = 一个受管的本机目录。平台对它做三件事：列目录、建索引、受控读取。

  • Markdown 与文本格式切片建全文索引；其它格式只登记文件名与路径。
  • 读取正文前检查知识库是否启用、是否被授权给当前项目。

文档头用 20px 实底图标，与左侧 16px 淡底图标同形不同色深，避免“同一文件两种外观”被误读为两种文件。

06按知识库能力分组

图标只负责“是什么格式”；能力（能否检索、能否预览）仍由文字徽标表达，不让图标承担权限或能力语义。

正文可读 / 可检索

切片进全文索引，AI 可读；Markdown 与 HTML 可编辑。

图片可预览

受检 MIME 后安全预览；不进全文索引，AI 不可读正文。

仅原件与元信息

不解析正文、不内联渲染；可导出原件。AI 只拿到文件名。

07图形规范与色彩令牌

24×24 网格；纸面 16×18 圆角 2；右上折角 7×7；内容符号限制在安全区（相对 33%–75% × 44%–77%），不贴边、不压折角。

纸面 / 类型色 折角 34% 白 内容安全区
  • 轮廓纸张 16×18、圆角 2；右上 7×7 斜折角。所有类型共用同一轮廓，只有内容符号与颜色变化。
  • 内容符号白色、线宽 1.75（24 网格内），端点圆角；面积不超过安全区，保证 15px 时仍成“可辨认的小块”而不是糊成一团。
  • 目录不套纸张：后片 = 类型色 78% + 深，前片 = 类型色；与文件形成“容器 / 内容”的区别，不用颜色区分。
  • 不用字母块沿用平台规范：不用 W / X / P 这类字母砖代替图形。Markdown 的 M↓ 是 Markdown 标志的几何化轮廓，属于图形而非字母；未知格式的“?”为全库唯一允许的符号化例外，与现行实现一致。
  • 能力不内置图标不画锁、眼睛、AI 角标；能否检索/预览由文字徽标与状态表达，避免图标同时承担格式与权限两种语义。

类型色令牌（浅色 / 深色）

实施时按 --ftc-<type> 命名并入 tokens；深色不是简单反转，而是提高明度、略降饱和，保证深底上不刺眼且仍可区分。

使用规则

  • 文件树行 15–16px（B 变体）；文档头 20px（A 变体）；类型说明/空态 32–44px（A 变体）。
  • 选中行只换底色与文字色，图标保留类型色，不跟着变主色。
  • 同一文件在不同位置必须同形：只用“实底 / 淡底”两个壳切换颜色强度，不改轮廓与符号。
  • 未知扩展名回退 ft-unknown；不阻止上传、阅读元信息与索引登记。

与现行实现的关系

  • 现行 CR-051 §5.2 是 14 类单色线稿（1.6px 描边，只换颜色）；本稿把“类型色”升级为彩色纸面，轮廓从线稿改为实心/淡底。
  • 扩展名映射沿用并收窄到知识库范围：新增 html（富文本）、drawio（图纸）、zip（导入包），pos 等归未知。
  • 本稿未改任何源码、依赖或构建产物；接入需另行授权，并同步 tokens、sprite 与文件树组件。

08确认点与验收边界

▲
本页只是设计稿，未接入软件。「看得见」仅指本页在浏览器中的呈现；知识库文件树、文档头与上传结果仍显示现行单色线稿，直到获得编码授权并完成实施与视觉对照。

需要你确认的 3 项

  • 变体取舍：A 实底 / B 淡底 / 按场景混用（推荐混用：树用 B、文档头用 A）。
  • 类型集合：14 类是否够——是否要单独区分 svg、代码文件（js/ts/css）或 odt/ods/odp。
  • 色彩浓度：是否接受当前明度（若觉得“太花”，可整体降一档饱和）。

确认后的实施范围（另需授权）

  • tokens：14 组 --ftc-* 浅/深取值，并入主题 CSS。
  • sprite：14 个 symbol 并入 icon-sprite.svg，保留现行 113 个语义图标不动。
  • 组件：文件树与文档头切换新符号，扩展名映射迁到同一来源；旧 14 类线稿保留为历史，不并存两套入口。
  • 验证：16px 树内可辨、浅/深两主题、选中态保色、未知回退、与设计稿逐场景对照截图。
