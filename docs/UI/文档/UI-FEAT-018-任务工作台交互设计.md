### 用户操作闭环

| 入口 | 操作与结果 | 失败/退回下一步 |
| --- | --- | --- |
| 需求 | 新增/编辑/确认、设计同步、选择CLI只分配或派发 | 缺设计到设计页，缺授权/配置到设置，修改后重检 |
| 派发预检 | 冻结范围/CLI/预算/依赖，一次确认，任务列表自动更新 | 排除原因可定位需求，不扩范围；取消无副作用 |
| 运行详情 | 原Story阶段联动，查看Run/transcript/工具/错误/用量，评论续接 | 失败从原Run重试；基线失效到需求重新确认 |
| Runtime/设置 | 离线等待、模型/权限/配置修复 | 不自动切CLI，恢复后同允许组合重检 |
| 评审 | 当前产物通过或理由退回，受限新尝试 | 旧证据历史保留，返工上限和预算明确 |
| 待验收 | 模拟验收通过或理由退回 | 失效/失败/缺证据不得通过，退回开发或需调整阶段 |
| 条件唤醒 | 创建/停用/触发/到期/历史，查看等待条件 | 条件不满足继续等；限次、阶段版本和防重复 |
| 报告/代码证据 | 查看当前与历史结果，返回来源需求/Run | 当前验收只看有效修订，未发布/真实未知明确 |

## 2. 页面信息架构与派发入口

code 项目页签为需求 → 设计 → 任务 → 编码，work 项目不出现研发任务树。任务页是运行视图，不引入必须人工批准的阶段。

需求页 Story行提供「派发故事」，Feature/Epic行为「派发特性/派发史诗」，当前范围工具栏提供「派发全部合格需求」。入口仅在需求；任务页无新派发按钮。无操作授权时只读并解释原因，缺确认/设计等不合格可在预检看到，但不得启动。

点击派发先进入预检，不立即创建任务。预检显示选择根/Story集合、合格条目、排除原因、范围外依赖与产物可用性、循环错误；「全部合格」明确当前项目当前范围，不包含未来新增项。零合格、配置/授权失效、环依赖时确认禁用。

## 3. 派发预检与一次授权

预检对话/侧页分为：范围与版本、依赖/资源、执行策略、交付终点四段。逐条列出已确认、设计可执行、无待同步草稿、未完成/取消检查；排除项不收起到不可见提示。显示 requirement/design/AC hashes摘要，详情可看完整值；选中范围改变或源版本变化重新预检。

执行策略展示 CLI/模型允许集及明确选定组合、最低必要能力/难度、最大并发、预算类型及可强制性、重试/返工次数、工作区/知识/工具/网络范围、restartPolicy、本地允许集成分支。点名组合仍需验证；不支持/未验证有文字，不能静默换CLI/模型。未知费用提示「未知，不承诺费用硬封顶」。

终点默认「技术验证后交付，Story待验收」。预授权客观自动验收必须显示真实授权来源和规则，不因为用户要自动执行就默认自动完成。默认未授权推送、保护分支合并和生产发布，文案明确。

确认文案「确认并派发合格范围」，显示实际选中条目与排除数量；确认时二次检验，基线变化显示重检提示，重复派发定位已有批次/活动任务，不生成重复列表。取消不创建任何批次/进程，返回焦点；失败保留输入、说明原因并可重检。加载态不能重复提交。

## 4. 项目任务工作区与依赖详情

任务页主区为批次选择、筛选栏和任务列表，详情为侧栏/独立页：

- 列表：任务编号/Story标题、运行状态、当前步骤、CLI/模型、依赖或资源等待原因、最近事件、结果入口。按状态/批次/Story/CLI筛选与清空；数量与列表一致。没有数据时说明到需求派发，不在任务页加派发按钮。
- 批次：冻结范围/策略、运行/成功/部分成功/失败/取消，暂停汇总与停止请求单列，不混同Story状态。
- 详情：Batch→Task→Step→Attempt层级；会话仅关联。并列「文档状态」和「运行状态」，还有基线/配置/权限摘要、资源锁、前置门槛、日志/差异/报告。
- 依赖：列表列出前置任务、requiredArtifact、verificationGate、expected/consumedRevision与当前可消费基线，说明尚缺什么。失败/取消前置显示阻塞，不显示已放行；循环显示闭环路径文字，不能让用户随意删边来执行。
- 资源：占用者、规范化资源范围、锁模式/槽、等待原因，说明独立worktree不是OS沙箱；敏感任务安全控制不能兑现时阻塞。
- 追溯：定位需求/设计/AC、代码差异或产物修订、尝试/日志；缺真实文件/提交时说明未生成，演示差异和HEAD均标「仿真」。

一次确认后授权内自动推进，不要求逐步骤点批准。暂停/继续/取消作用已有批次或任务，展示请求已接受与实际停止区别；stopPending时禁用重复恢复，不能把旧进程尚运行显示成可安全重启。取消前说明对后继影响，保留历史；不提供「忽略租约/强行恢复」按钮。

## 5. 结果报告与证据追溯

报告首先区分技术交付、文档状态、验收状态、发布状态。默认「技术验证完成，待用户验收，未发布」；部分成功不是全部需求完成。逐 Story 与 AC列passed/failed/notRun/notApplicable、当前修订有效性、命令/步骤、环境/时间、日志和差异。未执行测试不可出现通过图标。

证据详情展示artifactRevision、AC/设计hash、consumedBaseline、验证计划hash、环境fingerprint；旧证据标「已失效，历史记录」并解释修订变化，不删除。报告修订切换保留旧历史，但当前验收默认使用最新有效版。文档同步冲突显示当前/预期hash和结果保留，不给强制覆盖按钮。

失败区给AC/任务编号、失败分类、重试/返工次数及上限、影响、负责人和下一步。取消不能计为完成，未达AC不得标普通优化。预算显示可信usage；unknown为未知、估算单列、仿真样例不进真实账单，无真实提交/发布则标未生成/未发布。

人工验收属于真实授权操作，本轮评审稿只演示规则/状态，不写真实验收记录。预授权客观验收演示必须标「仿真授权」，不能被误认用户真实签名。

## 6. 异常、生命周期与适用状态

| --- | --- |

| 外部依赖无授权/循环/活动重复 | 列缺失产物或闭环/已有任务；不扩范围、不删边、不重复 |
| 等待资源/依赖 | 显示占用者/具体门槛；无需人工不断点下一步 |
| 暂时网络故障 | 重试等待、次数/时间/预算；可取消，达到上限停止 |
| 认证/额度/配置/权限/业务决定 | 停止受影响分支并说明谁需提供什么；独立任务继续 |
| 验证失败 | 有限返工进度与失败证据；不能改AC来通过 |
| 租约过期/旧回调/停止未确认 | 恢复对账/阻塞，旧事件标历史，禁止双写与强行忽略 |
| 窗口关闭/主进程退出/主机重启 | 正式设计说明独立runner语义；评审稿提示「仅模拟，关闭页面不代表真实后台执行」 |
| 文档/证据失效 | 结果保留、待同步/重验证；区分历史与当前凭据 |

## 7. 离线评审场景与限制

演示命名空间 DEMO：先契约产物通过，再后端/前端并行；独立审计并行；两个写同资源任务串行；暂时故障有限重试；验证失败有限返工；前置失败/取消阻塞后继；未确认、未同步、失效配置、环和重复派发拒绝。

计时器或确定性step推进仅模拟调度，异常注入控件放独立「评审仿真」区，不能伪装业务批准按钮。内存/本机快照恢复仅展示模型，不宣称真实daemon/进程树/DB租约。全过程无fetch/真实CLI/网络/SDK安装/Git/数据库迁移。
