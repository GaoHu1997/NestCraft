## 1. 设计目标

用户不需要理解"CLI 内部到底用哪个 Shell"的实现差异，也能在同一个位置：

1. 看见每个 CLI 当前使用的命令工具与检测结果；
2. 在 CLI 支持时改选，并知道改动只对之后的新会话生效；
3. 在 CLI 不支持时看到明确说明，而不是一个点了没反应的开关。

硬约束：不伪造能力；不把命令工具做成权限；不改现有 CLI 卡片的模型／思考／难度／权限字段顺序；窄屏与深色可用。

## 2. 界面结构

在「设置 → SDK 与 CLI → CLI 管理」每张已展开的 CLI 卡片内，新增一个「命令工具（Shell）」分组，位于权限模式之后、卡片保存按钮之前：

- 分组标题行：标题＋可控程度标签＋检测时间＋「重新检测」。
- 候选行：原生 radio 语义（`label` + `.opt`），每行含名称、状态标签、绝对路径与版本。
- 说明行：解释该 CLI 的限制（固定路径／实验性／仅展示）。
- 错误行：所选路径失效时的红色说明，并禁用保存。
- 检测中：显示 spinner 与「正在检测命令工具与版本…」，候选与保存禁用。
- 卡片底部：沿用原「保存」按钮与"仅影响之后的新会话"提示。

不新增弹窗、不新增设置一级菜单、不改设置弹窗的 1040×700 尺寸。

## 4. 能力分层在界面上的表达

| CLI | 标签 | 选择 | 说明文案要点 |
| --- | --- | --- | --- |
| Claude Code | 可指定类型 | 4 项 radio | PowerShell 只从固定绝对位置识别（不查 PATH）；本版不支持自定义安装路径；Git Bash 以 `CLAUDE_CODE_GIT_BASH_PATH` 指定 |
| Codex | 实验性 | 4 项 radio | 依赖环境变量传递、语义待实测；派发带 `--ignore-user-config`，用户 config.toml 不生效；实测前不承诺生效 |
| Grok CLI | 仅展示 | 无（只读行） | 未提供 Shell 配置项，只展示检测结果，不伪造"已切换" |

这条分层是本次设计最重要的约束：三个 CLI 的外观可以一致，但不能把"仅展示"画成可选项，也不能把"实验性"写成"已生效"。

## 5. 设计与实现的关系

- 本轮只改需求与设计，未修改 `src/`、`src-tauri/`、依赖或构建产物；设计稿不读写设置、不启动 CLI。
- 设计稿路径与版本（`C:\Program Files\PowerShell\7\pwsh.exe`、`7.6.10` 等）为渲染样例，取自标准安装位置与本机检测值，不代表用户环境承诺。
- 软件实现时必须另获编码授权，并在实现后按同一视口／主题／场景做设计—软件成对截图；构建通过或 DOM 存在不能替代视觉对照。

## 7. 待定与风险

1. Claude Code 只识别固定位置的 PowerShell：若用户把 pwsh 装在非标准目录，界面只能提示"未检测到"，不能"指定路径"。是否接受见 [Q-053-01](../../PRD/CR-053-CLI命令工具可选.md#7-待确认问题)。
2. Codex 的环境变量语义未经实测；若实测失败，该 CLI 应退回"仅展示"，不能保留可保存的假选择。
3. 路径检测在无权限读取目录时可能失败；需与"未安装"区分（待实现阶段定义）。
4. 设计中 390 画布高度固定 720，内容需滚动；实现时设置弹窗保持 1040×700，窄屏另定规则。
