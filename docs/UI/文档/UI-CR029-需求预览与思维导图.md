## 页面与交互

### REQ-READ-01：预览

需求Tab内相邻按钮“需求树／预览／思维导图”。预览显示章节目录与连续长文；项目H1、愿景H2、史诗H3、特性H4、故事H5、正文小节H6。正文不按派发资格筛掉未确认／取消／完成项；每实体保留源字段、长文本和缺项状态，目录点击定位。预览正文内不塞每Story操作条、任务卡或第二可编辑汇总。

### REQ-READ-02：导图与详情

从左向右展开业务层级；模型在项目下独立收纳，以虚线表达明确关联，不强制成为Story父项。五种类型都有文字、编号、名称和选中，完整名称通过可访问标签与右侧详情读取。图超出窗口只在图区域滚动；缩放50%～150%、重置100%、展开全部、单节点折叠和定位选中。每次选择更新右详情，不叠弹窗、不修改业务状态。

宽主区：图在左、340px详情在主区右。宽度不足时详情位于图下，避免挤占既有AI；AI仍是独立侧栏，不将详情塞进AI或覆盖它。选中节点、图滚动与缩放应保留；详情新选择从顶部开始阅读，清除旧正文。AI关掉时主区自然扩展。

## 样例真实性与保护

- 本次愿景与史诗／特性／Story叙述为**新增合成预约情景补充**；编号、源业务阶段、需求／设计／AC修订、依赖、分配、讨论、验收历史来自已有状态机，不能把二者混称真实仓库正文。
- 原状态机17个需求条目（2史诗、3特性、12Story）；原设计资料3个模型；新增1个合成愿景，共21个阅读实体。数量从当前实例实时算，不写死到Tab。
- 模型关联采用明确的合成评审映射（预约主流程关联bookings，保障关联users／service_slots），不是根据名称自动推断，也不写源父项；实际项目仅用真实关联，未关联单独收纳。
- 源样例AC只有编号时，保留编号并明确正式可执行正文待补充，不伪造真实通过；未知新增条目缺字段待补，不套用已知Story的旧叙述。
- 不覆盖旧快照／正文／草稿，图和全文为内存只读投影；保存模型后读取已保存修订，不将设计未保存草稿当已同步模型。
