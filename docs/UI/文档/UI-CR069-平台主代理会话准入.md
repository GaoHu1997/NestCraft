## 1. 结论（先给结论）

**本需求涉及用户可见界面变化，但当前没有任何有效 UI 设计，因此界面部分一律不得开发。**

可以先行实现且只通过命令／单测验证的部分：

- `session.runner` 迁移与读写；
- 平台模型客户端与流式解析；
- 工具循环、白名单、上限；
- `dispatch_work` 与批次创建。

**必须等设计补齐才能动的部分**：

1. 会话配置中的「运行通道」选择入口；
2. 未配置平台模型时的空状态与引导文案；
3. 平台会话下权限模式控件应隐藏还是标注不适用；
4. 主代理发起批次在任务页的来源标识（若需要）。

## 3. 每个场景的准入要求

### SC-069-01 运行通道选择

必须先补齐：

- 位置：会话配置浮层内，与「切换 CLI」「权限模式」「模型」同级或独立分组。
- 状态：默认值（`cli`）、已选 `platform`、平台通道不可用（无可用模型）、已有消息不可切换（禁用＋原因）。
- 文案：需说明「CLI 由外部程序作答」与「平台直接作答」的差别，不能只写代号。
- 与既有控件的关系：选 `platform` 时，CLI 选择与权限模式如何呈现（隐藏／禁用／替换）。

**未完成上述覆盖前，不得新增该控件。**

### SC-069-02 未配置模型空状态

必须说明：

- 缺的是供应商、端点、密钥还是模型；
- 引导到设置的具体位置（供应商配置页）；
- 不出现「请先安装 CLI」这类误导文案。

### SC-069-03 权限模式控件

当前 `ModelPicker.tsx:16-25` 的权限选项语义是 CLI 原生参数（`claude acceptEdits`、`codex workspace-write`）。平台会话没有这些参数。

必须设计：

- 平台会话时该控件隐藏、替换为「平台工具范围」说明，还是显示为禁用并附原因。
- **不得**让用户以为平台会话也受 CLI 沙箱保护——那会造成错误的安全预期。

### SC-069-07 长会话上下文

平台通道没有 CLI 的上下文压缩。超过模型上下文窗口时的行为需要设计：拒绝发送并提示、截断最旧消息并明示、还是触发摘要。**在设计与实现确定前，此场景按「未定义」处理，不得用不可见截断糊弄。**

## 4. 复用判断（无需新设计的两项）

### SC-069-04 工具步骤

现有渲染链：

- 中文名映射：`src-tauri/src/commands/ai_tools.rs:482-506`（`TOOL_LABELS`）；
- 前端消息类型：`src/api/index.ts:776`（`subagent` 事件）与 `ChatEvent::ToolUse`／`ToolResult`（`src-tauri/src/models.rs:405-406`）；
- 渲染：`src/modules/chat/ChatPanel.tsx` 的工具事件处理与消息流。

**复用条件**：平台通道产出的事件类型与字段与 CLI 通道完全一致。若需要新增事件类型（例如区分「平台工具」与「CLI 工具」），则**不再是纯复用**，需重新评估设计。

**验证要求**：实现后必须用同一会话分别产生 CLI 工具步骤与平台工具步骤，对比渲染结果一致。不得只测一边就声称一致。

### SC-069-05 派发结果

`dispatch_work` 的结果是一个普通工具结果（JSON 文本）。按既有工具结果渲染即可，**不需要专门卡片**。

若产品要求「派发后显示可点击的任务链接」，那属于新增交互，需要设计。

## 9. 前端实现登记（2026-11-23，按 v2 执行）

- 实现位置：`src/api/index.ts`（SessionMeta.runner、create/update 参数）、`src/modules/chat/overlay.tsx`（浮层类型加 runner）、`src/modules/chat/ModelPicker.tsx`（运行通道 chip + 弹层 + 平台态 CLI/权限禁用）、`src/modules/chat/ChatPanel.tsx`（runnerDraft / switchRunner / createSession 传 runner / startSend 平台校验分流）、`src/modules/chat/chat.css`（chip 与弹层样式）。
