# UI-FEAT-019：任务执行状态

- 版本：UI-FEAT-019-v1.3（2026-11-23）。本稿只覆盖**只读**任务执行状态展示，不包含派发、暂停、重试、审批等控制交互。v1.1 增加「执行计划」卡，v1.2 增加「待审批」行，v1.3 增加审批风险等级。
- 关联：[FEAT-019](../../Plan/Feature/FEAT-019-依赖调度与受管执行.md)、[STORY-040](../../Plan/Story/STORY-040-依赖与资源约束自动调度.md)、[STORY-068](../../Plan/Story/STORY-068-单特性执行会话与范围门禁.md)、[CR-047](../../PRD/CR-047-单特性执行与需求设计防遗漏.md)、[CR-032](../../PRD/CR-032-需求设计与代码双向变更及高保真逆向.md)。
- 授权与层级：2026-11-23 用户「其他的你完成一下」＝正式编码授权。本稿在正式 UI 接入前制作并实际打开检查；不把本稿当作已实现的软件界面。
- 入口关系：本目录是**设计资源**，不是第二公开原型入口；唯一公开入口仍为 [仿真原型UI](../仿真原型UI.html)。
- 主题与视口：浅色／深色各 1440×900，窄屏 390×844；缩放 100%，无浏览器扩展。深色通过 `?theme=dark` 切换，截图使用同一 HTML。
- 视觉基准：沿用项目现有浅深令牌（白底、`#2563eb` 主色、6px 圆角、细边框、13px 正文）。

## 1. 场景与状态覆盖

| 场景 | 结构与交互 | 覆盖状态 |
| --- | --- | --- |
| SC-019-01 空态 | 左侧「派发树」空，右侧说明任务账本已就绪但真实 runner 未接入；派发按钮禁用 | 无批次、无任务、未接入说明 |
| SC-019-02 运行中 | 左侧按批次分组，任务行显示编号、名称、状态徽章；右侧任务详情含 CLI、尝试、步骤、fence、执行计划（计划 hash／CLI 档位／授权）、待审批与事件时间线 | 排队、等待依赖、运行中、验证中、已完成、阻塞；有计划／无计划、授权有效／阻断、有待审批／无待审批 |
| SC-019-03 阻塞 | 阻塞原因横幅、检查点／fence／源版本、阻塞项列表；恢复与取消按钮禁用 | 旧 writer 未确认停止、需人工确认、无强制恢复 |
| SC-019-04 同步冲突 | 同步批次标题、目标对账列表（已应用／冲突／待应用）、冲突横幅与重新对账 | 第三方修改、base 未变、冲突不覆盖 |

不包含：真实派发与审批、暂停／取消／重试控制、任务日志全文、费用与用量、批量操作；这些需要 runner 控制通道与审批界面，另行设计与授权。

## 3. 实际检查记录

- 2026-11-23 实际打开设计稿并生成三张截图；检查发现窄屏 390 下同步冲突行被挤压、徽章拉伸。
- 修复：徽章 `white-space: nowrap`，冲突行 `align-items:center`；窄屏改为两列并将第三方 hash 换行。
- 复截后窄屏冲突行显示正常：标题、状态徽章、hash 分行，无横向溢出。
- v1.1 增加执行计划卡后重截三张，计划 hash／CLI／授权三列在 1440 与 390 均可读，未出现溢出。
- 软件详情栏 360px 下三列过挤，改为「计划 hash 独占一行、CLI 与授权各半」，设计稿与软件同步为两列并复截。
- v1.2 增加待审批行后重截三张；软件侧接 `execution_approval_pending`，任务详情显示「待审批 N」并过滤到当前任务或计划级请求。
- v1.3 增加审批风险等级（高／中／低），软件按待审批请求的最高风险显示；重截设计稿与软件页。
