## 1. 视觉与交互基准

| 部位 | 本版基准（UI-CR096-v1） | 与上一版差异 |
| --- | --- | --- |

| 标题层级 | h1 16／h2 15／h3 14／h4-h6 13px，行高 1.45，上 16 下 8px | 由 24/20/18 下调，避免正文变小后标题仍过大 |

## 4. UI-SCROLL-001 与验证边界

显式采用 [UI-CR049-v1](UI-CR049-滚动条按需显示.md) 及 [CR-049](../../PRD/CR-049-滚动条仅在滚动时显示.md)：

- 消息区、轮次刻度容器、分支下拉均用原生滚动；静止透明，实际滚动由共享 `scrollbar.js` 加 `.scrollbar-active` 着色，停止后约 700ms 隐藏。
- 本版**未**使用 `overflow:hidden` 禁用任何必要的纵向滚动；卡片上的 `overflow:hidden` 仅用于裁切圆角，不含滚动内容。
- 浮框通道计入容器宽度，避免「为显示浮框而裁掉滚动」的两难；容器 `pointer-events:none`，仅刻度按钮接收指针。
- 悬停/聚焦浮框不改变滚动位置，不触发重排。

**验证边界**：本版只验证设计稿自身（浏览器实际渲染、几何断言、浅深与窄屏截图）。**未**验证正式软件，不声称软件已与设计一致；软件侧需在编码授权后按相同条件做设计/软件成对对照。

## 5. 设计侧验证结果（2026-11-26）

执行：`node scripts/cr096-design-check.mjs`（真实启动 Chrome、加载唯一入口，两布局分别断言）。机读结果：`docs/Test/screenshots/cr096-design/result.json`。

| 项 | 断言 | 实测 | 结论 |
| --- | --- | --- | --- |
| R1 | 用户气泡与助手正文计算字号同为 12.5px | 侧栏 12.5／12.5；工作台 12.5／12.5 | 通过 |
| R3 | 消息区背景等于面板背景 | 两者 `rgb(255,255,255)`；暗色 `rgb(30,33,38)` | 通过 |
| R4 | 帽子与卡片顶边间距＝边框宽；帽子灰底 | 间距 1px（`cardPadTop:0`、边框 1px）；帽底 `rgb(242,243,245)` | 通过 |
| R2 | 浮框存在、12px、≤232px、摘要可读 | 1 刻度、12px、232px、两行完整文本 | 通过 |
| R2 定位 | 浮框完全落在视口内且在刻度左侧 | left 1160／宽 232／刻度 left 1402；在视口内 | 通过 |
| R5 | 工作台隐藏、其它页签显示 | 工作台 `present:false`；侧栏 `visible:true` | 通过 |
| 暗色 | 字号一致、背景随主题、帽子贴顶 | 12.5／12.5；`rgb(30,33,38)`；间距 1px | 通过 |
| 窄屏 390 | 刻度容器不越界 | left 266／right 386／在视口内 | 通过 |

运行期 JS 异常：0。截图：`01-chat-workbench`、`02-turnnav-label`、`03-composer-hat`、`04-turnnav-dark`、`05-narrow`。

修复记录（本轮实际发生，按时间）：
1. `cr096.css` 原排在 `message-reference.css` 之前，R1/R3 被覆盖 → 调整加载顺序并提高关键规则特异性。
2. `cr096.js` 原包装 `UI.render`，实际被 `main.js` 后续覆盖 → 改为 `MutationObserver` 观察挂载。
3. 浮框原用 `right:calc(100%+8px)`，以容器宽度为基准被横向裁掉 → 改为贴刻度定位。
4. 容器 `overflow-y:auto` + 浮框 `absolute` 时，单轮会话容器仅 28px 高，浮框顶部标题行被纵向裁掉 → 浮框改 `position:fixed` 并由 JS 计算坐标。
5. 容器 `transform:translateY(-50%)` 使 `fixed` 退化为相对容器定位（`left` 被算成 2292px）→ 容器改为 `top:96px` 定位，不再使用 transform。

**未验证项**：设计稿的键盘 Tab 遍历顺序实测、浮框在极端长摘要（>200 字）下的两行省略边界、真实 WebView/Tauri 渲染、软件侧成对对照。上述均不记为通过。
