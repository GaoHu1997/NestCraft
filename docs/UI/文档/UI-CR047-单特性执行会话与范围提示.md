# UI-CR047：单特性执行会话与范围提示

- 版本：UI-CR047-v1（设计说明，配套可操作原型补丁；本轮只锁定“会话归属与范围提示”，不重做 AI 侧栏）。
- 关联：[CR-047](../../PRD/CR-047-单特性执行与需求设计防遗漏.md)、[STORY-068](../../Plan/Story/STORY-068-单特性执行会话与范围门禁.md)、[LLD-CR047](../../LLD/LLD-CR047-单特性工作包与覆盖门禁.md)。
- 依据：2026-11-20 用户“我们本来就是按照特性派发的任务”，要求直接落实平台规则。
- 唯一入口：[仿真原型UI](../仿真原型UI.html) → 项目 → 需求 → 派发预检 / AI 侧栏。旧稿与历史状态不改写。
- 状态：新设计待实现；无视觉验收。原型只补状态展示与仿真交互，不连接真实执行或模型。

## 1. 设计原则

1. 不新增第二个 AI 侧栏、任务平台或并列入口；在既有派发预检、AI 会话头和会话历史增加单一“执行特性”身份。
2. 用户从 Feature 或 Feature 范围内派发时，特性由所选范围直接确定；从 Story 派发时，沿 `parent` 找到其唯一 Feature，预检只读展示，不允许在确认时改选其他 Feature。
3. 一个执行会话最多属于一个 Feature；同一 Feature 可包含多个 Story。切到别的 Feature 必须新建执行会话，不在原会话里“顺手实现”。
4. 视觉以紧凑文本标签与现有令牌呈现，不加厚卡片、不加颜色块；浅深主题、1440×900／1100×700／390×844 均需保持。
5. UI 只是提示与可操作入口；真正的拒绝/继承由服务端 ScopeBinding 与持久字段保证。UI 不能以“标签显示对了”当作门禁通过。

## 2. 受影响的既有界面与状态

| 场景 | 位置 | 变化 | 保留 |
| --- | --- | --- | --- |
| SC-047-01 派发预检（Feature 范围） | 需求 → 行尾菜单 → 派发范围 → 预检弹窗 | 摘要区新增“执行特性 FEAT-xxx · 名称”；显示本 Feature 的 Story 集合；确认按钮文案提示“为 FEAT-xxx 创建执行会话” | 原冻结范围、范围外列表、确认/取消、不自动补前置 |
| SC-047-02 派发预检（Story 范围） | Story → 派发 | 只读显示所属 Feature、来源 Story；若父链缺失/多父/跨项目则阻止确认并说明，不猜测 | 原 Story 准入与排除原因 |
| SC-047-03 派发预检（Epic／全范围） | Epic／当前范围 | 按 Feature 分组列出；每组标明将建立独立执行会话；一次性确认可产生多 Feature 批次，但不能把多个 Feature 放进同一执行会话 | 原批次、并发与预算授权 |
| SC-047-04 AI 会话头（执行会话） | AI 侧栏顶部 | 会话标题下/标题旁增加只读 `FEAT-xxx · 特性名` 标签与“单特性会话”提示；无 Feature 的普通会话显示“普通会话（非研发执行）”，不伪造 | 子智能体/后台/历史/新会话/CLI/权限/模型 |
| SC-047-05 会话历史 | 历史浮层行 | 执行会话行显示 Feature 编号；普通会话显示“普通”；筛选不新增独立页面，沿用搜索/滚动 | 状态点、更新时间、Token、删除确认 |
| SC-047-06 错范围提示 | 执行会话内引用/任务入口 | 若准备把另一 Feature 对象设为执行目标，显示“该会话属于 FEAT-A；FEAT-B 需新建执行会话”，提供明确的“新建执行会话”入口；不自动切换或清空当前草稿 | 原 @ 引用、任务入口、草稿保留 |
| SC-047-07 恢复/重新打开 | 会话重开、项目重开 | 会话头仍显示原 Feature；若 Feature 源已缺失/变更，标“归属源待核验”，允许只读查看与新建会话，不把状态改成无 Feature | 已有消息、草稿、历史 |
| SC-047-08 窄屏／深色 | 390×844、深色 | 标签可截断但 title/aria-label 保留全名；不挤压发送与输入；历史行不横向溢出 | 现有响应式与主题 |

## 3. 文案与可访问性

- 标签：`FEAT-019 · 依赖调度与受管执行`；超长用 ellipsis，`title` 与 `aria-label` 提供全称。
- 会话头提示：`单特性执行会话 · 仅实现本 Feature`；普通会话：`普通会话 · 非研发执行`。
- 错范围：`范围不符：当前会话属于 FEAT-A；FEAT-B 需新建执行会话`；按钮`新建 FEAT-B 执行会话`／`留在当前会话`。
- 预检：`为 FEAT-xxx 创建执行会话`；多 Feature 批次：`将创建 N 个独立执行会话`。
- 状态覆盖：正常、未选择 Feature、Feature 缺失、多父/循环父链、跨项目、源版本变化、运行中锁定、空 Story、长名称、深浅、窄屏。

## 4. 不包含

- 不改会话的普通聊天用途；不强制所有会话都必须有 Feature。
- 不实现跨 Feature 自动拆分后端、真实 runner、持久检查点或证据门禁（分别属于同父/其他 Story）。
- 不在 UI 层替代服务端范围校验；不新增权限或绕过原派发授权。
- 不重画 AI 侧栏整体交互（CR-042 保持）。
