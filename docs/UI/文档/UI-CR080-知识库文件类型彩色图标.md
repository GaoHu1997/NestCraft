# UI-CR080-v1：知识库文件类型彩色图标

- 归属：CR-080／FEAT-008／FEAT-009（知识库）。状态：**仅设计，待确认**；正式软件未修改。
- 可查看设计稿（唯一入口）：[file-type-icons/index.html](../file-type-icons/index.html) — 自包含、无外部依赖，可直接双击打开；浅／深主题可用右上按钮或 `?theme=dark` 切换。
- 证据截图：`docs/Test/screenshots/cr080/`（`v1-light`、`v1-dark`、`zoom-light`、`zoom-dark`）。
- 本项是**增量设计**，不替代 [UI-ICON-001](UI-ICON-001-平台图标与组件基准.md) 的 113 个平台语义图标基准；只覆盖“文件类型标识”这一族。

## 1. 为什么要有这一版

现行 CR-051 §5.2 的文件树图标是 **14 类单色线稿**（24×24、1.6px 描边、`currentColor`），类型只靠描边颜色区分：整棵树在视觉上仍是一排灰线，格式差异弱，且“彩色”只体现在线条色上。

本次用户要求「设计一版文件类型标识的图标，要彩色的」，并把类型范围限定为**知识库实际支持的格式**（不是通用编码项目的扩展名全集）。因此本版把纸面本身做成彩色，用「纸 + 折角 + 白色内容符号」的统一结构承载格式语义。

## 2. 类型集合（按知识库能力矩阵确定）

类型来源：知识库功能手册「支持的格式与能力」表 + 示例库实际出现的格式 + 后端 `kind` 判定。**共 14 类（含目录）**。

| # | 类型 | 扩展名 | 知识库能力 |
| --- | --- | --- | --- |
| 1 | 目录 | — | 容器，不套纸张 |
| 2 | Markdown | md · markdown · mdx | 渲染、可编辑、正文进索引 |
| 3 | 富文本 HTML | html · htm | 可编辑（文档工作区），不执行脚本 |
| 4 | 纯文本 | txt · log · ini · conf | 安全源码阅读、进索引 |
| 5 | JSON | json | 按源码阅读并索引 |
| 6 | CSV / TSV | csv · tsv | 按文本阅读，不是电子表格引擎 |
| 7 | 图片 | png · jpg · jpeg · gif · webp | 受检 MIME 后预览 |
| 8 | PDF | pdf | 元信息 + 导出原件 |
| 9 | Word 文档 | doc · docx · dot · rtf · odt | 元信息 + 导出原件 |
| 10 | Excel 表格 | xls · xlsx · ods | 元信息 + 导出原件 |
| 11 | 演示文稿 | ppt · pptx · pps · pot · odp | 元信息 + 导出原件 |
| 12 | 图纸 | drawio | 元信息 + 导出原件 |
| 13 | 压缩包 | zip · 7z · rar · tar · gz | 导入时解包为文档 |
| 14 | 未知格式 | 其它（如示例库的 `.pos`） | 不阻止上传与索引登记 |

> 与现行 CR-051 的差别：**新增** `html`（富文本，知识库一等公民）、`drawio`（图纸）、`zip`（导入包）；**收窄**不再单列音频／视频／压缩包以外的编码类扩展名（知识库不索引其正文）；`pos` 等归未知。

## 3. 两种呈现变体

同一套 24×24 symbol，只切换“纸面怎么上色”，形状、折角、符号位置完全一致。

| 变体 | 结构 | 适用尺寸 | 推荐场景 |
| --- | --- | --- | --- |
| **A 实底彩色**（`fti-solid`） | 纸面 = 类型色实心；折角 = 白 34%；内容符号 = 白 | 20px 以上 | 文档头、空态大图、类型图例、导入结果 |
| **B 淡底描边**（`fti-soft`） | 纸面 = 类型色 11%（深色 17%）；描边 = 类型色 1.35；符号 = 类型色 | 14–16px | 知识库文件树、会话引用、搜索结果行 |

**推荐混用**：树用 B（密集列表更安静、深色更稳），文档头用 A（远看即分类型）。两变体切换不引起布局变化。

## 4. 图形规范

- 网格 24×24；纸张 16×18、圆角 2；右上 7×7 斜折角。
- 内容符号限制在安全区（约 33%–75% × 44%–77%），不贴边、不压折角；线宽 1.75（24 网格内）。
- **目录不套纸张**：后片 = 类型色 78% 加深，前片 = 类型色，用“容器/内容”区分而非只靠颜色。
- **不用字母砖**：沿用平台规范，不用 W／X／P 这类字母块代替图形。Markdown 的 `M↓` 是 Markdown 标志的几何化轮廓（双峰折线 + 下箭头），属图形；未知格式的 `?` 是唯一允许的符号化例外，与现行 `fileUnknown` 一致。
- **能力不内置**：图标不画锁、眼睛、AI 角标。能否检索／预览由文字徽标表达，避免图标同时承担格式与权限两种语义。

## 5. 类型色令牌（浅色 / 深色）

实施时按 `--ftc-<type>` 并入 tokens。深色不是简单反转，而是提高明度、略降饱和。

| 类型 | 令牌 | 浅色 | 深色 |
| --- | --- | --- | --- |
| 目录 | `--ftc-folder` | `#E9A13B` | `#F2B559` |
| Markdown | `--ftc-md` | `#0FA98E` | `#3BC6AA` |
| 富文本 HTML | `--ftc-html` | `#2E9BC6` | `#5BB8DC` |
| 纯文本 | `--ftc-text` | `#6B7A90` | `#9DABBF` |
| JSON | `--ftc-json` | `#4E65D8` | `#8B9BFF` |
| CSV / TSV | `--ftc-csv` | `#8CAF2E` | `#AEC958` |
| 图片 | `--ftc-image` | `#C75BB5` | `#E08DD2` |
| PDF | `--ftc-pdf` | `#E24C4B` | `#FF8584` |
| Word | `--ftc-word` | `#3B72E8` | `#7FA6FF` |
| Excel | `--ftc-excel` | `#22A05C` | `#4FC489` |
| 演示文稿 | `--ftc-ppt` | `#E25C3D` | `#FF8E70` |
| 图纸 | `--ftc-drawio` | `#8B5CF6` | `#B49CFF` |
| 压缩包 | `--ftc-zip` | `#A8794C` | `#C9A276` |

色相是按“相邻类型不撞色”排布的：琥珀(38°) → 黄绿(76°) → 绿(150°) → 青绿(168°) → 青蓝(199°) → 蓝(221°) → 靛(231°) → 紫(258°) → 品红(307°) → 红(0°) → 橙红(12°) → 棕(32°)。表格家族（Excel／CSV）同绿系靠形状区分，属有意设计。

## 7. 使用规则

- 文件树行 15–16px（B）；文档头 20px（A）；类型说明／空态 32–44px（A）。
- 选中行只换底色与文字色，**图标保留类型色**，不跟着变主色。
- 同一文件在不同位置必须同形：只用“实底／淡底”两个壳切换强度，不改轮廓与符号。
- 未知扩展名回退 `ft-unknown`；不阻止上传、阅读元信息与索引登记。

### 8.1 实施要点（已验证，必读）

- **上色必须用「symbol 内联 `style` + CSS 自定义属性」**，不能靠外部后代选择器（如 `.fti .ft-body{fill:...}`）给 `<use>` 内部元素上色。`<use>` 引用 symbol 后内容位于 shadow tree，外部后代选择器无法稳定命中，实测表现为 icon 整体变黑（退回 SVG 默认 `fill: black`）。
- 正确做法：symbol 内每个图元写 `style="fill:var(--ft-fill);stroke:var(--ft-stroke);stroke-width:var(--ft-sw)…"`；`.fti-solid`／`.fti-soft` 只定义 `--ft-fill`／`--ft-stroke`／`--ft-sw`／`--ft-fold`／`--ft-deep`／`--ft-glyph` 等自定义属性。自定义属性会继承进 shadow tree，`var()` 在其中可解析。
- 变量链：内联 `--ftc:var(--ftc-md)` → `.fti-solid{--ft-fill:var(--ftc)}` → symbol 内 `fill:var(--ft-fill)`。三级任一断裂即显示黑色，可用于自检。
- 若实现方改用「独立 SVG 文件 + `<img>`」或「每类单独 `<svg>` 字符串」，同样按此变量语义落地；不要假设外部 CSS 能穿透 `<use>`。
