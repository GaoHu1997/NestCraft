# UI-CR063：会话历史分批加载与全项目搜索

- 版本：**UI-CR063-v2**，2026-11-22（评审修订版；v1 因加载/失败/删除态缺稿与文字按钮偏离被退回）。
- 状态：设计资源已更新并通过设计侧断言；正式软件按本版实现，待成对视觉对照。
- 确认依据：[CR-063](../../PRD/CR-063-会话历史分批加载与全项目搜索.md)；用户 2026-11-22 选定每批 20 条、全项目搜索模式、仅搜索标题，并授权需求／设计／方案／开发／测试／交付完整闭环。用户原话明确「继续加载」为**文字按钮**。
- 归属：FEAT-011（[STORY-082](../../Plan/Story/STORY-082-会话历史分批加载与搜索.md)）。
- 唯一公开入口：[仿真原型UI](../仿真原型UI.html) → 项目管理 → 预约服务 → 右侧 AI 侧栏 → 历史图标。
- 运行资源：`workbench-v4/ai.js`、`workbench-v4/cr063.css`、`workbench-v4/index.html`、`workbench-v4/data2.js`、`workbench-v4/core.js`、`workbench-v4/main.js`、`workbench-v4/pane-resize.js`。

## 1. 设计目标

1. **打开即可用**：首批 20 条，不因历史总量增长而白屏或卡顿。
2. **继续加载是用户显式动作**：列表末尾的纯文字按钮，不自动加载、不遮挡最后一行。
3. **找得到任何会话**：搜索作用于当前作用域全部会话标题，输入即查；「全部」一键回到逐页浏览。
4. **不迷路**：头部始终显示「已加载 X / 共 Y」；当前会话不在本批时钉在顶部并标注「当前」。
5. **状态不撒谎**：加载中、追加中、搜索中、失败、到底、空态都有明确呈现，失败可重试且不丢已加载内容。

## 3. 规格

### 3.1 搜索行

| 项 | 规格 |
| --- | --- |
| 位置 | 头部下方、列表上方，固定不随列表滚动 |
| 高度 | 约 37px（上下内边距 6/7px + 24px 输入框） |
| 结构 | 放大镜图标（`--muted`）+ 单行输入框 + 「全部」胶囊按钮 |
| 输入框 | 无边框透明底，11.5px；占位「搜索本项目会话标题」；聚焦时 `--primary-line` 边线 + `--surface-2` 底 |
| 「全部」按钮 | 10.5px 胶囊；默认透明底灰字；搜索态下 `--primary-strong` 字 + `--primary-soft` 底 |
| 防抖 | 250ms |
| 键盘 | Tab 可达；输入 Esc 关闭浮层（沿用浮层既有行为） |

### 3.2 头部计数

- 结构为 `已加载 X / 共 Y`，如 `20 / 60`；搜索态为 `匹配数 / 匹配总数`。
- 首批加载中显示 `…`，避免误报 0。
- 计数胶囊与正式软件 `.chat-history-count` 对齐：10px、`--muted`、1px `--line` 边框、8px 圆角、上下 0 / 左右 6px 内边距；不抢占标题层级（评审 N-08）。
- 搜索中（`loading="search"`）计数暂时保留上一轮结果并加 `title` 说明「结果更新中」，不作为最终值（评审 N-14）。

### 3.3 列表与钉住

| 项 | 规格 |
| --- | --- |
| 行结构 | 沿用 CR-042：状态点 + 标题（12px 单行省略）+ 元信息（10.5px）+ 右侧状态文字 + 行内删除 |
| 钉住容器 | 1px `--primary-line` 边、`--primary-soft` 底、`--r-sm` 圆角，容器上缘骑一个「当前」徽标 |
| 徽标 | 「当前」9px 白字、`--primary-strong` 底胶囊，`position:absolute; top:-8px; left:10px` |
| 钉住行状态文字 | 隐藏（徽标已表达「当前」语义），状态颜色仍由状态点表达 |
| 选中 | 当前会话仍用 `.active` 主色底；钉住容器内的 `.active` 不重复描边 |
| 搜索态 | **不显示钉住行**（搜索是明确查找，避免与结果混淆） |

### 3.4 继续加载与到底

| 项 | 规格 |
| --- | --- |
| 继续加载 | **纯文字按钮**：宽 100%、无边框、无底色、11px `--muted`、居中；hover 主色字；聚焦 2px 主色外框（圆角） |
| 文案 | `继续加载 · 还剩 N 条` |
| 追加中 | 同一位置显示「加载中…」，不可点击（`role=status`），不改变布局高度 |
| 已到全部 | 居中 10.5px `--muted` 文案「已到全部」，不可点击 |
| 滚动位置 | 追加后保持原 `scrollTop`，新行在原末尾之后 |

### 3.5 空态、加载与失败

| 状态 | 呈现 |
| --- | --- |
| 首批加载中 | 列表区居中「加载中…」，不显示空态 |
| 搜索中 | 列表区居中「搜索中…」，保留搜索行 |
| 无任何会话 | 「暂无历史会话」 |
| 搜索无匹配 | 「没有匹配的会话」+ 次级「清除搜索」 |
| 加载失败 | 行内错误块（`--danger-bg` 底、`--danger-line` 边）：「加载失败，已加载内容保留」+「重试」；已加载行仍在下方；**失败态与空态互斥**，首批失败（0 行）只显示错误块，不显示「暂无历史会话」 |
| 已到全部 | 「已到全部」 |

### 3.6 行删除（存量能力保留）

- 行内右侧 22px 删除图标，默认 `visibility:hidden`，行 hover 或 `focus-within` 时显示；占位固定，hover 不引发布局跳动。
- 点击弹出确认框，**与正式软件既有 `Confirm` 组件一致**：标题「删除会话」、正文「确定删除「会话标题」？删除后不可恢复。」、按钮「取消 / 确认」，确认按钮使用 `btn danger`（危险操作样式，不等于主色主按钮）。
- 钉住行同样带删除入口；删除当前会话后按既有规则切到剩余第一条。

### 3.7 交互

- 点击行切换会话并收起浮层（沿用 CR-042）；切换后分页状态重置回 20 条。
- 外点、Escape、关闭按钮关闭浮层；关闭即重置为「最近 20 条」并清空关键词。
- 搜索输入 250ms 防抖；IME 组合期间不重绘（设计稿已实现 `compositionstart/end` 防护）。
- 「全部」/「清除搜索」：清空关键词、回到第 1 页、按 20 条重新浏览（正式实现会取一次无关键词首页）。
- 新建会话插入顶部；删除从列表移除；两者不重置分页。

### 3.8 滚动条（UI-SCROLL-001）

- 列表容器仍为 `.ai-history-list`，滚动条默认隐藏外观；实际滚动时显示，停止 **700ms** 后隐藏。
- 新增搜索行与加载/错误块不引入新的滚动容器；不使用 `overflow:hidden` 隐藏滚动条。
- 搜索态与分批态共用同一滚动容器，行为一致。
- 采用规范版本：[UI-CR049](UI-CR049-滚动条按需显示.md) 现行版；验证方式为静止/滚动/连续滚动/停止 700ms 四帧截图（本稿已执行，见 §5）。

## 6. 覆盖缺口与限制

1. **设计稿窄屏限制**：`workbench-v4` 在视口 <960px 时由 `pane-resize` 既有机制收起 AI 侧栏，历史浮层隶属该面板，因此设计稿无法直接呈现窄屏历史抽屉。**已正式收窄 AC-13**：1440×900 做设计与软件成对对照；390×844 只验证正式软件行为（沿用 `chat.css` 既有 `@media (max-width:960px)` 全宽抽屉规则），并单独记录软件截图；`c63-08-narrow-390.png` 仅记录设计稿窄屏收起态，不作为 CR-063 视觉通过证据。
2. **P2「分组（今天/更早）」**：属 CR-054 首期未实现范围，本版不做。
3. **错误态文案**：设计稿采用「加载失败，已加载内容保留 / 重试」，正式软件需保证错误来源（后端 Err）不吞掉原因，可在 `title` 属性提供技术详情。
