## 2. 结构

```text
任务页
├── 页头统计：派发批次 / 子任务 / 执行中 / 等待依赖 / 已交付·待验收
├── 左侧：派发树（一次派发一棵）
│   ├── 根行  [折叠键] [CLI] 标题  · 协调者 · N 个子任务
│   └── 子行  [缩进+连接线] [CLI] 标题 进度 · 工作代理 · 模型
└── 右侧：详情
    ├── 根：派发目标 + 职责 / 本次派发的子任务 / 自身步骤·产物·日志
    └── 子：所属派发面包屑 / 子任务目标 / 步骤·产物·日志
```

- **根的定义**：无父运行者的运行。协调者派发与单层派发都表现为根。
- **子的定义**：`parentId` 指向根的工作代理运行。
- **单层派发**：只有根的树，不渲染子任务区，副标题写「协调者直接执行」。

### 2.1 层级表达

- 根行：折叠键（20px）→ CLI 标识（28px）→ 标题，白底、标题 600 字重。
- 子行：树槽（54px，内含 L 形连接线与缩进，高端 26px 起）→ CLI 标识（24px）→ 标题，浅底形成「本次派发」块，标题 500 字重。
- 同一根下相邻子行之间补一段贯穿竖线，使多个子任务读起来是一条分支而不是若干独立行。
- 连接线使用树专用线色（浅色 `#c3cad3`，深色 `#4a525e`），比普通分隔线更实，避免层级在低对比下发虚。

## 3. 详情

根节点详情自上而下：

1. 头部：CLI 标识、标题、状态标签、`运行号 · Story · 轮次 · 协调者`。
2. 职责框：左侧 3px 主色竖线 + 一句职责，说明本次派发要达成什么。
3. 本次派发的子任务：每行 = CLI 标识 + 任务名 + 一句职责 + 状态标签 + `进度 · 耗时`，整行可点击进入子任务。
4. 协调者自己的步骤条、产物、运行日志、用量与操作按钮。

子节点详情：

1. 头部标注「工作代理」。
2. 面包屑「所属派发 · 根标题」，点击回到根。
3. 子任务职责框、步骤、产物、日志、用量与操作按钮。

## 4. 状态

| 状态 | 树上表现 | 详情表现 |
| --- | --- | --- |
| 运行中 | 状态点常亮 + 「运行中」 | 步骤条当前段高亮，可暂停 |
| 验证中 | 「验证中」紫色标签 | 步骤条停在验证段 |
| 等待依赖 | 保留原位，显示等待原因 | 原因条 + 不可重试 |
| 待验收 | 「待验收」琥珀标签 | 出现「验收通过」 |
| 已交付 | 「已交付」绿色标签 | 只读记录 |
| 失败 | 「失败」红色标签，保留在树中 | 原因 + 「重试原运行」 |
| 折叠 | 根行折叠键转向，子行隐藏 | 详情仍显示当前选中节点 |
| 空项目 | 空态卡：去派发需求 | — |

## 5. 响应式与主题

- 1440×900：左右两栏，树宽约 524px，标题完整显示，状态与耗时右对齐。
- 390×844：树与详情上下堆叠，子任务行隐藏耗时列，无横向滚动。
- 深色主题：沿用既有令牌，连接线与缩进在深色下保持可见对比。
- 折叠键、面包屑、子任务行为按钮保持键盘可达与可见焦点。

## 6. 与既有设计的关系

- **不替代 CR-036**：任务页的壳、页签、统计条、详情容器、操作按钮沿用 CR-036-v 版本；本版只改变任务列表的组织方式与详情的协调区块。
- **承接 CR-037**：协调者与工作代理的角色、答疑与审查属于行为契约（[UI-CR037](UI-CR037-协作场景覆盖.md) 列出的待补场景）；本版先完成「派发树」这一可视结构，问答与决策关口的可视状态仍未制作。
- **与 CR-026 执行计划**：冻结计划、能力预检等仍属于既有执行配置区，本版不改动。
