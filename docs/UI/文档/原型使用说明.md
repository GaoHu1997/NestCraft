# 仿真原型使用说明

## CR-056：AI 侧栏全面重构（当前 AI 侧栏新稿）

[唯一原型](../仿真原型UI.html) → 打开任意编码项目 → 右侧 AI 侧栏。本版按 zcode 风格重做消息时间线：

- 用户消息为右侧紧凑内容块 + 时间行，**不显示头像与「我」前缀**；AI 回复**不显示头像、“AI · CLI/模型”标题**，只保留时间行，以排版区分两侧。
- 思考过程为独立折叠块，默认收起，摘要显示「思考 · 持续 N 秒」；展开后在块内滚动。
- 子代理、工具、审批、系统分别使用独立语义块；子代理行显示任务名、状态、稳定 ID 与 CLI。
- 运行中显示 logo 粒子打散重组指示 +「工作中…」+ 运行时长；供应商限流重试以系统行显示原因、次数与等待时间。
- 回复完成后底部提供复制操作，悬停或键盘聚焦时出现。

逐状态截图可直接用 URL 参数进入，不改变默认打开行为：

| 参数 | 作用 |
|---|---|
| `?demo=ai` | 直接打开项目窗口并展开 AI 侧栏 |
| `?demo=ai&top=1` | 同上，且消息区停在顶部（否则贴底跟随最新消息） |
| `?theme=dark` | 深色主题；与上面参数可组合 |

同条件设计截图：`docs/Test/screenshots/ui-cr056-timeline-light.png`、`ui-cr056-timeline-dark.png`（1440×900）。运行态 logo 动效可单独查看 [logo 预览](thinking-indicator-preview.html) 与 `ai-thinking-logo.gif`。全部为合成夹具，不联网、不调用真实 CLI 或模型。

## CR-043：办公文件树与统一AI（当前办公新稿）

[唯一原型](../仿真原型UI.html) → 项目管理 → 办公 → 市场研究资料／品牌与官网。左侧为可折叠目录树：选中根或文件夹，点击顶部文件夹图标创建子目录；`+`在该目录新建文件，上传图标添加资料。搜索展示祖先路径，清空恢复树。文件状态仍区分原件、草稿及保存版本。

## CR-036：公共壳及编码等模块（UI-CR036-v2）

打开[唯一公开原型](../仿真原型UI.html)（进入 `workbench-v4/`）。编码项目窗口顶部为需求／设计／任务／编码页签，办公项目依上方CR-038。内容与左右为同一白色面，无页头、无卡片边框。

- **工作台**：默认页。看运行中、等待依赖、已完成、待处理与最近完成／知识。
- **项目管理**：卡片网格；点击卡片或「打开」进入，右上铅笔改项目；新建时用「浏览…」选择本地目录（仿真目录树），不是手填路径；顶部可按编码／办公过滤。
- **项目·需求**：树占满整宽；行尾 `...` 打开菜单：史诗／特性可“新增下级”，全部可编辑、派发、删除；详情、表单、删除确认都是固定尺寸弹窗。
- **项目·设计**：左侧极窄图标栏（悬停显示名称）切换 PRD／UI／方案／模型，右侧目录可收起，目录顶部是文档信息；可编辑并保存、导出 Markdown。
- **项目·任务**：行首是实际执行 CLI 标识；可暂停、验收、查看运行记录。
- **项目·编码**：左侧菜单切「资源管理／Git 管理」，右为代码；可编辑保存。Git 面板支持勾选暂存、AI 生成提交信息、提交、提取／更新／推送、新建分支、查看历史。
- **AI 侧栏**：左边缘拖动改宽；顶部依次为历史、子智能体数、后台任务数、新会话；点历史打开覆盖在侧栏左侧的会话浮层（点其他位置自动收起），点子智能体／后台任务在按钮下方展开下拉悬浮框而不是弹窗；输入区 `＋` 打开添加／指令浮层，`@` 引用文件／对话／知识，`/` 调用 Skill／MCP／Tool；`＋` 右侧依次是 CLI（只列已安装）、权限（默认／规划／代理／自动审批／全自动）、模型（模型行末尾依次显示上下文／视觉／思考，生图模型不列出）；生成中再次发送按设置里的“立即发送／排队”处理；三统计在输入框下方，点开时弹层右对齐并贴住各自控件；分步骤执行时消息区显示等宽折叠框，区分执行中／已完成／未开始／失败。当前 AI 侧栏版本见 [UI-CR042](UI-CR042-AI侧栏交互细节.md)。
- **知识库**：卡片上「授权」可多选项目或对所有项目开放；进入后左树按目录展示多格式文件，中间按格式预览，右侧是页内目录或文件信息。
- **服务器**：满高三栏：文件树、终端（`help`/`uptime`/`free -h`/`df -h`/`ls`/`whoami`/`systemctl status`，其余拒绝）、实时监控。
- **设置**：点击左下头像／设置入口打开固定 1040×700 弹窗；通用（用户信息、代码样式预览、服务器、发送行为）、模型（卡片内联展开；获取模型勾选；模型行展开模态/思考并可自动配置；多密钥悬停改协议/模型/别名；多端点/请求头/伪装）、SDK 与 CLI（双 tab；SDK 为可展开卡片）、Skill／MCP／Tools（可添加导入，二级弹窗覆盖在设置之上）。
- **边界**：全部为虚构夹具，不联网、不调用真实 CLI／SSH／Git／模型；导出只生成本地 Markdown；正式软件未修改。

## CR-035：历史可操作稿（UI-CR035-v1，已由 CR-036 继续）

打开[唯一公开原型](../仿真原型UI.html)（自动进入 `workbench-v4/`）。

- **管理首页**：项目管理／知识库／服务器管理三个管理页固定；点击项目、知识库、服务器、设置会在独立窗口打开。只有首页、未打开对象时**不显示窗口页签条**；打开对象后内容区顶部出现 40px 胶囊页签条（首页 + 各对象 + 「全部窗口」），可切换与关闭，同一对象只聚焦原窗口。

- **外观**：右上角切换浅／深主题；390 宽度下顶栏菜单按钮打开侧栏。
- **诚实边界**：全部数据为虚构夹具；不联网、不调用真实 CLI／SSH／Git／模型，不写入正式数据库。设计待评审，正式软件未修改。

## 调度方案与边界

- 纯经典 JavaScript IIFE 挂载 `globalThis.TaskReviewScheduler`，浏览器使用普通 script；Node 直接 import 文件取得 global，无 ES 模块网络加载或 fetch。
- 确定性 `tick` 处理领取、模拟执行、验证、串行集成、产物记录与依赖消费。浏览器单一自动计时器持续推进；暂停后可单步调试。每个回调携带 epoch，重置、恢复、暂停或取消废弃旧代际。
- 业务父树与显式执行 DAG 分离。前置成功、验证及适用集成通过、存在已记录产物 revision 才可消费；CLI 模拟 exit 0 不直接成功。每任务独立样例工作区；全局并发与资源锁同时校验，集成队列串行。
- 范围与 requirement/design/AC hashes 冻结，活动基线与幂等键拒绝重复派发；未选项不改写，新需求不自动进入批次。需求修订、模型或权限失效只停止相关分支；单纯代码 HEAD 推进不使所有无关任务失效。
- `artifacts` 表示当前产物，`artifactHistory` 按 revision 保存已交付历史。需求修订使当前产物失效，不抹除旧任务与当次交付报告；从旧任务定位编码时仍展示该任务的产物修订。
- 暂时故障与验证返工均有上限，每次尝试保留独立记录。失败/取消不等于成功，后代阻塞，独立任务继续；预算按仿真单位止损，真实账单与真实 usage 均未知。
- Task 使用契约规定的 13 种状态，Batch 聚合为 running / succeeded / partial / failed / cancelled。Task succeeded 默认只使对应 DEMO Story 到待验收；显式客观自动验收演示模式且证据条件满足时才能将 DEMO Story 标完成。
- 评审页面里的 CLI、Git、SHA、路径、任务验证日志、费用与产物内容均为样例；页面运行时不读取/修改正式 Story，不创建 worktree、不运行 AI CLI、不联网、不合并、不安装依赖、不启动服务器。代理按本次指令只读需求与代码，Node / Chrome 检查是实际执行的专属验证。
- 本机 localStorage 仅保存评审快照，不是 daemon；关页停止仿真，恢复后只启动一个计时器，不承诺主机重启后继续执行。存储异常时退回内存，不阻塞操作。

| API | 参数与结果 |
| --- | --- |
| `createState({scenario, policy}?)` | 生成独立空 DEMO 状态，分配新 epoch；不派发、不创建计时器 |
| `preflight(state, scope?, policyOverrides?)` | 返回 `ok / frozen / excluded / errors / policy / fingerprint / idempotencyKey`，不启动任务；scope 为 `{type:'project'}`，或 `{type:'story'/'feature'/'epic', id, projectId?}` |
| `dispatch(state, previewOrScope?)` | 复检冻结范围，返回 `{ok, state, batchId?, preview, replayed?, error?, code?}`；同键同请求返回原批次且状态不变，同键异请求返回 `IDEMPOTENCY_MISMATCH`，活动任务、失效授权、循环均不会重复创建写任务 |
| `tick(state, expectedEpoch?)` | 当前代际推进一个确定性调度步；CLI → 验证 → 适用集成 → 记录产物 → 消费放行 |
| `pause(state, target?)` | 暂停 `all`、批次 ID、任务 ID 或 DEMO Story ID；保留现有槽与资源归属，废弃旧代际 |
| `resume(state, target?)` | 继续指定对象并复核基线与执行配置，使用新代际 |
| `cancel(state, target?)` | 取消指定未终结对象、释放资源、阻塞后代、保留历史；不把取消当成功 |
| `inject(state, event)` | 仅评审注入：`requirement-change / design-change / network-failure / verification-failure / cancel-parent / model-disabled / permission-disabled / code-head`；按需携带 `storyId / cli / model / permission / count` |
| `snapshot(state)` | 返回 `{version:1, source, state}` 的可序列化快照，不读写存储 |
| `restore(snapshot)` | 校验状态、关系、锁、预算、代际、历史产物后返回新 epoch；损坏快照抛错，界面退回空样例；不创建计时器 |
| `invariantErrors(state)` | 返回非法状态、并发越界、互斥/集成归属错误或成功产物证据缺失列表 |

`TASK_STATES`、`BATCH_STATES` 导出完整允许集。状态包含冻结需求、批次、任务、步骤、每次尝试、日志、当前/历史产物、消费修订、资源锁、样例工作区及未知真实用量。

界面调试入口 `window.TaskReviewApp` 仅提供 `getState / getUI / reset / debugStep / setIntervalForReview(30～5000ms) / getTimerInfo / getScheduledCallback / storageKey`。测试保存旧 callback 后重置/暂停/取消，直接调用旧 callback 验证不会继续写状态。正常操作不需调试入口。
