### 主题令牌契约（现行实现规范）

- **组件只引用变量，不写死颜色**。原型 `<style>` 与三处内联样式块（integration / settings / float）已全部令牌化，审计结果为 **0 处非令牌颜色**（品牌标识色 `#c96442/#10a37f/#383d44/#faeee9/#e8f6f1` 按 SDK 语义保留）。
- 颜色令牌：`--base --paper --nav --line --line-soft --ink --muted --accent --accent-dark --accent-ink --accent-ink-soft --accent-line --soft --purple --purple-bg --warn(-bg/-line/-deep/-dot) --danger(-bg/-line/-deep) --bad-dot --good-ink --good-dot --blue-bg --blue-ink --blue-dot --violet-dot --neutral-dot --tag-bg --tag-ink --panel-2 --inset --segment-bg --hover-bg --hover-line --input-line --empty-line --nav-active-bg --nav-active-ink --avatar-bg --avatar-ink --demo-ink --notice-bg --notice-ink --notice-line --progress-bg --msg-bg --approval-bg --approval-line --code-bg --gutter-ink --slide-bg --slide-line --th-bg --term-bg --term-ink --term-input --term-line --switch-off --switch-knob --toast-bg --toast-ink --backdrop --shadow-sm --shadow-md --node-sel-line --node-sel-bg --summary-bg --attach-bg --chip-line --chip-bg --suggest-sel-line --vtab-bg --vtab-sel-line --branch-line --branch-bg --diff-bg --pre-bg --focus`。
- 阅读面令牌：`--reader-bg --reader-ink --reader-line --reader-th --reader-th-ink --reader-btn-line`，两主题取值相同（白纸观感），供 Office 预览使用。
- 形状与排版：`--radius-card --radius-ctl --font-title`；标题使用衬线字体，正文使用系统无衬线。
- 覆盖顺序：先 `:root` 定义浅色，再用 `html[data-theme=dark]` 覆盖同名令牌；所有覆盖规则集中在样式表末尾，避免同特异性下被前面的规则反超。
- 切换只影响视觉：不重置会话、授权、Git 与审批状态；`notify` 明确提示"仅外观，业务数据不变"。

### 深色可读性规则

- Office 文档 / 表格 / 幻灯片预览在深色下仍是白底阅读面（`--reader-*`），表头、单元格按钮同步使用阅读面配色，不出现深底浅字。
- 侧栏、面板、卡片、弹框、浮层、终端、代码块均使用各自令牌，深色下保持分层（底 < 面板 < 卡片）。

### 验证与状态

- 对比件为单文件无依赖，双击可开；`?t=paper|studio|glass|enterprise|editorial|now` 直达任一方向。
- 落地验证：8 条路由 × 2 视口（1440×900 / 390×844）切换浅深往返正常、`aria-pressed` 正确、无横向溢出、无脚本异常、无外部请求；偏好刷新后保留；[prototype-smoke](../../Test/prototype-smoke.mjs) 80/80 组通过、[design-docs-check](../../Test/design-docs-check.mjs) 通过。详见 [REPORT-003](../../Test/REPORT-003-统一工作台设计验证.md)。

## v3.0：设置中心与模型设置

关联 [STORY-023](../../Plan/Story/STORY-023-设置中心弹框与菜单重组.md)、[STORY-024](../../Plan/Story/STORY-024-模型设置供应商卡与会话模型切换.md)、[STORY-025](../../Plan/Story/STORY-025-SDK装卸与已安装CLI过滤.md)。本节为 v3.0 交互基线，实际验证见 [REPORT-006](../../Test/REPORT-006-设置中心与模型SDK验证.md)，尚未用户验收。

- **设置弹框**：左下角只显示一个「设置与账户」入口。打开覆盖当前页面，不跳路由；基础设置、模型设置、SDK 管理、Skill、MCP、Tool 六项独立。1440×900 和 390×844 下弹框宽、高各不超过视口的 70%；窄屏可用单列、菜单横向滚动、内容框内纵向滚动，不把整页撑宽。关闭按钮与 Escape 返回原页面并将焦点交回入口。旧 `#settings/*` 与旧设置编号书签回项目主页，其它数字书签不重排。
- **模型设置**：每行一张供应商卡，展示名称、协议、可用状态、端点/密钥与模型数量，可禁用/启用、编辑、删除（行内确认）。编辑向下展开，按供应商配置、模型配置、高级配置、指纹检测四个 tab 切换。支持多密钥和多端点，密钥按掩码展示；模型可配文本、视觉、生图能力和思考等级；非法组合显示校验错误。指纹状态显示检测中与结果，标明无真实请求。
- **会话切换**：输入框旁模型按钮显示「模型 · 思考等级」。同一个浮层呈现供应商、模型和思考等级，选完模型可继续选档位；Claude 对应 Anthropic，Codex/Grok 对应 OpenAI。候选只含启用供应商下有有效密钥及端点、具备文本且非生图的兼容模型。切换模型或档位保留消息和会话 ID；切 CLI 沿用既有确认与新会话流程。已选项失效保留原选择并说明原因，禁止发送，不自动回落。
- **SDK**：仅显示 Codex、Claude、Grok，提供仿真安装、更新、卸载；清楚区分未安装、作业进行中、失败与已安装，失败不覆盖上次成功状态。会话只列已安装并启用的 CLI，卸载后立即移出切换列表。SDK 与模型设置不使用网络、真实凭证或数据库。

### 页面布局

```text
code 需求与迭代
├── 页头：迭代/状态摘要、预览、设计稿、新建 Story
├── 整个需求内容区：单棵树（不拆目录栏和详情栏）
│   └── 愿景 → Epic → Feature → Story / Bug
│       每行：展开按钮、编号、标题、类型/负责人/状态、查看详情
└── 右侧 AI（头部右上：新建会话 / 会话历史）
    ├── 消息、工具结果、引用、待审提案
    └── 输入区：左上 +；@ /候选；附件 chips；左下 CLI；右下发送
```

- **需求树**：展开和查看独立；详情不常驻。原生弹窗可读愿景/Epic/Feature/Story/Bug，Story 详细字段含背景、目标、范围、不包含、主流程/异常、规则、AC、依赖、设计/交付、验证与变更；编辑/验证/状态动作在弹窗内，避免嵌套模态。关弹窗保留树选择和展开；打开产物关闭弹窗并进入编码，可返回原 Story。
- **预览**：一个连续页面展示所有层级正文，可定位节点、返回详情；来自同一源而非维护第二份需求。正式采用 Markdown 文档生成；本轮内存样例不解析仓库文档。
- **设计稿**：项目适用仿真页面目录，研发与办公分别列适用页面；总览作为一站式入口、不自动回跳，旧页码兼容。设计资源标版本与仿真边界，不把跳到正式业务运行页当已交付设计稿。
- **办公/编码/运维**：既有资料/内容/AI 和文件/终端/AI 布局不变；work 不显示研发需求树。

### 知识库与权限反馈

- 管理卡片显示名称、样例资料数、已授权项目、“项目授权”和“查看目录”。所有者可见全部库；项目 AI 仅见当前已授权库，不暴露其他库摘要/数量。未选项目显示“无 · 默认不可用”。
- 授权弹窗多选，保存生效、取消保持；只读权限明示，不附带修改/删除。目录可关键词搜索和只读预览，项目 AI 通过工具搜索/读取并展示来源版本。
- 引用卡有库/笔记ID、标题、路径别名、版本和片段；点击再次校验权限，支持同库关联资料。正式长文显示完整/分页/截断，不掩盖内容不全。
- 撤权、停用或无权引用给明确不可用反馈，清理可发送引用，不将旧正文重放；已显示历史不假称收回。真实原生线程的安全终止/重建不由原型证明。

### AI 侧栏交互

- 新建保留旧会话；历史按项目或主机分组，显示标题/CLI/更新时间，恢复草稿、消息、附件引用。code 需求/编码共用项目会话，跨项目或主机不可恢复。
- + 菜单提供本地文件、项目文件/需求/知识上下文。本轮选文件只记录名称/大小/类型，显示“未读正文、未上传”的仿真说明；移除 chip 不发送内容。正式上传/parsing/ready/failed 状态独立。
- @候选只含本项目和授权对象；/候选区分技能/客户端命令/MCP prompt并检查开关。上下键、Enter 选择，Escape 关闭；IME 不误发送。普通输入不是执行命令，参数与来源需结构化解析。
- CLI 位于输入左下，模型与思考来源统一设置；无可用/不兼容时给原因和修复入口，不静默换目标。非空会话切 CLI 需确认新建，取消保持；待审或运行禁切。仿真兼容状态不得显示为真实 CLI 已验证。
- 设置默认值与会话选择明确分开；能力停用影响全部引擎和旧审批，模型运行快照与安全即时撤销规则按 LLD。

### 状态、可访问性与评审入口

| 状态 | 可观察反馈 |
| --- | --- |
| 加载/同步 | 正式文档索引或上传显示处理中，不假报可用；原型数据即时内存渲染 |
| 空需求/空资料/空历史 | 明确空态及新建/选上下文入口，上层正文仍可看 |
| 无命中 | 搜索成功但为空，区别于工具失败 |
| 无授权/被撤权/禁用 | 不显示被拒对象内容，说明不可用和修复入口 |
| 取消/拒绝/冲突 | 原值保持或旧提案失效，不自动写入、重放或换引擎 |
| 长文/窄屏 | 内容可换行，弹窗内部滚动；390px纵向排版、不整页横向溢出 |

## 3. 关键交互定义（旧静态稿历史基线）

设置入口、菜单、模型与 CLI 的现行交互以 v3.0 节为准。

1. **全局框架**：左侧栏固定；「设置」仅作入口（无子项常驻），点击进入设置视图；设置视图左侧并列菜单切换模型 / SDK / 能力管理。设置页与侧边栏入口状态同步高亮。
2. **项目管理 → 项目**：点击卡片进入工作区；code 直达编码页；work 默认落在「设计」tab；顶部「←」返回项目管理。
3. **work 双 tab**：设计 / 编码切换保留项目上下文。
4. **敏捷闭环（设计 tab，闭环规则对应 AGENTS.md）**：
   - 迭代概览条：当前迭代周期、进度（完成 Story 占比）、各状态数量 chips；数据随树状态自动汇总。
   - 需求树：Epic → Feature → Story 三级，Bug 挂在 Feature 下；节点 = 展开箭头 + 状态点 + 编号 + 标题 + 状态文字；底部图例（8 状态 + 缺陷）。
   - 详情：目标 → 验收标准（AC 编号 + 给定/当/则 + 勾选态）→ 关联与交付（PRD / 参考 / 知识库 / 交付物）→ 验证记录（AC 验证方式、结果、日期、阻塞 BUG）→ 操作（AI 协助 / 编辑 / 推进下一状态）。推进按钮驱动状态流转；存在未解决阻塞时禁止推进到「已完成」。
   - AI 助手可：生成/拆解需求、生成 AC、产出交付物（写入编码页）、更新 Story 状态（需确认）。
5. **服务器闭环**：
   - 授权模型：服务器卡片级「AI 可操作」开关；启用后注册为 ssh-exec 工具（能力 · Tools 中可见，关联服务器管理）。
   - 手动操作：工作台内终端（PTY）与文件树、SFTP 入口。
   - AI 运维：任务式对话（/巡检、/日志分析、/部署发布），每条命令以工具卡片展示（命令 + 结果摘要）；风险分级——高（重启/删除/变更配置）必须人工确认后执行。
   - 指标条：CPU / 内存 / 磁盘 / 负载，随终端会话刷新。
6. **AI 助手面板**（各工作区共用结构，340px）：头部（面板名 + 模型/思考等级选择器 + 新建会话）；消息流（用户气泡、工具卡片、diff 卡片、知识库引用卡、图表卡、确认卡）；输入区（Skill /命令快捷、MCP 提示、权限模式、上下文用量、发送）。模型与思考等级数据来自设置 · 模型管理。
7. **文件预览（编码 tab）**：按扩展名渲染——代码/md 编辑器视图；docx/pdf 文档视图；xlsx 表格视图（公式条 + sheet 页）；pptx 幻灯片视图（待补充样图）。工具栏标注渲染来源（office-sdk / code-sdk）。

### 项目工作台

- 页签：需求、设计、编码；项目标题行保留负责人、迭代与项目信息入口；愿景在项目信息弹框中查看，不在需求树。
- 需求：单列树，只含史诗（珊瑚方块闪电）、特性（紫色方块书本）、用户故事（青色书签），行高约 56px、细分隔线、编号常显；悬浮或键盘聚焦显示"新建特性/新建用户故事"与编辑、删除；页头只有预览与新建史诗。
- 需求与 AI 会话是两个独立区域，AI 侧栏占满可用高度；空会话只显示标题条、居中空状态与输入区，草稿工具仅在存在未同步差异时出现。
- 预览：史诗 h1、特性 h2、用户故事 h3 连续正文，正文右侧目录，页面右侧仍保留 AI 会话。
- 设计：44px 图标竖栏，仅"UI 设计""模型设计"，悬浮显示名称；UI 稿直接在中间以隔离画布渲染，右上可外部打开；模型设计逐表展示描述与字段表（字段名、类型、PK/FK、备注），右侧浮动表目录一一对应，可编辑并生成 Markdown。
- 编码：资源管理器 + 文件页签 + 行号编辑器 + 满高会话，底部状态条显示文件数与编码格式。
- Git：未提交（复选框、状态字母、路径、提交说明、AI 生成、提交）占两份高度并固定提交框；分支（搜索、新建、展开折叠、本地/远程分组）一份；提交历史（图谱、标题、引用徽章、作者、时间）两份；三段各自滚动。

### 服务器工作台

- 顶部标签条 `SSH / shell 1 / +` 与连接、断开操作；左栏文件树与 SFTP 目录；中间终端（欢迎信息、命令输入、快捷命令）；右栏"实时监控 | AI 助手"。
- 监控卡：系统、主机名、IP、架构、启动、运行时长；CPU 使用率（总览、趋势条、每核条形，默认 6 核并可展开）；内存使用。指标为演示值，不连接真实主机。

### 设置中心

- 基础设置：用户信息（昵称、邮箱、头像字母）、外观（浅色/深色/跟随系统）、代码样式（字号、缩进、行号、换行）。
- 模型设置：供应商行卡（拖柄、名称、自定义、状态点、开关、编辑、删除）；编辑区四页签；供应商页密钥表 + 显示名称 + 协议分段 + API 地址；模型页折叠行 + 恢复默认/获取可用/自动获取（仿真）+ 模态 + 思考档位 + 映射 + 默认强度 + 上下文窗口与最大输出；高级页请求头与请求伪装；指纹页逐模型检测与折叠结果。
- SDK 管理：registry 输入、全部重新检测、内置子代理只读提示、三个可展开 CLI 版本卡（版本箭头、徽章、目标版本、当前/卸载/重检、路径）。
- Skill/MCP/Tool：开关后不加文字，保留无障碍名称；Skill 与 MCP 支持创建并校验必填与重名。
