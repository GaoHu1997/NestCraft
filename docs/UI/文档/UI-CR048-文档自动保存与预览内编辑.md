## 2. 视觉与状态

- 正文沿用白蓝／深色主题，贯通主区，细分隔线。无外围表单边框、无整页语法输入框；获得焦点不把文档替换成另一块textarea。
- 格式工具条提供加粗／斜体／标题／正文／列表／代码及撤销重做；真实选区保持，按钮可键盘聚焦。源码文件用等宽编辑器；Markdown用正常文档字体。
- 轻量状态区分「已自动保存」「自动保存待处理」「正在自动保存…」「保存失败 · 内容已保留」「保存冲突 · 内容已保留」。成功不弹通知；失败有正文内错误和重试，冲突重试不能绕过基线检查。
- 新知识文件名只在Enter或失焦表示确认后自动创建。非法／重名保留输入、没有首保存按钮，未创建对象可放弃。
- 适用场景覆盖加载／空源／缺源、只读、无权拒写、新建未命名、重名、失败、冲突、成功、切换、撤销和选区。无源不能假设空白然后覆盖。正文格式兼容以本轮验证的基础子集为限，复杂扩展语法另需成熟引擎验证。
- 检查1440×900、1100×700、390×844，100%缩放；浏览器为隔离Chrome。设计图片与软件图片不混用，本批无软件成对证据。

## 3. 版本与保护

[公共样式](../workbench-v4/live-doc.css)只用现行令牌。源块保原Markdown分隔与原始字节：没改过的块不因自动保存统一重排。每个编辑器使用稳定范围／对象ID和独立队列，不使用`code-active`或`knowledge-active`共享身份；输入法组合期间不提交中间态。

原型仅在内存改变合成内容，不读本机源、云端、私密知识或正式业务。刷新丢失是演示限制，不冒充真正文件持久化、Office解析／格式保真、后台保存或崩溃恢复。

## 4. 替代与继承

本版只替代CR-045的正文编辑／显式保存以及CR-027/038的类似写作流程。已有文件根、上传、AI知识只读权限、需求审批、元信息表单、派发预检和关联同步不变。知识「阅读／编辑」是用户允许的防误改例外，不是「先点编辑再写源码」。此前源码恢复方案撤回。

软件准入还需独立Feature执行包、正式实现方案／数据结论、编码授权及逐场景对照，不能把本版原型操作直接记为正式AC通过。
