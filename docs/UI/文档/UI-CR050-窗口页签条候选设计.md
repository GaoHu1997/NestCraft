## 1. 诉求与问题诊断

现状（[对照图 00-current](../tab-redesign/figures/00-current.png)）：顶栏 56px 之下是一条 40px 全宽页签条，`--surface-2` 灰底 + 底边框，最左一个 88px 白色块「首页」，蓝字与 2px 蓝色下边线，右侧约 1300px 空白。

逐项原因：

| # | 现象 | 原因 |
| --- | --- | --- |
| 1 | 空条像未完成 | 条带高 40px 只为 1 个页签服务，其余 95% 是底色 |
| 2 | 白块浮在灰条上 | 文件夹式页签（圆角上沿 + 底部连体）假设下方是白色内容；首页时下方是 `--bg` 灰底，连体关系不成立 |
| 3 | 与整体语言冲突 | 全界面是扁平分栏 + 细线，唯独页签条用浏览器隐喻的抬升块 |
| 4 | 层级混在一起 | 「首页」是常驻管理首页，对象是打开的窗口，二者同权平铺 |
| 5 | 两段信息重复 | 面包屑已写「个人工作台 / 工作台」，页签再写「首页」 |
| 6 | 横跨侧栏 | 条带压在 224px 工作空间导航上方，与下方内容错位 |

## 2. 设计目标与硬约束

目标：单页签时不空、不丑；多页签时仍能一眼扫、能关、能收；不新增业务功能。

必须保持（来自 CR-033／CR-044）：首页固定且不可关闭；同一对象重复打开只激活原窗口；对象页签可关闭且有未保存/运行中关闭保护；页签可键盘聚焦与切换；溢出不得出现横向滚动条（按 UI-SCROLL-001 用「更多」+ 下拉）。

本次候选稿统一覆盖：1440 宽、1024 窄屏、深色主题、仅首页／1 对象／4 对象／8 对象溢出、对象激活（侧栏隐藏）。

## 3. 五版方案

### 方案 A｜细线页签（最小改动）

- 结构：位置不变（仍全宽、在侧栏上方），40→34px；去掉灰底与白块，改白底 + 底部 1px 线。
- 选中：主色文字 + 2px 主色底线（left/right 各内缩 8px）；首页与对象之间加 1px、14px 高竖分隔。
- 关闭：对象页签 hover／选中显示 16px ×；首页无关闭。
- 单页签：右侧显示一句极弱提示「打开对象后在此切换」（11.5px，`--muted-2`）。
- 取舍：改动最小、风险最低；但仍是常驻 34px，单页签时靠提示文案撑场面。

### 方案 B｜按需出现

- 结构：**没打开对象时整条不渲染**，内容直接接顶栏；打开对象后在内容区顶部出现 36px 页签条（`main` 内，不与侧栏错位）。
- 第一个页签固定为「首页」（home 图标 + 文字，点击回首页），其后是对象页签；对象全部关闭时条带回退为无。
- 侧栏：仅当当前窗口是对象时隐藏（沿用 `object-detail` 行为）；在首页时保留。
- 取舍：单页签问题彻底消失，最接近专业桌面工具；代价是打开／关闭首个对象时布局上下位移，「首页」的窗口身份变弱。

### 方案 C｜工作区胶囊栏

- 结构：条带移入内容区，44px 白底；首页与对象统一为 28px 胶囊。
- 选中：**只做文字与图标高亮**——`--primary-strong` 文字 + 600 字重 + 图标主色；不加底色、不加边框、不加下划线（用户 2026-11-21「页签高亮显示即可，不要框起来」「限制区域的底色不算框？」）；未选中纯文字，hover `--surface-3`；首页后加竖分隔。
- 右侧工具区：仅首页时一句提示；有对象时「全部窗口 N」按钮（打开全部页签下拉）。
- 取舍：一个胶囊也成立、可点面积大；代价是 44px 最高，密集多页签时略挤，右侧工具区需定义真实行为。

### 方案 D｜窗口切换器（无页签条）

- 结构：删除页签条。仅首页时顶栏与现状完全一致。
- 打开对象后：面包屑变为 `个人工作台 / 首页 / 预约服务 ⌄`；「首页」可点返回，对象名点击展开全部窗口下拉；右上角 layers 图标带窗口数。
- 取舍：零占位、信息密度最低；代价是切换两次点击、并行多对象时看不到全貌、关闭入口藏在展开层。

### 方案 E｜按需胶囊（B + C 组合，推荐）

- 结构：首页状态无条带（同 B）；打开对象后出现 40px 胶囊条（同 C 的形态，26px 胶囊）。
- 差异于 C：条带只在有对象时出现，因此「单页签空条」和「44px 常驻」两个代价同时消掉。
- 取舍：推荐理由见 §6；代价同 B 的一次布局位移，以及「全部窗口」需要定义行为（仅溢出时出现，或作为列表入口）。

## 6. 采用决定与实现

**采用方案 E**（用户 2026-11-21「先按照 e 调整吧」）。实现范围仅限仿真原型，正式软件未改。

原型实现（`docs/UI/workbench-v4/`）：

| 项 | 内容 |
| --- | --- |
| 结构 | `core.js` 的 `tabbar()` 改为「无对象返回空串」；`render()` 把页签条放进 `.main` 顶部，并切换 `body.has-window-tabs / no-window-tabs` |
| 样式 | 新增 `window-tabs.css`：40px 白底、26px 胶囊位；选中只做文字/图标高亮（`--primary-strong` + 600），**无底色、无边框、无下划线**；首页后竖分隔、右侧「全部窗口 N」；`overflow:hidden` 不出现横向滚动条 |
| 交互 | 新增 `window-tabs.js`：全部窗口下拉（列表、当前项打勾、Escape 关闭、点击外部关闭）；切换与关闭仍走原有 `switch-window` / `close-window`，关闭保护不变 |
| 高度 | `body.no-window-tabs { --tabbar-h: 0px }`，使沿用 `calc(100vh - var(--topbar-h) - var(--tabbar-h))` 的知识库、办公、项目面板在无条时不多减 40px |
| 入口 | `index.html` 末尾引入两个新文件，顺序位于 `live-doc*` 之后，覆盖 `cr044.css` 的旧条带规则；未改动旧 CSS 文件 |

行为：只有首页时不渲染整条；打开第一个对象时出现；关闭到 0 个对象时消失；首页固定、不可关闭；对象页签可关闭并保留原关闭确认；侧栏只在当前窗口是对象时隐藏。

## 7. 边界与本轮未做

- 已修改原型：`workbench-v4/core.js`、`workbench-v4/index.html`，新增 `window-tabs.css`、`window-tabs.js`；未改 `src/` 正式源码、依赖或构建产物。
- 未新增 Story／AC，未改需求基线；正式软件实现仍需单独编码授权。
- 交互只演示页签切换、关闭确认、全部窗口下拉与主题；不读写正式存储、不联网、不调用真实 CLI。
- 与并行 CR-052「页签溢出统一规则」的关系：其 `tab-overflow.js` 已由并行会话接入 `index.html`，实测在当前窗口页签条上不误隐藏、不报错，`scrollWidth === clientWidth`；极端窄屏下如页签继续收缩仍可能同时出现「更多」与「全部窗口」两个入口，后续应合并为一个。
- 工作区同时存在并行会话的未提交改动（CR-051 内联 sprite、CR-052、CR-037）；本轮只改 `core.js` 的 `tabbar()`/`render()` 与 `index.html` 两行引用，未覆盖其逻辑。
