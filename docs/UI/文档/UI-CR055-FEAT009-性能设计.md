## 阅读留存分账、目录复核与焦点（v1.4 行为补充）

本节补充交互行为与用户可见提示，不改变三栏布局、颜色或组件外观；新增两个提示状态已落在 `docs/UI/performance-knowledge/index.html`（SHA 同上）。

### 留存分账与载入准入（R02）

| 类别 | 计入内容 | 是否可淘汰 |
| --- | --- | --- |
| 清洁正文（clean） | 已读取的 Markdown/文本/图片正文与元信息，按 UTF-16 与 base64 实际长度估算 | 可淘汰；当前可见文件与 dirty 草稿对应原件除外 |
| 草稿正文（draft） | 所有 `drafts` 的标题/正文 UTF-16 字节加固定元数据开销 | 未落地（新建）或 dirty 的草稿不可淘汰；已保存且无未提交修改的草稿可淘汰并回落到原件 |
| 正文 DOM（dom） | 当前已挂载正文的估算：块数 × 固定开销 + 节点数 × 固定开销 + HTML 文本长度 × 2 | 当前显示文档随切换卸载后释放，不跨文档累计 |

- `knowledgeCacheStats()` 必须同时返回 `cleanBytes`、`draftBytes`、`domBytes`、`totalBytes`、`budgetBytes`、`evictions` 与 `pressure`；只报清洁缓存字节不再算通过。
- 载入准入先扣除草稿与 DOM 等不可驱逐占用，再计算清洁正文可用的剩余预算。顺序固定为：① 驱逐清洁文件；② 仍不足时淘汰“已保存且无未提交修改、非当前”的草稿；③ 仍不足则拒绝载入并显示压力反馈，**不得驱逐未保存草稿**。
- 压力反馈文案：「阅读缓存已达预算；清洁正文和已保存且无修改的草稿可回收，未保存草稿保留。请先关闭不需要的清洁文档后重试。」拒绝载入时正文区不得显示半截或空内容冒充成功。
- 估算假设：DOM 内存与浏览器像素不做真实测量，只按块数/节点数/HTML 字符数给保守系数；该数字用于预算决策，不声称等于实际进程内存。

### 目录刷新与正文失效（R03）

- 刷新目录后按当前可达实体清理已移除的树节点与已加载子树；不在当前页的父目录也必须能通过路径逐级定位并刷新，新建嵌套目录后父行立即可见。
- 同一路径原件的 `sourceRevision` 变化时：无草稿的清洁正文失效并重新读取；已保存且无修改的草稿失效并回到原件；**dirty 草稿不静默覆盖**，提示「原件已在外部变化，当前未保存草稿保留；保存时会提示版本冲突。」目录盘点与正文复核仍是两个任务，不因目录刷新宣称正文已重读。
- dirty 草稿的提示条必须自带动作入口「放弃草稿并重新读取」（可视稿元素 `#reload-original`，软件 `#reload-original` / `data-action="reload-original"`）。点击**先二次确认**（复用正文区确认条，提示「将释放本文档未保存的草稿并从原件重新读取；不修改已保存原文，此操作不可撤销。」），确认后才释放该文档草稿并从原件重读；读取失败、身份不一致或确认期间正文又被编辑时**草稿保留**，取消则不改变草稿。任何路径都不得静默丢弃未保存内容。
- 当前选中文件在刷新后不存在时，提示「所选文件已不存在；不会跳到其它文件或清除草稿。」，不自动跳到其它文件。提示区必须提供「刷新目录」入口（可视稿元素 `#refresh-tree-2`，软件 `#refresh-directory` / `data-action="refresh-directory"`），调用既有 `PagedKnowledgeTree` 的 `refreshTree`（`loadTree` → `directoryHandle.current.refresh(session.selectedFolder)`），不新造目录状态源；刷新后仍定位不到则继续提示，找到则正常载入，不跳其它文件、不清草稿。

### 键盘焦点（R05/R08）

- 文件树以稳定节点 id 维护 lead 与 `aria-activedescendant`；删除、重排、翻页后 lead 映射到最近的可聚焦行，不得指向已删除项、状态文字或容器本身。结构变化后先滚动使该行挂载，再让 `aria-activedescendant` 指向仍存在的 `treeitem`。
- 目录（TOC）键盘上下移动到尚未挂载的标题时，先改变滚动窗口并挂载该项，再聚焦/激活该项，不得静默跳过或把焦点留在空位。长目录收缩为短目录后，lead 与选中项必须限幅到现有标题；原聚焦项被移除时焦点回到新的有效项，不落到页面 body。
- 鼠标点击行或「加载更多」后焦点回到树控件，随后键盘上下移动从该行继续；该链路属于动态交互，缺少真实鼠标+键盘自动化时在验证记录中标为未验证，不用 DOM 断言冒充。

失败文案统一为「错误码 + 中文原因 + 可操作的下一步 + 重试入口」，保留错误码便于排查；重试重建新任务，不覆盖未确认的已有产物。多文件任务顶层 `error` 只是首条失败原因，失败明细以 `failedFiles` 为准。

### 进度语义（后端契约 2026-11-21 扩展）

- `processedBytes` / `totalBytes` **只描述当前文件**，多文件任务换文件时归零；不得用它算整体百分比。
- 整体进度按 `fileIndex` / `fileTotal` / `completedFiles.length` 与当前文件占比估算；`fileTotal` 缺失或为 0 时不编造总数（显示单一文件语义）。
- `completedFiles` 保留每个已成功文件的 `name/relativeUri/noteId/bytes/sha256`；`failedFiles` 保留失败明细。`phase=failed` 时可能已有成功项，必须按“部分成功、不回滚”展示。
- 终态记录超过 64 条会淘汰；`kbTransferStatus` 返回 `TRANSFER_NOT_FOUND` 时展示「结果已过期」，停止轮询，不当作进行中或成功。

### 轮询、作用域与清理

- `crypto.randomUUID()` 生成 taskId；导入/导出启动后每 300ms 调 `kbTransferStatus(taskId)`，直到 `completed｜failed｜cancelled` 立即停止（不空转、不无限重试）。
- 取消按钮调 `kbTransferCancel(taskId)`；结果以 `cancelRequested` 显示「已请求取消…」，仍需等 phase 变为 `cancelled` 才显示终态，不提前宣称已停止。取消竞态：cancel 返回 `copying` 后任务可能随即 `completed`，界面继续轮询并以后续 status 终态为准。
- 组件卸载、切库、切文件：清理轮询计时器与进行中请求；任务登记按 `libraryId + 任务归属（当前文件/当前目录）` 保存，旧任务回调必须校验 scope，不得更新新库/新文件的面板状态。
- completed 且 `indexPending`：只提示「全文索引待建立」，导入成功后刷新当前目录（复用现有子树刷新），不调用索引接口、不谎称索引完成。
- 每次状态返回都校验 `id`、`libraryId`、`kind` 防止串任务；错误状态保留可重试。
