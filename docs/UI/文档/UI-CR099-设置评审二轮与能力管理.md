## 3. 关键设计决策

### 3.1 模拟客户端身份的位置与措辞
放在「通用 → 会话与行为」末尾，作为一条字段行，而不是新开页面。理由是它与「生成中再次发送／完成后通知」同属会话行为偏好，用户找得到、也不会误以为这是供应商级配置。

措辞明确三点：作用于平台 runtime 请求模型时、按所选 CLI 携带客户端身份标识、不改变凭证与账号与计费归属，且不影响 CLI 会话自身启动参数。设计稿不展示任何凭证或版本号伪造细节。

### 3.2 权限挡位的取舍
采用按 CLI 分类的已验证定义，不再保留占位灰项。理由：灰项既不可选，又没有说明为什么不可选，等于用界面把「未完成」呈现给用户。逐项语义与后端现有映射保持可对接；**后端 `validate_permission` 的白名单需在同批实现时同步扩大**，否则选了界面允许的档位会被发送端拒绝——这一条作为实现前置登记，不在本设计稿内改动。

### 3.3 归因并入结果区（第三轮再收敛）
首轮用户要求「不要再加一个框」，我把内容搬进结果区仍是块；第三轮进一步要求「存在不通过项 这里要整段移除，这里只展示归因到那个模型」。因此结果区最终只保留**一段纯文本**：`指纹归因：最像 <候选>（d=…）+ 一致性标记 + 声称家族 [+ 其余候选]；概率性提示，不构成实锤。` 不列探针编号、不写不通过项计数、无边框无底色无阴影。

### 3.4 停用供应商折叠
停用项默认不渲染，避免常态下方列表被空配置占满；计数放在按钮文案里（`（N）`），用户不必先展开才知道有多少。**展开后的停用卡就是原卡片本身**：同一 `.provider-card`/`.provider-h` 结构、原开关、状态标签、删除入口与拖动手柄，头部内边距与间距与在用卡一致；只用原开关即可启用回列表。不另造只读简化卡，以免出现「停用后换了一副样子」。

## 6. 未决与限制

- Q1（身份是否在会话界面显示生效角标）未决，本稿不加角标。
- Codex「自动审核」的版本阈值需实现前取得；本稿按「可用时显示」呈现。
