## 2. 拟议工作包字段（STORY-054，未实现）

`AgentWorkPackage` 在既有 RequirementSnapshot / ExecutionPolicy 上扩展：

| 字段 | 含义／约束 |
| --- | --- |
| `rules[]` | 适用规则 URI、SHA-256、适用目录、读取时间和冲突／处置；外部数据不是指令来源 |
| `workLevel` | `requirements` / `design` / `implementation`；需求／设计包不生成正式 implement／build／integration 步骤 |
| `authorizations[]` | 授权类型、来源原话／URI、确认时间、项目／Story／文件／动作范围、有效性；设计、编码、软件验证／构建、集成、远端／发布分别核对 |
| `sources` | 唯一 Story、AC、设计资源／版本、需求 hash；不是可另编辑的第二正文 |
| `readScopes / writeScopes / allowedOutputs` | 规范化路径、禁止目标与产物类别；设计包只允许文档、原型与设计验证，不包含正式源码／依赖／配置／构建产物 |
| `delegationAssessment` | 是否必要、独立性／依赖／风险／预算、实际难度、选定执行器及其门槛，不为委派而委派 |
| `parentPackageRef` | 子包继承并取父边界交集，包含必要上下文；不能因转派或点名绕过约束 |
| `handoff` | 当前版本、状态、已完成、实际验证、遗留及下一步；事实、假设与计划分栏 |

规划生成步骤时先检查工作层级；例如设计包只产生 read/classify/design/review/designValidation/deliver，不使用当前执行方案固定的 `implement→verify→integrate`。这只改变未来契约，**本次 scheduler 保护不改，不代表 DEMO 已具备执行层强制隔离**。

缺授权、规则冲突、包版本过期分别返回可解释拒绝原因；确认前与实际执行前复检。规则／需求／设计漂移停止受影响分支并保留旧包，不通过新包自动扩权。既有停止／租约／fencing 机制继续适用，旧写进程未确认停止不可放开新 writer。

## 3. 拟议视觉证据门禁（STORY-055，未实现）

设计准入清单 `DesignCoverage[]` 至少包含场景 ID、页面／弹窗／状态、适用 Story/AC、资源 URI/hash、当前实现基线／新设计待实现／设计缺失／已替代历史、继承约束和授权依据。新设计保护区有来源和版本；缺页不取消存量能力。

`VisualEvidence` 至少绑定设计 hash、实现工作区版本、场景／状态、视口／缩放／主题、夹具版本、浏览器／系统／字体、两侧截图或叠加 URI/hash、事前允许差异、实际差异与结论。结论分别为 passed/failed/notExecuted/notApplicable；纯设计验证不写成软件视觉 passed。

未解决偏离有差异 ID、AC、负责人和下一步；没有成对证据、条件不相同或旧证据失效都不得通过相应交付／完成门槛。实现修订／设计修订／夹具条件变化使旧证据转历史，不删除历史，也不验证后放宽阈值。

## 4. 设计资源与数据边界（STORY-052/053）

原型长期固定 [同一入口](../UI/仿真原型UI.html)，[总览](../UI/文档/设计资源索引.html)只做目录；历史链接只追溯，不自动跳旧应用。新增设计模块在原设置／知识／服务器正常路径演示；保留原 TaskRuntime 与 AI SdkCatalogue 的作用域，独立配置 DEMO 必须明确标识，不能称统一真实库存。隔离知识授权演示不证明 AI 原生线程已清理或正式授权网关已实现。

夹具统一维护项目与来源身份，真实需求规则摘录与预约业务情景分开；统计／监控由同源量计算。保存用户快照优先，新增数据不强制迁移／覆盖。只允许不可执行占位凭证、文档 IP／域名；不读取生产日志、安装目录、外部知识或实际密钥。

DB 结论：设计补稿无正式数据库变化；未来工作包／视觉证据拟基于 [DB-FEAT-019](../DB/DB-FEAT-019-任务执行数据设计.md) 的不可变快照／证据扩展，但表结构／迁移尚待设计，**不是可立即开发的完整 DB 基线**。
