## CR-044 现行导航继承（2026-11-20）

用户本轮明确要求先需求／原型后软件：采用应用内唯一对象Tab，管理四表面不新增Tab，详情隐藏主菜单，整宽Tab栏首页固定最左。普通open命中键只activate；显式内部导航独立调用，不能覆盖普通打开的保状态语义。注册表、首页视图与对象视图分别保留；关闭可见Tab与保留后台／草稿实例分开，不由关闭Tab隐式stop。原型状态也需逐对象保存／恢复，不能仅改栏的位置。此节替代原OS独立窗口作为本轮首版呈现，安全／身份／默认拒绝与未实现业务内核边界继续。UI-CR044制作并登记hash后再进入软件。

56px融合标题栏以原生窗口API提供minimize/toggleMaximize/startDragging/isMaximized，关闭从Rust统一拦截发送确认事件，确认后受控单次关闭，不公开无条件destroy。官方品牌资源原样锁版；平台sprite由设计方维护、锁定复制正式软件；界面与系统图标独立资产。

## 1. 当前事实与复用

- 正式应用只有单一路由与单一 `projectId`（`src/store/app.tsx`），打开项目替换路由；项目内部的“需求／设计／任务／编码”是模块页签，不是项目窗口。
- 编码区文件页签与设计／Git 面板在切换时可能卸载，提交说明等本地状态会重置；AI 会话按项目持久化，但后台运行标记与引用仍是面板本地状态；SSH 终端卸载会关闭前台显示。
- 因此不能只加一排按钮：需要窗口注册表、每窗口页面状态、关闭生命周期与按对象防串写。
- 可操作原型已具备统一管理页、项目工作区、知识库阅读与服务器工作台样例；本批在原型上实现窗口模型，不改真实业务。

## 2. 选定方案（正式实现待授权）

### 2.1 窗口身份与注册表

- 窗口键：`project:<projectId>`、`knowledge:<libraryId>`、`server:<hostId>`；稳定 ID 来自宿主数据，不使用名称。窗口管理器维护 `key → 窗口句柄` 映射，创建前先查重。
- 再次打开：查重命中即 `focus()`（置前、按需解除最小化），并把焦点与阅读位置恢复到该窗口当前页；不重建 WebView、不重置滚动与表单。
- 若对象已删除或权限撤销：显示失效状态并禁用操作，不静默回落到同类其他对象。

### 2.2 固定首页

- 首页是项目管理、知识库、服务器管理三个管理表面的组合，始终保留并可通过模块导航到达；打开窗口不销毁首页实例。
- 首页滚动、搜索与列表状态独立保存；窗口关闭不重建首页。
- 窗口栏列出首页与窗口；它属于窗口管理系统，不属于任一详情。

### 2.3 每窗口状态

- 每个窗口持有自己的 UI 状态对象：页签、选中需求、设计子页、文件页签、知识库笔记与搜索、服务器主机与终端视图、滚动位置与未提交草稿的**显示状态**。
- 切换只替换“当前 UI 状态”的引用，不改写其他窗口；渲染上下文若由模块按引用持有（本原型中的设计资料、知识库、AI 侧栏上下文），切换时同步更新引用，避免读到上一个窗口。
- 草稿内容的权威仍在既有草稿存储；关闭窗口的“丢弃”必须显式删除对应草稿并持久化，取消则必须保留，不能仅靠销毁视图。

### 2.4 关闭生命周期

1. 无草稿无运行任务 → 直接关闭。
2. 有未保存草稿 → 询问“取消／关闭并丢弃”，并列出草稿来源；取消不动任何状态。
3. 有运行中任务 → 明确“任务继续在后台”，关闭不发送停止或取消；任务列表与证据保持。
4. 关闭只移除窗口与视图，不删除项目／库／主机，不关闭 SSH 会话、不终止任务、不改变验收。

### 2.5 返回按钮取消

- 详情内不渲染返回管理页按钮；关闭窗口（标题栏关闭按钮、窗口栏关闭、键盘）即回首页。
- 焦点：关闭后焦点回到窗口栏的首页入口或原触发对象；不能落到已销毁节点。
- 兼容旧书签／深链：若设计保留 URL 或窗口标识，打开已存在窗口应聚焦而不是叠加；本原型不实现深链。

## 3. 正式实现的取舍

- **方案 A：应用内窗口表面（本原型模型）**：实现代价低、状态与权限一处管理，但视觉上是同一窗口内的多面板。适合首版验证交互。
- **方案 B：Tauri 多 WebviewWindow**：更接近“独立窗口”，但需窗口标签→对象映射、跨窗口状态同步、关闭拦截、焦点与恢复、单实例去重，以及每窗口事件路由与权限复核；共享数据库、SDK／MCP 配置与 SSH 管理器不会自动隔离。建议在方案 A 的窗口生命周期与状态模型稳定后再升级，避免两套语义。
- 无论 A/B，**窗口不是安全边界**：AI 工具、终端、文件写入仍按项目／对象与权限校验；异步回调必须携带窗口键与对象 ID，防止串写。
- 同仓库并行：同一规范化目录只允许一个活动写入窗口；需要并行时使用独立 worktree／分支，并在仓库操作上串行化。本批不实现，只作为后续约束。

## 4. 数据、权限与兼容性

- 无数据库结构或迁移；窗口布局与最后位置是否需要持久化属后续设计（可复用本地配置，不进入业务库）。
- 不新增 AI 工具或权限；不改变知识授权与任务验收。
- 兼容性：CR-021 的返回导航被替代，旧设计与证据保留；其他模块（设计资料、任务、AI、知识阅读）内部交互不变。
- 原型窗口状态仅存内存，不写入正式存储；合成夹具与原状态机字段继续分开标注。
