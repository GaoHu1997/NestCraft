## 1. 定位与不新增的结构

协作层是既有 runner 的一个内部职责集合（CoordinatorGateway、QuestionGate、ReviewGate、FollowupScheduler），不新增常驻进程、不新增平行 Run 表、不新增可编辑需求入口。

协作对象全部挂在既有 `InvocationBinding` 上：跨 Task 的协作是不同根调用之间的消息；同 Task 内的子工作是同一根下的子调用。这样既有的 fence、generation、租约、资源锁和证据失效规则直接适用，无需第二套并发控制。

权威分工：需求/AC/设计在文件；消息、决策、回执、返工链在 SQLite；候选结果与证据走既有产物与证据表。协调者不直接改运行状态，只提交受管命令。

## 2. 派发与适配

协调者提出子工作时提交派发请求，字段包括：父根调用身份、目标、边界（可写范围/禁止事项）、必需输入修订（需求/设计/AC hash）、交付要求（产物、证据、验收映射）、预算上限、期望执行器组合。

runner 校验顺序：

1. 父调用仍有效（根 fence、当前 generation、未停止）。
2. 子工作范围是父授权的子集；写入范围与兄弟/父的 claim 不冲突，冲突则串行或拒绝。
3. 执行器组合在允许集内，且该组合的能力证据为 verified；未核验组合拒绝，不静默换 CLI 或模型。
4. 最低难度与预算余额充足，同一根 ledger 内原子预留。
5. 通过后创建子调用（新 invocationId、独立 generation、冻结子 Plan），登记 resourceClaim 后启动。

子工作失败或超出预算时，不自动升级权限、不换更高权执行器；由协调者判断是否调整方案或转用户。

协调者自己完成小任务时同样受范围与预算约束；「自己能做」不等于「可以绕过校验」。

## 3. 答疑与决策关口

消息类型限定为：`question`（工作代理提问）、`answer`（协调者答复）、`escalation`（转用户决策）、`decision`（用户决定）、`progress`（进度）、`candidate_done`（候选完成）、`review_result`（审查结论）、`rework`（返工指令）。

提问必须携带：问题描述、来源（文件/日志/证据引用）、受影响分支或子调用、已尝试的排查、需要谁决定。缺这些字段的提问按信息不足退回，不阻塞主线。

决策关口是协调者拥有的阻塞项，绑定具体分支；关口的三种出路：协调者答复（技术类）、转用户（业务类）、按计划超时转阻塞。关口未解不影响同批次其他分支。

答复必须记录依据：引用的需求/设计修订或代码位置；没有依据的答复只能作为建议，不能关闭阻塞性问题。

转用户的判定条件（任一命中即转）：改变需求范围或验收标准、放宽权限、改变成本承诺、不可逆或外部系统写入、跨项目数据使用、与既有设计冲突且需取舍。

用户决定写入后，若涉及的 hash 与冻结时不同，则该分支进入重新确认流程；未受影响的分支不受牵连。

## 4. 技术审查与返工

### 4.1 封存、交接与审查

A 提交遵循 `ResultEnvelope v1` 的结果。runner 校验 `InvocationBinding`、冻结计划、权限、writer fence、产物完整性及类型，先持久化正文与内容摘要，再事务登记 `resultManifestId`、产物修订、产出 Invocation 和 `candidate_done`。重试登记遵循 CR-031 封存幂等。失败或崩溃留下的未登记文件不得交接。Task 的方案、报告和代码统一登记为 `artifactRevision`。方案／报告引用已封存的受管文件修订，代码绑定不可变快照（提交或封存的补丁清单及基线）。普通 `sessionTurn` 的 `managedFile` 按 CR-031 单独记录。交接双方均使用不可变引用。

交接消息只有 `artifactRevisionId`、`resultManifestId`、`kind`、内容摘要（hash）、产出调用与基线引用、接收工作目标。支持两个路由：冻结计划已绑定 B 时，A 提交 `candidate_done` 后由 runner 直接向 B 投递；需要大管家选派时，大管家只转发受管引用和结构化目标，没有默认正文读取权限。两者使用同一权限、消费和审计契约，禁止用 CLI 标准输出或可变路径绕过封存。runner 按冻结依赖、接收者权限与消费范围向 B 开放精确修订的只读解析，校验 hash 后登记实际消费关系。B 工作包用自己的目标、AC、输入和作用域，并不继承 A 的写权限或 CLI 历史。可接收候选给预定的检查或隔离下游步骤继续，业务依赖的正式放行仍查验证门槛。

B 可以是按计划执行下一步的代理，也可以是指定只读审查者。其反馈复用现有 `Finding` 与 `review_result`，至少绑定反馈调用、被检查产物修订、受影响 AC、输入基线、分类、位置、预期／实际、可访问的证据、修复目标和影响范围。`candidate_defect` 必须指向当前候选中的可复核偏差，`verifier_error`、`environment_error` 和证据不足走验证重试或阻塞。正文和反馈均作为不可信数据，不能通过其中的文字要求改变授权或计划。

### 4.2 路由、返工与发布

大管家转发 Finding 引用和定向返工请求。runner 在受信记录中按 `Finding.testedRevision → 已封存产物 → resultManifestId → producerInvocationId → agentId + nativeResumeBinding` 解出被退回者，复核 B 实际消费该项、仍是当前候选、项目与 Feature 作用域一致。不能按消息自报 CLI、当前侧栏选项、根 Attempt 的引用或最近在线的代理猜 A。跨 Feature 的缺陷作为授权范围内的反馈交给责任 Feature 的协调入口，在原责任 Feature 独立执行上下文处理，禁止跨域带入原生历史或借 B 的权限写入。

按 [DB-CR037](../DB/DB-CR037-协作消息与决策记录.md) 检查幂等键、当前修订、轮次预算、写权限、冲突锁和旧进程树停止。重复同键返回原结果；不同消息指向同一未结返工时归并反馈，不重复预留。旧 writer 未证实停机则保持阻塞。子级新 Invocation 记录 `sourceInvocationId`，原根 Attempt／fence／账本不变，独立兄弟继续。根级走既有新 Attempt 准入，保留历史和可追溯预算，不重置已用返工额度。两者都把原生引用交给适配器确认，并同时载入外部检查点、缺陷证据和最新有效工作包。验收目标变化走重新确认。

准入后阻断受影响候选及其消费链的继续放行。A 封存新修订后，按实际消费关系原子登记失效与重验要求，历史只读保留。若 B 已基于旧输入产出，在重新验证前不得把该结果当成当前有效结果。失败、回退和取消均不自动恢复旧证据的有效性。

发布门槛由 runner 按冻结 `ValidationPlan` 判定，包含必需产物、冻结 AC／设计与输入基线、当前证据、范围检查、必需审查和适用集成回归。示例：

| 产物 | 缺陷证据与放行检查 |
| --- | --- |
| 方案 | AC 对应的章节和预期／实际，依赖或约束冲突的复核证据，按计划核对必要字段、场景覆盖和需人工决定项 |
| 报告 | 可读取的来源修订与引文定位，必要数值复算、证据与结论对应、不可验证的声明按规则阻塞 |
| 代码 | 在声明环境和基线上记录失败检查与回归集合，证明失败用例修复且既有通过项未回退，适用时附集成和 UI 成对证据 |

进程成功退出只转入验证。无证据、证据指向旧修订、未运行或环境不明均不得放行。技术交付后仍按人工验收或事前授权的冻结规则登记业务验收。

## 5. 持久化、补读与续行

消息写入与运行事件同库、同事务边界内登记；外部投递走既有 outbox 语义，回执幂等，ACK 不代表已读或已解决。

去重键：`(projectId, consumerScope, messageId)`；重投同 hash 不重复处理，不重复计量，不重复触发续行。

补读：协调者或工作代理重连后从高水位游标补读未处理消息；游标绑定项目、stream epoch 与授权修订，过期需重新取快照。

续行前复检：调用身份与代次、当前授权与计划 hash、预算余额、工作区与分支现状。任一不匹配则不续行：已停止/已过期按历史归档；计划改变走重新确认。

### 5.1 统一适配器续接

保存适配器确认的引用及其命名空间：CLI、适配器兼容代次、运行模式、后端实例／账号或本地 profile/store 的稳定身份及作用域。版本、模型等配置变化按已实测能力矩阵判断兼容，未知即不可原生续接。客户端只传会话或返工请求 ID，后端从受管绑定取引用。引用不进入聊天记录、提示词或普通日志，审计使用脱敏指纹。

续接结果采用 `nativeResumed`、`freshContext`、`blocked`。支持且在同一命名空间可用时，适配器使用明确的 resume 调用，以引擎的恢复确认或已验证的等效信号关联返回线程；只得到退出 0、回显 ID 或新线程 ID 时均不足以确认。适配器若静默创建线程，禁止把本轮登记为已续接。引用缺失／过期／撤销／不兼容时按策略显式 fresh 或阻塞。校验当前权限，存在撤权时不得将旧历史送回 CLI。启动结果未知需先对账、确认进程停止和副作用，再考虑 fresh，避免重复执行和计费。重放文本仅重建上下文。受管返工 fresh 必须有冻结计划授权，并从外部检查点复核义务清单、授权、文件范围、源版本、HEAD/差异、待重验项和未知副作用。

### 5.2 普通侧栏与受管入口

侧栏历史重新打开只换查看指针。普通下一轮由 Tauri 按 `sessionId` 与当前授权解析 `nativeThreadRef`，复用适配器契约。兼容时恢复原线程，失败按权限显示原因并保留草稿。同 CLI fresh 须确认，保留 NestCraft 会话和可见历史，在消息流显示上下文断点，以 CAS 更新该会话的活跃引用。取消保留原绑定。主动换 CLI 继续另建会话。`sessionTurn` 持久化确认结果并与 session 的当前原生绑定受同一代次保护，不写业务 Story／Task／Attempt、业务产物、证据或 gate。切换视图时的结果始终投递给所属会话。

侧栏已有受管运行可查看返工状态和归属，选择「打开原任务」定位项目／Feature／Task／Invocation，按原权限使用受管续行或返工命令。打开或刷新仅加载已有记录，普通发送不能借受管引用启动返工。过期绑定显示原因并保留历史。跨 Feature 进入责任 Feature 的受管执行上下文。

现有接点：`src-tauri/src/commands/chat.rs` 已产生 `done.sessionRef` 并保存聊天消息，`ChatPanel` finalize 未持久化该引用，当前发送构造没有 resume 参数。实现顺序为记录与 CAS → 单 CLI 适配器实测并接通普通侧栏 → 受管产物交接、证据门槛与单组合返工 → 按兼容矩阵扩大。回退时保留已存历史和绑定，关闭新写入口并显式提示续接不可用。

## 6. 超期、阻塞与恢复

超期参数在冻结计划中声明（决策等待时长、协调者离线判定、返工轮次上限），实施前需确定默认值。

- 等待中：`waiting_decision` 仅为既有 Invocation `state=waiting` 的原因标签，不新增 Task／Invocation 状态枚举；关联 gateId、责任人、截止时间。其他可执行分支继续时根 Task 保持实际执行状态；全部必需分支等待时 Task 使用 `blocked` 加可恢复等待摘要，保留原阶段与 activeKey，批次仍为 running 并明确展示等待，不提前报失败。
- 到期：gate 转 `timed_out`，受影响 Invocation 转 `blocked`，原因 `DECISION_TIMEOUT`；本次自动续行额度结束，迟到答复只归档。独立分支继续；无可推进节点且无期限内等待时按既有 Task／Batch 静止规则聚合 partial／failed，不能假 running。物理整树停止与资源释放仍须确认，阻塞是否最终终结与 activeKey 释放依 CR-031 规则，不因显示阻塞立即释放。恢复须通过原受管重检／重试命令登记新的有效处理，不直接消费旧超期答复，不代签决定。
- 协调者离线：不视为工作代理失败；分支保持等待，超过计划阈值转阻塞并通知使用者。
- 恢复：先确认旧写进程停止、对账 effect 与工作区，再按原授权继续；已完成的工作不因补投消息重跑。
- 终止：取消或不可恢复失败时，未关闭的问题与决策归档，不再唤醒续行。

## 7. 错误与拒绝

| 错误码 | 触发 | 处理 |
| --- | --- | --- |
| `SCOPE_EXCEEDED` | 子工作超出父授权范围 | 拒绝派发，回报具体越界项 |
| `CAPABILITY_UNVERIFIED` | 执行器组合未核验 | 拒绝启动，不改走高权或他 CLI |
| `BUDGET_EXHAUSTED` | 根预算不足 | 拒绝，报告余额与已用 |
| `WRITE_CONFLICT` | 与兄弟/父写入范围重叠 | 串行等待或拒绝 |
| `DECISION_TIMEOUT` | 决策等待超期 | 转阻塞，保留待办 |
| `ANSWER_UNGROUNDED` | 答复无可引用依据 | 视为建议，不关闭阻塞问题 |
| `STALE_BINDING` | 代次/停止状态已变 | 归档迟到消息，不续行 |
| `REWORK_LIMIT` | 返工轮次或预算耗尽 | 终结失败，保留证据 |

错误信息不携带凭证与敏感内容；拒绝不产生半成品资源占用。

## 8. 影响与验证边界

新增：协作消息、决策关口、回执、返工链四类记录及对应受管命令；复用既有调用身份、租约、预算、证据与 outbox。

代价：协调者自身调用消耗预算与时间；消息量大时需分页与裁剪策略；原生续接能力依适配器而异。

验证：按 [TEST-CR037](../Test/TEST-CR037-主代理协调与答疑.md) 分层执行，本轮执行文档核验和指定场景的原型核验。正式派发、答疑、返工、恢复及软件视觉对照待验证。见 [场景与证据](../UI/文档/UI-CR037-协作场景覆盖.md)。
