## 0. 实际实现记录（v2）

- 解析：`kb_links.rs` 的 `extract_links` 跳过围栏代码块；`resolve_target` 顺序为「完整相对路径 → 同目录 → 唯一后缀路径 → 唯一文件名 → 歧义 → 未解析」。
- 索引：`kb_link` 派生表（`db.rs` 建表）；`publish_note` 保存成功后同事务 `replace_for_note`；`scan_notes` 重建时 `rebuild_tx`；既有库首次打开若出链为空且正文含 `[[` 会惰性重建一次。
- 重命名/移动：`apply_move` 先回写所有引用源文件（CAS 保存），再更新 `knowledge_note_index` 路径与 `kb_link`；删除后 `rebuild_from_root` 使相关链接转未解析。链接改写失败不使已完成的文件改名失败，只记日志。
- 前端：`linkRender.decorateLinks` 只包装文本节点、用 `textContent` 写显示文本（不注入 HTML）；`MarkdownContent` 接收 `links`/`onLinkClick`；`Reader` 提供右栏三页签、反链打开、未解析新建、歧义候选 Modal、重命名前影响提示。
- 本版未做：悬停预览卡、自定义重命名对话框（用 confirm）、`[[#本页标题]]` 自锚点、块锚点与 `![[嵌入]]`；均需后续增量，当前不宣称支持。
- 验证：Rust 5/5、组件 10/10、`npm run build` exit 0，见 [REPORT-CR088](../Test/REPORT-CR088-正式实现与验证.md)。

## 1. 现状与最小影响面

- 现知识库为受管本机目录（`SafeRoot` 校验），文件为真相；正文渲染经 `MarkdownContent`，目录树用分页 `PagedKnowledgeTree`。
- 无链接概念：正文里的 `[[x]]` 目前按普通文本显示；重命名只改文件，不改内容。
- 拟改：Markdown 渲染增加双链识别；新增链接索引与反链查询命令；重命名流程加"更新链接"事务；右侧栏加反链页签。**不改**检索引擎（Tantivy/FTS）、授权、AI 工具、CR-084 预览链路。

## 2. 链接语法与解析

支持：`[[name]]`、`[[path/name]]`、`[[name|显示文本]]`、`[[name#标题]]`、`[[#本文标题]]`、`[[path/name.md]]`。

解析顺序（同一套规则给前端预览与后端索引共用，避免两处不一致）：

1. 若含 `/`：按库内相对路径精确匹配（自动补 `.md`）。命中即解析。
2. 无路径：先找**当前文件同目录**同名 `.md`；再找全库唯一 basename。
3. 多处同名且无路径 → `AMBIGUOUS`，返回候选列表（前 20 条，路径 + 标题），不自动选。
4. 都不存在 → `UNRESOLVED`，保留原文，可"点击新建"。

大小写：Windows 下按**不区分大小写**匹配，但保存原始写法；`#标题` 锚点按渲染后的标题 id 归一（复用 `allocateHeadingIds` 的重复标题去重逻辑）。

## 3. 索引与查询

- 派生表见 [DB-CR086](../DB/DB-CR088-知识库链接索引.md)：`kb_link`（源笔记、原始目标、解析目标、锚点、类型、行内序号）＋ `kb_link_unresolved` 视图思路。
- 维护时机：Markdown 保存成功后（同一事务内重算该文件链接）；目录扫描/重建时全量重算；文件删除/移出库时清理。
- 查询：`kb_links_backlinks(libraryId, noteId)` → 引用该笔记的来源列表（路径、标题、片段、行号）；`kb_links_outgoing(noteId)` → 该笔记的出链与解析状态；`kb_links_resolve(libraryId, target)` → 供编辑器自动补全/预览。
- 性能：索引只解析 Markdown 文本，纯字符串扫描，单文件 O(字符数)；不引入新的解析依赖。大库全量重建走后台任务（复用现有扫描任务通道），可取消。

## 4. 渲染与交互

1. `MarkdownContent` 在 sanitize 后把 `[[...]]` 转成 `<a class="kw-link" data-target="..." data-state="resolved|unresolved|ambiguous">`，保留原始文本；DOMPurify 白名单只放行 class/data-*，不注入 HTML。
2. 点击：resolved → 打开目标并跳到锚点；unresolved → 询问"新建《x》？"，新建成功后重渲染；ambiguous → 弹候选列表。
3. 悬停预览：复用现有只读读取命令，取目标前若干行做摘要（不执行、不联网），带 150ms 防抖与取消。
4. 右侧栏增加页签：`大纲`／`反向链接`（数量徽标）／`未解析`。空态分别为"暂无标题""还没有笔记引用它""没有未解析链接"。
5. 源码模式（原文）不解析链接，保持可编辑原文；切回阅读态重新解析。

## 5. 重命名／移动事务

1. 预检：列出将被修改的文件与命中数（按第 2 节规则解析，只改**解析到该文件**的链接，不误改同名歧义链接）。
2. 用户确认后：逐文件在内存改写 → 校验目标文件哈希未变（CAS）→ 写临时文件 → 原子替换；任一失败即回滚已改文件，报告失败位置。
3. 改写规则：`[[旧名]]` → `[[新名]]`；`[[旧路径]]` → `[[新路径]]`；保留 `|显示文本` 与 `#锚点`；含空格的路径按现有写法保留。
4. 完成后重建受影响文件的链接索引；记录一条操作摘要（改了哪些文件、多少处），可查看。

## 6. 安全与边界

- 链接目标只允许库内相对路径，禁止 `..`、绝对路径、盘符、UNC；打开前仍走 `SafeRoot` 与稳定 ID 解析。
- 未解析链接的"新建"必须经现有文件名校验（保留字、控制字符、深度限制）。
- 不改 AI：链接不进入 AI 检索上下文，不因链接存在扩大授权范围。
- 附件落点：沿用"上传到当前目录"，路径由现有校验函数处理；界面显示实际相对路径。
