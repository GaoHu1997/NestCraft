## ADR-001-A：正文存目录，数据库存索引与业务元数据

### 备选与取舍

| 方案 | 优点 | 主要代价 |
| --- | --- | --- |
| Markdown 目录作为全部状态存储 | 可人工/Git/AI直接读，简单 | 授权与会话不宜入 Git；复杂检索/关系难以校验 |
| 数据库保存全部需求正文 | 事务和查询方便 | 需求难直接审阅、diff、离线编辑，导出可能成第二份事实 |
| **Markdown 正文 + SQLite 索引/授权/会话** | 正文可版本追踪，业务元数据可事务校验 | 需处理源文件与派生索引同步、冲突与重建 |

选第三种：项目愿景、Epic、Feature、Story 正文沿用 `docs/Plan/`；状态/AC/归属等需求事实写在源文件元数据或正文，数据库只保存其派生投影。知识库正文保留其受管源目录/连接源，不能自动复制到所有项目。数据库权威保存项目-库授权、统一配置引用、会话元数据/消息；附件二进制存受管目录并用数据库关联。SQLite 是面向单用户本地工作台的正式实现选型；没有扩展到多人服务/云同步，此后若范围改变另记 ADR。

### 一致性与安全

- 用稳定 ID、类型、parent、源 URI、contentHash 建树；正文是唯一事实来源，预览和索引都从它生成。
- 正式写回按基线 hash 检查并原子替换；保存前留可恢复版本，文件成功后索引失败显示“已保存、索引待同步”，不回写旧正文。索引可重建，授权不能从正文暗示恢复。
- 路径解析必须限制项目目录、拒绝 traversal/符号链接逃逸；同名文件不是同 ID，移动文件不改变编号；duplicate/cycle/orphan 有错误反馈。
- 需求文档可跟随 Git；数据库、会话、密钥和真实附件不是自动纳入 Git 的交付物。原型不创建这些真实数据。
- 详见 [DB-FEAT-001](../DB/DB-FEAT-001-知识授权与工作台数据设计.md)。

### CR-028：完整设计文档和知识原件的存储边界

2026-11-19 用户再次明确要求按数据用途选文件／数据库，见 [CR-028](../PRD/CR-028-文件与数据库按职责存储.md)。延续第三种方案：完整 PRD／方案／说明用 Markdown 文件；UI 原型、样式、脚本与图片保留文件资源；知识上传原件、附件及办公产物按原格式保存到受管目录。数据库保存元数据、引用、授权、会话、运行状态及合理的派生检索信息，不另存完整文档的可编辑副本，不将原件塞入 BLOB／Base64／JSON。

结构化数据库设计模型仍可遵循当前设计资料需求的版本化数据库记录，不能把“数据库模型”与“完整数据库说明文档”混为一物；本次不强制搬迁合理的数据库状态或会话消息。原件与解析产物分离，解析失败保留已保存原件；索引可重建，授权和业务历史不可从索引恢复。文件与数据库分步持久化必须可对账，不宣称跨介质原子事务。具体字段、保存失败与备份恢复见 [DB-FEAT-001 CR-028](../DB/DB-FEAT-001-知识授权与工作台数据设计.md#cr-028文件与数据库分工现行增量)。

状态说明：CR-015 已有文件正文／SQLite 索引实现；本段新增原件保管与一致性约束仅设计，未实施或验收，不改写此前设计／验证事实。本次复用既有机制，无新增依赖或外部调研必要。

### CR-030：本地知识索引与按需引用

2026-11-19用户明确要求将已讨论的离线方案转为闭环需求／设计。作出增量选型：原件仍在文件系统；按格式使用应用内确定性解析，按实际来源保存派生正文／结构定位；同一 SQLite 数据库按库隔离 FTS5 的当前 generation，使用本地中文 pipeline；通过受管只读网关只返回有界切片并携带原件修订、解析代际和原文定位。此选择延续CR-028，而非把完整文件／正文当SQLite第二权威。

本次不选OCR／识别模型、向量或知识图谱数据库，不运行用户安装的Java/Python/Office/转换命令或云服务。无OCR意味着图像像素和扫描页文本不可搜／不可给AI读取；不将离线识别能力虚称“无模型”。只按明确格式矩阵承诺逐项验证，metadata_only／unsupported／failed都是有效可观察结果，不以调用大模型补齐失败。

选择理由：Tauri现有Rust+SQLite架构中减少逐篇打开原件搜索，保留撤权和引用来源一致，组件无需运行搜索服务器；全文检索、解析、AI上下文三层分开使失败可定位。代价：Rust多格式解析覆盖需逐格式加固，FTS5需中文词典版本、代际发布、分库统计及备份对账。搜索到索引命中仍需受限读取／验证命中文件；真实磁盘I/O、性能、token节省和定位质量均待实测。完整方案与替代／风险评估见 [LLD-FEAT-008](LLD-FEAT-008-本地知识索引与按需检索.md)；数据字段唯一源见 [DB-FEAT-008](../DB/DB-FEAT-008-知识原件切片与全文索引.md)。

状态：需求／架构方向经用户明确要求按推荐方案落到需求设计；**正式编码、依赖、DB迁移和用户验收未获授权／未执行**。不改变CR-015历史结果或CR-028既有存储决定。

## ADR-001-B：统一注册表与受管网关，不复制多套 CLI 用户配置

选定链路：`Settings Registry → EffectiveCapabilities → Context Compiler / Capability Gateway → CLI Adapter`。

- Registry 统一管理模型/provider/secretRef、MCP、Skill、Tools；项目授权与会话选择只能收窄能力。
- 网关统一校验 tool/resource/prompt，输入 @先解析为受检引用，/先解析为命令对象；不同运行模式的语法差异由适配器处理。
- CLI 适配器生成短期受管配置或启动参数，不改用户原生配置；进程凭证只通过受控通道，日志和历史只保留引用。
- 备选“每 CLI 复制配置”被否决：重复维护、密钥散落、权限漂移且无法满足一处配置。备选“所有 CLI 原生能力完全等价”不可成立；改为能力探测、明确适配/不支持/未验证，不静默降级。
- 知识授权必须执行层强制：只开放受检项目工具，隔离直接文件/shell/网络旁路；当前 CLI/平台达不到边界时禁止需隔离任务，不能拿 UI 过滤当系统隔离证明。

### 结果、风险与验证

代价是需要维护 CLI/版本/运行模式兼容矩阵、临时配置清理、撤权取消和上下文重建。收益是用户无需重配，能力来源与权限可审计。验证拆为原型交互、文档检查和正式安全/适配测试；本轮前两类可执行，第三类未实施。真实接入若不能安全隔离，应关闭该能力而非回落直连。
