# LLD-CR029：需求阅读只读投影

- 关联：[CR-029](../PRD/CR-029-需求全量预览与思维导图.md)／[STORY-010 AC-11～17](../Plan/Story/STORY-010-需求树与详细文档预览.md#cr-029全量分级预览与思维导图)。
- 工作层级：仅需求／方案／可视原型；正式软件尚未授权修改。预期设计以[UI-CR029-v1](../UI/文档/UI-CR029-需求预览与思维导图.md)为准。

## 当前事实、复用与影响边界

既有Story-010已要求同源连续全文，当前统一原型缺少入口且状态机仅保存部分需求元数据。本批只在原型需求渲染外包装阅读方式，读取原state和CR-027已保存模型；任务、设计、AI和管理导航不替换。全量预览不能复用派发合格集合，否则会漏未确认、取消、历史条目。

正式需求索引／文件读写已有基础，但多项目范围、CAS、真实Markdown与完整关联投影仍需明确授权后完善。正式Code设计页目前读取DB目录MD，与CR-027版本化数据库模型设计并非同一现行实现，不因本导图算已落地。

## 正式选定方案（待实现）

1. 以宿主确定的projectId读取授权的愿景／需求实体清单，固定源修订集合；需求MD从文件读取完整正文，不以索引摘要替代。模型从已有版本化设计记录读取，仍是只读。
2. `RequirementReadingSnapshot` 包含项目身份、各源ID／kind／parent／revision／正文引用／完整结构字段、模型及显式关系、缺源／关系错误列表。清单与正文分开；任何分页必须全部完成才标“完整”，失败部分明确列出，不在同一预览混用旧正文与新版本。
3. 业务树校验唯一父项、稳定ID、孤立／循环／重复ID。源错误不得静默丢弃：受检条目保留全文，错误定位，并禁止据错误投影派发；无权资料连标题／数量也不返回。
4. 从同一snapshot生成连续预览、图节点／边与右详情。预览遍历所有可读条目，与折叠／筛选／选中／派发资格无关；模型按显式关联，不把Story重挂模型父项。
5. Markdown正文安全渲染并保留表格、代码、列表与受检链接。汇总标题统一H1～H5，源小节重映射到实体内部H6／带标签段落；非安全HTML或可执行协议不执行，外部资源缺失有状态。完整长文不截断尾部，超大源可渐进加载并保留“未完整加载”标识。
6. 右详情绑定projectId＋对象ID＋revision，请求切换后旧回调不得覆盖新选择；加载／空／无权／移除清除旧内容，保留重试。缩放、选择、图滚动与树展开分别保留，图查看不修改模型或需求。
7. UI人类完整阅读不自动注入AI；按现有只读索引／分段工具预算，仍复查对象权限与缓存版本。

## DB／权限／兼容性

- 无新数据库结构或迁移；继承[CR-028文件职责](../PRD/CR-028-文件与数据库按职责存储.md)与[CR-027模型权威](../PRD/CR-027-Code项目设计资料与按需加载.md)。图只是派生缓存，不保存第二可编辑正文；完整需求以MD权威，模型以版本化DB设计记录权威。
- 导图不执行SQL、AI命令、写需求、重挂父项或发布。模型无关系时独立收纳，不自动AI推断。
- 样例模型关联与正文明确标“合成”，与原state实时元数据分开；未知ID不生成想象正文，只有现有字段和待补充。
