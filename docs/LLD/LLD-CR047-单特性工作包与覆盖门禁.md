# LLD-CR047：单特性工作包与覆盖门禁

- 关联：[CR-047](../PRD/CR-047-单特性执行与需求设计防遗漏.md)、STORY-054/055/059/068。工作层级仅研究与方案；没有正式编码、配置、依赖／数据库迁移授权。
- 目标：减少信息负载，同时使漏项、过期基线与无证据完成可以被独立检测和阻断；不承诺模型永久零遗漏。
- 当前事实：session绑定project/server/CLI，没有featureId、工作包或检查点；同sid busy/generation只防重复发送和迟到，不防跨Feature。既有CR026/031已设计计划、恢复和证据，尚未形成正式runtime门禁。本方案复用，不再立新任务平台。

## 1. 选定结构：三层而非更长提示词

1. **规范层**：Epic/Feature/Story/PRD/UI/LLD/DB各自为现行事实源；稳定条目与原文锚点不可因压缩删去。自然语言源必须人工/代理提取后复核成完整义务清单，不能声称正则能穷尽所有业务语义。
2. **控制层**：工作包编译器、Feature身份绑定、动作准入、检查点存储、覆盖/证据判定。来源hash、结构完整性、集合归属、受管文件范围、证据有无和状态用确定性检查；语义/视觉由合格验证者判断，不让生成代理自己签字。
3. **模型层**：只看当前Feature/Story所需的紧凑执行卡和按需正文/代码，生成候选改动与可核说明。模型建议不直接赋权、改AC、签验收或使运行succeeded。

### 1.1 ScopeBinding

`projectId, featureId, sessionRole, workPackageId/revision, allowedStoryIds, authorizationRef, planRef, executionGeneration`。

本阶段（STORY-068最小落实）先固定会话侧的 `projectId + featureId + featureTitle + featureSourceHash + sessionRole`：
- 创建执行会话必须同时提交项目与Feature；服务端复检Feature属于该项目根、唯一父链可解析、Feature源可读，然后写入不可变featureId。
- 会话更新不允许改featureId/role；发送时读取会话绑定并复检Feature源；普通会话保持featureId为空，不能冒充执行会话。
- 已落地（2026-11-20，UI-CR047-v1）：session增量列与索引、创建校验（项目/Feature/父Epic）、不可变更新白名单、发送前源hash复检、header/历史归属展示；单测及有限GUI通过。Feature源变化当前返回发送拒绝，恢复后需重新创建或按后续受检流程绑定，不静默改归属。
- 同一Feature可创建多个会话（不同任务/续接），但一个会话不跨第二个Feature。跨Feature子代理与强制工具拦截仍按下一阶段ScopeBinding执行，当前不宣称全工具硬隔离。

完整`ScopeBinding`：
- sessionRole为coordinator（跨域只读）、executor（单Feature）、reviewer（限定只读）、integrator（限定候选/动作）；executor featureId不可在会话中改成另一Feature。
- 创建/领取/发送/子调用/受管写入/恢复/结果发布分别复检。祖先包继承约束，child仅缩权；UI传featureId不是后端鉴权。
- 词法搜索“Feature A/B”不能证明输出范围。强范围指集合归属/受管工具与路径控制；任意原生CLI未被受管时只可声明提示约束，不能冒充全工具硬隔离。必须衔接STORY-041/058的已验证适配器与OS边界，能力缺失拒绝相应保证。

### 1.2 WorkPackage与ObligationManifest

每包保存稳定project/feature与以下来源：
- Feature目标/边界及Story/AC完整集合（含失败/取消/未就绪，不为凑数滤掉）；确认范围决定哪些允许执行，但仍记录未执行义务。
- PRD适用条款，UI页面/弹窗/菜单/状态/视口/主题/数据版本及继承/替代，LLD接口/异常/权限/性能等必需约束，DB适用设计。
- 规则/授权、读取权限、实现文件范围、依赖产物、接口schema/hash、评审必修条件和验证器能力。
- 每项义务：`id, sourceAnchor, sourceHash, requirementKind, applicability, ownerStory, taskIds, implementationRefs, verificationMethod, evidenceRefs, status`。

完整性算法：集合差集查孤立义务/任务、UI缺页、接口字段未定、无验证方法；必需源不可读或冲突拒绝ready。可选正文按需加载，但未确认读取/覆盖不能当已满足。源选择理由/截断必须可见，缓存只能在相同源修订与权限下使用；源hash不证明内容正确。

## 2. 小上下文与外部检查点

- **常驻执行卡**：单Feature/当前Story/原授权、阻断项、禁止项、必需义务ID/短规则、源版本、当前步骤。不能只剩任务标题。
- **按需上下文**：当前Story完整AC/涉及UI状态/对应LLD契约、最小代码片段；全量义务清单存外部，任一义务可定位原文。检索用于找材料，不能用于决定“没检索到的要求不存在”。
- **检查点**：阶段/进度/义务状态、baseline hashes、HEAD/worktree与未提交diff指纹、已做工具动作/证据、未知副作用、writer租约/代次、失败/未验证、下一步。完整日志/正文仍文件存储，DB只结构化索引与状态，不复制第二可编辑正文。
- **恢复握手**：验证相同Feature/授权→当前源对账→旧writer停止或租约/fence复核→真实磁盘/未提交diff/证据修订复核→当前Story/未做义务回述→准入。缺项、变更或未知副作用阻塞，不靠“摘要里说完成了”重建。
- token预算使用适配器真实计数/可信上限与本平台校准的有效窗口；未知不猜。初版可按任务容量配置保守预算，但阈值须试测后确定，不硬套论文32K或仅按百分比宣称安全。
- 触发主动检查点：阶段结束、源更新、接近已验证预算、长工具输出、模型失败/压缩/fresh、writer交接。长日志外部存全量、输入只保关键错误+引用，禁止为省token漏必需义务。

## 3. 覆盖与完成门禁

- G-SOURCE：必需源、授权、UI适用性/可查看稿/状态覆盖/确认版本及验证器能力都明确，且ready范围合法。
- G-SCOPE：执行会话单Feature，任务/child/工具动作及允许文件匹配；跨域共享文件靠责任包/资源锁和接口契约，不靠“顺手”。
- G-COVERAGE：每个被确认的义务有任务/实现/验证映射；未知、不适用、取消有独立依据，不默认通过。
- G-EVIDENCE：技术、功能、视觉、权限各按对应方法和版本核验；模型自评/三票多数仅输入，确定性检查通过也不能证明语义正确。
- G-RELEASE：全部必需结果有效、无开放阻断差异、集成回归及真实用户/事前客观验收依据满足，才允许对应Story完成。缺视觉能力可交付部分源码报告，但不能标视觉或整体完成。
- 新源/实现版本只使相交范围证据失效；过期与未执行独立显示。生成完成摘要从控制层有效台账读取，不自由填写passed count。

## 4. UI、DB与实施边界

### UI缺口（未制作，不能编码）

需要在既有派发预检/任务详情/AI会话/交接/交付中可查看：当前Feature/Story与角色、包版本和必读源、全义务覆盖/缺口、跨Feature拒绝、恢复对账/旧writer未知、视觉验证器不可用/过期证据、限定集成。保既有外壳/品牌/对象Tab，不新增并列入口；先补可操作稿、状态/版本登记，再正式UI开发。本轮不动原型脚本。

### 数据设计结论（仅方案）

未来Session与ExecutionPlan需要不可变binding引用，持久包manifest/检查点/义务与证据关联；复用DB-FEAT-019/DB-CR031计划/租约/效果去重/outbox，不另起全局记忆数据库。新增字段/表、迁移兼容窗口及恢复策略在获开发授权前补专属DB设计，本次不迁移。

### 推荐实施顺序与会话划分

- FEAT-018独立包：STORY054源清单/义务编译与工作包预检。
- FEAT-019独立包：STORY068单Feature身份；STORY059外部检查点恢复；先建立G-SCOPE/G-RESUME，再接真实适配器。
- FEAT-020独立包：STORY055覆盖/证据fail-closed与STORY042/043完成汇总；不以runner结束代验收。

协调会话只读编排三个包，不写三个Feature源码。各包有各自设计/授权/文件/测试/交付，集成按冻结候选授权，不占用超长开发会话。

## 5. 验证策略与来源

设计测试：注入漏一个AC/UI空态/接口字段；换设计hash；文档入口迁移漏页；长日志干扰后恢复；同会话加第二Feature；同Feature子包跨界；缺检查点/过期证据；模型无视觉；新writer停止未知；生成报告虚构全通过。必须拒绝/保状态/列缺项，不自动删标准。

目标分开报告：越界拒绝率、已注入漏项检测率、强制AC漏证放行数（验收目标0）、模型实现遗漏率、视觉偏离/恢复信息损失率。闭环测试全检输入集合/版本/结果，不用“若干测试passed”替代分母；模型能力比较采用同任务/版本/数据/预算对照，样本不足不宣称永久有效。
