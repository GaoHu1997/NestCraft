# ADR-001：计算引擎选型

- 状态：已采纳（2026-11-20）
- 关联：[LLD-FEAT-001](LLD-FEAT-001-实现方案.md)、[STORY-001](../Plan/Story/STORY-001-四则运算与连续计算.md)

## 背景

计算器需要支持四则运算与连续运算。可选实现有三类：

1. 用 `eval`／`new Function` 直接求值表达式字符串。
2. 引入第三方表达式解析库（如 mathjs）。
3. 自研显式状态机，按「左值 + 运算符 + 右值」顺序计算。

## 决策

采用 **方案 3：显式状态机 + 纯函数求值**。

## 理由

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| `eval` | 实现最短 | 安全风险、被 CSP 禁止、错误信息不可控、不符合零依赖 | 否决 |
| 第三方库 | 支持优先级与函数 | 引入依赖与打包步骤，超出本次范围（无优先级需求） | 否决 |
| 状态机 | 行为完全可控、可逐动作测试、无依赖、错误路径明确 | 不支持括号与优先级 | **采纳** |

顺序计算的语义与实体计算器一致（`2 + 3 × 4` 得 `20`），符合目标用户预期，也是 [PRD-001](../PRD/PRD-001-计算器需求规格.md) 明确的范围。

## 后果

- 后续若需要科学计算，需要在状态机上扩展动作与一元函数，而非替换解析器。
- 求值逻辑集中在 `apply()`，便于补充运算类型与单元测试。
