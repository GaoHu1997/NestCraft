# 产品定位：一句话与价值主张

> 资料版本：2026-11-21 · 内部对齐用 · 来源于平台现行功能与设计文档整理

## 一句话定位

栖造 NestCraft 是一个以「项目」为中心的个人 AI 工作台：把需求、设计、代码、文档、知识库、服务器与 AI 会话放在同一个窗口里，让工作过程可见、内容可追溯、结论可复核。

## 三句补充说明

1. **一个项目，一套上下文**：项目的需求树、设计资料、代码文件与 AI 会话共享同一个本地目录，不再在多个工具间搬运上下文。
2. **多模型、多 CLI**：内置 Anthropic / OpenAI 兼容协议接入、Claude Code / Codex / Grok 等 CLI 管理，同一会话可切换模型与思考档位。
3. **本地优先**：项目正文以 Markdown 存在本地目录，索引、授权与会话记录存本地 SQLite；知识库是受管本机目录，AI 读取需要显式授权。

## 价值主张对照表

| 用户痛点 | 传统做法 | NestCraft 的做法 |
| --- | --- | --- |
| 需求、设计、代码分散在多个工具 | 聊天记录 + 文档 + IDE 三处切换 | 项目工作区四页签：需求 / 设计 / 任务 / 编码 |
| AI 不懂项目上下文 | 每次手工粘贴背景 | 项目目录即上下文，需求源与文件可按需引用 |
| 知识资料无法被 AI 安全使用 | 直接上传到公网服务 | 本地知识库 + 按库按项目授权，AI 只读 |
| 多个 CLI 各自配置 | 每台机器重复配置 | 统一 SDK 安装、命令工具与参数映射 |
| 过程不可回溯 | 只留结果 | 会话历史、工具调用、步骤、用量都能回看 |

## 目标用户

- **独立开发者**：一人负责需求、实现与运维，需要把零散工作收进一个窗口。
- **小团队技术负责人**：需要可复核的需求—设计—代码链路，便于评审与交接。
- **知识密集型个人**：有大量本地资料（Word、PPT、PDF、图纸），希望 AI 能在授权范围内引用。

## 不做什么

- 不做多人实时协同编辑（当前为个人工作台定位）。
- 不做云端托管知识库与账号体系。
- 不替用户决定模型与费用：模型、密钥、端点都由用户配置。
- 不隐藏不确定性：未验证的能力、示例数据、仿真内容在界面上明确标注。

## 差异化

与「聊天窗口 + 插件」类工具相比，NestCraft 的关键差异是**以项目为单位组织事实**：需求有稳定编号与源文件、设计有版本与覆盖登记、验证有报告与证据。AI 在其中是协作者，而不是唯一的事实来源。
