# 项目与需求工作流

> 适用版本：平台 0.0.1 · 更新 2026-11-21

## 1. 项目是什么

一个项目 = 一个本地目录 + 一条数据库记录。目录里放真实文件，数据库只存索引、授权与配置。

- 项目类型：`code`（编码项目）与 `work`（办公项目）。
- 项目根目录由用户选择，平台不移动、不改写目录外内容。
- 项目身份（项目编号）创建后固定，改名与更换目录都不改变编号。

## 2. 需求树从哪里来

需求不是数据库里手工录入的，而是**从项目目录的 Markdown front matter 解析出来的投影**：

```text
项目根/
└── docs/
    └── Plan/
        ├── VISION-001-产品愿景.md
        ├── Epic/EPIC-001-目标.md
        ├── Feature/FEAT-001-能力.md
        └── Story/STORY-001-故事.md
```

每个文件头部：

```markdown
---
id: STORY-001
type: story
parent: FEAT-001
title: 四则运算与连续计算
status: 开发中
owner: 前端组
---
```

规则：

| 字段 | 作用 | 缺省行为 |
| --- | --- | --- |
| `id` | 稳定编号，树节点身份 | 缺失则不进入索引树，但全文仍可阅读 |
| `type` | `vision/epic/feature/story/bug` | 缺失时按文件名前缀推断 |
| `parent` | 上级编号 | 缺失则为根节点，不会被自动猜测 |
| `status` | 汇总视图状态 | 缺失显示为空 |
| `owner` | 负责人 | 缺失显示为空 |

## 3. 需求页签怎么用

1. 打开项目 → 「需求」页签，左侧是完整源清单（含未登记编号的文档，标注警告）。
2. 点击条目在右侧阅读全文，支持源码/预览切换。
3. 新建需求时平台按类型写入对应目录，并自动分配下一个编号。
4. 修改状态或验收标准会写回源 Markdown，不写数据库副本。

## 4. 四页签职责

| 页签 | 内容 | 事实来源 |
| --- | --- | --- |
| 需求 | 愿景、Epic、Feature、Story 与验收标准 | `docs/Plan/**/*.md` |
| 设计 | PRD、UI、LLD、DB 文档 | `docs/PRD`、`docs/UI`、`docs/LLD`、`docs/DB` |
| 任务 | 派发树与运行记录 | 会话与运行记录（未接入时显示空态，不编造数据） |
| 编码 | 文件树、编辑器、Git 面板 | 项目目录与 Git 仓库 |

## 5. 常见问题

**Q：为什么需求树里没有我刚写的文件？**
A：先确认文件在 `docs/Plan/` 下、扩展名为 `.md`，且 front matter 有 `id`。保存后回到需求页签刷新。

**Q：可以手改 front matter 吗？**
A：可以。平台每次读取都会重新扫描并重建投影，手改不冲突。

**Q：删除项目会删目录吗？**
A：不会。删除只移除项目记录、需求索引与知识授权，磁盘目录保持原样。

**Q：一个项目能有多个 AI 会话吗？**
A：可以。会话按项目归档，历史全部保留；同一项目可并行多个会话，但执行型会话需绑定单一特性。
